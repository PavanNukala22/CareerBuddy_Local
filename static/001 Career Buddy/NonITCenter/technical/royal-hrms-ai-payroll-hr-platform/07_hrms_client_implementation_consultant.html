    Module 01

    The Client Implementation Consultant

    How a new enterprise customer goes from signed contract to first live payroll on Royal HRMS — the consultant's responsibilities, the implementation methodology, and the four core skills: onboarding, legacy data migration, policy configuration and UAT.

    🧭 Course Overview: What the Role Is

    The Implementation Consultant turns a signed deal into a working Royal HRMS deployment. You run workshops, understand the customer's HR and payroll policies, migrate their data from legacy systems, configure the platform, lead testing, and support go-live. Your success metric: on-time, accurate first payroll and confident users.

    🚀
    Enterprise onboarding
    Kick-off, governance, plans, RACI, change management.
    🧹
    Legacy data extraction & cleansing
    From spreadsheets, Tally, SAP, old HRMS to clean templates.
    ⚙️
    Custom policy configuration
    Leave, attendance, pay structures, workflows — without code.
    ✅
    User acceptance testing
    Scripts, parallel payroll runs, defect triage, sign-off.

    🎯 Learning Objectives

    By the end of this course you will be able to:

    1. Run an enterprise HRMS implementation from kick-off to hypercare using a phased methodology.
    2. Set up governance: RACI, steering committee, RAID log and honest status reporting.
    3. Extract, profile, cleanse, validate and reconcile legacy HR and payroll data, including opening balances.
    4. Translate HR and payroll policies into Royal HRMS configuration with effective dating.
    5. Plan and lead UAT, defect triage and parallel payroll runs with variance analysis.
    6. Make criteria-based go-live decisions and manage change and adoption.
    7. Recover troubled implementations and manage scope.

    Module 02

    Enterprise Onboarding

    Starting an enterprise implementation right — kick-off, governance and RACI, discovery workshops, the configuration workbook, project plans and status reporting, risk management and change management.

    🚀 Basic: The Kick-off

    The kick-off aligns everyone on scope, timeline, roles and ways of working. Invite the customer sponsor (CHRO/CFO), HR and payroll leads, IT, and your Royal HRMS team.

    • Confirm scope from the contract: modules (core HR, attendance, payroll, ESS), entities, countries, employee count.
    • Agree key dates: discovery complete, UAT start, first parallel run, go-live payroll month.
    • Introduce governance: weekly status call, fortnightly steering committee, RAID log.
    💡
    Pick the go-live month carefully. Avoid financial year-end (March in India) and bonus months; mid-quarter months are safest for payroll go-lives.

    🧹 Basic: What Gets Migrated

    Data setExamplesCriticality
    Employee masterIDs, names, DOJ, department, location, grade, managerMust be complete before anything else
    Statutory IDsPAN, Aadhaar (masked), UAN, ESIC numberRequired for payroll compliance
    Bank detailsAccount, IFSCRequired for disbursement

    pythonimport re
def clean_ifsc(x: str | None):
    if not x: return None, "missing"
    v = re.sub(r"\s", "", x).upper()
    return (v, None) if re.fullmatch(r"[A-Z]{4}0[A-Z0-9]{6}", v) else (v, "invalid_ifsc")

LOCATION_MAP = {"hyd": "LOC-HYD", "hyderabad": "LOC-HYD", "hyd-1": "LOC-HYD", "blr": "LOC-BLR"}
emp["location_code"] = emp["Location"].str.strip().str.lower().map(LOCATION_MAP)
unmapped = emp[emp["location_code"].isna()]["Location"].unique()   # send back to customer
    ⚠️
    Never "fix" data silently. Every transformation needs a rule, and every exception goes back to the customer in an error report — they own their data.

    Module 04

    Custom Policy Configuration

    Translating a customer's HR and payroll policies into Royal HRMS configuration — leave and attendance rules, shifts, salary structures and components, statutory settings, approval workflows, eligibility and effective dating.

    ⚙️ Basic: Configuration, Not Customisation

    ✅ Configuration

    Using Royal HRMS settings, rules and formula builders. Upgrade-safe, supported, fast.

    ❌ Customisation

    Custom code for one customer. Slow, risky, breaks upgrades — avoid unless approved by product.

    Your job is to find the closest configuration that meets the policy intent, and to push back (politely, with options) when a policy is unusual or unclear.

    🗓️ Intermediate: Leave & Attendance Rules

    yamlleave_policy:
  - code: PL
    accrual: {amount: 1.25, frequency: monthly, start: after_probation}
    carry_forward: {max: 45, at: year_end}
    encashment: {on_exit: true, max_days: 30}
    sandwich_rule: true            # weekends between leaves counted
    applicable_to: {employment_type: [permanent], locations: all}
attendance_policy:
  shift: GENERAL_0930_1830
  grace_minutes: 15
  late_marks_to_half_day: 3        # 3 late marks = half-day LOP
  overtime: {eligible_grades: [W1, W2], after_minutes: 30, rate: 2.0}
  regularisation: {max_per_month: 3, approver: reporting_manager}
    📌
    Ask about edge cases: joining mid-month accrual, probation, leave during notice period, negative balances, holidays falling on weekly offs.

    ⚖️ Advanced: Parallel Run & Variance Analysis

    Run at least two parallel payrolls. Compare employee by employee, component by component.

    pythonlegacy = pd.read_csv("legacy_sep_payroll.csv")      # emp_code, component, amount
rhrms  = pd.read_csv("rhrms_sep_payroll.csv")
cmp = legacy.merge(rhrms, on=["emp_code", "component"], how="outer",
                   suffixes=("_legacy", "_rhrms")).fillna(0)
cmp["diff"] = cmp.amount_rhrms - cmp.amount_legacy
issues = cmp[cmp["diff"].abs() > 1]                    # tolerance ₹1 for rounding
summary = issues.groupby("component")["diff"].agg(["count", "sum"]).sort_values("count", ascending=False)
print(summary.head(10))

    Real-World Scenarios & Troubleshooting

    Situations implementation consultants face on real Royal HRMS projects.

    📉 Troubleshooting: 300 Net Pay Variances in Parallel Run

    Investigation: group by component — 260 variances in Professional Tax.

    • Cause: employees' work location state mapped from legacy "Office" field, which used billing office not work site.
    • Fix: map location from attendance site; rerun; variances down to 6, all explained by legacy rounding.
    💡
    Always group variances by component first — one root cause usually explains most differences.

    🧑‍💼 Scenario: Customer Wants a Custom Bonus Formula

    Customer insists on a bonus based on attendance %, rating and tenure with caps. Approach: model with the formula builder (attendance % and rating as inputs, tenure via lookup table), demonstrate in sandbox, document. If impossible, raise a product request with business impact — do not promise custom code.

    Module 11

    Interview Preparation

    Questions asked for HRMS/payroll implementation consultant roles.

    🌱 Beginner Interview Questions

    IQ1.What are the phases of an HRMS implementation?
    Initiate, discover, configure, migrate, test (SIT/UAT/parallel), go-live, hypercare.
    IQ2.What is a parallel run?
    Running payroll in legacy and new systems for the same period and comparing results employee by employee to validate accuracy.
    IQ3.Why are opening balances important?
    For mid-year go-lives, YTD earnings and taxes drive correct tax projections, statutory returns and annual statements.

    🛠️ Intermediate Interview Questions

    IQ4.How do you handle poor-quality legacy data?
    Profile, define cleansing rules, automate fixes where rules are clear, send error reports for customer decisions, mock loads, reconcile.
    IQ5.How do you run discovery workshops?
    By process with real data and policy documents, capture decisions in a configuration workbook, clarify edge cases, get sign-off.
    IQ6.How do you prioritise defects in UAT?
    Severity based on impact and workaround, S1 must be fixed, classify root cause (config/data/product/expectation), retest and track.

    🚀 Advanced Interview Questions

    IQ7.A customer wants custom code for a policy. What do you do?
    Understand intent, find configuration alternatives, demonstrate in sandbox, explain upgrade risks, escalate as product request with impact if needed.
    IQ8.How do you explain parallel-run variances?
    Group by component and cause, fix config/data issues, document legacy errors and timing differences, present a variance report for sign-off.
    IQ9.How do you manage a slipping timeline?
    Make it visible early in RAID and status, analyse critical path, options (resources, scope, date), steering committee decision, protect payroll quality.

    🏆 Expert Interview Questions

    IQ10.How would you run a 10-country rollout?
    Global template plus local statutory deltas, phased waves, reusable migration accelerators, local partners for statutory validation, PMO governance, lessons learned per wave.
    IQ11.How do you handle a difficult customer HR head?
    Listen for underlying concerns, provide facts and options, keep commitments visible, involve sponsors constructively, celebrate progress.
    IQ12.What does a great hypercare plan include?
    Named support roster, daily triage, SLA, known-issue list, payroll-day war room, adoption tracking, exit criteria to BAU support.
