    Monolith

    One deployable unit; simple to start, harder to scale parts independently.

    Microservices

    Many small services; independent scaling and deploys, but more operational complexity.

    🧩 Scalable microservices

    Design stateless services behind an API gateway (auth, routing, rate limits) and use asynchronous messaging to decouple them and absorb spikes. Consumers must be idempotent because delivery can repeat.

    pythondef consume(event, seen):
    if event.id in seen:      # at-least-once delivery
        return
    seen.add(event.id)
    process(event)

    🎥 WebRTC for video assessments

    Peers cannot connect without help. A signaling server exchanges offers, answers and ICE candidates. STUN finds a public address; TURN relays media when direct paths fail. For one candidate plus several reviewers, an SFU scales better than a full mesh.

    📊 Real-time analytics

    Flow: clients and services emit events → a log such as Kafka → a stream processor aggregates in windows (a tumbling window is a fixed, non-overlapping interval) → a fast store → dashboards. Track consumer lag so dashboards stay fresh.

    Advanced Architecture and Real-World Practice

    Handle scale, failure and compliance.

    🚀 Advanced concepts

    • Noisy neighbour: per-tenant quotas and rate limits.
    • Sagas: compensating steps instead of distributed transactions.
    • Backpressure: scale consumers and watch lag.
    • Data residency: regional deployments per tenant.
    • Media quality: use WebRTC stats for adaptive decisions.

    🏗️ Real-world project

    Scenario: 300 employers run automated video assessments on one platform.

    1. Define services and event contracts.
    2. Choose a tenancy model per customer tier.
    3. Design the SFU and TURN setup.
    4. Build the analytics pipeline and tenant dashboards.
    5. Load test with one oversized tenant.

    ⭐ Best practices

    • Propagate tenant and trace IDs everywhere.
    • Make consumers idempotent.
    • Always provide TURN over TCP/TLS.
    • Enforce isolation in the database, not only in code.

    ⚠️ Errors and troubleshooting

    Error

    One big tenant slows everyone.

    Correction

    Per-tenant rate limits and resource quotas.

    Error

    Candidates behind firewalls cannot connect.

    Correction

    Add TURN, including TCP on port 443.

    Error

    Dashboard counts are inflated.

    Correction

    Idempotent processing keyed by event ID.

    Why does WebRTC need TURN?NAT and firewall failures; relay fallback.

    “Dashboards are 5 minutes behind.” Walk through: check consumer lag, partitions, processing time, scale consumers, apply backpressure and alert on lag.
