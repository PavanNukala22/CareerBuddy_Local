Tokenization: turn text into usable units

Tokenization breaks text into tokens. The source demonstrates both sent_tokenize() and word_tokenize(), including punctuation as tokens and handling of contractions. fileciteturn3file0L483-L599

Python — word and sentence tokenization
from nltk.tokenize import sent_tokenize, word_tokenize

text = "NLP is useful. It helps computers process language!"

sentences = sent_tokenize(text)
tokens = word_tokenize(text)

print(sentences)
print(tokens)
▣
Intermediate: tokenization is a design choice
  • Sentence tokens are useful for document structure and sentence-level classification.
  • Word tokens are useful for lexical analysis, POS tagging and feature extraction.
  • For social media, code, URLs or domain-specific text, generic tokenization may need additional rules.
▣
Advanced: tokenization errors become downstream errors

If a URL is split incorrectly, a product code is broken into pieces, or a negation is lost, later stages inherit the mistake. Always test tokenization against representative data.

●
PracticeTry: “I can't access my account—please help!”. Inspect contractions, punctuation and the em dash.

Stop words: remove noise carefully

Stop words are frequent words that may carry limited discriminative value. The source demonstrates filtering with NLTK's English stop-word list and explicitly highlights the danger of removing not because it can reverse sentiment meaning. fileciteturn3file1L127-L139 fileciteturn3file1L729-L753

Python — task-aware filtering
from nltk.corpus import stopwords
from nltk.tokenize import word_tokenize

text = "I am not happy with this service."
stop_words = set(stopwords.words("english"))

tokens = word_tokenize(text)
filtered = [w for w in tokens if w.casefold() not in stop_words]

print(filtered)
Intermediate

When it can help

Bag-of-words style search or classification can sometimes benefit from reducing very frequent function words.

Advanced

When it can hurt

Sentiment, question answering, intent detection and phrase-level tasks may need words such as not, no or never.

●
Rule of thumbDo not remove a token merely because a library calls it a stop word. Remove it only when experiments show that the downstream task benefits.

Stemming: fast normalization, imperfect roots

Stemming reduces related word forms by stripping affixes. The source demonstrates PorterStemmer and shows outputs such as discoveri and discov, illustrating that a stem does not have to be a real dictionary word. fileciteturn3file2L757-L800

Python — compare words with a stemmer
from nltk.stem import PorterStemmer

stemmer = PorterStemmer()

words = ["connect", "connected", "connecting", "connection", "connections"]

for word in words:
    print(word, "->", stemmer.stem(word))

Engineering decisionUse stemming when speed and coarse normalization matter. Prefer lemmatization when preserving interpretable base words is important.

Lemmatization: normalize to a dictionary base form

Lemmatization aims to map an inflected word to a meaningful base form, using linguistic information rather than only suffix stripping.

Python — WordNet lemmatizer
import nltk
nltk.download("wordnet")

from nltk.stem import WordNetLemmatizer

lemmatizer = WordNetLemmatizer()

for word in ["cars", "running", "better", "studies"]:
    print(word, "->", lemmatizer.lemmatize(word))
▣
Stemming vs lemmatization

Stemming: faster, heuristic, can produce non-words.

Lemmatization: more linguistically meaningful, but requires language resources and correct context/POS information.

▣
POS-aware lemmatization

A word can have different lemmas depending on whether it is used as a noun or verb. Supplying the appropriate POS can improve the result.

Python — POS-aware example
from nltk.stem import WordNetLemmatizer

lemmatizer = WordNetLemmatizer()

print(lemmatizer.lemmatize("better", pos="a"))
print(lemmatizer.lemmatize("running", pos="v"))
print(lemmatizer.lemmatize("studies", pos="v"))

POS Tagging: add grammatical information

Part-of-Speech (POS) tagging assigns a grammatical label to each token. It is useful before chunking, linguistic analysis and some feature-engineering workflows.

Python — POS tagging
import nltk
from nltk.tokenize import word_tokenize

text = "The quick brown fox jumps over the lazy dog."
tokens = word_tokenize(text)
tags = nltk.pos_tag(tokens)

for token, tag in tags:
    print(f"{token:12} {tag}")

Chunking: group tokens into meaningful phrases

Chunking groups POS-tagged tokens into shallow syntactic structures such as noun phrases. The source uses nltk.RegexpParser with the grammar NP: {<DT>?<JJ>*<NN>}. fileciteturn3file5L277-L305

Python — noun phrase chunking
import nltk
from nltk.tokenize import word_tokenize

text = "It is a dangerous business, Frodo."
tags = nltk.pos_tag(word_tokenize(text))

grammar = "NP: {<DT>?<JJ>*<NN>}"
parser = nltk.RegexpParser(grammar)

tree = parser.parse(tags)
print(tree)

Read the grammar as: optional determiner → zero or more adjectives → noun. This is shallow parsing; it is not a complete syntactic parse of the sentence.

●
Practical useChunking can help extract product descriptions, noun phrases, titles, candidate keywords and simple information patterns without building a full parser.

Chinking: remove unwanted patterns from a chunk

Chinking is the complementary operation to chunking: you define patterns that should be removed from an existing chunk. It is useful when a broad chunk rule captures too much text.

Python — chunk then chink
import nltk
from nltk.tokenize import word_tokenize

text = "The very fast delivery service"
tags = nltk.pos_tag(word_tokenize(text))

grammar = r'''
  NP: {<DT>?<JJ>*<NN>*}
      }<RB>{
'''
parser = nltk.RegexpParser(grammar)
print(parser.parse(tags))
●
Think like an engineerChunking asks what belongs together? Chinking asks what should be removed from that group? Start with a small grammar, inspect errors, then refine it.

Named Entity Recognition (NER): find real-world entities

NER identifies spans of text that refer to entities such as people, organizations, locations, dates and monetary values. The source demonstrates the pipeline tokenize → POS tag → ne_chunk() and extraction of named entities. fileciteturn3file6L336-L359

Python — NLTK NER
import nltk
from nltk.tokenize import word_tokenize

text = "Google hired Riya in Hyderabad for $5,000."

tokens = word_tokenize(text)
tags = nltk.pos_tag(tokens)

tree = nltk.ne_chunk(tags)

print(tree)

Text Analysis: understand a corpus before modeling

The source tutorial includes concordance, frequency distributions and collocations as core analysis tools. fileciteturn3file8L431-L453

Python — frequency and lexical analysis
from collections import Counter
from nltk.tokenize import word_tokenize

text = "NLP helps people search text. NLP also helps classify text."

tokens = [t.casefold() for t in word_tokenize(text) if t.isalpha()]
freq = Counter(tokens)

print(freq.most_common(10))

Build a reusable NLP preprocessing pipeline

Instead of writing unrelated snippets for each dataset, structure preprocessing as explicit stages. This makes experiments reproducible and lets you turn individual steps on or off.

Python — configurable pipeline
from nltk.tokenize import word_tokenize
from nltk.corpus import stopwords
from nltk.stem import WordNetLemmatizer

STOP = set(stopwords.words("english"))
LEMMA = WordNetLemmatizer()

def preprocess(text, remove_stopwords=True, lemmatize=True):
    tokens = word_tokenize(text.casefold())
    tokens = [t for t in tokens if t.isalpha()]

    if remove_stopwords:
        tokens = [t for t in tokens if t not in STOP]

    if lemmatize:
        tokens = [LEMMA.lemmatize(t) for t in tokens]

    return tokens

print(preprocess("Cats are running quickly."))
Intermediate

Make every step testable

Input → output examples should exist for tokenization, normalization and feature extraction.

Advanced

Prevent training/serving mismatch

The exact preprocessing contract used during training should also be used when new data reaches production.

Advanced NLP: where NLTK fits today

Modern NLP often combines several layers rather than choosing one library for everything.

Foundation

NLTK

Tokenization, corpora, stemming, WordNet, POS tagging, chunking and classical NLP learning.

Modern representation

Embeddings

Represent text as dense vectors for semantic similarity, retrieval and clustering.

Modern AI

Transformers / RAG

Use contextual language models for richer understanding and generation, often with retrieval.

Production practice: what experienced engineers watch

▣
Data quality
  • Duplicate documents
  • Encoding problems
  • Unexpected HTML/markup
  • Very long or empty inputs
  • Domain-specific abbreviations
▣
Reproducibility
  • Pin compatible dependencies
  • Record preprocessing configuration
  • Version training data
  • Test language resources
  • Keep train/serve transformations consistent
▣
Evaluation
  • Create a representative test set
  • Measure task-specific metrics
  • Inspect failure cases
  • Test edge cases and negation
▣
Security & privacy
  • Do not log sensitive raw text unnecessarily
  • Protect uploaded documents
  • Restrict access to extracted entities
  • Consider data retention requirements
●
Debugging sequenceWhen an NLP result looks wrong, inspect the pipeline in order: raw text → tokens → normalized tokens → POS/NER → features → model output. The bug is often earlier than the final prediction.
