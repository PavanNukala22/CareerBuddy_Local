    Module 01 · Foundations

    What Technical Triage Means

    Triage is deciding quickly what kind of problem you're looking at and what to do first. Learn a repeatable five-step method, the questions that save hours, and how to classify issues.

    🩺 Triage in One Picture

    The word comes from hospital emergency rooms: a nurse quickly checks each patient to decide what's wrong and how urgent it is before treatment. In support, technical triage means quickly working out whether a problem is user error, a known issue, a browser/device problem, an account problem, or a genuine bug, and fixing the simple ones on the spot.

    Figure 1.1 · The triage flow
    💡
    Most Tier 1 technical tickets are solved by steps 1–4. The skill is doing them quickly and in the right order.

    🪜 The Five-Step Method

    1. Understand: what is the customer trying to achieve, and what happens instead? Separate the goal ("send invoices") from the symptom ("button does nothing").
    2. Gather: who is affected, which browser/device, since when, exact error message, screenshot.
    3. Check what's known: the status page, any active incident, the knowledge base, recent similar tickets.
    4. Try quick fixes: refresh, incognito window, clear cache/cookies, another browser, log out and in, reset password.
    5. Reproduce and escalate: if it still fails, try it on a test account and escalate with full notes.
    ⚠️
    Skipping step 3 is the most common mistake. If the whole service is down, asking customers to clear their cache wastes their time and makes support look uninformed.

    ❓ Asking the Right Questions

    Ask for everything you need in one message. Every extra back-and-forth adds hours on email.

    🗂️ Classifying the Issue

    CategorySignsTypical next step
    How-to / user errorProduct works as designed; customer unsure howExplain + KB link
    Known issue / incidentStatus page shows an incident; many similar ticketsLink to incident, share status updates
    Browser / deviceWorks in another browser, incognito or deviceCache, cookies, extensions, update browser
    Account / accessCan't log in, missing permission, locked accountCredential checks, permissions, reset
    NetworkWorks at home, not at office; timeoutsAsk about VPN/firewall; involve their IT
    Possible bugReproducible, contradicts documentationReproduce, document, escalate
    📌
    Classify first, fix second. The category tells you which checks to run and which team owns it.

    ⬆️ When to Stop and Escalate

    • You've worked through the standard checks and the KB has no answer.
    • You can reproduce something that contradicts the documentation (likely a bug).
    • You need access you don't have (logs, admin tools, database).
    • Several customers report the same thing within a short time (possible incident).
    • There's a security concern (unknown logins, suspected account takeover).
    • You've reached your team's time-box (often 15–20 minutes at Tier 1).
    ✅
    Escalating with a clear summary, what you tried, and evidence is a skill, not a failure. It's exactly what Tier 2 wants from you.

    Module 02 · Background

    How Web Apps Work (for Support)

    You don't need to code, but knowing what happens between the customer's browser and our servers tells you where a problem probably lives.

    🌐 Browser, Server & Internet

    When a customer uses a web app, three parts work together:

    💻
    Client (browser / app)
    Chrome, Edge, Safari or the mobile app. Shows the page and runs JavaScript.
    🛜
    Network
    Wi-Fi, mobile data, office firewall, VPN. Carries requests back and forth.
    🖥️
    Server
    Our computers that store data and answer requests.

    The browser sends a request ("give me the reports page"), the server sends back a response (the page, or an error). A problem can happen in any of the three parts, and triage is about finding which one.

    🔗 Reading a URL

    Figure 2.1 · Parts of a URL
    • A customer on http:// instead of https:// may see security warnings or redirects.
    • A wrong domain (old bookmark, staging site) can show old or test data.
    • A deleted item in the path gives "not found".
    • The query string holds filters; sharing the full URL helps you see exactly what they see.
    💡
    Ask customers to copy the URL from the address bar. It often reveals the problem instantly, like a bookmark to an old domain.

    ⚖️ Client-Side vs Server-Side

    💻 Client-side (their browser/device)

    • Only one user or device affected
    • Works in incognito / another browser
    • Started after a browser update or new extension
    • Fix: cache, cookies, extensions, update browser

    🖥️ Server-side (our system)

    • Many users affected at once
    • Fails on every browser and device
    • Started at a specific time / after our release
    • Fix: check status page, escalate
    📌
    A quick test: does it happen on a different device or network? If yes everywhere, suspect our side. If only one device, suspect theirs.

    🚦 Status Pages & Incidents

    Most SaaS companies run a public status page (e.g., status.example.com) showing whether each part of the service is operational, degraded or down, plus an internal channel where incidents are announced.

    StatusMeaningWhat you do
    OperationalAll normalTroubleshoot the individual case
    Degraded performanceSlow or partly failingShare the status link; set expectations
    Major outageDown for many usersUse the incident macro; link the ticket to the incident
    MaintenancePlanned downtimeShare the maintenance window
    ⚠️
    If you see a sudden spike of similar tickets and the status page is still green, tell your lead or the incident channel immediately. Support often notices problems before monitoring does.

    🧭 Browsers & Versions

    BrowserEngineNotes
    ChromeChromium/BlinkMost common; DevTools reference browser
    Microsoft EdgeChromium/BlinkBehaves very like Chrome; common in offices
    FirefoxGeckoDifferent engine; good second test browser
    SafariWebKitMac/iPhone; iPhone browsers all use WebKit underneath

    To find the version: Chrome/Edge menu → Help → About; or ask the customer to visit a "what is my browser" site and send the result.

    💡
    Testing in a different engine (e.g., Firefox after Chrome) is a stronger check than Chrome vs Edge, which share an engine.

    🏋️ Practice & Quick Check

    Practice
    P1.A customer's bookmark is https://old.example.com/dashboard and they see "This site can't be reached". What's likely wrong?
    The domain is outdated (the old domain was retired). Give them the current URL (e.g., https://app.example.com/dashboard) and ask them to update the bookmark.
    Practice
    P2.Three customers on different browsers and cities report login failures within ten minutes. The status page is green. What do you do?
    Treat it as a possible incident: alert the lead/incident channel with ticket links, timestamps and error details; tag the tickets consistently; give customers a holding reply that you're investigating, and avoid suggesting cache clearing as the main fix.

    Browser Debugging with DevTools

    Every browser has built-in Developer Tools. Learn the four panels a support rep actually uses: Console, Network, Application and Device mode.

    🧰 Opening DevTools

    BrowserShortcutMenu path
    Chrome / Edge (Windows)F12 or Ctrl+Shift+I⋮ → More tools → Developer tools
    Chrome / Edge (Mac)Cmd+Option+IView → Developer → Developer Tools
    FirefoxF12 / Ctrl+Shift+I☰ → More tools → Web Developer Tools
    SafariCmd+Option+IFirst enable: Settings → Advanced → Show Develop menu
    💡
    Right-click anything on a page → Inspect opens DevTools focused on that element.

    🧾 The Console Panel

    The Console shows messages from the page's JavaScript. Red lines are errors; yellow lines are warnings.

    console (example)Uncaught TypeError: Cannot read properties of undefined (reading 'map')
    at ReportTable (reports.js:214:18)
Failed to load resource: the server responded with a status of 500 ()
    api.example.com/v1/reports?range=30d
    What you seeWhat it suggests
    TypeError / ReferenceErrorA bug in the page's code, or unexpected data. Screenshot and escalate if reproducible.
    Failed to load resource: 4xx/5xxAn API request failed; check the Network panel.
    Blocked by CORS policy / Content Security PolicyConfiguration issue, or an extension/proxy interfering.
    net::ERR_BLOCKED_BY_CLIENTAn ad blocker or privacy extension blocked a request.
    📌
    You don't need to understand the code. A screenshot of the red error lines is gold for Tier 2 and Engineering.

    🌐 The Network Panel

    The Network panel lists every request the page makes, with its status code, size and time.

    1. Open DevTools → Network.
    2. Tick Preserve log (keeps requests after page reloads).
    3. Reproduce the problem.
    4. Look for rows in red or with status 4xx/5xx.
    5. Click a row → Headers (URL, status) and Response (error message).
    StatusMeaningUsual next step
    200OKRequest fine; look elsewhere
    401 / 403Not logged in / not allowedRe-login; check permissions
    404Not foundWrong link or deleted item
    429Too many requestsWait and retry
    500–504Server errorCheck status page; escalate with details
    (failed) / (blocked)Never reached the serverNetwork, VPN, firewall or extension
    💡
    Use the Fetch/XHR filter to hide images and fonts so you only see data requests.

    📱 Application Panel & Device Mode

    🍪 Application (Storage in Firefox)

    Shows cookies, local storage and cached data for the current site. Use Clear site data to reset just this site, which is a quick fix for login loops.

    📱 Device toolbar

    Click the phone/tablet icon (Ctrl+Shift+M) to simulate screen sizes. Use it to reproduce "the button is cut off on my phone" reports.

    📌
    Device mode simulates screen size, not the real mobile browser. For Safari-on-iPhone bugs, you still need a real device or a cloud testing service.

    📸 Getting Evidence from Customers

    Customers can't always describe errors. Guide them to capture evidence:

    EvidenceHow to ask
    Screenshot"Press Windows+Shift+S (Windows) or Cmd+Shift+4 (Mac) and paste it here."
    Console screenshot"Press F12, click the Console tab, reproduce the issue, and screenshot the red lines."
    Screen recording"A short video of the steps helps a lot (e.g., using Loom, or Windows Snipping Tool's record option)."
    HAR file"In DevTools → Network, reproduce the issue, then right-click → Save all as HAR." Only for Tier 2 requests, via secure upload.
    ⚠️
    HAR files and some screenshots can contain session cookies or personal data. Use secure upload links, never public channels, and delete them when done.

    🏋️ Practice & Quick Check

    Practice
    P1.Write simple instructions a non-technical customer could follow to send you a Console screenshot in Chrome on Windows.
    1) Open the page with the problem. 2) Press F12 (or Ctrl+Shift+I). 3) Click the Console tab at the top of the panel. 4) Repeat the action that fails. 5) Press Windows+Shift+S, select the panel, and paste the screenshot into your reply.
    Practice
    P2.In the Network panel you see GET /v1/reports returning 403 for one user, while it returns 200 for their colleague. What's your conclusion?
    403 means the request is authenticated but not allowed. Since the colleague gets 200, the user likely lacks the permission/role to view reports. Ask their admin to check the user's role, or explain how to request access.

    Clearing Cache & Cookies the Right Way

    A large share of "the site is broken" tickets are solved by these fixes. Learn what cache and cookies are, which symptoms point to each, and how to clear them in every major browser.

    🍪 What Are Cache & Cookies?

    🗃️ Cache

    Copies of files (images, stylesheets, scripts) that the browser saves so pages load faster next time. After we release an update, an old cached copy can clash with the new version.

    🍪 Cookies

    Small pieces of data a site stores in the browser, most importantly your login session. Broken or outdated cookies cause login loops and "session expired" errors.

    ✅
    Analogy for customers: the cache is like a photocopy of a notice board: quick to read but possibly out of date. A cookie is like a cloakroom token that proves you already checked in.

    🔎 Symptoms to Recognise

    SymptomLikely cause
    Page looks unstyled or half-loaded after an updateOld cached files
    Buttons do nothing; new feature missing for one userOld cached scripts
    Logged in, then immediately sent back to login (loop)Bad/old cookies
    "Session expired" repeatedlyCookies blocked or corrupted
    Shows a different account than expectedOld session cookie from another login
    Works in incognito but not normallyCache, cookies or extensions
    💡
    The incognito test is your best diagnostic: incognito starts with no cache, no cookies and (by default) no extensions. If it works there, the cause is one of those three.

    🪜 The Fix Ladder

    Start with the fix that costs the customer least effort:

    1. Hard refresh: Ctrl+Shift+R or Ctrl+F5 (Windows), Cmd+Shift+R (Mac).
    2. Incognito / private window test.
    3. Clear data for this site only (keeps them logged in elsewhere).
    4. Disable extensions, especially ad blockers and privacy tools.
    5. Clear all cache and cookies (last resort; logs them out of every site).
    6. Try another browser or device to confirm.
    ⚠️
    Clearing all cookies logs the customer out of email, banking and everything else. Prefer site-only clearing and warn them before suggesting the full clear.

    🧭 Step-by-Step per Browser

    BrowserClear for one siteClear everything
    ChromeClick the icon left of the URL (tune/padlock) → Site settings → Delete dataCtrl+Shift+Delete → choose time range → tick Cookies and Cached images → Delete data
    EdgeIcon left of the URL → Cookies and site data → Manage → delete for the siteCtrl+Shift+Delete → Cookies + Cached images → Clear now
    FirefoxPadlock → Clear cookies and site dataCtrl+Shift+Delete → Cookies + Cache → Clear
    Safari (Mac)Settings → Privacy → Manage Website Data → search site → RemoveSettings → Privacy → Manage Website Data → Remove All
    Safari (iPhone)Settings → Safari → Advanced → Website Data → swipe to deleteSettings → Safari → Clear History and Website Data
    📌
    Menu labels change between browser versions. Keep your team's KB article with current screenshots and link it rather than typing steps from memory.

    🧩 Extensions & Other Culprits

    CulpritExample symptomCheck
    Ad blockers / privacy extensionsChat widget missing, payment form blankDisable for our site, or test in incognito
    Password managersLogin form fields behave oddlyDisable autofill temporarily
    Outdated browserLayout broken, features missingUpdate browser; check supported versions
    Wrong system date/timeCertificate or login token errorsSet clock to automatic
    VPN / corporate proxyPages time out or load partlyTry without VPN or on mobile data
    💡
    Many SaaS companies publish a supported browsers list (often "latest two versions of Chrome, Edge, Firefox, Safari"). Check it before troubleshooting an old browser for an hour.

    Module 05 · Account Access

    Verifying Credentials & Fixing Login Problems

    "I can't log in" is one of the most common tickets. Learn a safe, step-by-step way to diagnose wrong emails, passwords, locked accounts, two-factor problems and SSO, without ever compromising security.

    🌳 The Login Decision Tree

    Figure 5.1 · Narrowing down a login problem
    1. Confirm the exact email they type (typos, old work email, personal vs work address).
    2. Look up the account in the admin tool: does it exist, is it active, locked or suspended?
    3. Check how they log in: password, Google/Microsoft sign-in, or company SSO.
    4. Ask for the exact error message.
    5. Apply the matching fix (reset, unlock, 2FA recovery, SSO admin) and confirm it worked.
    💡
    A surprising number of "can't log in" tickets come from people using a different email from the one on their account, e.g., priya@gmail.com vs priya@acme.com.

    🔑 Passwords & Resets

    SymptomCheck / fix
    "Incorrect password"Caps Lock, keyboard language, autofill of an old password → send reset link
    Reset email not arrivingSpam/junk folder, correct address, company email filter; resend once; check email logs if possible
    Reset link "expired / invalid"Links expire (often 30–60 min) and only the newest works → send a fresh one, click once
    New password rejectedPassword policy (length, special characters, can't reuse old ones) → share the rules
    ⚠️
    Never ask for, accept or type a customer's password, and never set a password for them over chat or email. Always use the official reset flow.

    🔒 Locked & Suspended Accounts

    🔒 Locked

    Usually temporary after too many wrong attempts (e.g., 5 tries → 15-minute lock). Fix: wait, or unlock via admin tool after verifying identity, then reset the password.

    ⛔ Suspended / deactivated

    Done on purpose: unpaid invoice, admin removed the user, or a security/policy action. Don't simply reactivate; find out why and follow policy (billing, account admin, trust & safety).

    📌
    In business accounts, the customer's own admin often controls users. If an admin deactivated someone, support usually can't reverse it without that admin's approval.

    📲 Two-Factor Authentication (2FA)

    2FA adds a second step after the password: a code from an authenticator app, an SMS code, or a security key.

    ProblemLikely causeFix
    Authenticator code "invalid"Phone clock out of syncSet phone date/time to automatic; retry
    SMS code not arrivingNetwork delay, DND/blocking, wrong numberWait 1–2 min, resend once, check number on file
    Lost or new phoneAuthenticator app not movedUse backup/recovery codes; otherwise follow the strict identity-verification process to reset 2FA
    Code works for colleague, not themEach user has their own 2FA setupCheck it's their own device/account
    ⚠️
    Resetting 2FA is a high-risk action because attackers try it too. Follow your company's verification steps exactly, and escalate if anything seems off.

    🏢 SSO & Security Rules

    With SSO (Single Sign-On), users log in through their company's identity provider (Okta, Microsoft Entra ID/Azure AD, Google Workspace) instead of a password with us.

    • If SSO is enforced, password resets with us won't help; the user must log in via their company.
    • "Not assigned to this app" type errors mean their IT admin must grant access in the identity provider.
    • If SSO is down for a whole company, it's usually their identity provider or a certificate that needs renewing on their side.

    Identity verification basics

    • Only discuss or change an account with the verified account owner or an authorised admin.
    • Verify using your company's method (reply from email on file, security questions, last 4 digits of card, admin confirmation).
    • Be extra careful with requests to change the account email or disable 2FA; these are classic account-takeover tactics.
    ✅
    It's always acceptable to say: "For your security, I need to verify a few details before I can make that change." Customers respect it.

    🏋️ Practice & Quick Check

    Practice
    P1.A customer says the password reset link "doesn't work". List your checks in order.
    (1) Ask what happens: expired/invalid message, page error or nothing. (2) Confirm the email address the reset was sent to. (3) Ask them to use only the most recent email (older links are invalidated) within the time limit. (4) Try opening the link in incognito or another browser (link scanners/extensions can consume links). (5) Send a fresh link once; if it still fails, check email/reset logs and escalate.
    Practice
    P2.Someone emails from a Gmail address asking to change the email on a business account to that Gmail and turn off 2FA. How do you respond?
    Treat it as a possible account-takeover attempt. Don't make changes. Reply that for security you need to verify ownership, and follow the verification process (confirmation from the current email on file and/or the account admin). Note the ticket and escalate to trust & safety/security if verification fails or details don't match.

    Module 06 · Reproduction

    Reproducing Straightforward User Errors

    If you can make the problem happen yourself, you can test fixes and hand Tier 2 a clear report. Learn how to set up, reproduce, record and report.

    🔁 Why Reproduce?

    ✅
    Confirms the problem
    Separates a real issue from a misunderstanding.
    🧪
    Lets you test fixes
    Try a workaround before suggesting it to the customer.
    🎯
    Narrows the cause
    Change one thing at a time to see what matters.
    📨
    Better escalations
    Tier 2 trusts reproduced issues and acts faster.
    ⚠️
    Reproduce on a test account or sandbox. Don't click around a customer's live account (or impersonate them) unless policy and the customer allow it.

    🧭 Matching the Customer's Environment

    DetailExampleWhy
    Browser + versionChrome 129Browser-specific bugs
    Operating systemWindows 11 / macOS / Android 14OS-level differences
    Device / screenLaptop 1366px wide; iPhone 13Layout issues
    App version (mobile)v4.2.1Old app versions may have fixed bugs
    Account role / planMember (not Admin); Free planPermissions and plan limits change behaviour
    DataFile size, number of records, special charactersMany bugs need specific data
    💡
    Role and plan matter as much as the browser. "It works for me" often means "I tested as an Admin on the Pro plan, they're a Member on Free".

    👣 Reproducing Step by Step

    1. Write down the customer's steps exactly as described.
    2. Set up a matching environment (browser, role, plan, similar data).
    3. Follow the steps slowly; note each result.
    4. If it fails, repeat once to confirm it's consistent.
    5. Change one variable (browser, role, file size) to see what triggers it.
    6. Capture evidence: screenshot, console error, short screen recording.
    internal note: reproductionReproduced: YES (3/3 attempts)
Environment: Chrome 129, Windows 11, test account (Member role, Free plan)
Steps:
  1. Projects → New project
  2. Name: "Q3 Plan & Budget"
  3. Click Create
Result: spinner, then "Something went wrong"
Variable test: name without "&" → works
Console: 400 on POST /v1/projects (screenshot attached)

    ⚖️ Expected vs Actual

    Every reproduction note and escalation should state both clearly:

    ✅ Expected

    What should happen according to the product's design or documentation.
    "Project is created and opens."

    ❌ Actual

    What really happens, with exact error text.
    "Error: Something went wrong. Project not created."

    ✅
    Expected vs Actual removes guesswork, and it also helps you notice when the "actual" is just how the product is designed, which makes it a how-to or a feature request, not a bug.

    🤷 When You Can't Reproduce

    Not reproducing is still useful information. Report what you tried and what's different about the customer:

    • Ask for a screen recording of the problem happening.
    • Compare environments again: role, plan, data size, browser extensions, network/VPN.
    • Ask if it happens every time or occasionally (and when).
    • Try with data like theirs (large files, many records, special characters).
    • Escalate with "Could not reproduce" plus your test details; Tier 2 can check logs.
    Good "can't reproduce" noteCould not reproduce on Chrome 129 / Firefox 131 with a Member test account and a 2 MB file. Customer's files are 45 MB and they use a VPN; may be size- or network-related. Requested a screen recording; escalating for log check (customer ID 88213).

    Module 07 · Putting It Together

    Common Issue Playbooks

    Ready-made checklists for the problems you'll see every week. Each playbook lists the symptoms, the checks in order, and when to escalate.

    ⬜ Blank or Broken Page

    1. Status page / incident check.
    2. Hard refresh → incognito test.
    3. Clear site data; disable extensions.
    4. Another browser; check it's a supported version.
    5. Console screenshot + Network errors.
    6. Escalate if it reproduces on your side or many users report it.
    💡
    If incognito works, you already know it's cache, cookies or an extension, so you can skip straight to those fixes.

    📭 Emails Not Received

    Covers invitations, password resets, notifications and reports.

    CheckDetail
    AddressCorrect spelling; the address on the account
    Spam / junk / promotionsAsk them to search for our sender name
    Company filtersCorporate email security may quarantine it; IT can allowlist our sending domain
    Notification settingsUser may have turned that email type off
    Resend onceThen wait a few minutes; avoid repeated resends
    Delivery logs (Tier 2)Bounced, blocked or delivered? Share findings
    📌
    If emails reach Gmail but not the company address, the customer's company email system is likely blocking them. Their IT team needs to allowlist us.

    📤 File Upload Fails

    CheckWhy
    File size vs limitMost products have a max size (e.g., 25 MB)
    File typeUnsupported formats are rejected (.heic, .exe…)
    File nameSpecial characters or very long names can break uploads
    NetworkSlow or unstable connection; VPN/proxy
    BrowserExtensions or old browser
    Small test fileIf small files work, it's size/type/network related
    Helpful replyThe file you're uploading is 48 MB and our limit is 25 MB. You can compress it (e.g., export the PDF at "reduced size") or split it into two parts, and both will upload fine.

    🐢 App Is Slow

    QuestionPoints to
    Slow for everyone or just them?Everyone → our side (status page, escalate). One user → their device/network.
    Slow everywhere or one page?One page → maybe large data (reports over long ranges).

    Since when?Matches a release or growth in their data?

    📱 Mobile App Problems

    StepDetail
    VersionUpdate to the latest app version from the store
    RestartForce-close and reopen the app; restart the phone

    Module 08 · Interviews

    Interview Preparation: Basic Technical Triage

    Technical questions and troubleshooting scenarios interviewers use for support roles, with model answers, comparisons and common mistakes.

    🎤 Concept Questions

    QuestionModel answer
    What is technical triage?Quickly classifying a problem (how-to, known issue, browser/device, account, network, bug), applying quick fixes, and escalating with evidence.
    Your first steps for "the site is broken"?Check status page/incidents, ask for screenshot/browser/steps, test incognito, clear site data, try another browser, reproduce, escalate.
    What is cache? What are cookies?Cache stores copies of page files to load faster; cookies store small site data like the login session.
    What do 401, 403, 404 and 500 mean?401 not authenticated, 403 not allowed, 404 not found, 500 server error.
    How do you troubleshoot a login issue?Confirm exact email, check account status, login method (password/SSO), exact error, reset/unlock/2FA steps; never ask for the password.
    Why reproduce an issue?To confirm it, test fixes, find the trigger and give Tier 2 a reliable report.
    Client-side vs server-side?One user/device affected and works elsewhere = client-side; everyone, every browser = server-side.

    📋 Comparison Cheat Sheet

    PairKey difference
    Cache vs CookiesSaved page files vs saved site data/session
    Client-side vs Server-sideUser's browser/device vs company servers
    4xx vs 5xxRequest/user side vs server side
    Console vs Network panelJavaScript errors vs request list with status codes
    Locked vs Suspended accountTemporary after failed attempts vs deliberate action needing policy
    Hard refresh vs Clear site dataReload ignoring cache vs delete cookies + stored data for one site
    Incognito test vs another browserNo cache/cookies/extensions vs different engine/settings
    Expected vs ActualWhat should happen vs what really happens

    🚫 Common Mistakes & Fixes

    MistakeWhy it hurtsDo this instead
    Skipping the status pageWastes time on individual fixes during an outageCheck incidents first
    Asking "more details?" onlyExtra back-and-forthAsk for screenshot, browser, steps, scope in one message
    Suggesting full cookie clear firstLogs the customer out everywhereStart with hard refresh → incognito → site-only clear
    Asking for passwordsSerious security breachUse reset flows and identity verification
    Testing as Admin when the user is a Member"Works for me" false negativesMatch role, plan, browser and data
    Escalating without evidenceTier 2 repeats your workInclude steps, expected vs actual, screenshots, console errors

    🧩 Scenario Questions

    Practice
    P1."A customer sees a blank page after our update. Teammates are fine. Walk me through it."
    Since others are fine it's likely client-side: hard refresh, incognito test; if incognito works, clear site data/disable extensions; check supported browser version; if still failing, collect a console screenshot, browser/OS, reproduce on a test account and escalate.
    Practice
    P2."A user's 2FA codes are always rejected."
    Check the phone's date/time is set to automatic (time-based codes need accurate time), confirm they use their own authenticator entry, try backup codes; if the device is lost, follow the strict identity-verification process to reset 2FA.
    Practice
    P3."How do you explain cookies to a non-technical customer?"
    "Cookies are like a cloakroom token: they prove you've already logged in. If the token gets old or mixed up, the site keeps asking you to log in again, so clearing it for our site gives you a fresh one."
