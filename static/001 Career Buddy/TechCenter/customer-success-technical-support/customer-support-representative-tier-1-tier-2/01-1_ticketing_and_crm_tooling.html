    Help Desk & Support CRM Fundamentals

    Before learning any one tool, understand the ideas every help desk shares: tickets, channels, statuses, fields, and the difference between a help desk and a CRM.

    🎫 Why Ticketing Systems Exist

    Imagine a support team using only a shared Gmail inbox. Two agents reply to the same email, another email is never answered, and nobody knows how long customers wait. A ticketing system fixes this by turning every customer request into a ticket: one record with an owner, a status, a history and timestamps.

    Figure 1.1 · Many channels, one ticketing system
    👤
    Ownership
    Each ticket has one assignee, so nothing is answered twice or forgotten.
    🕓
    Tracking
    Every reply and change is timestamped in one history.
    ⚙️
    Automation
    Rules tag, prioritise and route tickets without manual work.
    📊
    Reporting
    Managers can measure volume, response times and satisfaction.

    🔀 Help Desk vs Support CRM

    The words are often used interchangeably, but there is a difference worth knowing in interviews:

    🎫 Help desk

    Focused on tickets: receiving, assigning, replying, solving. Examples: Zendesk, Freshdesk.

    🗂️ CRM (Customer Relationship Management)

    Focused on the whole customer relationship: sales deals, contracts, marketing and support in one database. Example: Salesforce (Service Cloud is its support part).

    ToolCategoryTypical customers
    ZendeskHelp desk (with CRM-like features)Mid-size to large companies
    FreshdeskHelp deskStartups, SMBs, many Indian companies
    IntercomConversational support / messaging platformSaaS and app companies with in-app chat
    Salesforce Service CloudSupport module of a full CRMEnterprises already using Salesforce for sales
    💡
    A good rule: if support needs to see sales data (contract value, account owner, renewal date), companies lean towards a CRM like Salesforce. If they just need fast, simple ticketing, a help desk is enough.

    🧾 Ticket Fields & Types

    Organization / AccountThe customer's companyLets you see all tickets from the same company.
    Assignee & Group / QueueWho owns it nowGroups (Zendesk), Groups (Freshdesk), Teams (Intercom), Queues (Salesforce).
    PriorityLow, Normal/Medium, High, UrgentBased on impact and urgency, not tone.
    TypeQuestion, Incident, Problem, TaskDrives reports and workflows.

    Ticket types (Zendesk naming, used widely)

    • Question: "How do I…?"
    • Incident: one customer's report of a problem.
    • Problem: the underlying issue that many incidents link to (e.g., an outage).
    • Task: something to do by a date (e.g., call the customer on Friday).

    Zendesk

    One of the most widely used help desks. Learn the Agent Workspace, views, macros, triggers, automations, SLA policies, the knowledge base and reporting.

    🟢 Zendesk at a Glance

    Zendesk is a cloud help desk used by thousands of companies. Its core product for support teams is Zendesk Support (tickets), surrounded by add-ons for chat/messaging, voice, knowledge base and reporting, all in one Agent Workspace.

    PartWhat it does
    SupportTickets, views, macros, triggers, automations, SLAs
    Messaging / ChatLive chat and messaging widget on websites and apps
    TalkPhone support; calls become tickets
    Guide (Knowledge)Help Center articles and community
    ExploreReports and dashboards
    AI agentsBots that answer common questions using Help Center content
    Admin CenterWhere admins configure everything
    📌
    Zendesk statuses: New → Open → Pending → On-hold → Solved → Closed. Solved tickets close automatically after a set period; after that, a customer reply creates a follow-up ticket.

    🖥️ Agent Workspace & Views

    The Agent Workspace shows the ticket conversation in the middle, ticket fields on the left, and the customer's context (other tickets, organisation, apps) on the right.

    AreaWhat you do there
    Views (left sidebar)Pick your queue, e.g., "Your unsolved tickets", "Unassigned tickets".
    Ticket propertiesSet requester, assignee, group, type, priority, tags.
    ConversationRead history; write a Public reply or an Internal note.
    Context panelCustomer's past tickets, organisation info, connected apps (Jira, Slack).
    Submit buttonChoose the new status as you send: "Submit as Pending", "Submit as Solved".

    Building a view

    example view: "Billing – unassigned, urgent first"Conditions (ALL):
  Status   is less than  Solved
  Group    is            Billing
  Assignee is            -
Columns: Subject, Requester, Priority, Requested, SLA
Order by: Priority (descending), then Requested (ascending)
    💡
    Sort your main view by next SLA breach so the tickets closest to breaking their target are always at the top.

    📋 Macros

    A Zendesk macro is a saved set of actions an agent applies manually: add a reply, set fields, add tags, change status. Macros can be personal or shared with a group.

    macro: "Billing › Invoice copy"Actions:
  Comment/description:
    Hi {{ticket.requester.first_name}},

    You can download every invoice from Settings → Billing → Invoices.
    I've also attached the copy for {{ticket.ticket_field_123}}.

    Best regards,
    {{current_user.first_name}}
  Status:   Pending
  Add tags: invoice_copy
  Group:    Billing
    PlaceholderInserts
    {{ticket.requester.first_name}}Customer's first name
    {{ticket.id}}Ticket number
    {{current_user.first_name}}Your name
    {{ticket.organization.name}}Customer's company
    ⚠️
    Macros apply actions to the ticket before you submit. Always read the inserted reply, personalise it, and check the status it sets.

    ⚡ Triggers & Automations

    ⚡ Triggers

    Run immediately when a ticket is created or updated. Checked in order, top to bottom. Example: "If ticket is created AND subject contains refund → Group = Billing, Priority = High".

    ⏰ Automations

    Run on a schedule (about every hour) based on time conditions. Example: "If status is Pending AND hours since pending > 96 → send reminder; after 7 days → Solved".

    trigger: "Route refund requests"Meet ALL of the following conditions:
  Ticket          is       Created
  Comment text    contains  refund, chargeback, money back
Actions:
  Group           Billing
  Priority        High
  Add tags        refund_request
  Email user      (requester) "We've received your refund request…"
    📌
    Default triggers send the "request received" and "request solved" emails to customers. Admins edit those rather than creating duplicates, or customers get two emails.

    📈 SLAs, Knowledge & Reporting

    SLA policies

    Admins define targets like First reply time, Next reply time and Requester wait time per priority. Agents see a countdown badge on each ticket; red means breached.

    Guide / Knowledge

    The Help Center where articles live. Agents can search and link articles inside a ticket, and the AI agent uses them to answer customers automatically.

    Explore

    Reporting tool with ready dashboards for tickets, SLAs, satisfaction (CSAT) and agent activity.

    ✅
    Practise for free: start a Zendesk free trial, email the support address it gives you from your personal email, and build one view, one macro, one trigger and one automation.

    Freshworks' help desk, popular with startups and Indian companies. Learn its ticket views, canned responses, the three automation types, SLA policies, Freddy AI and the agent gamification features.

    🟩 Freshdesk at a Glance

    Freshdesk is made by Freshworks, a company founded in Chennai. It's known for being affordable and easy to set up, with a free tier that makes it ideal for practice.

    FeaturePurpose
    TicketsEmail, portal, phone, chat and social requests in one list
    Canned responsesSaved replies with placeholders
    Scenario automationsOne-click bundles of actions (like Zendesk macros)
    AutomationsRules on ticket creation, ticket updates and time triggers

    Freddy AIAI features: suggested replies, summaries, bots

    📌
    Default Freshdesk statuses: Open, Pending, Resolved, Closed. Admins commonly add Waiting on Customer and Waiting on Third Party, and choose whether each pauses the SLA timer.

    🗂️ Ticket List & Ticket View

    The ticket list is filterable by status, priority, group, agent, type, tags and date. Save frequent filters as custom views (e.g., "My overdue tickets").

    In the ticket viewUse
    Reply / Forward / Add notePublic reply, forward to a third party, or private internal note
    Properties panelType, status, priority, group, agent, tags
    Contact & company detailsCustomer history and other tickets
    Merge / SplitCombine duplicate tickets, or split a new question out of a thread
    Link ticketsLink related tickets to a tracker ticket (e.g., for a known bug)
    Time logsTrack time spent per ticket
    💡
    Use Merge when the same customer opens two tickets about one issue, so they get one answer and reports aren't inflated.

    💬 Canned Responses & Scenarios

    💬 Canned response

    Inserts text only into your reply. Organised in folders, with placeholders like {{ticket.requester.name}}.

    🎬 Scenario automation

    Performs several actions at once: set status, priority, group, tags, add a note or send a reply. Run manually from the ticket.

    scenario: "Escalate to Tier 2 – Integrations"Actions:
  Set Group      Tier 2 – Integrations
  Set Priority   High
  Add Tag        escalated, integrations
  Add Note       "Escalated by {{ticket.agent.name}} — see notes above"
  Set Status     Waiting on Third Party
    ✅
    A scenario turns a 6-click escalation into one click and makes sure every agent escalates the same way, so reports stay clean.

    ⚙️ The Three Automation Types

    Freshdesk automations run without an agent. There are three kinds (older Freshdesk accounts call them Dispatch'r, Observer and Supervisor):

    TypeOld nameRuns whenExample
    Ticket creationDispatch'rA new ticket arrivesEmail from @bigclient.com → Priority High, Group Enterprise
    Ticket updatesObserverSomething changes on a ticket (reply, status, field)Customer replies to a Resolved ticket → Status Open, notify agent
    Time triggersSupervisorPeriodically (about every hour), based on timePending > 3 days → send reminder; > 7 days → Resolved
    ticket creation rule: "VIP routing"When:  Ticket is created
If:    Requester email  ends with  @bigclient.com
Then:  Set priority   Urgent
       Assign group   Enterprise Support
       Add tag        vip
    ⚠️
    Order matters. Ticket creation rules run top to bottom, and by default Freshdesk can stop at the first match. Put specific rules (VIP) above general ones (all billing emails).

    🏆 SLAs, Freddy AI & Arcade

    SLA policies

    Set First response, Every response and Resolution targets per priority, with business hours and escalation emails when a target is breached.

    Freddy AI

    Freshworks' AI layer: suggested replies and article suggestions for agents, ticket summaries, and bots that answer customers on chat using your knowledge base.

    Arcade (gamification)

    Agents earn points for fast responses, resolutions and good CSAT, unlocking badges and levels. Used to motivate teams.

    💡
    Practise for free: Freshdesk has a free plan. Sign up, email the support address, and build: 3 canned responses, 1 scenario, 1 creation rule, and 1 time trigger.

    Intercom

    A chat-first, in-app customer service platform. Learn the Inbox, conversations and tickets, macros, Workflows, the Fin AI agent and the Help Center.

    💙 Intercom at a Glance

    Intercom started as an in-app chat widget (the Messenger) and grew into a full customer service platform. Its centre is the conversation, not the email ticket, which makes support feel like messaging.

    💬
    Messenger
    The chat bubble customers use inside a website or app.
    📥
    Inbox
    Where agents handle conversations from chat, email, WhatsApp and more.
    🤖
    Fin AI Agent
    AI that answers customers using your help content, then hands over to humans.
    🔀
    Workflows
    Visual automation builder for routing, bots and follow-ups.
    📚
    Help Center
    Articles customers can search, also used by Fin.
    🎫
    Tickets
    For issues that need tracking over time, beyond a quick chat.
    📌
    Because Intercom runs inside the product, agents can see who the user is and what they were doing (plan, last page visited, custom attributes), which speeds up support.

    📥 The Inbox & Conversation States

    StateMeaningWhen to use
    OpenNeeds attentionActive work
    SnoozedHidden until a set time or until the customer repliesWaiting on customer or an internal team
    ClosedDoneIssue resolved; reopens automatically if the customer writes again
    Inbox featureUse
    Team inboxesConversations assigned to teams (Billing, Technical)

    Notes & mentionsPrivate notes; @mention a colleague to pull them in
    Customer details panelUser attributes, company, past conversations

    💡
    In chat, response speed matters most. Use Snooze instead of leaving a conversation open if you're waiting; it keeps your inbox showing only what needs action now.

    🎫 Tickets in Intercom

    When a chat turns into something that takes days (a bug, a refund approval), it becomes a ticket. Intercom has three ticket categories:

    Ticket typeWho sees itExample
    Customer ticketCustomer and team; customer gets status updates"Refund request" with states Submitted → In progress → Resolved
    Back-office ticketInternal teams onlySupport asks Finance to approve a refund
    Tracker ticketInternal; many conversations link to it"Login outage 5 Oct": update all linked customers at once
    ✅
    Tracker tickets are Intercom's version of Zendesk's Problem/Incident linking: resolve the tracker and notify every linked customer together.

    🔀 Macros & Workflows

    Macros

    Saved replies that can also perform actions (assign, tag, snooze, close). Agents insert them from the composer.

    Workflows

    A visual, drag-and-drop builder. A workflow has a trigger (e.g., customer opens a new conversation) and steps (ask a question, show buttons, tag, assign, wait, hand over to Fin or a human).

    workflow: "Route new chats"Trigger: Customer sends their first message
Step 1: Let Fin answer
Step 2: If customer clicks "Talk to a person":
          Ask: "What is this about?"  [Billing] [Technical] [Other]
Step 3: Billing   → assign Team: Billing,   tag: billing
        Technical → assign Team: Technical, tag: tech
        Other     → assign Team: General
Step 4: If plan = Enterprise → set priority, notify account owner
    ⚠️
    Don't trap customers in bots. Always give a clear path to a human, especially for billing or account-access problems.

    🤖 Fin AI Agent & Help Center

    Fin is Intercom's AI agent. It reads your Help Center articles (and other content you allow) and answers customers in natural language. When it can't help, it hands the conversation to a human with the context.

    • Your job as an agent: spot questions Fin answered badly and improve or write the articles behind them.
    • Resolution rate: the share of conversations Fin resolves without a human; a key metric for support leaders.
    • Handover quality: read what Fin already said before replying, so you don't repeat it.
    💡
    The better the Help Center, the better the AI. Writing clear, up-to-date articles is now one of the highest-impact things a support rep can do.

    🚦 Queues, Assignment & Omni-Channel

    📥
    Queues
    Holding areas for cases owned by a team (e.g., "Billing Queue"). Members pick or are routed cases from it.
    📏
    Assignment Rules
    Conditions that decide which queue or user owns a new case.
    🔀
    Omni-Channel
    Pushes work to available agents based on capacity, skills and presence status.
    🧠
    Skills-based routing
    Matches cases to agents with the right skills (language, product).
    case assignment rule (entries run in order)Entry 1: Account Type = Enterprise          → Queue: Enterprise Support
Entry 2: Case Reason = Billing               → Queue: Billing
Entry 3: Case Origin = Web AND Language = Hindi → Queue: Hindi Support
Entry 4: (everything else)                  → Queue: General Support
    💡
    In Omni-Channel, agents set a presence status (Available, Busy, Offline). Work is only routed to available agents with free capacity, so remember to change it on breaks.

    ⏱️ Entitlements, Milestones & Escalation

    Salesforce handles SLAs with Entitlements (what support the customer is entitled to) and Milestones (time-bound steps like "First Response within 1 hour").

    ConceptExample

    Entitlement processThe timeline of milestones applied to a case
    MilestoneFirst Response (1 h), Resolution (8 h)

    Escalation Rules are a simpler, older way to reassign or notify when a case stays open too long (e.g., "High priority not closed in 4 hours → reassign to Tier 2 queue").

    ⚠️

    Designing Clean Help Desk Workflows

    Whatever tool you use, the same habits keep a help desk fast and its reports trustworthy: a clear tag list, good routing, a tidy macro library, integrations and the right reports.

    🏷️ Tagging & Field Hygiene

    Reports are only as good as the data agents enter. Messy tags like refund, refunds, Refund_req split one topic into three.

    • Use a controlled list: prefer dropdown custom fields (Product Area, Contact Reason) over free-text tags for reporting.
    • Name tags consistently: lowercase with underscores, e.g., billing_refund, login_sso.
    • Set required fields on solve, so a ticket can't be solved without a Contact Reason.
    • Review tags monthly and merge or delete unused ones.
    💡
    A good contact-reason field lets the team answer the most important question in support: "Why are customers contacting us, and how do we reduce it?"

    🧭 Routing Design

    Routing methodHow it worksGood for
    Manual / cherry-pickAgents choose from a shared viewVery small teams

    Load-balanced / capacityAssigns to the agent with the fewest open itemsChat and busy queues

    ⚠️
    Too many routing rules become impossible to debug. Keep rules few, ordered from specific to general, and document what each does.

    📚 Building a Macro Library

    1. Start from the top 10 contact reasons; one macro each.
    2. Organise in folders by topic: Billing ›, Access ›, Bugs ›.
    3. Use placeholders for names and IDs; leave a clear spot to personalise.
    4. Include the right actions (status, tags, field values) so data stays clean.
    5. Assign an owner and review quarterly; outdated macros send outdated answers.

    Interview Preparation: Ticketing & CRM Tools

    Questions interviewers ask about help desks and CRMs, with model answers, a comparison cheat sheet, common mistakes and scenario questions.

    🎤 Concept Questions

    QuestionModel answer
    What is a ticketing system?Software that turns every customer request into a tracked record with an owner, status, history and SLA, so nothing is lost and work can be measured.
    Help desk vs CRM?A help desk focuses on tickets; a CRM covers the whole customer relationship (sales, marketing, support). Service Cloud is Salesforce's support module.
    Which tools have you used?Name one deeply (e.g., Zendesk: views, macros, triggers, automations, SLAs) and map concepts to others (macro = canned response).
    Trigger vs automation (Zendesk)?Triggers run instantly on create/update; automations run on a schedule using time conditions.
    What are ticket statuses?New, Open, Pending (waiting on customer), On-hold (waiting on third party), Solved, Closed; they show who acts next.
    Public reply vs internal note?Replies go to the customer; notes are visible only to agents and hold investigation details.
    How do you keep help desk data clean?Agreed tag list, required fields on solve, macros that set fields, regular clean-up.
