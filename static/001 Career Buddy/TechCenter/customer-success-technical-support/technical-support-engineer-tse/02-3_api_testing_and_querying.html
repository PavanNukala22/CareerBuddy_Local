    Why TSEs Test APIs

    When a customer's integration fails, the fastest path to the truth is replaying their API call yourself. Learn what API testing means in support, what to verify, and the rules for doing it safely.

    🔌 API Testing in Support

    Developers test APIs to check that new code works. A Technical Support Engineer tests APIs for a different reason: to reproduce and isolate a customer's problem. The question is always: is the problem in the customer's request, their data or account, or our API?

    🔁
    Reproduce
    Send the same request the customer sent and see the same result.
    🧪
    Isolate
    Change one variable at a time until it flips from failing to working.
    🧾
    Prove
    Capture the exact request/response as evidence for the customer or engineering.
    📤
    Unblock
    Give the customer a working example they can copy.

    🔁 The Support API Workflow

    Figure 1.1 · Capture → Replay → Isolate → Resolve
    1. Collect: endpoint, method, headers (secrets redacted), body, response, request ID, time.
    2. Replay the request in Postman or cURL using a test account or approved access.
    3. Compare your result with theirs.
    4. Isolate: change credentials, environment, payload fields, client, network one at a time.
    5. Conclude and act: fix advice + working example, or a bug report with a minimal reproduction.

    ✅ What to Verify

    CheckQuestion
    Status codeIs it the expected 2xx? If not, which 4xx/5xx?
    Response bodyWhat does the error message or data say?
    HeadersContent-Type, request ID, rate-limit and Retry-After headers
    Data correctnessAre values, types and fields as documented?
    Response timeIs it slow (timeouts, p95)?
    Side effectsDid the record actually get created/updated? (verify with GET or SQL)

    🧰 Choosing a Tool

    PostmancURLBrowser DevTools
    TypeGUI appCommand-line toolBuilt into every browser
    Best forBuilding, saving and sharing requests; testsQuick checks; sharing exact commands; scriptsSeeing what a web app actually sends

    💡
    A common flow: grab the failing call from DevTools → "Copy as cURL" → import into Postman → experiment → send the customer a working cURL or code snippet.

    🛡️ Safety Rules

    • Use your own test/sandbox account by default.
    • Never use a customer's secret key or impersonate them without explicit permission and an approved process.
    • Be careful with POST/PUT/PATCH/DELETE in production: they change real data.
    • Redact secrets from tickets, screenshots and shared collections.
    • Don't store customer data in personal Postman workspaces.
    ⚠️
    A careless DELETE against a live account is one of the most serious mistakes a TSE can make. Double-check the environment before sending.

    🚫 Common Mistakes

    MistakeWhy it hurtsDo this instead
    Testing with different inputs than the customerYou "can't reproduce" for the wrong reasonCopy their exact request
    Only checking the status codeMisses error details or wrong dataRead body and headers
    Testing in the wrong environmentSandbox vs live give different resultsConfirm base URL and key type
    Not verifying side effectsRequest "succeeded" but nothing changedConfirm with GET or SQL

    Postman Essentials

    Build and send requests in Postman: methods, URLs, query parameters, headers, authorization and request bodies, and read the response panel properly.

    📮 The Postman Interface

    AreaUse
    WorkspaceContainer for your collections and environments (personal or team)
    Collections (left)Saved, organised requests
    Request builder (centre)Method, URL, Params, Authorization, Headers, Body, Scripts
    Response panel (bottom)Status, time, size, body, headers, cookies, test results
    Environment selector (top-right)Switch between sets of variables (e.g., Sandbox, Production)
    ConsoleRaw details of every request sent

    🔧 Building a Request

    1. Choose the method (GET, POST…).
    2. Enter the URL, e.g., https://api.example.com/v1/orders.
    3. Add query params, authorization and headers.
    4. For POST/PUT/PATCH, add a body (usually raw JSON).
    5. Click Send; read the response.
    6. Save it into a collection with a clear name.

    🏷️ Params, Headers & Auth

    PartExampleNotes
    Query paramsstatus=paid · limit=50Appended as ?status=paid&limit=50; for filtering/paging
    Path variables/v1/orders/:order_idFill the value in the Params tab
    HeadersContent-Type: application/jsonPostman adds some automatically
    Authorization tabBearer Token · API Key · Basic · OAuth 2.0Set once; can inherit from the collection

    Query params

    Part of the URL. Used for filters, search and pagination on GET requests. Visible in logs.

    Body

    Data sent with POST/PUT/PATCH to create or change resources. Usually JSON.

    📦 Request Bodies

    Body typeWhen
    raw → JSONMost REST APIs
    form-dataFile uploads (multipart)
    x-www-form-urlencodedHTML-form style APIs, OAuth token endpoints
    binaryUploading a raw file
    GraphQLGraphQL APIs
    raw JSON body{
  "customer_id": "cus_901",
  "items": [{"sku": "TSHIRT-M", "qty": 2}],
  "currency": "INR"
}
    💡
    Postman highlights JSON syntax errors in the body editor in red, a quick way to catch trailing commas and missing quotes.

    📊 Reading the Response

    ElementLook for
    Status201 Created? 400? 401? 500?
    TimeSlow responses / timeouts
    SizeUnexpectedly empty (0 B) or huge
    Body (Pretty)Error message, missing fields, wrong values
    HeadersX-Request-Id, rate-limit headers, Content-Type
    Test ResultsPass/fail of your tests

    🗂️ Collections

    • Group requests by API area: Orders API › Create order, Orders API › List orders.
    • Set authorization at collection level and let requests inherit it.
    • Add descriptions with example bodies; share collections with your team.
    • Many companies publish an official Postman collection for their API; customers can import it.

    🚫 Common Mistakes

    MistakeWhy it hurtsDo this instead
    Body type set to Text instead of JSONContent-Type wrong → 415/400Choose raw → JSON
    Hard-coding keys in every requestLeaks secrets; hard to switch envsUse variables + collection auth
    Sending GET with a bodyIgnored by many serversUse query params
    Unsaved requestsLost work, no reuseSave to a named collection

    🌍 Variables & Environments

    ScopeUseExample

    EnvironmentSwitch sets: Sandbox vs Production{{base_url}}, {{api_key}}

    ⚠️
    Mark keys as secret variables and keep them in the "current value" (local) field so they aren't synced to shared workspaces.

    ⚙️ Pre-request Scripts

    JavaScript that runs before a request: generate timestamps, IDs or signatures, or fetch a token.

    pre-request script// unique idempotency key and timestamp for every send
pm.environment.set('idem_key', crypto.randomUUID ? crypto.randomUUID() : Date.now().toString());
pm.environment.set('now_iso', new Date().toISOString());
// then use header:  Idempotency-Key: {{idem_key}}

    🧪 Writing Tests

    Test scripts run after the response arrives and show pass/fail in the Test Results tab.

    tests (post-response script)pm.test('status is 201', () => pm.response.to.have.status(201));

pm.test('responds in under 1s', () => {
  pm.expect(pm.response.responseTime).to.be.below(1000);
});

const body = pm.response.json();
pm.test('has an order id', () => pm.expect(body.id).to.match(/^ord_/));

// save the new id for the next request in the chain
pm.environment.set('order_id', body.id);
    💡
    Chaining requests (create → save id → get by id → delete) lets you reproduce multi-step customer flows quickly.

    🏃 Collection Runner & Newman

    ▶️ Collection Runner

    Runs every request in a collection in order, optionally many times with a CSV/JSON data file (e.g., 50 different customer IDs). Shows a pass/fail summary.

    ⌨️ Newman (CLI)

    Command-line runner for Postman collections, used in scripts and CI.

    bashnpm install -g newman
newman run orders.postman_collection.json \
  -e sandbox.postman_environment.json

    🖥️ Console & Code Snippets

    • The Postman Console shows the exact raw request sent (URL after variables, all headers, body) and the raw response. Use it when "Postman is sending something different than I think".
    • The Code button (</>) converts a request into cURL, Python requests, JavaScript fetch, Java, C#, PHP and more.
    • Import works the other way: paste a cURL command via Import to create a request.
    generated Python snippetimport requests

url = "https://api.example.com/v1/orders"
headers = {"Authorization": "Bearer <API_KEY>", "Content-Type": "application/json"}
payload = {"customer_id": "cus_901", "items": [{"sku": "TSHIRT-M", "qty": 2}]}

response = requests.post(url, json=payload, headers=headers, timeout=30)
print(response.status_code, response.json())
    ✅

    Module 04 · Command Line

    cURL for API Testing

    cURL is the universal way to send HTTP requests from a terminal, and the language customers and engineers share. Learn the syntax, essential flags, authentication, JSON, file uploads, timing and Windows quirks.

    ⌨️ cURL Basics

    bash# GET (default method)
curl https://api.example.com/v1/orders/ord_5512 \
  -H "Authorization: Bearer $API_KEY"

# POST JSON
curl -X POST https://api.example.com/v1/orders \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"customer_id":"cus_901","items":[{"sku":"TSHIRT-M","qty":2}]}'

# PATCH and DELETE
curl -X PATCH https://api.example.com/v1/orders/ord_5512 -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" -d '{"status":"cancelled"}'
curl -X DELETE https://api.example.com/v1/orders/ord_5512 -H "Authorization: Bearer $API_KEY"
    💡
    Store the key in an environment variable (export API_KEY=sk_test_…) so it doesn't appear in commands you share or in screenshots.

    🚩 Essential Flags

    FlagMeaning
    -X METHODSet method (GET default; -d implies POST)
    -H "Name: value"Add a header
    -d / --dataSend a body
    -iInclude response headers in output
    -IHeaders only (HEAD)
    -vVerbose: DNS, connection, TLS, request and response headers
    -s / -SSilent / show errors when silent
    -LFollow redirects
    -o fileSave body to a file
    -u user:passBasic auth
    -F "file=@path"Multipart file upload
    --max-time 30Timeout after 30 s
    -G --data-urlencodeEncode query params safely

    🔑 JSON, Auth & Headers

    bash# Body from a file (avoids quoting problems)
curl -X POST https://api.example.com/v1/orders \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  --data @order.json

# Basic auth
curl -u "client_id:client_secret" https://api.example.com/oauth/token \
  -d "grant_type=client_credentials"

# API key in a custom header
curl https://api.example.com/v1/me -H "X-API-Key: $API_KEY"

# Query params with spaces/special characters
curl -G https://api.example.com/v1/customers \
  --data-urlencode "search=R&D Labs" -H "Authorization: Bearer $API_KEY"

    📤 Uploads, Output & Timing

    bash# Multipart file upload
curl -X POST https://api.example.com/v1/files \
  -H "Authorization: Bearer $API_KEY" \
  -F "file=@invoice.pdf" -F "purpose=billing"

# Status code only
curl -s -o /dev/null -w "%{http_code}\n" https://api.example.com/health

# Timing breakdown (where is it slow?)
curl -s -o /dev/null -w "dns=%{time_namelookup} connect=%{time_connect} tls=%{time_appconnect} total=%{time_total}\n" \
  https://api.example.com/v1/orders -H "Authorization: Bearer $API_KEY"
    📌
    The timing breakdown shows whether delay is in DNS, connecting, TLS or the server's processing (total minus the others).

    🪟 Windows Quoting & jq

    ShellJSON body example
    Bash / Git Bash / macOS-d '{"qty":2}'
    Windows CMD-d "{\"qty\":2}"
    PowerShellUse curl.exe (not the alias) and a file: --data "@order.json"
    bash (jq for readable JSON)curl -s https://api.example.com/v1/orders -H "Authorization: Bearer $API_KEY" | jq .
curl -s ... | jq '.data[] | {id, status, amount}'
curl -s ... | jq '.data | length'
    💡
    When customers on Windows struggle with quotes, ask them to put the JSON in a file and use --data @file.json.

    🚫 Common Mistakes

    MistakeWhy it hurtsDo this instead

    Smart quotes from Word/SlackCommand breaks mysteriouslyUse plain straight quotes

    Module 05 · DevTools

    Inspecting API Calls with Browser DevTools

    For problems inside a web app, the Network panel shows every API call the page makes. Learn to filter, inspect headers, payloads, responses and timing, copy requests as cURL, and work with HAR files.

    🧭 Network Panel Setup

    1. Open DevTools (F12 / Ctrl+Shift+I / Cmd+Option+I) → Network.
    2. Tick Preserve log (keeps requests across page loads and redirects).
    3. Optionally tick Disable cache while DevTools is open.
    4. Filter by Fetch/XHR to see only API calls.
    5. Reproduce the problem; failed requests appear in red.

    🔍 Inspecting a Request

    TabWhat you learn
    HeadersURL, method, status code, request and response headers (auth present? content-type?)
    PayloadQuery string parameters and request body the page sent
    Preview / ResponseFormatted / raw response body, including error messages
    TimingWhere time was spent: queueing, connection, waiting for server (TTFB), download
    InitiatorWhich script or action triggered the call
    💡
    The Payload tab often reveals the bug instantly: a field sent as empty string, wrong date format, or a missing ID.

    ⏱️ Timing & Waterfall

    Timing phaseLong time means…
    Queueing / StalledBrowser waiting (too many parallel requests)
    DNS / Initial connection / SSLNetwork or TLS slowness
    Waiting for server response (TTFB)Server is slow to process
    Content downloadVery large response or slow connection
    📌
    If TTFB is long, the problem is likely server-side (escalate with request ID and timing). If download is long, the response may be too big (pagination needed).

    📋 Copy as cURL / fetch & Replay

    • Right-click a request → Copy → Copy as cURL (bash or cmd) to replay it in a terminal or import into Postman.
    • Copy as fetch gives JavaScript you can paste into the Console.
    • Chrome supports Replay XHR to resend a request quickly.
    • Remember copied requests include cookies/tokens; treat them as secrets.

    📦 HAR Files & Throttling

    📦 HAR file

    A recording of all network activity (right-click → Save all as HAR). Lets you see exactly what the customer's browser did. Contains cookies and tokens, so share via secure upload only and delete after use.

    🐢 Throttling

    Network panel → No throttling dropdown → "Slow 4G" / "3G" to reproduce issues customers have on slow connections.

    🚫 Common Mistakes

    Sharing HARs in public channelsSession hijacking riskSecure upload; delete after

    Module 06 · Payloads

    Inspecting & Comparing Payloads

    Most API failures hide in the payload. Learn how to read request and response bodies, compare working vs failing requests, validate against documentation, and interpret API error bodies.

    📨 Request vs Response Payloads

    ➡️ Request payload

    What the client sent: fields, types, IDs, formats. Most 400/422 errors are caused here.

    ⬅️ Response payload

    What the server returned: data or an error object explaining the problem.

    🔍 Comparing Working vs Failing

    ✅ Your working request

    json{
  "customer_id": "cus_901",
  "amount": 2499,
  "currency": "INR",
  "due_date": "2026-10-31"
}

    ❌ Customer's failing request

    json{
  "customerId": "cus_901",
  "amount": "2,499",
  "due_date": "31/10/2026"
}
    DifferenceProblem
    customerId vs customer_idField name/case doesn't match docs
    "2,499" (string with comma)Should be number 2499 (often in smallest unit, e.g., paise)
    currency missingRequired field
    31/10/2026Expected ISO date 2026-10-31
    💡
    Use a diff tool (VS Code compare, online JSON diff) for long payloads; eyes miss single characters.

    📘 Validating Against Docs

    Check in API docsExample
    Required vs optional fieldscurrency required
    Types and formatsamount integer in paise; dates ISO 8601
    Allowed values (enums)status ∈ {draft, sent, paid}
    Limitsmax 100 items; name ≤ 255 chars
    API versionField renamed in v2
    Authentication & scopeswrite:invoices scope needed

    🧾 Interpreting Error Bodies

    typical error bodyHTTP/1.1 422 Unprocessable Entity
{
  "error": {
    "type": "validation_error",
    "code": "invalid_date_format",
    "param": "due_date",
    "message": "due_date must be in YYYY-MM-DD format",
    "request_id": "req_44e1"
  }
}
    ✅
    The error body names the exact field (param), the reason, and a request ID for log lookup. Quote these in your reply.

    ✔️ Verifying Side Effects

    • After a POST/PATCH, confirm the change with a GET on the resource.
    • Check related data: was the webhook sent? the email queued? the invoice total updated?
    • For data-integrity tickets, confirm in the database with read-only SQL (next course).

    🚫 Common Mistakes

    MistakeWhy it hurtsDo this instead
    Ignoring the error bodyGuessing instead of readingRead type/code/param/message
    Not checking API version docsField names differ between versionsMatch the version used
    Assuming 200 means correct dataData may be wrong/incompleteValidate values and side effects

    Module 07 · Isolation

    Isolating API Problems Systematically

    A repeatable decision process to find whether an API problem comes from credentials, environment, payload, client/SDK, network or our service.

    🧪 Change One Variable

    Start from the customer's exact failing request. Change one thing, send, observe. Keep notes. When the result flips, you've found the cause.

    🧮 The Isolation Matrix

    VariableTestIf it fixes it…
    CredentialsYour own test keyTheir key is wrong/revoked/lacks scope
    EnvironmentSandbox vs production URL/keyTest vs live mismatch
    PayloadRemove optional fields; minimal bodyA specific field/value breaks it
    ClientRaw cURL vs their SDKSDK bug, old version, wrong config
    NetworkYour machine vs their serverFirewall/proxy/IP allowlist
    Account / dataYour account vs theirs (with permission)Account setting, plan limit, or data-specific bug
    TimeDid it work before? What changed?Release, key rotation, deprecation

    🧰 SDK vs Raw HTTP

    • SDKs (official libraries) add defaults: API version headers, retries, timeouts, serialisation.
    • Ask for the SDK name and version; compare with the latest release notes.
    • Enable SDK debug logging, or capture the raw request (proxy, logs).
    • If raw cURL works and the SDK fails, the difference is in how the SDK builds the request.

    🔁 The End-to-End Workflow

    Ticket → Collect request/response → Check logs by request ID → Replay (Postman/cURL) → Isolate → Conclude → Working example or bug report → Reply

    🧾 Case 1: 400 on Create Order

    evidenceResponse: 400 {"error":{"param":"items[0].qty","message":"must be an integer"}}
Customer body: {"items":[{"sku":"TSHIRT-M","qty":"2"}]}
Replay with qty: 2 → 201 Created
    ✅
    Resolution: send qty as a number. Reply with the corrected JSON and a cURL example.

    🔔 Case 2: Webhook Testing

    1. Check our webhook delivery logs for the customer endpoint (status, timing).
    2. Use a request-inspection service (e.g., a temporary webhook test URL) to see exactly what we send.
    3. Have the customer replay a sample payload to their endpoint with cURL to test their handler.
    4. Check signature verification (shared secret, raw body used for HMAC).
    5. Confirm their endpoint returns 2xx quickly.
    bashcurl -X POST https://hooks.acme.com/orders \
  -H "Content-Type: application/json" \
  -H "X-Signature: <sample>" \
  --data @sample_order_paid.json -w "\n%{http_code} %{time_total}s\n"

    TestResultMeaning

    Customer sent body as JSON base64400Wrong format; endpoint expects multipart

    🔍 Case 4: Data Missing in Responses

    evidenceGET /v1/orders?limit=100 → 100 items, has_more: true
Customer: "only 100 of 2,300 orders returned"
Replay with starting_after=<last id> → next 100

    ✉️ Replying to Developer Customers

    • Lead with the cause in one sentence.
    • Show the exact fix: corrected payload or header.
    • Include a working example (cURL + their language), with placeholders for keys.
    • Link the relevant API docs section.
    • Give the request ID / time you checked, so they can match it.
    Example replyThe 400 comes from items[0].qty being sent as a string ("2"); the API expects a number. Changing it to "qty": 2 fixes it. Here's a working request (replace YOUR_KEY): curl -X POST … I tested this in our sandbox and it returns 201. Docs: Orders → Create order → items.

    Module 09 · Interviews

    Interview Preparation: API Testing & Querying

    Interview questions about Postman, cURL, DevTools and API troubleshooting, with model answers, comparisons, common mistakes and scenarios.

    🎤 Concept Questions

    QuestionModel answer
    How do you troubleshoot a failing API call?Collect the exact request/response and request ID, check logs, replay in Postman/cURL, isolate one variable at a time (key, env, payload, client, network), conclude and provide a fix or bug report.
    What are Postman environments?Sets of variables (base_url, api_key) to switch between sandbox and production without editing requests.
    How do you write a Postman test?pm.test with assertions, e.g., pm.response.to.have.status(200) and pm.expect(json.id).to.exist.
    Key cURL flags?-X method, -H header, -d data, -F file, -v verbose, -i headers, -o output, -L redirects, -u basic auth.
    How do you see what a web app sends?DevTools Network → Fetch/XHR → Headers, Payload, Response, Timing; copy as cURL.
    What is a HAR file?A recording of browser network activity; contains sensitive data, so handle securely.
    Query params vs body?Params in the URL for filters/paging (GET); body carries data for POST/PUT/PATCH.

    📋 Comparison Cheat Sheet

    PairKey difference
    Postman vs cURLGUI with collections/tests vs universal command line
    cURL vs DevToolsSend your own requests vs observe what the browser sends
    Collection vs EnvironmentSaved requests vs variable sets
    Pre-request vs Test scriptRuns before sending vs after response
    Collection Runner vs NewmanIn-app batch runs vs CLI/CI runs
    -d vs -FRaw/form body vs multipart file upload
    Payload vs Response tabWhat was sent vs what came back
    SDK vs raw HTTPLibrary with defaults vs exact request control
