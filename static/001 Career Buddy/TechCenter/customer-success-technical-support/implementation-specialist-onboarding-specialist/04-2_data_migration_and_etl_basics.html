    Module 01 · What Is What

    What Data Migration & ETL Are

    Start from the basics: what data migration is, what ETL means, the types of migration approaches, the migration lifecycle and why migrations fail.

    🚚 What Is Data Migration?

    Data migration is moving data from an old system (spreadsheets, a legacy CRM or help desk) into a new platform, so customers can start using it with their existing records: contacts, accounts, tickets, products, history.

    👥
    Master data
    Customers, contacts, products, users
    🧾
    Transactional data
    Orders, tickets, invoices, activities
    📎
    Attachments
    Files linked to records
    ⚙️
    Configuration
    Picklists, categories, tags

    🔁 What Is ETL?

    Figure 1.1 · Extract, Transform, Load

    ETL

    Transform before loading. Typical for implementations: data is cleaned in spreadsheets or tools, then imported.

    ELT

    Load raw data first, transform inside the target (common with data warehouses like Snowflake/BigQuery).

    🗂️ Types of Migration

    ApproachHowPros / cons
    Big bangEverything moved at once over a cutover windowSimple, one switch / high risk if it fails
    PhasedBy team, region or data type over timeLower risk / longer, two systems in parallel
    Trickle / parallel runOld and new run together; data syncedSafest / complex, more effort
    Fresh startOnly open/active records migrated; history archivedFast, clean / history not in new tool

    🪜 The Migration Lifecycle

    1. Plan: what data, how much history, which approach, who owns it.
    2. Extract & profile: export from source; check volume, quality, formats.
    3. Map: source fields → target fields; transformations.
    4. Cleanse & transform: dedupe, standardise, fix errors.
    5. Test load: import a sample into a sandbox; validate.
    6. Full load: import everything (often during cutover).
    7. Reconcile & sign off: counts, spot checks, customer approval.

    💥 Why Migrations Fail

    CauseResult
    Poor data quality discovered lateDelays, dirty new system
    No field mapping documentData lands in wrong fields
    No test loadErrors found during go-live
    Wrong import order (children before parents)Broken relationships
    No reconciliationMissing records unnoticed
    Unclear data ownershipNobody approves decisions

    🚫 Common Mistakes

    MistakeWhy it hurtsDo this instead
    Migrating everything "just in case"Moves junk into new systemAgree what data has value
    Skipping sandbox testsProduction errorsTest load first
    No customer sign-offDisputes laterFormal data acceptance

    🏋️ Practice & Quick Check

    csvid,name,email,city,notes

    • Values containing commas must be wrapped in double quotes; quotes inside are doubled ("").

    Module 03 · Cleansing

    Data Cleansing Techniques

    Fix the data before it reaches the new system: deduplication, standardisation, validation, handling missing values, and the spreadsheet functions that do the work.

    🧽 What Is Data Cleansing?

    Data cleansing (data cleaning/scrubbing) is detecting and fixing incorrect, incomplete, inconsistent or duplicate data. Garbage in = garbage out: dirty data in a new system destroys user trust from day one.

    Type of fixExample
    RemoveDelete test records, obviously junk rows
    CorrectFix typos, invalid emails
    StandardiseSame format for phones, dates, countries
    MergeCombine duplicate contacts
    EnrichFill missing company names from domain (if agreed)

    👯 Deduplication

    1. Decide the matching rule: same email? same name + company? same phone?
    2. Normalise first (lowercase, trim) so matches are found.
    3. Flag duplicates (COUNTIF or Remove Duplicates on a copy).
    4. Choose the survivor record (most recent/most complete).
    5. Merge useful fields from the others; keep a mapping of merged IDs.
    flag duplicate emails (Excel / Google Sheets)=COUNTIF($C$2:$C$50000, C2) > 1          → TRUE = duplicate
=LOWER(TRIM(C2))                           → normalise before comparing
    ⚠️
    Always deduplicate on a copy. "Remove Duplicates" deletes rows permanently in that sheet.

    📐 Standardisation

    FieldBeforeAfterHow
    Name" priya RAO ""Priya Rao"=PROPER(TRIM(A2))
    Email"Priya@Acme.COM ""priya@acme.com"=LOWER(TRIM(B2))
    Phone"098480-12345""+919848012345"SUBSTITUTE / REGEXREPLACE
    Country"india""India"Lookup table
    Date"05/10/2026""2026-10-05"=TEXT(DATE(...),"yyyy-mm-dd")

    ✅ Validation & Missing Values

    RuleFormula idea
    Email looks valid=ISNUMBER(SEARCH("@",B2)) or REGEXMATCH(B2,"^[^@\s]+@[^@\s]+\.[^@\s]+$") (Sheets)
    Required field present=IF(B2="","MISSING","OK")
    Value in allowed list=COUNTIF(Allowed!A:A,D2)>0
    Numeric amount=ISNUMBER(E2)
    Missing value strategyWhen
    Leave blankOptional fields
    Default valuee.g., "Unknown" for region
    Ask customerRequired business data
    Exclude recordUnusable without key fields

    CLEANRemoves non-printable characters
    UPPER / LOWER / PROPERChange case
    SUBSTITUTEReplace text
    LEFT / RIGHT / MID / LENExtract parts of text
    TEXTSPLIT (Excel 365) / SPLIT (Sheets)Split by delimiter

    Module 04 · Mapping

    CSV Field Mapping

    Mapping tells you exactly where each source column goes in the new system and how it's transformed. Learn mapping documents, picklist mapping, IDs and relationships, and import order.

    🔗 What Is Field Mapping?

    Field mapping links each source field to a target field, with any transformation rule needed. It's the blueprint of the migration and should be approved by the customer.

    Mapping typeExample
    Direct (1:1)email → Email
    Transformcreated (05/10/2026) → Created Date (2026-10-05)
    Split (1:many)full_name → First Name + Last Name
    Combine (many:1)street + city + pin → Address
    Lookupcountry "india" → Country "IN"
    Default/constantSource = "Legacy CRM" for all records
    Not migratedfax_number (dropped)

    📄 The Mapping Document

    mapping document (contacts)Source column   Target field       Type      Required  Transformation                 Notes
cust_id         External ID        Text      Yes       none (keep leading zeros)      used for upserts
full_name       First/Last Name    Text      Yes       split on last space            "Rao, Priya" → reverse
email           Email              Email     Yes       LOWER(TRIM())                  dedupe key
mobile          Phone              Phone     No        to +91XXXXXXXXXX               
region          Region (picklist)  Picklist  No        value map (see tab 2)          
created         Created Date       Date      No        DD/MM/YYYY → YYYY-MM-DD        
fax             —                  —         —         not migrated                    agreed 10 Oct
    💡
    Keep mapping in a shared sheet with a version number and a "signed off by/date" field.

    🎚️ Picklist / Value Mapping

    Source valueTarget picklist value
    N, North, northNorth
    S, SouthSouth
    Gold, PlatinumEnterprise
    SilverMid-market
    (blank)Unassigned
    lookup formula=IFERROR(XLOOKUP(TRIM(D2), Map!A:A, Map!B:B), "UNMAPPED")
(Google Sheets/older Excel: =IFERROR(VLOOKUP(TRIM(D2), Map!A:B, 2, FALSE), "UNMAPPED"))
    ⚠️
    Picklist values must match the target exactly (spelling, case, spaces) or imports fail/reject rows. Filter for "UNMAPPED" before importing.

    🆔 IDs & Relationships

    • Keep the legacy ID in an "External ID" field to link records and allow re-runs (upserts).
    • Child records (contacts, tickets) reference parents (accounts) by external ID or by the new system ID after parents are loaded.
    • Many platforms support upsert: update if the external ID exists, insert if not.
    relationship exampleaccounts.csv:  ext_id=ACC-0012, name=Acme
contacts.csv:  ext_id=CON-0450, account_ext_id=ACC-0012, email=priya@acme.com
→ import accounts first; contacts link via account_ext_id

    🔢 Import Order

    1. Users / owners (so records can be assigned)
    2. Accounts / companies
    3. Contacts (linked to accounts)
    4. Products / catalogue
    5. Transactions: orders, tickets, opportunities (linked to contacts/accounts)
    6. Activities, notes, attachments
    📌
    Parents before children. Loading tickets before their contacts exist breaks the links.

    🚫 Common Mistakes

    MistakeWhy it hurtsDo this instead
    No external IDsCan't link or re-run safelyKeep legacy IDs
    Unmapped picklist valuesRejected rowsValue map + UNMAPPED check
    Wrong import orderBroken relationshipsParents first

    Module 05 · Workflows

    Export & Import Workflows

    A safe, repeatable workflow for moving data: export, transform, test import in a sandbox, validate, full import, reconcile, and a rollback plan.

    🔁 The Standard Workflow

    1. Export raw data; store an untouched copy.
    2. Profile and agree cleansing rules.
    3. Transform per mapping document (cleansing, splits, picklists, formats).
    4. Test import a sample (e.g., 100–500 rows) into a sandbox.
    5. Validate with the customer; fix mapping; repeat.
    6. Full import in the agreed window.
    7. Reconcile counts and spot checks; customer sign-off.

    📤 Exporting from Source Systems

    SourceTypical export
    SpreadsheetsSave as CSV UTF-8 per sheet
    Legacy CRM/help deskBuilt-in export (CSV), reports, or API
    DatabasesSQL query to CSV (by technical team)
    Email/attachmentsBulk export tools, often zipped
    💡
    Record export date/time and filters. If you export again later, you need the same criteria plus a "delta" of new/changed records.

    🧪 Test Imports in a Sandbox

    • Use a sandbox/test environment, never production first.
    • Import a small but representative sample: special characters, long text, edge cases.
    • Check: field placement, picklists, dates, relationships, owners, attachments.
    • Have the customer review records in the UI, not just counts.

    🚀 Full Import & Cutover

    cutover plan (example)Fri 18:00  Freeze data entry in old system (read-only)
Fri 18:30  Final export (full or delta since test)
Fri 20:00  Transform with approved scripts/formulas
Sat 10:00  Import: users → accounts → contacts → tickets → attachments
Sat 16:00  Reconciliation (counts, samples)
Sun 12:00  Customer validation; go/no-go
Mon 09:00  Users start in new system; hypercare

    🧯 Error Handling & Rollback

    SituationAction
    Import tool returns error rowsDownload error file; fix; re-import only failed rows
    Wrong mapping discoveredStop; fix mapping; delete/upsert affected records
    Major failureRollback: keep old system active; restore/clear new data; re-plan
    Partial duplicates createdUse external IDs to identify and merge/delete
    ⚠️
    Always have a rollback plan before cutover: who decides, how to revert, and how users are told.

    🚫 Common Mistakes

    MistakeWhy it hurtsDo this instead
    Importing straight into productionHard-to-undo errorsSandbox test first
    No data freeze at cutoverRecords created after export are lostFreeze or delta export
    Ignoring error filesSilent data lossReview and re-import failures

    Spreadsheet Formulas for Migration

    The Excel and Google Sheets formulas implementation specialists use daily: lookups, conditions, text manipulation, dates and duplicate checks, plus Power Query for repeatable cleaning.

    🔎 Lookups: VLOOKUP, XLOOKUP, INDEX/MATCH

    formulas=VLOOKUP(A2, Accounts!A:C, 3, FALSE)          → exact match, 3rd column
=XLOOKUP(A2, Accounts!A:A, Accounts!C:C, "NOT FOUND")   (Excel 365 / Google Sheets)
=INDEX(Accounts!C:C, MATCH(A2, Accounts!A:A, 0))        → works left or right
    VLOOKUPXLOOKUPINDEX/MATCH
    Look left?NoYesYes
    Default exact match?No (use FALSE)YesYes (0)
    Not-found valueNeeds IFERRORBuilt inNeeds IFERROR
    ⚠️
    Forgetting FALSE in VLOOKUP gives approximate matches, a classic silent error.

    🔀 Conditions: IF, IFS, IFERROR

    formulas=IF(B2="", "MISSING", "OK")
=IFS(D2="Gold","Enterprise", D2="Silver","Mid-market", TRUE,"SMB")
=IFERROR(VLOOKUP(D2, Map!A:B, 2, FALSE), "UNMAPPED")
=IF(COUNTIF($C$2:$C$50000, C2)>1, "DUPLICATE", "")

    ✂️ Text Functions

    formulas=TRIM(A2)                       remove extra spaces
=PROPER(A2)                     Priya Rao
=LOWER(B2)                      priya@acme.com
=LEFT(A2, FIND(" ", A2)-1)      first name
=MID(A2, FIND(" ", A2)+1, 100)  rest of name
=TEXTJOIN(", ", TRUE, C2:E2)    combine address parts
=SUBSTITUTE(F2, "-", "")        remove dashes from phone
=REGEXREPLACE(F2, "[^0-9]", "") (Sheets) keep digits only

    📅 Dates & Numbers

    formulas=DATE(RIGHT(A2,4), MID(A2,4,2), LEFT(A2,2))   "05/10/2026" (DD/MM/YYYY text) → date
=TEXT(B2, "yyyy-mm-dd")                       → "2026-10-05"
=VALUE(SUBSTITUTE(C2, ",", ""))                "2,499" → 2499
=ROUND(D2*100, 0)                              rupees → paise integer
    💡
    Check a few converted dates manually, especially days ≤ 12, where DD/MM vs MM/DD confusion hides.

    ⚙️ Power Query & Sheets Tools

    ToolUse
    Excel Power Query (Get & Transform)Repeatable cleaning steps: trim, split, replace, merge tables; refresh on new exports
    Pivot tablesProfile values and counts
    Data validationRestrict values to lists
    Google Sheets QUERY()SQL-like filtering: =QUERY(A:E,"select * where D is null")
    Conditional formattingHighlight duplicates/blanks
    ✅
    Power Query records each step, so re-running cleaning on a fresh export at cutover takes minutes, not hours.

    Module 07 · Scripting

    Basic Spreadsheet Scripting: Excel VBA & Google Apps Script

    Automate repetitive cleaning with simple scripts. Learn what macros are, recording vs writing, beginner VBA and Apps Script examples, and how to script safely.

    🤖 What Is Spreadsheet Scripting?

    Excel VBAGoogle Apps Script
    LanguageVisual Basic for ApplicationsJavaScript
    WhereExcel desktop (Alt+F11 editor)Extensions → Apps Script
    File type.xlsm (macro-enabled)Inside the Google Sheet/project
    StrengthOffline, mature, record macrosCloud, triggers, Google services integration
    💡
    Use scripts when the same cleaning must be repeated many times (e.g., every test load and cutover). For one-off tasks, formulas or Power Query may be enough.

    📘 Excel VBA Basics

    • Record Macro (View/Developer → Record Macro) captures your clicks as code, a great way to learn.
    • Open the editor with Alt+F11; code lives in Modules.
    • Save as .xlsm, otherwise macros are removed.
    • Key objects: Workbook, Worksheet, Range, Cells.

    🧹 VBA Example: Clean a Column

    VBASub CleanEmails()
    ' Trims spaces and lowercases emails in column C (from row 2)
    Dim ws As Worksheet, lastRow As Long, r As Long
    Set ws = ThisWorkbook.Sheets("contacts")
    lastRow = ws.Cells(ws.Rows.Count, "C").End(xlUp).Row
    For r = 2 To lastRow
        ws.Cells(r, "C").Value = LCase(Trim(ws.Cells(r, "C").Value))
        If InStr(ws.Cells(r, "C").Value, "@") = 0 Then
            ws.Cells(r, "C").Interior.Color = RGB(255, 200, 200)   ' highlight invalid
        End If
    Next r
    MsgBox "Cleaned " & (lastRow - 1) & " emails"
End Sub

    📗 Google Apps Script Basics

    • Open: Extensions → Apps Script.
    • Uses JavaScript with services like SpreadsheetApp.
    • Run functions from the editor, a custom menu, or triggers (time-based, on edit).
    • First run asks for authorisation; review permissions carefully.

    🧾 Apps Script Example

    Apps Script (JavaScript)function cleanContacts() {
  const sheet = SpreadsheetApp.getActive().getSheetByName("contacts");
  const range = sheet.getRange(2, 1, sheet.getLastRow() - 1, 3); // A:C from row 2
  const rows = range.getValues();
  const cleaned = rows.map(([name, phone, email]) => [
    String(name).trim().replace(/\s+/g, " "),
    String(phone).replace(/[^0-9+]/g, ""),
    String(email).trim().toLowerCase()
  ]);
  range.setValues(cleaned);   // one write = fast
}

function onOpen() {
  SpreadsheetApp.getUi().createMenu("Migration").addItem("Clean contacts", "cleanContacts").addToUi();
}
    📌
    Reading and writing whole ranges with getValues()/setValues() is much faster than cell-by-cell loops.

    MistakeWhy it hurtsDo this instead
    Running scripts on the only copyCan't undo bulk changes (VBA has no undo)Run on a copy; keep raw export
    Macros from unknown sourcesSecurity riskOnly trusted code; review it
    Saving VBA as .xlsxCode lostSave as .xlsm
    Cell-by-cell writes in Apps ScriptVery slow, timeoutsBatch getValues/setValues

    👯 Scenario: Duplicates Discovered After Go-live

    • Users report duplicate contacts. Check whether they came from the migration (external IDs, created date) or new entry.
    • Agree merge rules; merge in the platform (bulk merge tools) or upsert.
    • Fix the root cause: dedupe key, matching rule, or integration creating duplicates.

    🔗 Scenario: Missing Relationships

    • Tickets show "no contact". Cause: contacts imported after tickets, or ID mismatch.
    • Fix: re-import ticket links via upsert using external IDs; validate a sample.
    • Lesson: enforce import order and test relationships in sandbox.

    Module 09 · Interviews

    Interview Preparation: Data Migration & ETL Basics

    Interview questions on migration planning, cleansing, CSV mapping, import workflows and spreadsheet scripting, with model answers, comparisons, common mistakes and scenarios.

    🎤 Concept Questions

    QuestionModel answer
    What is ETL?Extract data from source, Transform (clean, map, format), Load into the target system.
    How do you plan a data migration?Agree scope (objects, history), profile data, mapping document, cleansing rules, test load in sandbox, full load plan with freeze, reconciliation and sign-off.
    How do you handle duplicates?Agree matching rules, normalise, flag, choose survivor, merge fields, keep a merge log.
    What is a field mapping document?Source→target fields with types, required flags, transformations and value maps, approved by the customer.
    Why import parents before children?Children reference parents; loading children first breaks relationships.
    VLOOKUP vs XLOOKUP?XLOOKUP looks left, defaults to exact match and has a not-found argument.
    When would you use VBA or Apps Script?For repeatable bulk cleaning/formatting across test and final loads.

    📋 Comparison Cheat Sheet

    PairKey difference
    ETL vs ELTTransform before load vs after load in target
    Big bang vs PhasedAll at once vs in stages
    CSV vs XLSXPlain text vs workbook with formatting
    VLOOKUP vs XLOOKUPRight-only, needs FALSE vs flexible exact match
    Insert vs UpsertAlways new vs update-or-insert by external ID
    Test load vs Full loadSample in sandbox vs everything at cutover
    VBA vs Apps ScriptExcel desktop VB vs Google Sheets JavaScript
    Completeness vs ConsistencyData present vs same format everywhere
