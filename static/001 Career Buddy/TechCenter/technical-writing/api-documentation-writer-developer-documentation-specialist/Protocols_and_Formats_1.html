    Protocols & Formats

    Understand the protocols and data formats that allow applications, services, browsers, devices, and systems to communicate reliably.

    Communication Fundamentals

    Communication protocols define shared rules for addressing, messages, transport, timing, and failure behavior.

    Clients and servers

    Protocols define shared rules for communication, including message structure, addressing, transport, timing, and failure behavior. They allow independently developed components to interoperate.

    Messages and envelopes

    A client consumes or requests a service while a server or service provides capabilities. A system can act as a client in one interaction and a server in another.

    Ports and endpoints

    Messages can include an operation, target, metadata, payload, and correlation information. Clear message boundaries help receivers parse and validate information safely.

    Request-response

    Ports identify logical network services. An endpoint may combine a host, port, and application-level path. Exposing only required services reduces unnecessary attack surface.

    Streaming and events

    Request-response is one communication pattern. Streaming, event-driven, publish-subscribe, and bidirectional patterns can be better when data must flow continuously or asynchronously.

    HTTP and HTTPS

    HTTP provides application-level web communication, while HTTPS adds TLS protection for data in transit.

    HTTP requests

    HTTP is an application-layer protocol widely used by browsers and APIs. A request includes a method, target, headers, and optionally a body; a response includes a status code, headers, and optionally a body.

    HTTP responses

    GET commonly retrieves representations, POST commonly submits or creates, PUT commonly replaces a representation, PATCH applies partial changes, and DELETE requests removal.

    Headers

    Headers carry metadata such as content type, authorization, caching instructions, language preferences, and conditional request information. Application-specific headers should have documented semantics.

    HTTPS and TLS

    HTTPS is HTTP protected by TLS. Correct TLS configuration provides confidentiality and integrity in transit and helps authenticate the server, but HTTPS does not make insecure application logic secure.

    Caching and content negotiation

    Caching can reduce latency and server load. Cache-Control directives, validators, and conditional requests help clients and intermediaries reuse responses safely.

    Data Formats

    Structured formats allow systems to exchange information in predictable representations.

    JSON

    JSON represents objects, arrays, strings, numbers, booleans, and null values. It is popular because it is compact, readable, and supported across many programming languages.

    XML

    XML represents structured information through elements, attributes, and namespaces. It remains important in enterprise, publishing, configuration, and integration environments.

    CSV

    CSV is useful for tabular exchange but requires careful handling of delimiters, quoting, line endings, headers, and character encoding.

    Form encoding

    Form encoding supports common browser-style key-value submissions, while multipart encoding can carry fields and files together.

    Schemas and validation

    Schema validation checks that data has an expected structure and satisfies constraints. Explicit schemas reduce ambiguity between producers and consumers.

    Network and Application Protocols

    Different protocols solve different communication problems at network, transport, and application layers.

    DNS

    DNS translates domain names into network addresses and provides other records used for routing and service discovery. DNS failures can appear as application outages.

    TCP and UDP

    TCP provides reliable, ordered byte-stream communication with connection and congestion mechanisms. UDP provides datagrams without TCP's delivery guarantees and can support different application-level trade-offs.

    WebSocket

    WebSocket provides a persistent bidirectional communication channel useful for live updates, collaborative interfaces, and interactive applications.

    Email protocols

    SMTP is associated with mail transfer, while IMAP and POP are associated with retrieving mail. Separating protocol roles helps clarify system architecture.

    Protocol layers

    Protocols operate in layers. Understanding the layer responsible for a behavior helps isolate failures and prevents application code from compensating for the wrong problem.

    Interoperability and Integration

    Successful integrations depend on compatible encodings, schemas, serialization, error handling, and evolution practices.

    Character encoding

    Interoperability requires agreement on syntax, semantics, encoding, schemas, authentication, errors, and compatibility. Shared support for a format does not guarantee shared meaning.

    Serialization

    Character encoding determines how text becomes bytes. UTF-8 is widely used, but integrations should still make encoding assumptions explicit.

    Deserialization

    Serialization converts in-memory data into an exchange representation; deserialization reconstructs data for processing. External input should be validated before use.

    Integration failures

    Integration failures can include timeouts, network errors, authentication failures, validation errors, rate limits, and upstream application failures. Recovery should match the failure type.

    Compatibility and evolution

    Protocol evolution should favor compatibility when practical. Producers and consumers should follow documented deprecation and migration policies for breaking changes.
