    Module 01

    Content Governance for Technical Editors

    Managing review cycles, peer review, localization readiness and content deprecation schedules so documentation stays accurate, owned and trusted at scale.

    🏛️ Course Overview: What the Role Needs

    Content governance keeps documentation a reliable product asset. Owned, reviewed, localized and retired on schedule, content stays accurate while teams and products change.

    🔄
    Review cycles
    Stages, owners, SLAs.
    👥
    Peer review
    Quality through colleagues.
    🌐
    Localization
    Ready for translation.
    🗓️
    Deprecation
    Retire content safely.
    💡
    Content governance is the set of roles, rules and rhythms that keep every page owned, reviewed, current and eventually retired.

    🎯 Learning Objectives

    By the end of this course you will be able to:

    1. Design review cycles with clear stages, owners and service levels.
    2. Run peer review that improves quality without becoming a bottleneck.
    3. Prepare content for localization and manage translation workflows.
    4. Plan deprecation: announcements, redirects, archives and removal.
    5. Build a content inventory and run audits.
    6. Define ownership, policies and escalation paths.
    7. Track governance metrics: freshness, review time, translation cost.

    🔄 Basic: A Standard Review Cycle

    StageOwnerChecksSLA
    DraftAuthorComplete, tested—
    Technical reviewSME / engineerAccuracy2 days
    Editorial reviewTechnical editorStyle, clarity, structure2 days
    Compliance reviewLegal / security (if needed)Claims, data, licensing2 days
    ApprovalContent ownerReady to publish1 day
    PublishDocs teamBuild, links, release1 day
    textCYCLE TIME
Stages with SLAs: technical 2 + editorial 2 + compliance 2 + approval 1 + publish 1 = 8 days (if all run in sequence)
Run technical, editorial and compliance reviews in parallel: 2 + 1 + 1 = 4 days
Saving = 4 days (50%)

    🌐 Writing for Translation

    PracticeExample
    Short, simple sentencesAim for 25 words or fewer
    One term per conceptUse the termbase
    Avoid idioms and humorUse "start", not "kick off"
    Avoid ambiguityName the noun after "this" or "it"
    Keep articles and relative pronounsUse "the file that you saved"
    No text in imagesUse captions or editable layers
    Neutral examplesAvoid local dates, currencies and names
    textBEFORE: "Hit the ground running by spinning up a new instance."
AFTER: "To start quickly, create a new instance."

BEFORE: "Once this is done, it will show up."
AFTER: "After the deployment finishes, the status appears in the dashboard."

    💰 Intermediate: Translation Memory and Cost

    textCOST EXAMPLE
Update: 50,000 words x $0.15/word = $7,500 per language
TM leverage: 30% of words are 100% matches (free) -> 35,000 billable words
35,000 x $0.15 = $5,250 per language -> saving $2,250 (30%)
For 5 languages: $26,250 vs $37,500
Editing for consistency raises match rates, reducing cost.
    TermMeaning
    Translation memory (TM)Stored source and target segments
    Fuzzy matchPartly similar segment; discounted
    MT + post-editingMachine translation reviewed by humans
    GlossaryApproved terms per language
    Do-not-translate listProduct names, code, commands
    Figure 4.2 · Layers of localization

    🔧 Intermediate: Internationalization Checks

    CheckWhy
    Strings externalizedText can be extracted
    Variables not splitAvoid broken grammar: "You have {n} files"
    Placeholders documentedTranslators know the meaning
    Dates and numbers formatted by localeAvoid 10/11 ambiguity
    Expansion allowanceGerman text is about 30% longer
    Right-to-left supportArabic and Hebrew layouts
    Code and commands in code fontProtected from translation
    code# Bad: concatenated strings
"You have " + n + " new " + (n == 1 ? "message" : "messages")

# Better: ICU message format
"{n, plural, one {You have # new message} other {You have # new messages}}"

    Module 11

    Interview Preparation

    Questions asked in Technical Editor interviews about content governance, grouped by level. Draft your answer, then compare with the model answer.

    🌱 Beginner Interview Questions

    IQ1.What is content governance?
    Roles, policies and processes that keep content owned, reviewed, accurate and retired on schedule.
    IQ2.How do you design a review cycle?
    Define stages, owners, SLAs and risk-based depth, then measure cycle time and bottlenecks.
    IQ3.How do you avoid review becoming a bottleneck?
    Risk-based tiers, parallel reviews, automation for mechanics and reviewer load caps.

    🛠️ Intermediate Interview Questions

    IQ4.What makes peer review effective?
    Checklists, specific and prioritized comments, rotation and a respectful culture.
    IQ5.How do you handle reviewer disagreement?
    Consult the style guide, let the owner decide, record and apply the decision.
    IQ6.How do you prepare content for localization?
    Simple sentences, consistent terms, no idioms, no text in images and externalized strings.

    🚀 Advanced Interview Questions

    IQ7.How does translation memory save money?
    Reuses previous translations, so matched segments are not billed again.
    IQ8.How do you plan content deprecation?
    Announce, warn, freeze, retire with notice, redirect and archive on a clear schedule.
    IQ9.How do you run a content audit?
    Inventory, score by use and age, decide keep, update, merge or retire, assign owners.

    IQ11.Which governance metrics matter?
    Freshness, ownership coverage, SLA compliance, translation coverage and broken links.
