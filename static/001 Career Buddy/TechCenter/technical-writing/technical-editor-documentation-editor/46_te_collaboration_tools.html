    Module 01

    Collaboration Tools for Technical Editors

    Git pull-request review workflows, track changes in word processors, and editorial issue tracking in Jira and GitHub: the toolchain that lets editors work with authors and engineers at scale.

    🏛️ Course Overview: What the Role Needs

    Collaboration tools make editing a shared, traceable process. With good Git habits, clear issue tracking and automated checks, editors scale quality across many contributors.

    🔀
    Git and PRs
    Branches, reviews, merges.
    📝
    Track changes
    Redlines and comments.
    🎫
    Issue tracking
    Jira and GitHub.
    🤖
    Automation
    Bots and CI checks.
    💡
    Collaboration tools are where editorial standards meet daily workflow: every edit, query and decision should be visible, reviewable and traceable.

    🎯 Learning Objectives

    By the end of this course you will be able to:

    1. Use Git branches, commits and pull requests for documentation work.
    2. Review documentation pull requests efficiently with checklists and suggestions.
    3. Use track changes, comments and version comparison in word processors.
    4. Run editorial issue tracking in Jira and GitHub Issues.
    5. Define labels, templates, workflow states and priorities for doc work.
    6. Automate checks with CI: linting, link checks and preview builds.
    7. Measure collaboration health: PR cycle time, issue age, backlog trend.

    Track Changes, Comments and Version Compare

    Word and Google Docs review modes, comment etiquette, merging multiple reviewers, document comparison, and moving content to Git.

    📝 Track Changes Workflow

    TaskWordGoogle Docs
    Turn on trackingReview > Track ChangesEditing > Suggesting
    Add commentReview > New CommentInsert > Comment
    Accept or rejectReview > Accept / RejectAccept or reject suggestion
    Compare two versionsReview > CompareTools > Compare documents
    Combine reviewersReview > CombineUse one shared document
    Version historyFile > Info > VersionsFile > Version history
    textTRACK CHANGES RULES
1. Always track edits; never silently change meaning.
2. One reviewer file or one shared doc; avoid emailing 5 copies.
3. Name versions: Guide_v0.3_editor_2026-10-06.
4. Comments use severity: [must-fix] [should] [nit].
5. Resolve comments only when fixed or answered; keep a decision log.
6. Before publishing: accept all, final read, remove comments, check metadata.

    📭 Case Study: PRs Wait for Days

    1. Measure first-review time and find the bottleneck.
    2. Use CODEOWNERS with backups.
    3. Add a weekly review slot.
    4. Reduce PR size and automate mechanical checks.
    5. Report cycle time monthly.

    StepAction

    3Re-triage the rest with priority and owner

    5Review the backlog weekly

    Interview Preparation

    Questions asked in Technical Editor interviews about collaboration tools, grouped by level. Draft your answer, then compare with the model answer.

    🌱 Beginner Interview Questions

    IQ1.How do you contribute a docs change in Git?
    Branch from main, edit, commit with a clear message, push, open a PR, respond to review and merge.
    IQ2.What is a good commit message?
    Imperative, specific subject with a type prefix, and a body that explains why when needed.
    IQ3.How do you review a docs PR?
    Read description, check CI, open the preview, review the diff for accuracy and style, use severity labels and suggestions.

    🛠️ Intermediate Interview Questions

    IQ4.How do you resolve a merge conflict?
    Fetch, inspect markers, confirm the correct content with the author, edit, build and commit.
    IQ5.What is CODEOWNERS?
    A file that maps paths to required reviewers so the right people approve changes.
    IQ6.How do you use track changes well?
    Always track edits, comment with severity, use one shared file, compare final against approved.

    🚀 Advanced Interview Questions

    IQ7.How do you combine feedback from many reviewers?
    One shared document or Combine, resolve conflicts with guide or owner, keep a decision log.
    IQ8.How do you set up editorial issue tracking?
    Templates, labels, workflow states, priorities with SLAs, saved queries and a triage routine.
    IQ9.How do you link PRs and issues?
    Use Closes #123 in the PR description and keep the issue updated.

    🏆 Expert Interview Questions

    IQ10.Which checks run in docs CI?
    Vale, link check, markdown lint, spell check, build, secret scan and metadata validation.
    IQ11.How do you measure collaboration health?
    PR cycle time, first review time, issue age, reopen rate and CI first-pass rate.
    IQ12.Tell me about improving a review process.
    Describe the bottleneck, the data, the change and the measured result.
