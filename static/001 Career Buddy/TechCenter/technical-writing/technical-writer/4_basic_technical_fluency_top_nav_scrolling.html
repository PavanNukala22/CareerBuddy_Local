    📁 Repository model

    A Git repository stores versioned project content. The working tree contains local files, the staging area selects changes for a commit, and commits record snapshots.

    🌿 Branches

    Branches isolate work so documentation changes can be reviewed before integration. Name branches clearly and keep changes focused.

    💾 Commit workflow

    A common documentation workflow is edit → status → add → commit → pull/rebase or merge as needed → push → review.

    ✕ BAD

    Configure the settings as appropriate and continue.

    ✓ GOOD

    Select Settings, choose Notifications, and enable Email alerts.

    ⚔️ Merge conflicts

    When Git cannot automatically combine overlapping changes, inspect the conflict markers, choose the intended content, remove markers, stage, and complete the merge.

    💡
    Practical tip: Always review the resolved document before committing.

    🧪 Worked example

    ```bash git switch -c docs-release-notes # edit release.md git status git add release.md git commit -m "Update release notes" git push -u origin docs-release-notes ```

    🧪
    Worked example: Use pull requests or the team’s review process before integrating into the main branch.

    🔬 🌿 Advanced Git documentation workflow

    Advanced technical writers use Git to review changes, isolate work, resolve conflicts, and maintain traceability.

    🚀
    Advanced practice: Prefer focused commits, meaningful branch names, and pull-request descriptions that explain documentation impact.

    🖼️ Framing and cropping

    Capture the correct UI state, crop irrelevant areas, and retain enough context for the reader to orient themselves.

    Good practiceWhy it helps
    Use precise, task-focused wordingReaders can act without guessing.
    Show dependencies before actionsPrevents avoidable failure.

    ✏️ Annotation

    Use restrained callouts, boxes, or numbers to direct attention. Avoid clutter and do not obscure interface text.

    ✕ BAD

    Configure the settings as appropriate and continue.

    ✓ GOOD

    Select Settings, choose Notifications, and enable Email alerts.

    🔒 Privacy and quality

    Redact sensitive data before publication and preserve enough resolution for UI labels to remain readable.

    💡
    Practical tip: Never assume a screenshot is safe just because it is an image.

    🧪 Worked example

    For a “Create API key” task, capture the dialog in its correct state, crop to the relevant controls, highlight the button, replace real account data with sample values, and verify readability at published size.

    🧪
    Worked example: Re-run the procedure before capture so the image matches the written steps.

    🔬 📸 Advanced screenshot strategy

    Advanced screenshot work treats images as maintained documentation assets rather than permanent decorations.

    🚀
    Advanced practice: Capture only the UI region needed, remove sensitive information, annotate one focal action at a time, and record the product version when visual changes are likely.

    🧠 🔄 Screenshot maintenance

    If a UI changes every release, avoid screenshots for stable text. When a screenshot is essential, keep the source image editable and tie its review to the documentation release cycle.
