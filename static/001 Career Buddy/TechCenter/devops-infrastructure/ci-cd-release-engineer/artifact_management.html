    Module 01 · Foundations

    Artifact Management Fundamentals

    What artifacts are, where they live, and why a repository manager is essential.

    📦 What is an artifact?

    Basic

    An artifact is any versioned, immutable output of a build: a JAR, npm package, Python wheel, Docker image, Helm chart, or binary. An artifact repository stores, versions, secures and serves them so builds are reproducible and fast.

    Source

    The repository is the single source of truth between build and deploy.
    ☕
    PackagesMaven, Gradle, npm, PyPI, NuGet, Go, Cargo
    🐳
    ContainersDocker/OCI images and Helm charts
    🗜️
    Generic binariesInstallers, ZIPs, firmware, ML models
    📜
    MetadataSBOM, signatures, build-info, provenance

    🗃️ Repository types

    TypePurposeExample
    Local / HostedYou publish your own artifactslibs-release-local
    Remote / ProxyCache of an upstream registryProxy of Maven Central, Docker Hub
    Virtual / GroupOne URL combining several reposlibs-all = local + remote
    Release vs SnapshotImmutable final versions vs overwritable dev builds1.4.0 vs 1.5.0-SNAPSHOT
    💡
    Developers and CI should point to one virtual repo. You can then change upstreams, add scanning or block bad packages without touching any project.

    🧬 Core principles

    • Immutability: a released version is never overwritten.
    • Traceability: every artifact links to commit, build and dependencies.
    • Proxy caching: protects from upstream outages and rate limits.
    • Retention: automated cleanup to control storage cost.
    • Least privilege: separate read, deploy and admin permissions.

    🧹 Expert: cleanup, security & HA

    Expert
    • Cleanup policies by age, last downloaded, or version regex; then run Compact blob store to reclaim disk.
    • Nexus IQ / Firewall quarantines malicious or vulnerable components at the proxy.
    • Content selectors + RBAC restrict who can read/write which paths.
    • Back up DB + blob store together; use S3 blob stores and HA (Pro) for scale.
    📝
    Artifactory vs Nexus: both are excellent. Artifactory leans toward universal formats, build-info and promotion; Nexus offers a strong OSS edition and tight IQ policy integration.

    🏷️ Tagging and digests

    Intermediate
    • Tags are mutable pointers; the digest (sha256:…) is the true identity.
    • Good tags: 1.4.2, 1.4.2-a1b2c3d (version + SHA), 1.4, main-742.
    • Avoid latest in any deployment manifest.
    bashaws ecr get-login-password --region ap-south-1 | docker login --username AWS --password-stdin 123456789012.dkr.ecr.ap-south-1.amazonaws.com
docker build -t app:1.4.2 .
docker tag app:1.4.2 123456789012.dkr.ecr.ap-south-1.amazonaws.com/app:1.4.2
docker push 123456789012.dkr.ecr.ap-south-1.amazonaws.com/app:1.4.2

    Artifact Security & Governance

    Trust what you ship: scanning, SBOM, signing and retention.

    🛡️ Supply-chain controls

    ControlWhat it doesTool examples

    SBOMLists every component insideSyft, CycloneDX, SPDX

    ✍️ Sign and verify

    Expert
    bashsyft app:1.4.2 -o cyclonedx-json > sbom.json
cosign sign --yes registry/app@$DIGEST
cosign attest --yes --predicate sbom.json --type cyclonedx registry/app@$DIGEST
cosign verify registry/app@$DIGEST --certificate-identity-regexp 'github.com/acme/.*' --certificate-oidc-issuer https://token.actions.githubusercontent.com

    📅 Retention & governance checklist

    • Keep released artifacts per compliance period; expire snapshots and PR builds quickly.
    • Block downloads of critical CVEs at the proxy.
    • Audit logs on publish/delete; no direct deletes by developers.
    • Separate repos per stage (dev, staging, release) to enable promotion.
    • Dependency confusion defence: prefer virtual repos with explicit namespaces/priority for internal packages.
