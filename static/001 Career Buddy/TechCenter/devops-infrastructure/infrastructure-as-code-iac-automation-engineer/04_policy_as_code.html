    Module 01 · Policy as Code · Foundations

    What is Policy as Code?

    Turn compliance documents into automated, testable rules that run in your pipeline. Learn the types of policy, where to enforce them, and the tools available.

    📏 From Documents to Guardrails

    Policy as Code (PaC) expresses rules such as “S3 buckets must never be public” or “every resource needs an Owner tag” as machine-readable code that is stored in Git, reviewed, tested, and enforced automatically.

    Without PaC

    • PDF standards nobody reads.
    • Manual review by security at the end.
    • Violations found in production audits.
    • Slow, inconsistent, argumentative.

    With PaC

    • Rules live next to the code.
    • Instant feedback in the pull request.
    • Violations blocked before deployment.
    • Same rule, same result, every time.
    💡
    Think of policies as unit tests for your infrastructure’s compliance: failing tests block the merge.

    🧭 Types of Policy Controls

    TypePurposeExamples
    PreventiveStop a bad change from happeningCI policy check fails the PR; SCP denies public S3; admission controller rejects a pod
    DetectiveFind violations that existAWS Config rule, scheduled Checkov scan of live accounts, drift detection
    CorrectiveFix violations automaticallyAuto-remediation Lambda closes an open security group
    AdvisoryWarn without blockingCost or best-practice recommendations in a PR comment

    📍 Where to Enforce

    Shift left — the earlier a violation is found, the cheaper it is to fix.
    StageInput checkedTypical toolsStrength
    Pre-commit / IDESource filesCheckov, Trivy, tflintFastest feedback

    📝

    Module 02 · Policy as Code · Open Policy Agent

    Open Policy Agent & Rego

    Learn the Rego language from first rule to production patterns: plan-time Terraform checks, unit tests, exceptions, and running OPA as a service.

    💡 What OPA Does

    OPA decouples policy decisions from enforcement. Your system (CI job, API, Kubernetes) sends OPA a JSON input; OPA evaluates Rego rules plus optional data and returns a decision (allow/deny, a list of violations, …).

    OPA never enforces by itself; the caller acts on the decision.
    📝
    This tab uses Rego v1 syntax (the default in OPA 1.0+): rules that produce sets use contains, and rule bodies need if. On older OPA versions add import rego.v1 at the top of the file.

    🌱 Rego Basics

    BASIC Rules, input and defaults

    regopackage example.authz

default allow := false                 # safe default

allow if {                              # all lines must be true (logical AND)
  input.user.role == "admin"
}

allow if {                              # a second rule with the same name = logical OR
  input.user.role == "developer"
  input.action == "read"
}
    bashecho '{"user":{"role":"developer"},"action":"read"}' > input.json
opa eval --format pretty --data policy.rego --input input.json "data.example.authz.allow"
# true
    Rego ideaMeaning
    packageNamespace; becomes data.<package>
    inputThe JSON document supplied by the caller
    := vs ==Assignment vs comparison
    Rule bodyA list of conditions; every line must be true (AND)
    Several rules, same nameOR between rules
    UndefinedIf any condition is false/missing the rule is simply undefined (not an error)

    📚 Collections & Iteration

    INTERMEDIATE Sets, comprehensions, some, every

    regopackage example.collections

allowed_regions := {"ap-south-1", "eu-west-1"}      # set

region_ok if input.region in allowed_regions

names := [r.name | some r in input.resources]        # array comprehension

open_ports contains p if {                           # partial set rule
  some rule in input.firewall_rules
  rule.cidr == "0.0.0.0/0"
  p := rule.port
}

all_encrypted if {
  every r in input.resources { r.encrypted == true }  # universal check
}

    ☁️ Policies for Terraform Plans

    INTERMEDIATE Check what Terraform is about to do

    bashterraform plan -out=tfplan
terraform show -json tfplan > plan.json       # structured plan = OPA input
    regopackage terraform.aws

required_tags := {"Owner", "CostCenter", "Environment"}
taggable := {"aws_instance", "aws_s3_bucket", "aws_db_instance"}

# 1. Mandatory tags
deny contains msg if {
  some rc in input.resource_changes
  rc.type in taggable
  not "delete" in rc.change.actions
  provided := {k | some k, _ in object.get(rc.change.after, "tags", {})}
  missing := required_tags - provided
  count(missing) > 0
  msg := sprintf("%s is missing required tags: %v", [rc.address, sort(missing)])
}

# 2. No SSH open to the world
deny contains msg if {
  some rc in input.resource_changes
  rc.type == "aws_security_group_rule"
  rc.change.after.type == "ingress"
  rc.change.after.from_port <= 22
  rc.change.after.to_port >= 22
  "0.0.0.0/0" in rc.change.after.cidr_blocks
  msg := sprintf("%s opens SSH to the internet", [rc.address])
}

# 3. Approved instance sizes only
approved_sizes := {"t3.micro", "t3.small", "t3.medium", "m5.large"}
deny contains msg if {
  some rc in input.resource_changes
  rc.type == "aws_instance"
  not rc.change.after.instance_type in approved_sizes
  msg := sprintf("%s uses unapproved instance type %s", [rc.address, rc.change.after.instance_type])
}
    bashopa eval --format pretty --data policy/ --input plan.json "data.terraform.aws.deny"
conftest test plan.json --policy policy/ --all-namespaces      # fails the build if deny is non-empty
    💡
    Return clear messages that name the resource and say how to fix it. Good messages are the difference between developers adopting policies and routing around them.

    🔧 Exceptions, Data & Reuse

    EXPERT Keep policy logic separate from allow-lists

    json{
  "exceptions": {
    "unapproved_instance_type": {
      "aws_instance.legacy_batch": { "owner": "team-data", "expires": "2026-12-31", "ticket": "SEC-1432" }
    }
  }
}
    regopackage terraform.aws

import data.exceptions

deny contains msg if {
  some rc in input.resource_changes
  rc.type == "aws_instance"
  not rc.change.after.instance_type in approved_sizes
  not exempt(rc.address)
  msg := sprintf("%s uses unapproved instance type", [rc.address])
}

exempt(addr) if {
  e := exceptions.unapproved_instance_type[addr]
  time.parse_rfc3339_ns(sprintf("%sT00:00:00Z", [e.expires])) > time.now_ns()   # exception still valid
}
    ✅
    Exceptions in data files with an owner, ticket and expiry are auditable and expire on their own — far better than commenting out a policy.

    🚀 OPA as a Service & Beyond (Expert)

    bashopa run --server --addr :8181 policy/ &
jq '{input: .}' plan.json | curl -s localhost:8181/v1/data/terraform/aws/deny -d @-
    • Bundles: package policies and data, distribute them from S3/HTTP; OPA polls and hot-reloads.
    • Decision logs: stream every decision (input, result, policy version) for auditing.
    • Kubernetes: Gatekeeper uses Rego inside ConstraintTemplates; Kyverno offers a YAML alternative.
    • Application authorisation: microservices query OPA via sidecar or library for fine-grained access control.
    • Performance: avoid unbounded iteration, use indexed lookups (data.x[key]), profile with opa eval --profile.

    A static IaC scanner with a huge library of ready-made checks for Terraform, CloudFormation, Kubernetes, Dockerfiles, Helm and more.

    🔍 What is Checkov?

    🧩 Custom Policies

    EXPERT YAML policy (no Python needed)

    yaml# custom_policies/s3_owner_tag.yaml
metadata:
  id: "CKV2_ACME_1"
  name: "S3 buckets must have an Owner tag"
  category: "GENERAL_SECURITY"
definition:
  cond_type: "attribute"
  resource_types: ["aws_s3_bucket"]
  attribute: "tags.Owner"
  operator: "exists"

    EXPERT Python policy (full flexibility)

    pythonfrom checkov.common.models.enums import CheckResult, CheckCategories
from checkov.terraform.checks.resource.base_resource_check import BaseResourceCheck

class RdsNoPublicAccess(BaseResourceCheck):
    def __init__(self):
        super().__init__(
            name="RDS instances must not be publicly accessible",
            id="CKV_ACME_2",
            categories=[CheckCategories.NETWORKING],
            supported_resources=["aws_db_instance"],
        )

    def scan_resource_conf(self, conf):
        value = conf.get("publicly_accessible", [False])[0]
        return CheckResult.FAILED if value is True else CheckResult.PASSED

check = RdsNoPublicAccess()
    bashcheckov -d . --external-checks-dir ./custom_policies

    Checkov also supports graph checks (IDs like CKV2_*) that reason across resources — for example, “every S3 bucket must have a matching public-access-block resource”.

    Module 04 · Policy as Code · tfsec / Trivy

    tfsec and Trivy

    Fast, developer-friendly security scanning for Terraform and other IaC. tfsec’s engine now lives inside Trivy, which also scans images, dependencies and secrets.

    🧬 tfsec → Trivy

    tfsec (originally by Aqua Security) was a popular Terraform static analyser. Its checks and engine were merged into Trivy, and the tfsec project recommends migrating. Existing tfsec pipelines still work, but new work should target Trivy.

    tfsecTrivy (trivy config)
    StatusMaintenance mode; migration recommendedActively developed
    ScopeTerraformTerraform, CloudFormation, Kubernetes, Helm, Dockerfile, Azure ARM + container images, dependencies, secrets
    Check IDsaws-s3-enable-bucket-loggingAVD-AWS-xxxx (same underlying checks)
    SpeedVery fastVery fast

    ▶️ Running Scans

    BASIC Quick start

    bash# tfsec
tfsec .
tfsec . --minimum-severity HIGH
tfsec . --format sarif --out tfsec.sarif

# Trivy (recommended)
trivy config .
trivy config --severity HIGH,CRITICAL --exit-code 1 .       # fail the build on HIGH+
trivy config --tf-vars prod.tfvars .                         # resolve variables
trivy config --format sarif --output trivy.sarif .
    SeverityMeaningTypical policy
    CRITICAL / HIGHSerious exposure (public data, open admin ports)Block the pull request
    MEDIUMWeak configuration (missing logging)Warn, require a ticket
    LOWHygieneReport only
    💡
    Use --exit-code 1 with --severity to make Trivy a quality gate. Start with HIGH,CRITICAL only to avoid overwhelming teams.

    ⚖️ Choosing the Right Tool

    NeedBest fitWhy
    Quick wins, ready-made rulesTrivy / tfsec / CheckovZero policy writing required
    Broadest framework + rule coverageCheckovLarge library, graph checks, baselines
    One tool for IaC, images and dependenciesTrivySingle binary, one pipeline step
    Organisation-specific rules on plan valuesOPA / ConftestArbitrary logic, exceptions, unit tests
    Control plane enforcementSCP, Azure Policy, admission controllersCannot be bypassed from a laptop
    ✅
    Common combination: Trivy or Checkov for broad baseline coverage + OPA/Conftest for your company-specific rules on the plan.

    🛠️ Custom Checks (Expert)

    Trivy’s custom checks are written in Rego, so everything you learned in the OPA tab applies. You load them from a directory when scanning and give them IDs, titles and severities through metadata annotations.

    bashtrivy config --help | grep -i check      # custom-check flags differ by version, confirm in your release
    • Keep company checks in a dedicated repository, versioned and tested with opa test.
    • Distribute them to all pipelines as a pinned bundle or Git ref.
    • Document each rule with rationale and a remediation snippet.

    Module 05 · Policy as Code · Putting it together

    Pipelines, Rollout & Governance

    Combine scanners and OPA in CI/CD, roll policies out without breaking teams, manage exceptions, and measure compliance.

    🧱 A Layered Pipeline

    Fast checks first, expensive checks later, human approval last.
    yaml# .pre-commit-config.yaml
repos:
  - repo: https://github.com/antonbabenko/pre-commit-terraform
    rev: v1.96.1
    hooks:
      - id: terraform_fmt
      - id: terraform_validate
  - repo: https://github.com/bridgecrewio/checkov
    rev: 3.2.0
    hooks:
      - id: checkov
        args: ["--framework", "terraform", "--quiet"]

    ⚙️ CI Example

    INTERMEDIATE Static scan → plan → OPA gate

    yamlname: iac-policy
on: [pull_request]

permissions: { id-token: write, contents: read, security-events: write }

jobs:
  static-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install checkov
      - run: checkov -d . --framework terraform --compact -o cli -o sarif --output-file-path results/
      - run: docker run --rm -v "$PWD:/src" aquasec/trivy config --severity HIGH,CRITICAL --exit-code 1 /src
      - uses: github/codeql-action/upload-sarif@v3
        if: always()
        with: { sarif_file: results/results_sarif.sarif }

  plan-policy:
    needs: static-scan
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::111122223333:role/ci-readonly-plan
          aws-region: ap-south-1
      - uses: hashicorp/setup-terraform@v3
      - run: |
          terraform init -input=false
          terraform plan -input=false -out=tfplan
          terraform show -json tfplan > plan.json
      - name: Install Conftest
        run: |
          curl -sSL https://github.com/open-policy-agent/conftest/releases/latest/download/conftest_Linux_x86_64.tar.gz | tar xz
      - run: ./conftest test plan.json --policy policy/ --all-namespaces
    💡
    Pin tool versions in real pipelines instead of using latest so a tool update never breaks every build overnight.

    🛣️ Rolling Out Policies

    EXPERT Audit → warn → enforce

    PhaseBehaviourGoal
    1. AuditRun everywhere, --soft-fail, results visible onlyMeasure the real violation rate, tune noisy rules
    2. WarnPR comments and annotations, no blockingTeach teams, collect feedback
    3. Enforce newBlock new violations (baseline legacy)Stop the bleeding
    4. Enforce allBlock everything, exceptions need approvalFull compliance
    • Announce rules before enforcement with a date and a remediation guide.
    • Start with a small set of high-value rules (public exposure, encryption, tagging).
    • Treat a noisy rule as a bug: fix or demote it quickly.

    🎓 Capstone Project

    1. Write five OPA rules (tags, no public S3, no open SSH, approved regions, approved instance sizes) with unit tests.
    2. Scan a deliberately insecure Terraform repo with Checkov and Trivy; fix the HIGH findings.
    3. Build a CI pipeline: scan → plan → Conftest → approval → apply.
    4. Add an expiring-exceptions file with CODEOWNERS protection.
    5. Run in audit mode, then promote to enforce, and report the metrics.
    📝
