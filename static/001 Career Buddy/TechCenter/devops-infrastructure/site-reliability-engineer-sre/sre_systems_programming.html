    Module 01 · Foundations

    Systems Programming for SREs

    SREs are software engineers who treat operations as a software problem. The goal: write small, reliable tools so humans stop doing the same task twice.

    🧹 What is toil? Basic

    Toil is manual, repetitive, automatable work that scales with service size and brings no lasting value. Google SRE caps toil at 50% of an SRE's time.

    🔁
    Repetitive
    Same steps every week, e.g. rotating certs by hand
    🤖
    Automatable
    A script could do it
    📈
    Scales linearly
    More servers = more manual work
    🚫
    No enduring value
    Service is no better afterwards
    🚰
    Analogy: bailing water with a bucket (toil) vs fixing the leak (engineering).

    🧰 Choosing a language Basic

    LanguageStrengthsTypical SRE useLearning curve
    PythonFast to write, huge librariesGlue scripts, API automation, data analysisEasy
    GoSingle static binary, great concurrencyCLIs, Kubernetes operators, exporters, agentsModerate
    RustMemory safety, no GC, top speedPerformance-critical agents, proxies, eBPF toolsSteep
    BashAlways thereOne-off glue, CI stepsEasy but fragile
    📌
    Rule of thumb: start in Python, move to Go when you need distribution and concurrency, use Rust when latency or safety is critical.

    📊 Measure toil before automating Intermediate

    Automate by return on time: 

    pythondef worth_automating(minutes_per_run, runs_per_month, build_hours):
    saved = minutes_per_run * runs_per_month * 12 / 60   # hours per year
    return saved > build_hours, round(saved, 1)

print(worth_automating(20, 30, 8))   # (True, 120.0)

    Module 02 · Scripting

    Python for Automation

    Python is the SRE's Swiss army knife: readable, quick and well supported by every cloud and monitoring tool.

    🐍 Basics: a health-check script Basic

    Check a list of URLs and report failures:

    pythonimport requests

URLS = ["https://example.com", "https://api.example.com/health"]

for url in URLS:
    try:
        r = requests.get(url, timeout=3)
        status = "OK" if r.ok else f"BAD {r.status_code}"
    except requests.RequestException as e:
        status = f"DOWN ({e.__class__.__name__})"
    print(f"{url:40} {status}")
    ⚠️
    Always set a timeout. The default is none, and a hung call can freeze your tool forever.

    ⚡ Intermediate: concurrency Intermediate

    Checking 500 hosts one by one is slow. I/O-bound work parallelises easily with threads:

    pythonfrom concurrent.futures import ThreadPoolExecutor
import requests

def check(url):
    try: return url, requests.get(url, timeout=3).status_code
    except requests.RequestException: return url, None

with ThreadPoolExecutor(max_workers=20) as pool:
    for url, code in pool.map(check, urls):
        if code != 200: print("ALERT", url, code)

    📡 Intermediate: a Prometheus exporter Intermediate

    Expose your own metrics in 10 lines:

    pythonfrom prometheus_client import Gauge, start_http_server
import shutil, time

disk = Gauge("backup_disk_free_bytes", "Free space on backup volume")

while True:

    🔁 Expert: retries with backoff & jitter Expert

    Naive retries cause retry storms. Use exponential backoff plus randomness:

    pythonimport random, time

def retry(fn, tries=5, base=0.5, cap=30):
    for n in range(tries):
        try: return fn()
        except Exception:
            if n == tries - 1: raise
            time.sleep(random.uniform(0, min(cap, base * 2**n)))   # full jitter
    💡
    Only retry idempotent operations (safe to run twice) and respect rate limits.

    Module 03 · Tooling

    Go for SRE Tooling

    Go compiles to a single static binary, starts instantly and makes concurrency simple. Docker, Kubernetes, Terraform and Prometheus are all written in Go.

    🐹 Basics: a small CLI Basic

    A tool that prints whether a TCP port is open:

    gopackage main

import ("fmt"; "net"; "os"; "time")

func main() {
    addr := os.Args[1]                      // e.g. db.internal:5432
    conn, err := net.DialTimeout("tcp", addr, 2*time.Second)
    if err != nil { fmt.Println("CLOSED:", err); os.Exit(1) }
    defer conn.Close()
    fmt.Println("OPEN:", addr)
}
    ✅
    GOOS=linux GOARCH=amd64 go build gives one file you can copy to any server. No runtime to install.

    🧵 Intermediate: goroutines & channels Intermediate

    A goroutine is a lightweight thread; a channel passes results between them.

    gofunc probe(url string, out chan<- string) {
    resp, err := http.Get(url)
    if err != nil { out <- url + " DOWN"; return }
    out <- fmt.Sprintf("%s %d", url, resp.StatusCode)
}

out := make(chan string)
for _, u := range urls { go probe(u, out) }
for range urls { fmt.Println(<-out) }

    Module 04 · Performance & Safety

    Rust for Critical Tools

    Rust gives C-like speed with compile-time memory safety. Use it where a crash or a pause is expensive: agents on every host, proxies, eBPF programs.

    🦀 Ownership in one minute Intermediate

    Each value has one owner; when the owner goes out of scope the memory is freed. No garbage collector, no use-after-free, no data races.

    rustlet a = String::from("log line");
let b = a;              // ownership MOVES to b
// println!("{}", a);   // compile error: a was moved
println!("{}", b);

    📂 Intermediate: fast log scanner Intermediate

    Count ERROR lines in a large file with a few lines of safe code:

    rustuse std::{fs::File, io::{BufRead, BufReader}};

fn main() -> std::io::Result<()> {
    let f = BufReader::new(File::open("app.log")?);
    let n = f.lines().flatten().filter(|l| l.contains("ERROR")).count();
    println!("errors: {n}");
    Ok(())
}

    🚀 Expert: async with Tokio Expert

    Probe thousands of endpoints concurrently with one small binary:

    rust#[tokio::main]
async fn main() {
    let urls = vec!["https://a.example", "https://b.example"];
    let tasks: Vec<_> = urls.into_iter().map(|u| tokio::spawn(async move {
        let r = reqwest::get(u).await;
        (u, r.map(|x| x.status()))
    })).collect();
    for t in tasks { println!("{:?}", t.await.unwrap()); }
}
    📌
    Typical trade: Rust takes longer to write, but the result is tiny, fast and rarely crashes in production.

    Module 05 · Engineering discipline

    Eliminating Toil Well

    Good automation is itself a reliability risk. These patterns keep your tools safe.

    ♻️ Idempotency Intermediate

    Running a tool twice must give the same result as running it once.

    ❌ Not idempotent

    • echo "line" >> file appends every run

    • "create user" fails on second run

    ✅ Idempotent

    • "ensure line exists in file"

    • "create user if missing"

    🛑 Safety rails Intermediate

    • Dry-run flag that prints actions only
    • Blast-radius limits: act on max N hosts per run
    • Rate limiting and pause between batches
    • Audit logs of who ran what
    • Kill switch to stop mid-run
    pythondef drain(nodes, dry_run=True, max_nodes=3):
    if len(nodes) > max_nodes:
        raise SystemExit(f"refusing: {len(nodes)} > {max_nodes}")
    for n in nodes:
        print(("[dry-run] " if dry_run else "") + f"drain {n}")

    🧪 Test your tooling Expert

    Treat tools as production software: unit tests, integration tests against a staging account, linting, versioned releases and a changelog.
