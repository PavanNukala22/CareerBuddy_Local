    Topic 01 · Foundations

    Cloud Cost Analysis: What & Why

    Before touching any tool, understand where cloud cost data comes from, how bills are structured, and which cost views answer which question.

    ☁️ What is Cloud Cost Analysis?

    Cloud cost analysis is the practice of collecting, normalising, slicing and explaining cloud spend so that engineers, finance and leadership can make decisions. Visualization is how that data is shown (dashboards, trend lines, treemaps, reports) so patterns are obvious.

    Pay-as-you-go
    You are billed for usage (hours, GB, requests), not for ownership. Bills change daily.
    Variable cost
    Spend moves with traffic, deployments and forgotten resources, so you need continuous monitoring.
    Shared responsibility
    Engineers create cost, finance pays it. Analysis tools bridge the two.
    Many dimensions
    Service, account, region, tag, usage type, SKU: every bill can be cut many ways.
    Basic exampleYour AWS bill is $42,000 this month vs $35,000 last month. Cost analysis answers why: grouping by service shows EC2 +$4k and Data Transfer +$3k. Grouping by tag team shows the Data team caused it.

    📊 Where the Data Comes From

    Every tool in this module reads the same raw source: the provider's billing export.

    CloudRaw billing dataDelivered to
    AWSCost and Usage Report (CUR / CUR 2.0, Data Exports)S3 bucket, queried with Athena
    AzureCost Management Exports (actual / amortized usage)Storage account (CSV/Parquet)
    GCPCloud Billing exportBigQuery dataset
    KubernetesPrometheus metrics plus node pricingKubecost / OpenCost
    💡
    The lowest-level data is a line item: one row per resource, per usage type, per hour/day, with a cost and tags. Everything else is aggregation.

    🧮 Cost Types You Must Know

    Cost viewMeaningUse when
    Unblended / ActualWhat was charged on the day of the chargeCash-flow, invoice reconciliation
    AmortizedUpfront and recurring commitment fees spread across the termFair team/product costing
    Net amortizedAmortized after discounts (EDP, credits, private pricing)True cost after negotiated rates
    Blended (AWS)Averaged rate across consolidated accountsLegacy; rarely recommended
    Credits / Refunds / TaxOffsets and add-onsExclude to see real run-rate
    ExampleYou buy a 1-year Savings Plan with $12,000 All Upfront on 1 Jan. Actual view shows a $12k spike in January and nothing after. Amortized shows $1,000 per month. Charging teams on actual cost would be unfair; use amortized.

    📈 Choosing a Visualization

    QuestionBest chart
    How is cost trending?Line / area chart (daily or monthly)
    Who spends the most?Sorted bar chart or treemap
    Which part of the bill changed?Stacked bar, month over month, or waterfall
    Are we on budget?Budget vs actual gauge with forecast line
    Where is the spike?Daily bars with anomaly marker

    🎓 Expert Level: Analysis Maturity

    1. Crawl: monthly bill review by service and account.
    2. Walk: daily cost by tag, budgets, anomaly alerts, forecast.
    3. Run: unit-cost dashboards (cost per customer or transaction), engineer-facing showback, cost in CI/PR checks.
    4. Fly: automated anomaly triage, FinOps as Code, forecasts tied to product roadmap.
    ⚠️
    Data-quality traps: untagged spend, data-transfer misattribution, double counting credits, comparing a 28-day month with a 31-day month (compare daily averages).

    Topic 02 · AWS

    AWS Cost Explorer

    AWS's built-in console tool to visualise, filter, group and forecast spend. Free to use in the console; the API is charged per request.

    🔰 Basics: What Cost Explorer Does

    Cost Explorer shows historical cost and usage for the last 13 months (optionally up to 38 months with multi-year data), and forecasts up to 12 months ahead. Default granularity is monthly or daily; hourly and resource-level data are opt-in.

    Group by
    Service, Linked Account, Region, Usage Type, Instance Type, Tag, Cost Category.
    Filters
    Narrow by account, service, tag, purchase option, charge type.
    Saved reports
    Reusable views, including built-in RI and Savings Plans reports.
    Forecast
    Projects spend using past trends; shows a prediction interval.
    Walk-throughConsole → Billing → Cost Explorer → set range to last 6 months, Daily, Group by Service. Top bar is EC2-Other; filter Usage Type to find NAT Gateway bytes.

    🧩 Intermediate: Tags, Cost Categories, Budgets

    • Cost allocation tags must be activated in the Billing console; only then do they appear in Cost Explorer (data is not retroactive).
    • Cost Categories map accounts/tags/services into business groups (e.g., Team=Payments) with rules.
    • AWS Budgets raise alerts or run actions when actual or forecasted cost passes a threshold.
    • Cost Anomaly Detection uses ML to flag unusual spend and notify via SNS/email.
    ReportAnswers
    RI / Savings Plans UtilizationAre the commitments I bought being used?
    RI / Savings Plans CoverageWhat share of eligible usage is covered by commitments?
    Reservation recommendationsWhat should I buy next?
    Rightsizing recommendationsWhich EC2 instances are oversized?

    🚀 Expert: API, CUR and Athena

    The console hides line-item detail. For deep analysis use the Cost and Usage Report with Athena.

    -- Top 10 untagged spend by service (CUR in Athena)
SELECT line_item_product_code AS service,
       SUM(line_item_unblended_cost) AS cost
FROM   cur_db.cur_table
WHERE  year='2026' AND month='9'
  AND  resource_tags_user_team IS NULL
GROUP  BY 1 ORDER BY cost DESC LIMIT 10;
    # Cost Explorer API (CLI): daily cost grouped by service
aws ce get-cost-and-usage \
  --time-period Start=2026-09-01,End=2026-10-01 \
  --granularity DAILY --metrics AmortizedCost \
  --group-by Type=DIMENSION,Key=SERVICE
    ⚠️
    Each paginated Cost Explorer API request costs about $0.01, so a dashboard that polls every minute adds up. Prefer CUR + Athena or scheduled exports for heavy automation.
    Expert scenarioEC2-Other jumped 40%. In CUR, filter line_item_usage_type LIKE '%NatGateway-Bytes' and group by line_item_resource_id: a single NAT gateway moving S3 traffic. Fix: add an S3 gateway VPC endpoint (free) and cost drops.

    Topic 03 · Azure

    Azure Cost Management + Billing

    Microsoft's native suite for analysing, budgeting and optimising Azure (and, via connectors, AWS) spend.

    🔰 Basics: Scopes and Cost Analysis

    Everything in Azure Cost Management is evaluated at a scope. Pick the scope first, then the view.

    ScopeTypical owner
    Billing account / profileFinance, EA or MCA admin
    Management groupPlatform / FinOps team
    SubscriptionProduct or environment owner
    Resource groupApplication team

    Cost analysis offers smart views, group-by (resource, resource group, tag, meter category, location) and an Actual vs Amortized toggle.

    🧩 Intermediate: Budgets, Exports, Advisor

    Budgets
    Monthly/quarterly/annual budgets with email, action group or automation triggers at % thresholds.
    Exports
    Scheduled daily CSV/Parquet exports of actual or amortized cost to a storage account.
    Azure Advisor
    Cost recommendations: right-size VMs, delete idle resources, buy reservations.
    Anomaly alerts
    Notify when daily cost deviates from the learned pattern.
    • Tag inheritance: copies subscription/resource-group tags onto child usage records for cleaner allocation.
    • Cost allocation rules: split shared costs (e.g., a shared hub network) across subscriptions or tags by proportion.

    🚀 Expert: Automation and Power BI

    Use exports + Power BI (or Fabric/Synapse) for custom dashboards, and the Cost Management API for automation.

    # Azure CLI: monthly cost by resource group
az costmanagement query --type ActualCost \
  --scope "/subscriptions/<sub-id>" \
  --timeframe MonthToDate \
  --dataset-grouping name=ResourceGroup type=Dimension
    Expert scenarioA hub VNet/Firewall costs $18k per month and sits in one subscription, which makes the platform team look expensive. Create a cost allocation rule that redistributes it to 6 spoke subscriptions proportionally to compute spend. Now showback is fair.
    💡
    Compare amortized cost when reservations or Savings Plans exist; otherwise the purchase month looks like a huge spike for one subscription.

    Topic 04 · Kubernetes

    Kubecost / OpenCost

    Cloud bills show nodes; Kubernetes teams think in namespaces and pods. Kubecost bridges that gap.

    🔰 Basics: Why Kubernetes Cost Is Hard

    You pay the cloud provider for nodes (VMs). Many teams share those nodes, so the invoice cannot tell you which team's pod used what. Kubecost (built on the open-source OpenCost standard) allocates node cost down to namespace, deployment, label and pod.

    ExampleA 3-node cluster costs $900/month. Namespace checkout requests 50% of CPU/RAM, search 30%, and 20% is idle. Allocation: checkout $450, search $270, idle $180.

    🧩 Intermediate: How Allocation Works

    Cost per pod ≈ max(CPU request, CPU usage) × CPU price + max(RAM request, RAM usage) × RAM price + storage + network + GPU.

    ConceptMeaning
    Allocation viewCost by namespace, controller, label, pod, team
    Assets viewCost of nodes, disks, load balancers
    Idle costCapacity paid for but not requested by any workload
    Shared costkube-system, monitoring, ingress: split across tenants
    EfficiencyUsage ÷ request; low efficiency means over-provisioning
    # Install (Helm)
helm install kubecost cost-analyzer \
  --repo https://kubecost.github.io/cost-analyzer/ \
  --namespace kubecost --create-namespace

# Query allocation API
curl "http://kubecost/model/allocation?window=7d&aggregate=namespace"

    🚀 Expert: Savings and Governance

    • Request right-sizing: compare requests to P95 usage, then lower requests.
    • Cluster right-sizing and node pools: consolidate and move to Spot for tolerant workloads.
    • Cloud integration: reconcile with the real bill (CUR/Azure exports) so discounts and commitments are reflected.
    • Alerts and budgets per namespace; showback reports to team leads.
    ⚠️
    Allocation by request punishes teams that over-request, but allocation by usage hides waste. Most mature teams charge the greater of the two.

    Topic 05 · Multi-cloud

    CloudHealth

    A multi-cloud FinOps platform (originally VMware, now Broadcom) for reporting, governance policies and organisational hierarchies.

    🔰 What CloudHealth Is

    CloudHealth ingests billing from AWS, Azure, GCP and others into one place. Strength: enterprise governance and hierarchy modelling.

    Perspectives
    Custom groupings of assets into business units, apps, environments by tag or account rules.
    Reports
    Cost history, forecasts, RI/CUD utilisation, rightsizing.
    Policies
    Rules that detect and automate actions (e.g., stop untagged instances).
    FlexOrgs / Hierarchy
    Delegate views to different business units and customers (useful for MSPs).

    🧩 Intermediate: Perspectives and Policies

    ExamplePerspective Business Unit: Group Retail = accounts 111, 222; Group Banking = tag bu=banking. Reports can now be sliced by BU across all clouds.

    Policies combine conditions (idle > 14 days, CPU < 5%) with actions (notify, tag, snapshot-and-terminate).

    🚀 Expert: Multi-cloud Governance

    • Normalise multi-cloud tags into a single key via Perspectives.
    • Run RI/CUD purchase workflows with approval.
    • Use APIs to feed ServiceNow/Jira tickets for waste.
    📌
    Pick based on need: native tools (free) for single cloud; platforms like CloudHealth or Vantage for multi-cloud, shared-cost allocation and enterprise governance.

    Topic 06 · Modern FinOps

    Vantage

    A developer-friendly multi-provider cost platform with fast reports, virtual tags and a strong API/Terraform story.

    🔰 What Vantage Provides

    Cost Reports
    Saved, shareable views filtered/grouped by service, tag, account, provider.
    Virtual Tags
    Create tags retroactively without touching infrastructure (map accounts, services or patterns to a tag).
    Business Metrics
    Import KPIs (orders, users) to see unit cost.
    Providers
    AWS, Azure, GCP, Kubernetes, Datadog, Snowflake, and more in one view.

    🧩 Intermediate: Virtual Tags and Segments

    ExampleHalf the spend is untagged. Create a virtual tag team: rule 1 matches account prod-data → data; rule 2 matches service Amazon Redshift → data. Untagged spend drops from 50% to 12% with zero code changes.

    🚀 Expert: FinOps as Code

    Define reports and budgets in Terraform so cost views are versioned and reviewed like code.

    resource "vantage_folder" "platform" { title = "Platform" }
resource "vantage_cost_report" "eks" {
  folder_token = vantage_folder.platform.token
  title        = "EKS by Namespace"
  filter       = "(costs.provider = 'kubernetes')"
}
    💡
    Combine cost reports with Business Metrics to chart cost per 1,000 requests over time. Falling unit cost with rising total spend is healthy growth.
