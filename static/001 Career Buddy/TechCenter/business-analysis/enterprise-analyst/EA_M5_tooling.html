    Microsoft Excel for Financial Modeling — Foundations

    Model architecture, essential functions, formatting standards and error-proofing — from first formulas to a clean, auditable model.

    📗 Model Architecture and Standards

    FresherIntermediate

    A good financial model separates inputs, calculations and outputs, so any reviewer can trace a number back to its assumption.

    SheetContentRule
    Cover / READMEPurpose, owner, version, change log, colour legendOne page
    AssumptionsAll inputs: rates, volumes, prices, datesSingle source; units + source + owner
    CalculationsYearly/monthly cash flowsSame formula across a row; no hard-codes
    OutputsNPV, IRR, payback, charts, summaryLink only; no logic
    SensitivityData tables, scenarios, tornadoDriven from assumptions
    ChecksReconciliations and error flagsMaster check cell = OK/ERROR
    ConventionMeaning
    Blue fontHard-coded input
    Black fontFormula
    Green fontLink to other sheet
    Yellow fillKey assumption to review
    Consistent timelineSame columns = same period on every sheet
    📌
    Industry standards such as FAST promote flat, consistent, transparent layouts. Fewer clever formulas, more readable ones.

    🧮 Essential Functions: What Is What

    FresherIntermediate
    FunctionUseExample
    NPV(rate, values)Net present value, first value at end of period 1=NPV(B2,D10:H10)+C10
    IRR(values)Internal rate of return, evenly spaced periods=IRR(C10:H10)
    XNPV / XIRRNPV/IRR with actual dates=XNPV(B2,C10:H10,C9:H9)
    PMT / FV / PV / RATELoan and annuity maths=PMT(0.09/12,60,-1000000)
    SUMPRODUCTMultiply and sum arrays (revenue = units × price)=SUMPRODUCT(D5:H5,D6:H6)
    SUMIFS / COUNTIFSConditional totals=SUMIFS(Cost,Year,2027,Type,"Opex")
    XLOOKUP / INDEX-MATCHLook up assumptions or scenarios=XLOOKUP(A2,Tbl[ID],Tbl[Cost])
    IF / IFERROR / AND / ORLogic and error handling=IFERROR(B2/C2,0)
    CHOOSE / INDEXScenario switch=CHOOSE(Scenario,D5,E5,F5)
    EDATE / EOMONTHDates and timelines=EOMONTH(B2,0)
    ⚠️
    NPV() treats the first value as occurring at the end of period 1. Add the time-zero investment outside the function.

    🛡️ Error-Proofing: Checks, Validation and Auditing

    IntermediateAdvanced
    • Data validation: drop-downs for scenario, discount-rate bounds, date rules.
    • Named ranges / structured tables: Discount_Rate is clearer than Assumptions!$C$7.
    • Check cells: total of years = total of lines; balance checks; =IF(ABS(a-b)<0.01,"OK","ERROR").
    • Trace precedents/dependents and Evaluate Formula to audit.
    • Sheet protection on calculation areas; input cells unlocked.
    • Version control: file naming (v1.2), change log, save milestones.
    💡
    Reviewer test: could a colleague understand and rerun the model in 30 minutes without you?

    Scenario ManagerStores named input sets and builds summaryQuick comparison table
    One-variable Data TableRecalculates output for a list of one inputNPV for discount rates 6–14%
    Two-variable Data TableGrid of two inputsNPV by adoption rate × capex overrun
    Goal SeekFind the input that gives a target outputBreak-even adoption rate for NPV = 0

Column input cell: Capex
          adoption ->  60%    80%    100%
capex 4.0M            -0.2   0.9    1.9
capex 5.0M            -1.1  -0.1    0.9

    📌
    Data Tables recalculate all the time and slow large workbooks; set calculation to Automatic except Data Tables when needed.

    🎒 Solver for Portfolio Selection

    AdvancedExpert

    Excel Solver (add-in) finds the best decision values under constraints. For project selection use binary decision variables (1 = fund, 0 = not fund).

    solverDecision cells : X2:X9   (0/1 per project)
Objective      : Max  =SUMPRODUCT(X2:X9, Score)
Constraints    : =SUMPRODUCT(X2:X9, Cost) <= Budget
                 X2:X9 = binary
                 X_P5 = 1             (mandatory)
                 X_P3 <= X_P6         (P3 requires P6)
Method         : Simplex LP (or Evolutionary if non-linear)
    💡
    Always sanity-check Solver output by hand and keep the constraint list on the sheet for transparency.

    🎲 Monte Carlo Simulation and Dashboards

    Expert

    Replace single-point assumptions with distributions, run the model hundreds of times and read the spread of results.

    monte-carloAdoption  =NORM.INV(RAND(), 0.75, 0.10)     // mean 75%, sd 10%
Capex     =TRIANGULAR via inverse: min 4.0, mode 4.6, max 6.5
Runs      Data Table with blank column input -> 1,000 recalcs of NPV
Outputs   =AVERAGE(NPVs)  =PERCENTILE.INC(NPVs,0.1)  =COUNTIF(NPVs,"<0")/1000  // P(NPV<0)
    • Report P10 / P50 / P90 and the probability of negative NPV.
    • Tornado charts show which assumption drives results.
    • Waterfall charts explain bridges (budget → forecast).
    • PivotTables + slicers for portfolio dashboards; Power Query to clean and refresh data from CSV/Jira exports; Power Pivot for large models.
    ⚠️
    Avoid volatile functions (OFFSET, INDIRECT) in big models and avoid VBA unless necessary — they hurt performance and auditability.

    Gartner & Forrester Research Frameworks

    How to read and use analyst research: Magic Quadrant, Hype Cycle, Wave, Total Economic Impact and application-rationalization models — and their limits.

    📚 Why Analyst Research Is Used and Its Limits

    Fresher
    PointDetail
    What it isIndependent-style market research firms (e.g., Gartner, Forrester) that evaluate technologies, vendors and trends and publish frameworks, rankings and benchmarks.
    Why it is usedSpeeds vendor shortlisting, provides defensible evidence to executives, reveals maturity and risk of technologies.
    How it worksAnalysts survey vendors, customers and market data, apply a published methodology and publish reports/visuals; access is by subscription.
    LimitsGeneric criteria, not your context; vendors may be influenced by size and briefing activity; trends lag; reports are inputs, not decisions.
    ⚠️
    Do not copy a vendor's position into your recommendation. Test it against your requirements, references and a proof of concept.

    📈 Gartner Frameworks: What Is What

    Intermediate
    FrameworkPurposeStructure
    Magic QuadrantPositions vendors in a marketAxes: Ability to Execute × Completeness of Vision → Leaders, Challengers, Visionaries, Niche Players
    Critical CapabilitiesScores products against use casesWeighted capability scores by use case
    Hype CycleShows technology maturity and expectationsInnovation Trigger → Peak of Inflated Expectations → Trough of Disillusionment → Slope of Enlightenment → Plateau of Productivity
    Peer InsightsVerified customer reviewsRatings and written feedback
    TIME modelApplication portfolio dispositionTolerate, Invest, Migrate, Eliminate
    Pace-Layered Application StrategyManage apps by rate of changeSystems of Record, Differentiation, Innovation
    5 Rs (cloud migration)Choose migration pathRehost, Refactor, Revise, Rebuild, Replace
    💡
    Use the Magic Quadrant to build a long list, Critical Capabilities to compare fit, and Peer Insights to cross-check real experience.

    🌊 Forrester Frameworks and Total Economic Impact

    IntermediateAdvanced
    FrameworkPurposeNotes
    Forrester WaveEvaluates vendors in a categoryScored on current offering, strategy and market presence; vendors grouped as Leaders, Strong Performers, Contenders, Challengers
    Now Tech / LandscapeOverview of vendors by segmentMarket orientation rather than ranking
    Total Economic Impact (TEI)Financial value of a specific solutionBenefits, Costs, Flexibility, Risks; risk-adjusted ROI/NPV from customer interviews (often vendor-commissioned)
    Customer Experience Index (CX Index)Measures CX qualityBenchmarks by industry
    📌
    TEI studies are frequently commissioned by vendors. Treat them as a template and hypothesis source, then rebuild the numbers with your own data.

    🔍 Using Research in a Vendor Selection

    AdvancedExpert
    1. Define requirements and weighted criteria first.
    2. Long list from Magic Quadrant / Wave / Now Tech.
    3. Shortlist 3–5 against must-haves; check Peer Insights and references.
    4. RFP / demos / PoC using your scenarios.
    5. Score with a weighted matrix; include TCO and risk.
    6. Negotiate & decide; record the rationale.
    scorecardCriterion (weight)            Vendor A   Vendor B   Vendor C

    Jira Portfolio (Advanced Roadmaps / Plans)

    Planning work across teams in Jira: hierarchy, plans, capacity, dependencies, scenarios and reporting — and how it connects to portfolio governance.

    🧩 What It Is and the Hierarchy

    FresherIntermediate

    Jira Portfolio was Atlassian's planning add-on for Jira Software; it evolved into Advanced Roadmaps and, in Jira Cloud, Plans (available in Premium/Enterprise editions). Names and features vary by edition and deployment (Cloud vs Data Center) — confirm in your tenant.

    LevelJira issue typeMeaningExample
    Strategic (custom)Theme / InitiativeBusiness objective or large investmentReduce cost-to-serve
    EpicEpicLarge body of work for a teamDigital onboarding
    Story / TaskStory, Task, BugDeliverable work itemKYC upload screen
    Sub-taskSub-taskBreakdown of an itemAPI integration
    PointDetail
    Why it is usedVisualizes cross-team plans, capacity and dependencies; supports ‘what-if’ planning without changing live data.
    How it worksPull issues via filters/boards/projects into a plan; add teams, releases, estimates; auto-schedule; create scenarios.
    💡
    Add hierarchy levels above Epic (Initiative/Theme) to link delivery to strategic objectives — this is the traceability bridge to portfolio tools.

    🛠️ Plans: Capacity, Dependencies, Scenarios

    IntermediateAdvanced
    FeatureWhat it doesAnalyst use
    Issue sourcesBoards, projects or JQL filters feeding the planInclude only relevant work
    Teams & capacityTeam velocity or capacity (hours/story points) per sprintCheck over-allocation
    ReleasesGroup work by release/versionAlign with business milestones
    Dependencies‘Blocks / is blocked by’ links, shown on the timelineIdentify critical path, resequence
    Auto-schedulingSchedules items based on priority, estimates, capacityFirst-cut roadmap
    ScenariosDraft changes in a sandbox before committing to JiraCompare plan A (add team) vs plan B (cut scope)
    Custom fields & colourShow risk, theme, statusExecutive view
    ReportsRelease, capacity and dependency reportsGovernance packs
    jqlproject in (PAY, ONB) AND issuetype in (Initiative, Epic) AND statusCategory != Done ORDER BY Rank
labels = "FY27-Strategic" AND fixVersion in unreleasedVersions()
issueFunction in linkedIssuesOf("issuetype = Initiative", "is blocked by")  // requires ScriptRunner
    ⚠️
    A plan is only as good as its data: inconsistent estimation, missing links and stale statuses give a beautiful but wrong roadmap.

    🧠 Expert Practice with Jira Planning

    AdvancedExpert
    • Standardize estimation (story points or time) per team; mixing units breaks capacity views.
    • Dependency discipline: require links for cross-team work; review in planning ceremonies.
    • Use scenarios for budget/capacity trade-offs and take screenshots into portfolio packs.
    • Limit scope of each plan (e.g., per value stream) for performance and clarity.
    • Link to Excel / PPM: export plan data, validate cost and benefit assumptions, keep initiative IDs consistent.
    • Governance: roadmap items are commitments or forecasts? Label them to manage expectations (Now / Next / Later).
    ✅
    Jira shows what the teams will do and when; it does not by itself decide which investments to fund — that sits with portfolio governance (and tools like Planview).

    Planview and Enterprise Portfolio Management

    Strategic portfolio management platforms: investment planning, resource and capacity management, financials, benefits and integration with delivery tools.

    🏢 What Planview Is and Does

    FresherIntermediate

    Planview is a vendor of enterprise portfolio management (PPM / SPM) and work-management solutions. Its portfolio products (e.g., Planview Portfolios, formerly Enterprise One) help organizations plan, fund, govern and track investments; related products cover Agile/Lean work (e.g., AgilePlace) and collaboration (e.g., Projectplace). Product names and packaging change — verify against current vendor documentation.

    CapabilityWhat it providesAnalyst use
    Strategic planningObjectives, strategic themes, alignmentLink initiatives to objectives
    Demand & intakeRequest forms, workflow, scoringStandard intake and scoring models
    Investment & scenario planningCompare portfolios under budget/capacity constraintsOptimization and what-if
    Resource & capacity managementDemand vs supply by role/teamPrevent over-allocation
    Financial planningBudgets, forecasts, actuals, CapEx/OpExTrack cost vs plan
    Benefits & value trackingBenefit owners, KPIs, realizationClose the loop
    Roadmaps & dashboardsExecutive and portfolio viewsBoard reporting
    IntegrationConnects to Jira, Azure DevOps, ERP, HRRoll up delivery data
    💡
    Planview-type tools answer: Are we funding the right mix? Do we have the people? Are benefits showing up?

    ⚖️ Jira Plans vs Planview: Who Does What?

    IntermediateAdvanced
    DimensionJira Plans / Advanced RoadmapsPlanview (enterprise PPM)
    Primary levelTeam and cross-team deliveryEnterprise investment portfolio
    Main usersDelivery leads, product owners, RTEsPMO, finance, executives, portfolio managers
    DataIssues, estimates, sprints, releasesInvestments, budgets, resources, benefits, risks
    Decision supportedWhat to build next, delivery sequencingWhat to fund, stop, defer
    FinancialsLimitedStrong (budget, forecast, actuals)
    Scenario focusSchedule/capacity scenariosFunding, capacity and value scenarios
    Typical integrationFeeds delivery status upwardReceives delivery roll-up, sends approved scope/budget downward
    📌
    Large organizations commonly use both: PPM for portfolio governance and Jira for execution, connected by consistent initiative/epic IDs.

    🏁 Implementation, Governance and Case Practice

    AdvancedExpert
    1. Agree the operating model first: intake, criteria, decision rights, cadence.
    2. Define taxonomy: investment types, strategic themes, benefit categories, standard fields.
    3. Start small: one portfolio, mandatory fields only; expand.
    4. Integrate with Jira/finance and define the system of record per data item.
    5. Data quality ownership: who updates what and when.
    6. Adoption: training, simple dashboards, retire shadow spreadsheets.
    7. Measure: data completeness, forecast accuracy, decision cycle time, benefit realization.
    PointDetail
    Mini caseFY27 planning: 42 requests; $60M demand vs $38M envelope.
    ProcessIntake in PPM → scoring model → Excel/Solver cross-check → capacity (resource module) → scenarios → board decision.
    Delivery linkApproved initiatives created as Initiatives in Jira; teams plan epics in Plans; status rolls up weekly.
    BenefitsOwners confirm KPIs quarterly; PIR at month 12.
    ⚠️
    Failure modes: over-customizing, too many mandatory fields, no data owner, duplicate sources of truth, tool treated as project rather than as an operating-model change.

    🚫 Pitfalls and Expert Checklist

    Expert

    Pitfalls

    • Excel models with hidden hard-codes
    • Treating analyst rankings as proof
    • Roadmaps without capacity data
    • Inconsistent IDs between tools
    • Duplicate spreadsheets alongside the PPM tool
    • Tool configuration before process agreement

    • Checks and sensitivity in place?
    • Research validated with references/PoC?
    • Jira hierarchy linked to strategy?
