    Modelling Tools: EA, Visio & StarUML

    Enterprise Architect, Visio and StarUML in depth.

    🏗️ Compared

    FeatureEnterprise ArchitectVisioStarUML
    Model repositoryYes, shared DBNo, drawings onlyFile-based
    Traceability matrixYesManualLimited
    UML standard coverageFullBasicGood
    Learning curveSteepEasyModerate
    CostLicensedMicrosoft 365 add-onLow-cost licence

    Good practices

    • EA: use packages per layer, baselines for versions, link requirements to components for traceability
    • Visio: use stencils/templates and link shapes to data
    • StarUML: keep diagrams small, export SVG for documentation

    Types of SQL and everyday analyst queries.

    🗄️ SQL families and queries

    TypeStatementsAnalyst use
    DQLSELECTProfiling and reports
    DMLINSERT, UPDATE, DELETETest data changes
    DDLCREATE, ALTER, DROPReading schemas
    DCL / TCLGRANT / COMMIT, ROLLBACKAccess and transactions
    sql-- Data profiling: nulls and duplicates
SELECT COUNT(*) total,
       SUM(CASE WHEN email IS NULL THEN 1 ELSE 0 END) null_emails
FROM customers;
SELECT email, COUNT(*) c FROM customers GROUP BY email HAVING COUNT(*) > 1;

-- Migration reconciliation: in legacy but missing in target
SELECT l.id FROM legacy_customers l
LEFT JOIN customers t ON t.id = l.id
WHERE t.id IS NULL;
    ⚠️
    Run analyst queries on read replicas or non-production data and never on live tables without approval.

    Swagger & OpenAPI

    OpenAPI contracts and expert-level tool strategy.

    📘 OpenAPI example

    yamlopenapi: 3.0.3
info: {title: Customer API, version: 1.0.0}
paths:
  /customers/{id}:
    get:
      summary: Get customer
      parameters:
        - {name: id, in: path, required: true, schema: {type: string}}
      responses:
        '200': {description: OK}
        '404': {description: Not found}
    ElementMeaning
    pathsEndpoints and operations
    schemas (components)Reusable data models
    responsesStatus codes and bodies
    securitySchemesOAuth2, API key

    Ecosystem: Swagger Editor (author), Swagger UI (interactive docs), Codegen (stubs/SDKs), Postman (testing).

    Tools, Quality & Best Practices

    Workflow, review checklist and habits.

    🔧 Tools & Workflows

    Model in EA/StarUML → publish diagrams → validate data with SQL → define APIs in OpenAPI → mock and test in Postman.

    ✅ Testing & Quality

    • Diagrams open in the agreed viewer and follow naming standards
    • SQL runs on a read replica and row counts reconcile
    • OpenAPI spec lints cleanly and examples validate

    ⭐ Best Practices

    • Model in EA/StarUML, publish diagrams, validate data with SQL, define APIs in OpenAPI before build (design-first).
    • Consistent artefacts reduce rework and speed reviews.
