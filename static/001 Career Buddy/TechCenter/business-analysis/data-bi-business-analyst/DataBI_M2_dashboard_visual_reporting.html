    KPI & Metric Design

    Turning business goals into precise, trusted, actionable measures.

    🎯 Metrics vs KPIs

    A metric is any measurement. A KPI is a metric tied to a strategic objective with a target and an owner. Not every number deserves to be a KPI.

    TermMeaningExample
    MetricAny measurable valuePage views
    KPIMetric linked to a goal, with targetCheckout conversion rate >= 3.2%
    Leading indicatorPredicts future outcomeDemos booked
    Lagging indicatorReports past outcomeQuarterly revenue
    Input / output metricControllable action vs resultCalls made vs deals won
    Vanity metricLooks good, drives no decisionTotal registered users
    Guardrail metricProtects against harmful side effectsRefund rate while pushing sales
    💡
    Test a KPI: if this number moves, what decision changes? If none, drop it.

    🧮 Defining a Metric Precisely

    Most dashboard disputes come from unclear definitions. Write each metric as a contract: name, business question, formula, grain, filters, time window, source, owner, refresh rate.

    textMetric: Monthly Active Customers (MAC)
Formula: COUNT(DISTINCT customer_id) with >=1 paid order in calendar month
Grain: month x region   Source: fact_orders   Owner: Finance BI
Excludes: test accounts, fully refunded orders
    MetricFormulaCommon pitfall
    Conversion rateOrders / SessionsMixing user and session denominators
    Churn rateCustomers lost / Customers at startCounting new-then-lost customers
    ARPURevenue / Active usersDividing by registered, not active
    Average order valueRevenue / OrdersOutliers skew the mean; add median
    Gross margin %(Revenue - COGS) / RevenueInconsistent COGS rules
    RetentionCustomers active in P+n / cohort sizeWrong cohort definition
    ⚠️
    Ratios must be aggregated as ratio of sums, not average of ratios, when rolling up.

    🌳 KPI Trees & Frameworks

    A KPI tree decomposes a top metric into drivers: Revenue = Visitors x Conversion x Average order value. It shows where to act.

    FrameworkIdeaFit
    OKRObjective with measurable key resultsGoal setting
    Balanced ScorecardFinancial, customer, process, learning viewsExecutive reporting
    North Star MetricOne metric capturing delivered valueProduct teams
    AARRR (Pirate)Acquisition, Activation, Retention, Referral, RevenueGrowth funnels
    HEARTHappiness, Engagement, Adoption, Retention, Task successUX
    SMARTSpecific, Measurable, Achievable, Relevant, Time-boundTarget setting

    🧠 Advanced: Metric Rigor, Decomposition & Goodhart Advanced

    Mature KPI design asks whether a number is valid, sensitive and hard to game. Goodhart's law: when a measure becomes a target it ceases to be a good measure, so pair every target with a guardrail (e.g. tickets closed per agent with reopen rate and CSAT).

    ConceptWhat it meansExample / action
    Simpson's paradoxA trend in every segment reverses in the aggregate because of mix shiftConversion rises in both mobile and desktop yet falls overall as mobile share grows; always segment before concluding
    Rate vs mix effectChange in a ratio = change within segments (rate) + change in segment weights (mix)Decompose blended margin movement before blaming pricing
    Multiplicative KPI treeRevenue = Traffic × Conversion × AOV; use log-share or Shapley contribution to attribute changeRank drivers by contribution to the delta, not by size
    Leading-indicator validationTest lagged correlation and predictive lift before promoting a metricDoes week-N activation predict week-N+8 retention?
    Sensitivity (MDE)Smallest change the metric can reliably detect given its varianceNoisy daily metrics need smoothing or longer windows
    Metric contract as codeDefinition, grain, owner, tests and SLA stored in version controlYAML spec reviewed like a pull request
    sql-- Rate/mix decomposition of conversion change between two periods
SELECT segment,
  (w1 - w0) * c0            AS mix_effect,
  w1 * (c1 - c0)            AS rate_effect
FROM seg_stats;   -- w = traffic share, c = segment conversion; effects sum to total change

    Chart Selection & Visual Design

    Choosing the right visual for the question and applying perception science.

    📊 Choosing the Right Chart

    QuestionBest chartAvoid
    Trend over timeLine chartPie
    Compare categoriesSorted horizontal bars3D bars
    Part-to-whole (few parts)Stacked bar, treemap, donut with 5 or fewer slicesPie with 12 slices
    DistributionHistogram, box plotAverage only
    Relationship of two numbersScatter plotDual-axis lines
    RankingSorted bar, slope chartRadar
    Flow / funnelFunnel, SankeyPie
    Target vs actualBullet chartSpeedometer gauge
    GeographicChoropleth, symbol mapMap when location is irrelevant
    Precise lookupTable with conditional formattingChart
    💡
    Bar charts must start at zero. Line charts may not, but disclose a truncated axis.

    👁️ Visual Perception & Design Principles

    People read position and length accurately, angle and area poorly, color hue worst for quantity. Use this hierarchy when encoding data.

    📐
    Pre-attentive attributes
    Color, size, position and orientation are noticed in under a second. Use one to highlight the key point.
    🎨
    Color use
    Sequential for ordered values, diverging around a midpoint, categorical for groups. Keep to 5-7 hues; design for color blindness.
    🧹
    Data-ink ratio
    Remove gridlines, borders and 3D effects that carry no information.
    🧭
    Layout
    Top-left is read first. Place the most important KPI there; group related visuals.
    📌
    Gestalt laws (proximity, similarity, enclosure, alignment) explain why spacing and grouping communicate relationships without extra lines.

    ♿ Accessibility & Anti-patterns

    • Never rely on color alone: add labels, shapes or patterns.
    • Maintain contrast ratio of at least 4.5:1 for text.
    • Write meaningful titles that state the insight.
    pie with many slicesdual axis misleading scales3D chartsrainbow palettestruncated bar axisgauge overusetoo many filtersno units or date range

    🔬 Advanced: Encoding Science, Colour & Uncertainty Advanced

    Cleveland and McGill ranked perceptual tasks by accuracy: position on a common scale > position on non-aligned scales > length > angle/slope > area > volume > colour saturation. Pick the highest-ranked encoding the question allows.

    TopicAdvanced guidance
    Small multiplesRepeat the same chart per category with shared axes; beats multi-line spaghetti beyond ~4 series
    Banking to 45°Choose aspect ratio so average line slope is near 45° to make rate changes legible
    Bullet charts & slope chartsBullet charts show actual vs target vs bands compactly; slope charts compare two time points per entity
    Dual axesScale choice manufactures correlation; prefer indexed lines or stacked panels sharing an x-axis
    Log scalesShow proportional change and heavy-tailed data; label clearly and avoid for audiences unfamiliar with them
    ColourUse perceptually uniform sequential palettes (viridis-like), diverging only around a meaningful midpoint, and encode redundantly (shape/label) for colour-vision deficiency; keep contrast ≥ 4.5:1 for text
    OverplottingBin, hexbin, sample, or use transparency and density contours for large scatter data
    UncertaintyShow confidence/prediction bands, fan charts or intervals; a point estimate alone implies false precision
    ⚠️
    Truncated bar axes exaggerate differences because bar length encodes value; bars must start at zero. Lines and dot plots may use a non-zero baseline if labelled.

    Data Storytelling

    From numbers to decisions: structure, context and persuasion.

    📖 Story Structure

    Storytelling is data + narrative + visuals. A reader should know what happened, why it matters, and what to do.

    ElementQuestion answeredExample
    ContextWhy should I care?Renewals drive 70% of ARR
    InsightWhat did the data show?Churn rose 2 pts in SMB
    CauseWhy did it happen?Price change in March
    ActionWhat now?Pilot a grandfathered tier

    Use the Situation-Complication-Resolution or the Pyramid Principle: lead with the answer, then support it.

    🔦 Focus, Context & Insight Titles

    Every chart needs one message. Use a headline title ("Churn doubled after the March price change"), highlight the key series in color and grey out the rest, add an annotation, and show a comparison (target, prior year, benchmark).

    💡
    Numbers without comparison are trivia. Always show vs target, vs prior period, or vs peers.
    AudienceNeedsFormat
    ExecutiveAnswer and decision in 1 pageKPI summary + exceptions
    ManagerDrivers and drill-downInteractive dashboard
    AnalystDetail and exportExplorable tables
    OperationsReal-time statusAlerts and monitors

    ⚖️ Ethics & Bias in Visualization

    Honest reporting avoids cherry-picked ranges, truncated axes, misleading aggregations and correlation shown as causation. Report uncertainty, sample sizes and data limitations. Beware Simpson's paradox: a trend in groups can reverse when combined.

    🎤 Advanced: Narrative Frameworks & Decision Framing Advanced

    Executives need answer first. Use the Pyramid Principle: lead with the recommendation, support with 3 grouped arguments, then evidence. SCQA (Situation, Complication, Question, Answer) structures the opening.

    TechniqueApplication
    So-what / now-whatEach chart title states the finding; each section ends with the decision or action it implies
    Progressive disclosureHeadline KPI → driver breakdown → record-level detail, with drill paths rather than one dense view
    Annotation over legendsLabel lines directly and annotate events (launch, outage, price change) to explain inflections
    Counterfactual and baselineAlways show a comparator: target, prior period, peer or forecast; a number alone is not insight
    Cognitive biases to manageAnchoring on the first number shown, framing (gain vs loss), confirmation bias in cherry-picked windows, survivorship bias in cohorts
    Ethics checksConsistent time windows, disclosed exclusions, no truncated axes, uncertainty shown, avoid implying causation from correlation

    Self-Serve Dashboard Construction

    Designing, building and operating dashboards that people use without analyst help.

    🧭 Requirements & Dashboard Types

    TypePurposeRefresh
    StrategicExecutive, high-level KPIsDaily / weekly
    AnalyticalExploration, drill-downDaily
    OperationalMonitoring current activityNear real-time
    TacticalDepartmental decisionsDaily

    Gather requirements by asking: who uses it, what decision it informs, what action follows, how often, and what questions it must answer. Sketch a wireframe before building.

    💡
    Apply the 5-second test: can a new viewer state the main takeaway within five seconds?

    🏗️ Build Steps & Interactivity

    1. Connect to a governed, modeled source (star schema).
    2. Create measures once in a semantic layer.
    3. Place KPI cards top, trends middle, details bottom.
    4. Add filters, slicers, drill-down and tooltips.
    5. Test with users; document definitions.
    FeatureUseCaution
    Filters / slicersLet users slice by date, regionToo many confuse users
    Drill-down / throughMove from summary to detailKeep path clear
    ParametersWhat-if, metric switchingDocument defaults
    TooltipsExtra context on hoverNot available on mobile
    BookmarksSaved viewsVersion carefully

    🛡️ Performance, Governance & Adoption

    A self-serve dashboard succeeds when it is fast, trusted, and discoverable.

    AreaPractice
    PerformanceAggregate tables, import mode, limit visuals per page, avoid heavy row-level security joins
    SecurityRole-based access, row-level security by region or team
    CertificationMark trusted datasets and reports as certified or endorsed
    DocumentationMetric glossary, data refresh time shown on page
    AdoptionTrack views and active users; retire unused dashboards
    AlertingData-driven alerts on thresholds
    📌
    Semantic layer = single place to define metrics so every report agrees. It is the foundation of reliable self-service.

    🏗️ Advanced: Semantic Models, Performance Budgets & Delivery Advanced

    DecisionOptions and trade-offs
    Connectivity modeImport (fast, cached, refresh latency) vs DirectQuery/Live (fresh, depends on source speed) vs composite/hybrid with aggregation tables
    Large dataPre-aggregate to dashboard grain, incremental refresh, partitioned fact tables, query folding to push work to the source
    SecurityRow-level security by role or user mapping table; object-level security for sensitive columns; test with "view as"
    Release managementDev → Test → Prod deployment pipelines, version control for models, certified vs promoted vs personal content tiers
    Performance budgetAim for first meaningful render under ~3 s; limit visuals per page, avoid high-cardinality slicers, avoid row-level calculated columns where measures suffice
    Adoption analyticsTrack active viewers, repeat usage, load times and unused reports; retire dashboards with no usage in 90 days
    AlertingThreshold and anomaly alerts reduce dashboard-checking; route to owners with runbooks
    💡
    Design the model before the dashboard: one governed semantic model with certified measures serves many reports and prevents "five dashboards, five revenues".
