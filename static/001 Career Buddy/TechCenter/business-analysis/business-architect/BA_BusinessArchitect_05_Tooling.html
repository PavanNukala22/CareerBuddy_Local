    Why EA Tools and Tool Categories

    What enterprise architecture tools do, the main categories, and what to look for before choosing one.

    🧰 Why not just use slides and diagrams?

    Drawing tools (PowerPoint, Visio) produce pictures. EA tools produce a model: every box is an object stored once in a repository, with attributes and relationships. Change the object and every diagram and report that uses it updates.

    Drawing tool

    • Shapes only, no meaning
    • Duplicated and out of date
    • No impact analysis
    • Good for quick sketches

    Modelling / EA repository

    • Objects with metadata
    • Single source of truth
    • Impact analysis, reports, roadmaps
    • Governance, versioning, collaboration
    💡
    Rule of thumb: if you need the same fact (e.g. "CRM-A supports Customer Onboarding") in more than one view, you need a repository, not a drawing.

    🗂️ Categories of EA tooling

    CategoryFocusExamples
    Notation / modelling toolsStandards-based modelling (ArchiMate, UML, BPMN)Archi (open source), Sparx Enterprise Architect, Bizzdesign Enterprise Studio
    Enterprise-wide EA suitesRepository + analysis + reporting + collaborationBizzdesign Horizzon, SAP LeanIX, Ardoq, Orbus iServer, MEGA HOPEX, Software AG Alfabet, Avolution ABACUS
    APM / TBM toolsApplication and cost portfolio focusLeanIX, Planview, Apptio
    Process modelling toolsBusiness process managementARIS, Signavio, Bizagi
    Diagramming toolsDrawing, light-weightVisio, draw.io, Lucidchart
    CMDB / ITSMOperational configuration recordsServiceNow, BMC
    📌
    Many programmes combine: a notation tool for deep modelling, an EA / APM suite for portfolio and roadmaps, and a CMDB for operational data.

    ✅ What makes a tool fit for purpose

    CriterionQuestions to ask
    MetamodelDoes it support ArchiMate/TOGAF/BIZBOK concepts? Can it be extended?
    Ease of useCan non-architects (business owners) contribute?
    Data import / integrationCMDB, HR, finance, CI/CD, cloud inventories, Excel, APIs?
    VisualisationHeatmaps, roadmaps, dependency maps, dashboards?
    Collaboration & governanceWorkflows, roles, surveys, approvals, versioning?
    AnalysisImpact, cost, risk, lifecycle, redundancy?
    Deployment & securitySaaS vs on-premise, SSO, data residency, audit
    Total costLicences, implementation, training, data-quality effort
    Vendor viabilityRoadmap, community, support, certified standards

    ArchiMate Fundamentals: Layers and Elements

    The Open Group modelling language: its layers, generic element types and notation conventions.

    🧩 What is ArchiMate?

    ArchiMate is an open, vendor-neutral enterprise architecture modelling language maintained by The Open Group (current major version 3.x). It gives one consistent notation to describe business, application and technology architectures and the relationships among them. It aligns closely with TOGAF, which defines process while ArchiMate defines notation.

    📌
    ArchiMate is deliberately limited in size (~60 element types) so business people can read the diagrams; UML or BPMN can be linked for detail.

    🏢 The layers

    LayerDescribesTypical elements
    StrategyDirection, resources, capabilitiesResource, Capability, Value Stream, Course of Action
    BusinessBusiness services, processes, actorsBusiness Actor, Role, Process, Function, Service, Object
    ApplicationSoftware and dataApplication Component, Service, Interface, Data Object
    TechnologyInfrastructureNode, Device, System Software, Technology Service, Artifact
    PhysicalEquipment, facilities, materialsEquipment, Facility, Distribution Network, Material
    MotivationWhy: stakeholders, drivers, goalsStakeholder, Driver, Goal, Outcome, Principle, Requirement, Constraint
    Implementation and MigrationChangeWork Package, Deliverable, Plateau, Gap, Implementation Event
    Layered view: each upper layer is served by the one below.

    🔠 Generic element aspects

    AspectMeaningBusiness / App / Tech examples
    Active structureWho or what performs behaviourBusiness Actor / Application Component / Node
    BehaviourWhat is performedBusiness Process / Application Function / Technology Function
    Passive structureWhat behaviour acts uponBusiness Object / Data Object / Artifact
    ServiceExternally visible behaviour offeredBusiness Service / Application Service / Technology Service
    InterfaceAccess point to a serviceBusiness Interface / Application Interface / Technology Interface
    EventSomething that happensBusiness Event / Application Event / Technology Event
    💡
    Remember "Who does What to Which" = Active structure, Behaviour, Passive structure.

    ArchiMate in Practice: Relationships, Viewpoints, Patterns

    Relationship families, viewpoints, junctions, cross-layer patterns, modelling rules and exchange formats.

    🔗 Relationship types

    FamilyRelationshipsMeaning
    StructuralComposition, Aggregation, Assignment, RealizationHow things are built or implement others
    DependencyServing, Access, Influence, AssociationHow one element depends on or uses another
    DynamicTriggering, FlowSequence and exchange between behaviours
    OtherSpecialization, Junction (and/or)Generalisation and combined relationships
    RelationshipTypical useExample
    AssignmentActive structure performs behaviourRole assigned to Process
    RealizationConcrete realises abstractApplication Component realises Application Service
    ServingProvides functionality toApplication Service serves Business Process
    AccessBehaviour reads/writes passive objectProcess accesses Customer Data Object
    TriggeringTemporal/causal orderOrder Received triggers Validate Order
    FlowTransfer of information/valueInvoice flows to Payment process

    🔭 Viewpoints

    A viewpoint selects the element types useful for a particular audience and concern. Examples in the ArchiMate specification:

    ViewpointAudiencePurpose
    Capability MapExecutives, strategistsShow capabilities and levels
    Value StreamBusiness managersStages of value delivery
    Business Process CooperationProcess ownersInteractions among processes and actors
    Application CooperationSolution architectsInterfaces and flows among applications
    LayeredArchitectsOverview across business, application, technology
    Technology UsageInfrastructure teamsNodes and software supporting applications
    Migration / ImplementationProgramme managersPlateaus, gaps, work packages
    Goal Realization / RequirementsBusiness analystsGoals to requirements traceability
    ✅
    Model once, publish many viewpoints. Never draw a diagram without knowing its audience and concern.

    📐 Modelling best practices and exchange

    1. Define a modelling guideline: naming rules, layers used, level of detail.
    2. Keep diagrams to 7 plus or minus 2 main elements where possible.
    3. Use derivation rules carefully: a derived relationship may be valid but less precise.
    4. Use junctions for AND/OR when one element relates to several.
    5. Keep elements unique; reuse rather than recreate.
    6. Use the Open Exchange Format (XML) to move models between tools.
    Cross-layer patternCustomer Onboarding (Business Process)
   <-serves-- Identity Verification Service (Application Service)
                  <-realized by-- KYC Platform (Application Component)
                                      <-serves-- Cloud Compute (Technology Service)
Customer Onboarding --accesses--> Customer (Business Object) --realized by--> Customer Record (Data Object)

    Sparx Systems Enterprise Architect

    The modelling tool by Sparx Systems: capabilities, repositories, extensibility and typical EA use.

    🛠️ What Enterprise Architect (EA) is

    Sparx Systems Enterprise Architect is a long-established, relatively low-cost, multi-purpose modelling platform. It covers UML, SysML, BPMN, ArchiMate, TOGAF ADM support, requirements, testing, database and code engineering, and simulation, making it popular where architecture, design and engineering meet.

    AspectDetail
    NotationsUML, SysML, BPMN, ArchiMate, ERD, DMN and more via MDG Technologies
    RepositorySingle-user file-based project files, or a shared database (e.g. SQL Server, Oracle, PostgreSQL, MySQL); recent versions also offer a file format based on SQLite
    Web / collaborationPro Cloud Server provides web access and integrations (WebEA, OSLC)
    EditionsTiered licences (Professional, Corporate, Unified, Ultimate) with increasing enterprise capabilities
    StrengthsBreadth, traceability, price, customisation, scripting
    WeaknessesUI learning curve; less polished business-friendly analytics than SaaS suites
    📌
    Features and edition names change; verify against current vendor documentation before any selection.

    🧱 Core concepts in EA

    ConceptPurpose
    Project / RepositoryContainer for the entire model
    PackageFolder-like structure for elements and diagrams
    ElementA model object (e.g. Application Component)
    ConnectorRelationship between elements
    DiagramView of elements and connectors
    ToolboxPalette of element types per technology
    MDG TechnologyPlug-in extending the metamodel (e.g. ArchiMate 3, BPMN 2)
    Tagged values / propertiesAttributes such as owner, cost, lifecycle
    Traceability / Relationship MatrixLink requirements to design to tests; spot gaps
    Baseline / Version controlSnapshots and change tracking
    Model Views / Charts / ReportsDashboards, documents (RTF, HTML) generated from the model

    ⚙️ Customising and automating

    • Custom MDG: define your own element types, stereotypes and toolboxes (organisation metamodel).
    • Model templates & patterns: reusable structures.
    • Scripting: built-in scripts (JScript, VBScript, JavaScript) and the Automation Interface (COM) for batch updates.
    • SQL searches: query the repository for reports and quality checks.
    • Model Transformation (MDA): generate models, code or documents.
    • Document generation: templates for architecture documents.
    SQL (illustrative)-- Find applications without an owner (Sparx SQL search sketch)
SELECT o.Name, o.Object_ID
FROM t_object o
WHERE o.Stereotype = 'ApplicationComponent'
  AND NOT EXISTS (SELECT 1 FROM t_objectproperties p
                  WHERE p.Object_ID = o.Object_ID AND p.Property = 'Owner')
    ⚠️
    Without governance, a shared Sparx repository can become a graveyard of inconsistent packages. Set package structure, naming standards and access roles first.

    Bizzdesign (Enterprise Studio and HoriZZon)

    Bizzdesign's modelling and enterprise transformation platform, strengths, analysis and collaboration features.

    🏛️ What Bizzdesign is

    Bizzdesign is a vendor with strong ties to the ArchiMate standard. Its products include the Enterprise Studio modelling desktop tool and the web-based HoriZZon platform for collaborative enterprise transformation. It is known for rigorous ArchiMate support, analysis and governance of large models.

    AspectDetail
    StandardsArchiMate (certified), BPMN, DMN, UML, TOGAF and others
    Model repositoryCentral multi-user repository with versioning and access control
    AnalysisImpact and dependency analysis, quantitative analysis (cost, performance), lifecycle and risk views
    CollaborationBrowser-based viewing, commenting, surveys, stakeholder portals
    ViewsHeatmaps, roadmaps, capability and portfolio dashboards
    IntegrationImport/export (Excel, Exchange Format), APIs and connectors to other systems
    StrengthsModel rigour, analysis, large enterprise governance
    ConsiderationsLicence cost and implementation effort; best with a defined modelling approach
    📌
    Always confirm current product names, modules and packaging with the vendor; they evolve.

    📊 Typical Bizzdesign use cases

    Use caseHow the tool helps
    Capability-based planningCapability map with maturity, importance and heatmaps linked to initiatives
    Application portfolioApplication inventory with lifecycle, cost, fit; TIME-style views
    RoadmappingPlateaus, work packages and timeline views
    Impact analysisIf a system is retired, which processes and capabilities are affected?
    Risk and complianceLink controls, regulations and architecture elements
    Process and strategy alignmentLink BPMN processes to ArchiMate and goals
    Typical workflow in a modelling-centric EA platform.

    🧭 Making a modelling-centric tool succeed

    • Define the metamodel and viewpoints before modelling; avoid "model everything".
    • Train core modellers; give business users dashboards, not raw models.
    • Automate data feeds (CMDB, finance) so models do not decay.
    • Appoint repository stewards and a review cadence.
    • Show value early with one decision supported (e.g. rationalisation case).
    💡
    Success is 20% tool and 80% metamodel, data quality and ownership.

    LeanIX (SAP LeanIX)

    SaaS enterprise architecture and application portfolio platform: fact sheets, reports, surveys and integrations.

    ☁️ What LeanIX is

    LeanIX is a SaaS EA management platform, now part of SAP and offered as SAP LeanIX. It is aimed at fast, crowd-sourced, data-driven EA — especially application portfolio management, cloud and technology governance, and business capability planning — with a light, business-friendly interface. Unlike deep modelling tools, its core unit is not the diagram but the Fact Sheet.

    AspectDetail
    DeliverySaaS (cloud); API-first
    Core unitFact Sheets with relations, tags, lifecycle
    VisualisationInteractive reports (landscape, matrix, roadmap, dependency)
    CollaborationSurveys and subscriptions to crowd-source data from owners
    IntegrationAPIs (GraphQL), connectors to CMDB, cloud, CI/CD, other SAP and non-SAP tools
    StrengthsSpeed to value, usability, application portfolio and lifecycle
    ConsiderationsLess notation depth than modelling tools; metamodel customisation within platform limits
    📌
    LeanIX modules (application portfolio, technology risk, value stream, microservice intelligence, etc.) have been repackaged over time; check the current catalogue.

    📇 Fact Sheet types

    Fact Sheet typeRepresentsExample
    Business CapabilityWhat the business can doCustomer Onboarding
    ApplicationSoftware supporting businessCRM-A
    IT ComponentTechnology or software product / serviceOracle DB 19c
    InterfaceData exchange between applicationsOrder API
    Data ObjectBusiness data conceptCustomer
    ProviderVendor / supplierMicrosoft
    Initiative / ProjectChange effortCRM Consolidation
    OrganizationBusiness unit / ownerRetail Banking
    ProcessBusiness processOrder to Cash
    Tech CategoryTechnology standard classificationRelational database
    Fact sheet with relationsApplication: CRM-A
  Lifecycle: Active (2021) -> Phase-out (2027)
  Relations: supports Business Capability "Customer Onboarding"
             uses IT Component "Cloud DB"
             owned by Organization "Retail Banking"
             provided by Provider "Vendor X"
  Quality: Business criticality = Mission-critical; Technical fit = Adequate

    📈 Key workflows

    1. Import application and IT component lists from CMDB or Excel.
    2. Complete data through owner surveys (lifecycle, fit, criticality).
    3. Link applications to capabilities, providers and IT components.
    4. Analyse with matrix and landscape reports; filter by lifecycle or fit.
    5. Plan with roadmaps and initiatives; track decommissions.
    6. Govern through data-quality KPIs and approval workflows.
    💡
    Data-quality score (percentage of fact sheets with required fields) is a leading indicator of whether LeanIX will deliver reliable decisions.

    ⚠️
    This comparison is directional. Capabilities and licensing change; run a proof of concept with your own data before purchase.

    🧪 Selection method

    Decide using your own data and scenarios, not vendor demos.
    • Start with decisions, not features: "We must answer which applications to retire and what depends on SAP ERP."
    • Weighted scorecard (functionality, usability, integration, cost, vendor risk).
    • PoC with 50-100 real applications, 20 capabilities, and an actual question.
    • Total cost of ownership over 3-5 years, including data work.
    • Exit strategy: can you export the model (Open Exchange Format, API, CSV)?

    🔌 Integration and data-quality patterns

    SourceData feeds the repositoryPattern
    CMDB (ServiceNow)Applications, servers, relationshipsScheduled sync; CMDB as operational truth
    Cloud APIs (AWS, Azure)Services, cost, tagsDiscovery and tag-based mapping
    Finance / procurementCost, contracts, vendorsCost allocation to applications
    HR / identityOwners, organisationOwnership validation
    CI/CD & repositoriesMicroservices, dependenciesAutomated architecture discovery
    Surveys / formsBusiness fit, lifecycleCrowd-sourcing with reminders
    ✅
    Define system of record per attribute: CMDB owns technical CIs, finance owns cost, EA tool owns capability mapping and lifecycle decisions.
