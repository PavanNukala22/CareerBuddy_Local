    Module 01

    PMO Analyst Soft Skills: Foundations

    Why soft skills decide an analyst’s credibility and how the five skills connect.

    🧠 Course Overview: What the Role Needs

    A PMO Analyst is trusted when the numbers are right, the reasoning is clear and the message is easy to act on. This course covers the five soft skills behind that trust.

    🔎
    Analytical thinking
    Structure problems and find root causes.
    🎯
    Data accuracy
    Make sure numbers are correct and reconciled.
    ⚙️
    Process optimisation
    Remove waste and delay from workflows.
    ✉️
    Written communication
    Write clearly for busy readers.
    🔬
    Attention to detail
    Catch small errors before they travel.
    💡
    Soft skills are habits you can practise: a structure for thinking, a checklist for accuracy, a template for writing.

    🎯 Learning Objectives

    By the end of this course you will be able to:

    1. Define a problem and structure it before analysing.
    2. Find root causes with the 5 Whys and Pareto analysis.
    3. Apply data quality dimensions and reconcile figures to a source.
    4. Map a process, find bottlenecks and measure improvement.
    5. Write clear emails, summaries and escalations using BLUF.
    6. Use checklists and maker-checker reviews to catch errors.
    7. Diagnose common reporting and communication problems.

    Module 02

    Analytical Thinking

    Structuring problems, finding root causes and testing hypotheses with evidence.

    🧩 Basic: Structured Problem Solving

    StepQuestion to askOutput
    DefineWhat exactly is wrong, how big, since when?Problem statement
    Break downWhat are the parts or drivers?Issue tree
    GatherWhat evidence do we have?Facts and data
    AnalyseWhat do the facts show?Findings
    ConcludeWhat should we do?Recommendation

    Symptom

    • Reports are late
    • Dashboard looks wrong
    • Team is overloaded

    Root cause

    • No agreed data deadline
    • Two sources with different definitions
    • Work not prioritised across projects
    💡
    Break problems into parts that do not overlap and together cover everything (MECE).

    🌳 Intermediate: Root Cause Tools

    5 Whys example: status reports arrive late.

    1. Why late? Teams send data after the deadline.
    2. Why after? They only learn the deadline the day before.
    3. Why? The reminder is sent manually.
    4. Why? There is no calendar of reporting dates.
    5. Root cause: no published reporting calendar.
    Delay causeCountCumulative %
    Missing data4040%
    Approval wait2565%
    Template errors1580%
    System downtime1090%
    Other10100%

    The first three causes create 80% of delays — fix those first (Pareto).

    🔬 Advanced: Hypothesis-Driven Analysis

    Figure 2.1 · Hypothesis-driven analysis

    Start with a likely answer and look for evidence that could disprove it. This is faster than reading every data set.

    formula// Variance percentage
=(Actual-Forecast)/Forecast
// Example: (99-110)/110 = -10%
    ⚠️
    State your assumptions. A conclusion nobody can challenge is a conclusion nobody can trust.

    Module 03

    Data Accuracy

    Data quality dimensions, reconciliation and controls that keep numbers trustworthy.

    ✅ Basic: Dimensions of Data Quality

    DimensionMeaningPMO example
    AccuracyMatches realityBudget equals the finance figure
    CompletenessNothing required is missingEvery project has an owner
    ConsistencySame value everywhereSame project name in all reports
    TimelinessCurrent enough to useStatus from this month
    UniquenessNo duplicatesOne row per project
    ValidityFollows format and rulesDates are real dates

    🔄 Intermediate: Validation and Reconciliation

    Figure 3.1 · Reconciliation steps
    • Compare record counts and control totals before and after each step.
    • Check ranges, dates and mandatory fields.
    • Document every adjustment with a reason.
    formula// Control total check
=SUM(Budget[Amount]) - FinanceTotal
// Duplicate check
=COUNTIF(A:A,A2)>1

    🛡️ Advanced: Controls and Data Ownership

    Weak

    • Anyone edits the master file
    • No version labels
    • Errors fixed silently

    Strong

    • Named data owner
    • Version and date on every file
    • Error log with cause and fix

    Error rate = errors ÷ records checked. Example: 12 ÷ 400 = 3%. Track it monthly to prove improvement.

    ⚠️
    A correct number with no source is still a risk. Always keep traceability back to the origin.

    Module 04

    Process Optimization

    Mapping processes, finding bottlenecks and sustaining improvements.

    🗺️ Basic: Map the Process

    SIPOCExample: monthly report
    SuppliersProject managers, finance
    InputsStatus updates, budget data
    ProcessCollect → validate → consolidate → review
    OutputsMonthly portfolio report
    CustomersSteering committee
    • Waiting for inputs or approvals
    • Rework from errors
    • Over-processing such as extra approvals
    • Handoffs that lose information

    🚧 Intermediate: Finding Bottlenecks

    Compare work time with wait time for each step. The longest wait is usually the best target.

    StepWork timeWait time
    Draft2 h1 day
    Review1 h3 days
    Finance check1 h2 days
    Approval0.5 h3 days
    Figure 4.1 · Improvement loop (DMAIC)

    ⚡ Advanced: Standardise, Automate and Sustain

    • Use templates and checklists to remove variation.
    • Run steps in parallel where they do not depend on each other.
    • Set service levels (e.g. review within 1 day).
    • Automate repeat tasks only after the process is stable.
    • Measure benefit: time saved, errors reduced, cost avoided.
    💡
    Benefit example: 15 minutes saved × 40 reports = 10 hours per month.
    ⚠️
    Automating a broken process only makes mistakes faster. Fix the flow first.

    Module 05

    Written Communication

    Clear, action-focused emails, summaries and escalations.

    ✍️ Basic: Principles of Clear Writing

    PrincipleDoAvoid
    AudienceWrite for what the reader needsWriting for yourself
    PurposeState the ask in the first linesBurying the request
    ClarityShort sentences, familiar wordsJargon and long paragraphs
    StructureHeadings, bullets, one idea eachWalls of text

    Before

    • “As discussed, there have been some issues with the timelines and we may need to look at the plan.”

    After (BLUF)

    • “Decision needed by Friday: move go-live from 10 May to 24 May because testing is 2 weeks behind.”

    📧 Intermediate: Emails and Status Summaries

    PartWhat to include
    SubjectAction + deadline
    Opening lineThe conclusion or request
    BodyKey facts, dates, numbers
    AskWhat, who, by when
    CloseNext step and contact
    • Executive summary: one page: status, key numbers, risks, decisions needed.
    • Use the same layout every month so readers know where to look.
    • Check that every number matches the source before sending.

    📣 Advanced: Escalation and Sensitive Messages

    Use Situation → Impact → Options → Recommendation.

    exampleSituation: Vendor delivery is 3 weeks late.
Impact: Go-live moves to 24 May; $40k extra cost.
Options: (A) add testers; (B) reduce scope; (C) accept delay.
Recommendation: Option A. Decision needed by Friday.
    ⚠️
    Keep the tone factual and respectful. Describe the problem, not the person.

    Module 06

    Attention to Detail

    Spotting small errors, using checklists and building checks into the process.

    🔬 Basic: What Details Matter

    DetailTypical errorExample
    NumbersTransposed or mistyped digits1,260 → 1,620
    DatesWrong year or format03/04 read as March or April
    NamesMisspelt project or person“Apolo” vs “Apollo”
    UnitsMixed thousands and millions$5 vs $5M
    VersionsOld file sentv2 instead of v4
    💡
    Small errors damage trust far more than their size suggests.

    ☑️ Intermediate: Checking Techniques

    Figure 6.1 · A simple review flow
    • Checklist: numbers, dates, names, units, version.
    • Read aloud to catch missing or awkward words.
    • Reverse check: recalculate key totals from the source.
    • Sample check: verify a few rows in depth.

    🧱 Advanced: Building Detail Checks into the Process

    Relying on memory

    • “I will remember to check”
    • Last-minute review
    • No record of errors

    Built-in controls

    • Template with validation
    • Maker-checker sign-off
    • Error log reviewed monthly
    ⚠️
    Tired eyes miss errors. Schedule checks when you are fresh and avoid rushing the final step.

    Module 07

    Scenarios & Troubleshooting

    Four realistic situations with symptoms, diagnosis and resolution.

    🔢 Case: The Report With Three Totals

    Situation

    Three team members send three different total budgets for the same project.

    What you observe

    • Different file versions
    • Different cut-off dates

    Diagnosis

    No single source of truth and no version control.

    Resolution

    1. Agree the source system
    2. Compare versions line by line
    3. Reconcile to finance
    4. Label file with date and version

    ⏳ Case: The 9-Day Approval

    Situation

    A resource request takes 9 days; actual work is under 2 days.

    What you observe

    • Seven days are queues between steps
    • Approvals happen one after another

    Diagnosis

    Waiting time and sequential approvals create the delay.

    Resolution

    1. Map the process
    2. Run reviews in parallel
    3. Set a 1-day review service level
    4. Measure cycle time monthly

    📭 Case: The Email Nobody Answered

    Situation

    A long email asking for a decision gets no response for a week.

    What you observe

    • The ask is in paragraph five
    • No deadline or owner

    Diagnosis

    The message buries the request.

    Resolution

    1. Rewrite using BLUF
    2. Put the ask and date first
    3. Name the decision maker
    4. Follow up once with a short summary

    📅 Case: The Wrong Date in the Board Pack

    Situation

    A go-live date in the board pack is wrong by two weeks.

    What you observe

    • Date copied from an older version
    • No second reviewer

    Diagnosis

    There was no final check against the source.

    Resolution

    1. Correct and notify
    2. Add date check to the checklist
    3. Introduce maker-checker review
    4. Log the error and monitor

    Module 10

    Interview Preparation

    Questions asked in PMO Analyst interviews, grouped by level. Draft your answer, then compare with the model answer.

    🌱 Beginner Interview Questions

    IQ1.Which soft skills matter most for a PMO analyst?
    Analytical thinking, data accuracy, process improvement, clear writing and attention to detail — because they build trust in the numbers and the message.
    IQ2.How do you structure a problem before analysing it?
    Define it clearly (what, how big, since when), break it into non-overlapping parts, gather evidence, then conclude.
    IQ3.What does data accuracy mean and why does it matter?
    Data that matches reality and reconciles to a source. Wrong numbers lead to wrong decisions and lost trust.

    🛠️ Intermediate Interview Questions

    IQ4.How do you make sure you do not miss details?
    Use a checklist, check numbers against the source, take a break before proofing and ask for a second review on important outputs.
    IQ5.How do you find the root cause of a recurring issue?
    Use 5 Whys and Pareto analysis, validate with data, and fix the process rather than reminding people.
    IQ6.How do you validate data before reporting?
    Check counts and control totals, validity of dates and fields, duplicates, timeliness and reconcile key figures to the source system.

    🚀 Advanced Interview Questions

    IQ7.How do you write for executives?
    Lead with the conclusion or decision needed, keep it to one page, use key numbers and plain language.
    IQ8.How do you identify a process to improve?
    Look for long cycle times, waiting, rework and handoffs; map the process and measure work versus wait time.
    IQ9.Tell me about a time you caught an error before release.
    Use STAR: describe the situation, what you checked, the error found, the fix and the control you added afterwards.

    🏆 Expert Interview Questions

    IQ10.Two sources show different numbers. What do you do?
    Trace both to origin, compare definitions and dates, reconcile the difference, agree the source of truth and document it.
    IQ11.How do you prove that an improvement worked?
    Compare before and after using time, error rate or cost, over a meaningful period, and report the result.
    IQ12.Tell me about a time you delivered bad news in writing.
    State the situation and impact first, give options and a recommendation, keep a factual and respectful tone and agree next steps.
