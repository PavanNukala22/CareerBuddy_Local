🎯 1. What Problem Does a Vector Database Solve?

Traditional search is excellent when the exact term matters. Vector search is useful when the meaning of the query matters.

🔤 Traditional / Keyword SearchLooks for matching terms, identifiers, phrases or structured conditions.
🧠 Vector / Semantic SearchRepresents content numerically and retrieves content whose vector is similar to the query vector.
Example: A user asks “How can I reset my company password?” A relevant document might say “Employees can recover their account credentials through the identity portal.” The wording differs, but the intent can be related.

🔢 2. What Is a Vector?

A vector is an ordered collection of numbers. Your original classroom example represents fruit using measurable features such as sweetness and crunchiness.

FruitSweetnessCrunchinessVector
🍎 Apple79[7, 9]
🍌 Banana81[8, 1]

🧠 3. What Is an Embedding?

An embedding is a numerical representation generated by an embedding model. It is designed so that useful relationships in the source data can be represented in vector space.

Text
  ↓
Embedding Model
  ↓
[0.12, -0.43, 0.77, 0.21, ...]
  ↓
Vector Database
Important distinction: A vector is the numerical object. An embedding is a vector representation produced from data by an embedding model.

📐 4. Dimensions

A vector can have 2, 4, 128, 384, 768, 1024, 1536 or many other dimensions depending on the representation/model. The source guide introduces the idea that real AI systems can use thousands of dimensions. fileciteturn1file9L431-L443

In learned language embeddings, individual dimensions generally should not be interpreted as simple human-readable features such as “dimension 1 = sweetness.” The representation is distributed across dimensions.

🗄️ 5. Vector Database

A vector database is designed to store vectors and efficiently perform similarity search. A practical record commonly combines a vector with an ID, metadata and a reference or copy of the source content.

{
  "id": "doc_101",
  "vector": [0.21, -0.14, 0.77, "..."],
  "metadata": {
    "department": "HR",
    "document_type": "policy",
    "year": 2026
  },
  "text": "Employees can reset their password..."
}

The original guide explains the basic flow as: store vectors → convert the query into a vector → calculate similarity → return the best match. fileciteturn1file9L447-L456

🔄 Core Lifecycle

Ingest

Transform
Extract, clean and chunk the content.

Retrieve
Convert a query to an embedding and retrieve nearest candidates.

📏 6. Similarity Metrics

MetricIdeaUseful intuition
Cosine similarityMeasures angle/directionHow similarly two vectors point
Euclidean distanceMeasures straight-line distanceHow far apart two points are
Dot productMeasures vector alignment and magnitudeLarge score can reflect both direction and magnitude

📐 Cosine Similarity

cos(θ) = (A · B) / (||A|| × ||B||)

A = [7, 9]
B = [8, 1]

A · B = (7×8) + (9×1) = 65
||A|| = √130 ≈ 11.40
||B|| = √65  ≈ 8.06

cos(θ) ≈ 65 / (11.40 × 8.06)
       ≈ 0.707

The uploaded guide works through this same Apple/Banana calculation and gets approximately 0.707. fileciteturn1file0L602-L651

Key insight: If two vectors point in the same direction, cosine similarity is close to 1. Scaling a vector by a positive constant does not change its direction, so cosine similarity remains unchanged.

🔎 7. Top-K Retrieval

Applications usually need the best few results, not every possible result.

Query
  ↓
Similarity Search
  ↓
Rank candidates
  ↓
Top-K

1. Document 91 → 0.94
2. Document 32 → 0.91
3. Document 72 → 0.89
4. Document 11 → 0.86
5. Document 48 → 0.84

If K = 5, the system returns the five selected candidates.

🏷️ 8. Metadata Filtering

Similarity alone cannot express every business rule. Metadata lets you combine semantic retrieval with structured constraints.

Query:
"Find reimbursement policy"

Semantic search
       +
department = "Finance"
document_type = "Policy"
access_level <= user's access
       ↓
Top-K results
Security principle: Retrieval should respect authorization. Similarity is not a substitute for access control.

✂️ 9. Chunking

Large documents are normally divided into smaller retrievable pieces.

100-page handbook
       ↓
Chunk 1 → Leave Policy
Chunk 2 → Salary
Chunk 3 → Security
Chunk 4 → Attendance
       ↓
Embedding for each chunk
       ↓
Vector Database

Common strategies

Fixed-sizeSplit content by a target number of characters/tokens.
Sentence-basedKeep sentence boundaries where practical.
RecursiveTry larger structural boundaries before smaller ones.
Structure-awareUse headings, tables, sections and document layout.

Chunk overlap can preserve context across boundaries, but excessive overlap increases storage and retrieval duplication.

💬 10. Semantic Search

Semantic search attempts to retrieve by meaning rather than requiring exact wording.

Query“How can I purchase a vehicle?”
Potentially related result“Customers can finance a new automobile through...”

⚡ 11. Exact Search vs ANN

Exact Nearest Neighbor

Compare the query against all candidates and select the true nearest neighbors.

Approximate Nearest Neighbor — ANN

Use an index/algorithm to find very good nearest neighbors without exhaustively checking every vector. This can greatly improve speed at large scale, with a possible recall trade-off.

Query
  ↓
ANN Index
  ↓
Candidate vectors
  ↓
Similarity / ranking
  ↓
Top-K
Engineering trade-off: More search effort can improve recall but may increase latency and resource usage.

🕸️ 12. HNSW

Hierarchical Navigable Small World (HNSW) is a graph-based approximate nearest-neighbor approach.

             A
           /   \
          B     C
         / \     \
        D   E     F
             \
              G

Vectors are represented as nodes with connections to other nodes. Search navigates the graph toward promising neighbors rather than scanning the entire collection.

Concepts to understand

  • Graph connectivity
  • Construction effort
  • Search effort
  • Recall vs latency
  • Memory consumption

🗂️ 13. IVF — Inverted File Index

IVF groups vectors into clusters. A query first identifies promising clusters and then searches within selected regions.

All vectors

Cluster into regions
   ↓
Query
   ↓
Nearest promising cluster(s)
   ↓
Search selected candidates
   ↓
Top-K

🔀 14. Hybrid Search

Some applications need both semantic understanding and exact term matching.

                  Query
                    ↓
        ┌───────────┴───────────┐
        ↓                       ↓
   Keyword Search          Vector Search
        ↓                       ↓
        └───────────┬───────────┘
                    ↓
              Merge / Rank
                    ↓
               Final results

Hybrid search is especially useful for identifiers, product codes, error codes, names and other exact terms where keyword matching can complement semantic retrieval.

🏆 15. Reranking

Initial vector retrieval can be fast but imperfect. A reranker can examine the query and candidate documents more carefully and reorder them.

Query
 ↓
Vector Search
 ↓
Top 20 candidates
 ↓
Reranker
 ↓
Best 5
 ↓
LLM
Two-stage retrieval: Stage 1 emphasizes fast candidate generation. Stage 2 emphasizes more precise ordering.

🤖 17. Vector Databases + RAG

Retrieval-Augmented Generation (RAG) uses retrieval to provide relevant external context to an LLM before generation.

User Question ↓ Query Embedding ↓ Vector Search ↓ Metadata Filtering ↓ Top-K Chunks ↓ Optional Reranking ↓ Context Builder ↓ LLM ↓ Answer

📦 Complete RAG Ingestion Pipeline

Collect
PDFs, websites, Word documents, FAQs, databases or other sources.
Extract
Convert source content into usable text/structured data.
Chunk
Split the content into retrievable units.
Embed
Generate vectors using an embedding model.
Store
Save vectors and metadata in the vector database.
