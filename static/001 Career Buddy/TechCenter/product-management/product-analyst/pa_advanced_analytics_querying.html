    Module 01

    Advanced Analytics & Querying for Product Analysts

    Complex SQL, Python and R for exploratory data analysis, and database querying that answers product questions accurately, fast and reproducibly.

    🏛️ Course Overview: What the Role Needs

    A Product Analyst turns questions about users and features into reliable answers. Advanced querying and exploratory analysis are the foundation for experimentation, dashboards and insight work.

    🗃️
    Advanced SQL
    CTEs, window functions, cohorts, funnels, sessions.
    🐍
    Python / R
    Explore, clean, model and visualize data.
    ⚡
    Query performance
    Write queries that scale and cost less.
    ✅
    Data quality
    Validate, reconcile and document your numbers.
    💡
    A product analyst is trusted for correct numbers and clear definitions more than for clever queries.

    🎯 Learning Objectives

    By the end of this course you will be able to:

    1. Write complex SQL with CTEs, joins, window functions and conditional aggregation.
    2. Build funnels, cohorts, retention and sessionization queries.
    3. Optimize queries with partitions, indexes, filters and efficient joins.
    4. Run exploratory data analysis in Python (pandas) or R (tidyverse).
    5. Detect and handle missing data, duplicates, outliers and bias.
    6. Validate numbers through reconciliation and tests.
    7. Document metric definitions and make analysis reproducible.

    🗃️ Basic: Joins, Grain and Conditional Aggregation

    Figure 2.1 · Layers of an analytical query
    code<span class="tok-c">-- Conversion by platform in a week</span>
<span class="tok-k">SELECT</span> u.platform,
       <span class="tok-f">COUNT</span>(<span class="tok-k">DISTINCT</span> u.user_id) <span class="tok-k">AS</span> visitors,
       <span class="tok-f">COUNT</span>(<span class="tok-k">DISTINCT</span> <span class="tok-k">CASE WHEN</span> e.event_name = <span class="tok-s">'purchase'</span> <span class="tok-k">THEN</span> u.user_id <span class="tok-k">END</span>) <span class="tok-k">AS</span> buyers,
       <span class="tok-f">ROUND</span>(<span class="tok-n">100.0</span> * <span class="tok-f">COUNT</span>(<span class="tok-k">DISTINCT CASE WHEN</span> e.event_name = <span class="tok-s">'purchase'</span> <span class="tok-k">THEN</span> u.user_id <span class="tok-k">END</span>)
             / <span class="tok-f">COUNT</span>(<span class="tok-k">DISTINCT</span> u.user_id), <span class="tok-n">2</span>) <span class="tok-k">AS</span> conv_pct
<span class="tok-k">FROM</span> users u
<span class="tok-k">JOIN</span> events e <span class="tok-k">ON</span> e.user_id = u.user_id
<span class="tok-k">WHERE</span> e.event_date <span class="tok-k">BETWEEN</span> <span class="tok-s">'2026-09-01'</span> <span class="tok-k">AND</span> <span class="tok-s">'2026-09-07'</span>
<span class="tok-k">GROUP BY</span> u.platform;
    PitfallFix
    Joining one-to-many then summingAggregate first or use DISTINCT keys
    LEFT JOIN with WHERE on right tableMove filter to ON clause
    COUNT(*) vs COUNT(DISTINCT)Decide users vs events
    Time zonesConvert to one zone explicitly
    NULL comparisonsUse IS NULL / COALESCE

    🔗

    Time

    🪟 Intermediate: CTEs and Window Functions

    code<span class="tok-k">WITH</span> daily <span class="tok-k">AS</span> (
  <span class="tok-k">SELECT</span> event_date, <span class="tok-f">COUNT</span>(<span class="tok-k">DISTINCT</span> user_id) <span class="tok-k">AS</span> dau
  <span class="tok-k">FROM</span> events <span class="tok-k">GROUP BY</span> event_date
)
<span class="tok-k">SELECT</span> event_date, dau,
       <span class="tok-f">AVG</span>(dau) <span class="tok-k">OVER</span> (<span class="tok-k">ORDER BY</span> event_date <span class="tok-k">ROWS BETWEEN</span> <span class="tok-n">6</span> <span class="tok-k">PRECEDING AND CURRENT ROW</span>) <span class="tok-k">AS</span> dau_7d_avg,
       dau - <span class="tok-f">LAG</span>(dau, <span class="tok-n">7</span>) <span class="tok-k">OVER</span> (<span class="tok-k">ORDER BY</span> event_date) <span class="tok-k">AS</span> wow_change
<span class="tok-k">FROM</span> daily;
    FunctionUse
    ROW_NUMBER()Pick first or latest row per user
    RANK() / DENSE_RANK()Top N with ties
    LAG() / LEAD()Previous or next value (time between events)
    SUM() OVERRunning totals
    AVG() OVER (ROWS ...)Moving averages
    NTILE()Deciles and quartiles

    🔻 Intermediate: Funnels, Cohorts and Retention

    code<span class="tok-c">-- Strict-order funnel: view -> add_to_cart -> purchase (same user, within 7 days)</span>
<span class="tok-k">WITH</span> v <span class="tok-k">AS</span> (<span class="tok-k">SELECT</span> user_id, <span class="tok-f">MIN</span>(ts) t <span class="tok-k">FROM</span> events <span class="tok-k">WHERE</span> event_name=<span class="tok-s">'view_item'</span> <span class="tok-k">GROUP BY</span> user_id),
     a <span class="tok-k">AS</span> (<span class="tok-k">SELECT</span> user_id, <span class="tok-f">MIN</span>(ts) t <span class="tok-k">FROM</span> events <span class="tok-k">WHERE</span> event_name=<span class="tok-s">'add_to_cart'</span> <span class="tok-k">GROUP BY</span> user_id),
     p <span class="tok-k">AS</span> (<span class="tok-k">SELECT</span> user_id, <span class="tok-f">MIN</span>(ts) t <span class="tok-k">FROM</span> events <span class="tok-k">WHERE</span> event_name=<span class="tok-s">'purchase'</span> <span class="tok-k">GROUP BY</span> user_id)
<span class="tok-k">SELECT</span> <span class="tok-f">COUNT</span>(v.user_id) viewed,
       <span class="tok-f">COUNT</span>(a.user_id) carted,
       <span class="tok-f">COUNT</span>(p.user_id) purchased
<span class="tok-k">FROM</span> v
<span class="tok-k">LEFT JOIN</span> a <span class="tok-k">ON</span> a.user_id=v.user_id <span class="tok-k">AND</span> a.t &gt;= v.t <span class="tok-k">AND</span> a.t &lt; v.t + <span class="tok-k">INTERVAL</span> <span class="tok-s">'7 days'</span>
<span class="tok-k">LEFT JOIN</span> p <span class="tok-k">ON</span> p.user_id=a.user_id <span class="tok-k">AND</span> p.t &gt;= a.t <span class="tok-k">AND</span> p.t &lt; v.t + <span class="tok-k">INTERVAL</span> <span class="tok-s">'7 days'</span>;
    code<span class="tok-c">-- Weekly retention by signup cohort</span>
<span class="tok-k">WITH</span> c <span class="tok-k">AS</span> (<span class="tok-k">SELECT</span> user_id, <span class="tok-f">DATE_TRUNC</span>(<span class="tok-s">'week'</span>, signup_date) cohort <span class="tok-k">FROM</span> users),
     a <span class="tok-k">AS</span> (<span class="tok-k">SELECT</span> <span class="tok-k">DISTINCT</span> user_id, <span class="tok-f">DATE_TRUNC</span>(<span class="tok-s">'week'</span>, event_date) wk <span class="tok-k">FROM</span> events)
<span class="tok-k">SELECT</span> cohort, <span class="tok-f">DATEDIFF</span>(<span class="tok-s">'week'</span>, cohort, wk) <span class="tok-k">AS</span> week_n,
       <span class="tok-f">COUNT</span>(<span class="tok-k">DISTINCT</span> a.user_id) <span class="tok-k">AS</span> active
<span class="tok-k">FROM</span> c <span class="tok-k">JOIN</span> a <span class="tok-k">ON</span> a.user_id = c.user_id
<span class="tok-k">GROUP BY</span> <span class="tok-n">1</span>, <span class="tok-n">2</span> <span class="tok-k">ORDER BY</span> <span class="tok-n">1</span>, <span class="tok-n">2</span>;
    Figure 2.3 · Retention analysis steps

    🏆 Advanced: Sessionization and Attribution

    code<span class="tok-c">-- Sessions: new session after 30 minutes of inactivity</span>
<span class="tok-k">WITH</span> g <span class="tok-k">AS</span> (
  <span class="tok-k">SELECT</span> *, <span class="tok-f">LAG</span>(ts) <span class="tok-k">OVER</span> (<span class="tok-k">PARTITION BY</span> user_id <span class="tok-k">ORDER BY</span> ts) prev_ts
  <span class="tok-k">FROM</span> events
), f <span class="tok-k">AS</span> (
  <span class="tok-k">SELECT</span> *, <span class="tok-k">CASE WHEN</span> prev_ts <span class="tok-k">IS NULL OR</span> ts - prev_ts &gt; <span class="tok-k">INTERVAL</span> <span class="tok-s">'30 minutes'</span> <span class="tok-k">THEN</span> <span class="tok-n">1</span> <span class="tok-k">ELSE</span> <span class="tok-n">0</span> <span class="tok-k">END</span> new_s
  <span class="tok-k">FROM</span> g
)
<span class="tok-k">SELECT</span> user_id, ts, <span class="tok-f">SUM</span>(new_s) <span class="tok-k">OVER</span> (<span class="tok-k">PARTITION BY</span> user_id <span class="tok-k">ORDER BY</span> ts) <span class="tok-k">AS</span> session_id
<span class="tok-k">FROM</span> f;
    TopicTechnique
    AttributionFirst touch, last touch, linear; state the rule
    DeduplicationROW_NUMBER() OVER (PARTITION BY id ORDER BY ts DESC) = 1
    Slowly changing dimensionsJoin on effective date ranges
    Late-arriving dataUse event time and watermarks
    Bot and test trafficFilter with documented rules

    Query Performance and Database Querying

    Reading query plans, partitioning, indexes, efficient joins, warehouse cost control and safe production access.

    ⚡ Why Queries Are Slow

    CauseSymptomFix
    Full table scanReads everythingFilter on partition or indexed column
    SELECT *Wide scans, high costSelect only needed columns
    Join explosionRow count balloonsCheck join keys and grain
    Functions on filtered columnIndex unusedFilter on raw column ranges
    Large sort / distinctMemory spillPre-aggregate; approximate distinct
    Skewed keysOne slow workerSalting, filtering hot keys
    Figure 3.1 · Query optimization loop

    🧱 Warehouse Concepts and Cost

    ConceptMeaningAnalyst action
    PartitioningSplit table by date or keyAlways filter by partition column
    Clustering / sort keysCo-locate related rowsFilter and join on clustered columns
    Materialized viewsStored query resultsUse for repeated heavy aggregations
    Columnar storageReads only needed columnsAvoid SELECT *
    Cost per bytes scannedBilling model on many warehousesPreview with dry run; sample first
    code<span class="tok-c">-- Good: partition filter + only needed columns</span>
<span class="tok-k">SELECT</span> user_id, event_name
<span class="tok-k">FROM</span> events
<span class="tok-k">WHERE</span> event_date <span class="tok-k">BETWEEN</span> <span class="tok-s">'2026-09-01'</span> <span class="tok-k">AND</span> <span class="tok-s">'2026-09-07'</span>
  <span class="tok-k">AND</span> event_name <span class="tok-k">IN</span> (<span class="tok-s">'view_item'</span>, <span class="tok-s">'purchase'</span>);

<span class="tok-c">-- Bad: function on column blocks pruning</span>
<span class="tok-k">WHERE</span> <span class="tok-f">DATE</span>(event_ts) = <span class="tok-s">'2026-09-01'</span>

    📊 Uncertainty and Intervals

    textConversion: 480 purchases from 4,000 visitors = 12.0%
Standard error = sqrt(p(1-p)/n) = sqrt(0.12 x 0.88 / 4000) = 0.0051
95% CI = 12.0% +/- 1.96 x 0.51% = 11.0% to 13.0%
Report: "12.0% (95% CI 11.0%-13.0%)"
    ConceptMeaning
    Sampling errorEstimates vary between samples
    Confidence intervalRange consistent with the data
    BiasSystematic error, not reduced by size
    CorrelationAssociation; may be confounded
    Causal inferenceNeeds experiments or careful design

    Module 11

    Interview Preparation

    Questions asked in Product Analyst interviews about querying and exploratory analysis, grouped by level. Draft your answer, then compare with the model answer.

    🌱 Beginner Interview Questions

    IQ1.How do you avoid double counting in SQL?
    Know the grain of each table, aggregate before joining one-to-many relations, use distinct keys deliberately, and reconcile totals against a source.
    IQ2.Explain window functions with an example.
    They calculate across related rows without collapsing them, for example ROW_NUMBER to find a first purchase, LAG for time between events or a 7-day moving average.
    IQ3.How do you build a funnel in SQL?
    Take the first occurrence of each step per user, join steps with order and time-window conditions, and count distinct users at each stage.

    🛠️ Intermediate Interview Questions

    IQ4.How do you calculate retention?
    Define the cohort event and the active event, bucket time since cohort start, count distinct returning users and divide by cohort size.
    IQ5.How do you speed up a slow query?
    Read the plan, filter on partition columns, select only needed columns, pre-aggregate before joins, avoid functions on filter columns and materialize repeated logic.
    IQ6.When do you use Python or R instead of SQL?
    For statistical tests, modeling, complex transformations, plotting and automation after SQL has extracted and aggregated the data.

    🚀 Advanced Interview Questions

    IQ7.How do you handle outliers?
    Investigate cause first; keep real values, use robust statistics such as median, cap or transform for modeling, and document any removal.
    IQ8.What is Simpson's paradox?
    A trend in overall data reverses when segmented, so always check segments before concluding.
    IQ9.How do you validate your numbers?
    Run quality checks, reconcile with other sources, sanity check against known values, peer review the logic and document definitions.

    🏆 Expert Interview Questions

    IQ10.How do you handle conflicting metric definitions?
    Compare definitions, agree one governed definition with an owner, publish it in the metric layer and communicate the change.
    IQ11.How do you scope an ad hoc request?
    Clarify the decision, time period, definition and precision needed, estimate effort, deliver the answer first and note caveats.
    IQ12.Tell me about an analysis that changed a decision.
    Describe the question, data and method, the finding, how you communicated it, the decision and the measured result.
