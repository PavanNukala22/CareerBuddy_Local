    Module 01

    Experimentation Rigor for Product Analysts

    Power analysis, hypothesis testing, sample size determination and variance reduction (CUPED): designing and analyzing A/B tests that give trustworthy decisions.

    🏛️ Course Overview: What the Role Needs

    Experimentation rigor separates real product learning from noise. A product analyst designs tests that are powered to detect meaningful effects, analyzed honestly, and sharpened with variance reduction.

    🧪
    Design
    Hypotheses, metrics, randomization and guardrails.
    ⚡
    Power & sample size

    📐
    Hypothesis testing

    📉
    Variance reduction
    CUPED and stratification for faster, sharper tests.
    💡
    A rigorous experiment answers one question: did the change cause the effect, and how sure are we?

    🎯 Learning Objectives

    By the end of this course you will be able to:

    1. Design experiments with clear hypotheses, primary metrics, guardrails and randomization units.
    2. Run power analysis and compute sample size and duration.
    3. Choose and run tests: z-test, t-test, chi-square, non-parametric and bootstrap.
    4. Interpret p-values, confidence intervals and practical significance.
    5. Apply variance reduction: CUPED, stratification and covariate adjustment.
    6. Handle multiple comparisons, peeking, SRM, novelty and network effects.
    7. Communicate results and decisions, including inconclusive outcomes.

    Module 03

    Power Analysis and Sample Size

    Type I and II errors, effect size, MDE, formulas for proportions and means, duration planning and trade-offs.

    ⚡ Errors, Power and Effect Size

    H0 true (no effect)H1 true (real effect)
    Reject H0Type I error (α) - false positiveCorrect (power = 1 - β)
    Do not reject H0CorrectType II error (β) - missed win
    Figure 3.1 · What drives sample size
    LeverEffect on required n
    Halve the MDEAbout 4x larger sample
    Raise power 80% to 90%About 30% larger
    Lower alpha 5% to 1%About 70% larger
    Reduce variance by halfAbout half the sample

    🧮 Intermediate: Sample Size Formulas

    textRule of thumb (alpha 5% two-sided, power 80%): n per arm = 16 x variance / delta^2

Proportions: variance = p(1-p)
  Baseline 10%, absolute MDE 1pp: n = 16 x 0.10 x 0.90 / 0.01^2 = 16 x 0.09 / 0.0001 = 14,400 per arm

Means: variance = sigma^2
  sigma = 20, delta = 2: n = 16 x 400 / 4 = 1,600 per arm

Duration: total users needed / eligible users per day
  2 arms x 14,400 = 28,800; at 2,100 eligible users/day = 13.7 days -> run 14 days (2 full weeks)

MDE from n: MDE = 2.8 x sigma x sqrt(2/n)   (n=1,600, sigma=20 -> 2.8 x 20 x 0.0354 = 1.98)
    Figure 3.2 · Power analysis steps

    🔧 Intermediate: Power in Python

    Module 04

    Statistical Hypothesis Testing

    Z-tests, t-tests, chi-square, non-parametric tests, bootstrap, confidence intervals, p-values and practical significance.

    📐 The Logic of a Test

    Figure 4.1 · Hypothesis testing flow
    textTwo-proportion z-test
Control: 1,000 / 10,000 = 10.0%   Treatment: 1,100 / 10,000 = 11.0%
Pooled p = 2,100 / 20,000 = 0.105
SE = sqrt(0.105 x 0.895 x (1/10,000 + 1/10,000)) = 0.00434
z = (0.11 - 0.10) / 0.00434 = 2.31  -> two-sided p = 0.021
95% CI for difference (unpooled SE 0.00434): 1.0pp +/- 0.85pp = 0.15pp to 1.85pp
Interpretation: statistically significant; lift between 0.1 and 1.9 points; relative lift 10%.

    🧰 Intermediate: Choosing the Right Test

    MetricTestNotes
    Conversion (binary)Two-proportion z-test / chi-squareLarge samples
    Mean (revenue per user)Welch t-testHandles unequal variances
    Skewed metricMann-Whitney U or bootstrapHeavy tails
    Ratio metric (CTR per session)Delta method / bootstrap by userUnit mismatch
    CountsPoisson / negative binomialOverdispersion
    Time to eventSurvival analysis, log-rankCensoring

    Module 05

    Variance Reduction: CUPED and Beyond

    CUPED, regression adjustment, stratification, post-stratification and metric design to detect smaller effects with fewer users.

    📉 CUPED: Controlled-experiment Using Pre-Experiment Data

    Figure 5.1 · How CUPED works
    textCUPED
Y = metric during experiment (e.g., revenue per user)
X = same metric for the same user in the pre-experiment period
theta = cov(X, Y) / var(X)   (estimated on pooled data)
Y_adj = Y - theta x (X - mean(X))
Variance(Y_adj) = Variance(Y) x (1 - rho^2)   where rho = corr(X, Y)

Example: rho = 0.7 -> variance falls by 49% -> needed sample falls to 51%
  1,600 users per arm -> about 816 per arm (or MDE shrinks by ~29%)
    Correlation ρVariance reductionSample needed
    0.39%91%
    0.525%75%
    0.749%51%
    0.981%19%
    📅
    Pre-period
    Before assignment only.
    🔗
    Correlated
    Higher ρ, bigger gain.
    ⚖️
    Unbiased
    Same expected effect.
    🚀
    Faster tests
    Fewer users.

    🐍 CUPED in Python

    code<span class="tok-k">import</span> numpy <span class="tok-k">as</span> np, pandas <span class="tok-k">as</span> pd

<span class="tok-c"># df: user_id, variant, y (experiment metric), x (pre-period metric)</span>
theta = np.<span class="tok-f">cov</span>(df.x, df.y)[<span class="tok-n">0</span>, <span class="tok-n">1</span>] / np.<span class="tok-f">var</span>(df.x, ddof=<span class="tok-n">1</span>)
df[<span class="tok-s">"y_cuped"</span>] = df.y - theta * (df.x - df.x.<span class="tok-f">mean</span>())

g = df.<span class="tok-f">groupby</span>(<span class="tok-s">"variant"</span>).y_cuped
lift = g.<span class="tok-f">mean</span>()[<span class="tok-s">"treat"</span>] - g.<span class="tok-f">mean</span>()[<span class="tok-s">"ctrl"</span>]
se = np.<span class="tok-f">sqrt</span>(g.<span class="tok-f">var</span>()[<span class="tok-s">"treat"</span>]/g.<span class="tok-f">count</span>()[<span class="tok-s">"treat"</span>] + g.<span class="tok-f">var</span>()[<span class="tok-s">"ctrl"</span>]/g.<span class="tok-f">count</span>()[<span class="tok-s">"ctrl"</span>])
print(lift, lift - <span class="tok-n">1.96</span>*se, lift + <span class="tok-n">1.96</span>*se)

    Covariate measured after assignmentUse only pre-period data
    New users with no pre-dataImpute with 0 or segment; consider other covariates
    Different metric definitionsUse same metric definition for X and Y
    θ fitted per armFit on pooled data to avoid bias
    Weak correlationGain small; choose better covariates

    Multiple Testing, Peeking and Experiment Health

    Corrections for many metrics and variants, sequential monitoring, SRM, A/A tests and common validity threats.

    🩺 Validity Threats and Fixes

    ThreatWhat happensRemedy
    PeekingStopping on first p < 0.05; about 14% false positives with 5 looksFixed horizon or sequential methods
    Multiple metricsChance wins among many metricsOne primary metric; Bonferroni or Holm for others
    Multiple variantsMore comparisons, higher errorCorrect alpha; Dunnett
    Sample ratio mismatchArms unbalanced beyond chanceChi-square test; fix logging or assignment
    Novelty effectEarly lift decaysRun longer; look at cohorts
    Selection biasTriggering differs by armTrigger on assignment-independent logic
    Bots and outliersDistort meansFilter and cap with documented rules
    textSRM CHECK: expected 50/50, observed 10,300 vs 9,700 (total 20,000)
Expected 10,000 each. Chi-square = 300^2/10,000 + 300^2/10,000 = 9 + 9 = 18
Critical value at p = 0.001 is 10.8 -> p < 0.001 -> SRM. Do not trust the results; find the cause.

BONFERRONI: 5 secondary metrics, alpha 0.05 -> per-metric alpha 0.01

    Real-World Scenarios & Troubleshooting

    Case studies: a test stopped early, an SRM alarm, an underpowered pricing test and a metric win with a guardrail loss.

    ⏱️ Case Study: The Test Stopped Early

    A PM stops a test at day 3 because p = 0.03; two weeks later the full rollout shows no lift.

    Figure 8.1 · The cost of peeking
    ✅
    Outcome: team adopted a fixed horizon with sequential monitoring dashboards; false-win rate fell and trust improved.

    🚨 Case Study: SRM Alarm

    1. Confirm SRM with chi-square.
    2. Check assignment logs and exposure logging by platform and version.
    3. Find that treatment crashed on older Android, dropping events.
    4. Fix, restart; do not analyze the corrupted run.
    Figure 8.2 · Handling SRM

    💰 Troubleshooting: Underpowered Pricing Test

    StepAction
    1Compute power with revenue variance and realistic MDE
    2Apply CUPED with prior purchase value
    3Cap outliers; consider conversion as primary
    4Extend duration or use a larger MDE
    5If still hopeless, decide with qualitative and model evidence

    ⚖️ Scenario: Metric Win, Guardrail Loss

    Conversion rises 1.0pp but refund rate also rises 0.4pp. Quantify net revenue, check refund reasons and segments, discuss the trade-off with the owner, and consider a variant that keeps the lift while reducing refunds.

    Baseline conversion 5%, absolute MDE 0.5pp. Rule-of-thumb n per arm?

    Task 4IntermediateDuration
    You need 30,400 per arm and have 4,000 eligible users per day. How long?

    60,800 / 4,000 = 15.2 days; run 3 weeks to cover whole weeks, or accept a larger MDE.

    🚀 Advanced Tasks

    Task 5AdvancedZ-test
    Control 500/5,000; treatment 560/5,000. Compute lift and z.
    Pooled SE.
    p1=10%, p2=11.2%; pooled p = 1060/10000 = 0.106; SE = sqrt(0.106 x 0.894 x 2/5000) = 0.00616; z = 0.012/0.00616 = 1.95; p about 0.051; borderline, not significant at 5%.
    Task 6AdvancedCUPED gain
    Pre and post revenue correlation is 0.6. By what % does variance fall, and what sample fraction is needed?
    1 - rho².
    Variance falls 36% (0.6² = 0.36); sample needed 64% of original.

    🏆 Expert Tasks

    Task 7ExpertDiagnose SRM
    A 50/50 test shows 52,000 vs 48,000 users. Is it SRM and what do you do?
    Chi-square.
    Expected 50,000 each; chi-square = 2 x 2000²/50000 = 160; far beyond critical value, so SRM. Check assignment and logging by platform; fix and rerun; do not trust the results.
    Task 8ExpertPresent an inconclusive test
    Lift +0.3pp, 95% CI -0.4 to +1.0pp, MDE was 1pp. Write the conclusion.
    What is ruled out?
    No evidence of a lift of the planned size, but a modest gain or small loss is not excluded. Inconclusive and underpowered. Options: extend with CUPED, accept uncertainty and decide on cost or qualitative grounds.

    Module 11

    Interview Preparation

    Questions asked in Product Analyst interviews about experimentation, grouped by level. Draft your answer, then compare with the model answer.

    🌱 Beginner Interview Questions

    IQ1.How do you design an A/B test?
    State the hypothesis, pick one primary metric and guardrails, choose the randomization unit and eligibility, compute sample size and duration, plan ramp, pre-register the decision rule and run health checks.
    IQ2.What is statistical power and why does it matter?
    The chance of detecting a true effect of the MDE, typically 80%. Low power means real wins are missed and significant results are more likely exaggerated.
    IQ3.How do you compute sample size?
    Use baseline rate or variance, MDE, alpha and power in a formula or tool; for example 16 times variance divided by delta squared per arm for 5% alpha and 80% power.

    🛠️ Intermediate Interview Questions

    IQ4.Explain a p-value.
    The probability of observing data at least as extreme as ours if the null hypothesis were true. It is not the probability that the variant is better.
    IQ5.What is CUPED?
    A variance reduction method that adjusts the experiment metric using pre-experiment data, with variance cut by a factor of one minus rho squared, giving smaller samples or smaller MDEs.
    IQ6.What is peeking and how do you avoid it?
    Stopping when p dips below 0.05, which inflates false positives. Use a fixed horizon or sequential testing with alpha spending.

    🚀 Advanced Interview Questions

    IQ7.How do you handle multiple metrics or variants?
    Pick one primary metric, correct secondary comparisons with Bonferroni or Holm, correct for multiple variants, and label segment cuts exploratory.
    IQ8.What is SRM?
    Sample ratio mismatch: arm sizes differ from the planned split beyond chance, usually a logging or assignment bug. Results are invalid until resolved.
    IQ9.What if you cannot randomize?
    Use quasi-experiments such as difference-in-differences, synthetic control, regression discontinuity or geo experiments, and be explicit about assumptions.

    🏆 Expert Interview Questions

    IQ10.How do you handle novelty effects?
    Run long enough, compare early and late cohorts, look at new versus returning users, and use holdouts for long-term effects.
    IQ11.How do you communicate an inconclusive test?
    Report the effect with its interval, say what effect sizes are ruled out, state the power limits and recommend a decision path or follow-up.
    IQ12.Tell me about an experiment that changed your mind.
    Describe the hypothesis, design, result, what surprised you, the decision and the lesson.
