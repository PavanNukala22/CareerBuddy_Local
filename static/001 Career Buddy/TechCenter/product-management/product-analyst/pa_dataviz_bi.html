    Module 01

    Data Visualization & BI for Product Analysts

    Dashboard development in Tableau, Looker, Metabase and Power BI, plus behavioral event instrumentation, so that product teams see the right numbers clearly and trust them.

    🏛️ Course Overview: What the Role Needs

    Data visualization and BI turn trusted data into shared understanding. Combined with well-designed behavioral instrumentation, they give product teams fast, consistent answers.

    📊
    Visual design
    Choose charts and layouts that communicate.
    🧰
    BI tools
    Tableau, Looker, Metabase and Power BI.
    🧱
    Semantic layer
    Governed metrics and models behind dashboards.
    📡
    Instrumentation
    Design event tracking that captures behavior accurately.
    💡
    A dashboard is a decision tool. If nobody changes an action because of it, it is decoration.

    🎯 Learning Objectives

    By the end of this course you will be able to:

    1. Apply visualization principles: chart choice, hierarchy, color and clarity.
    2. Build dashboards in Tableau, Looker, Metabase and Power BI with correct logic.
    3. Design a semantic layer: dimensions, measures, definitions and access control.
    4. Plan event instrumentation: taxonomy, properties, naming, identity and QA.
    5. Create dashboards for product health, funnels, retention, experiments and executives.
    6. Optimize performance, refresh, cost and security of BI assets.
    7. Drive adoption through documentation, training and governance.

    Module 04

    Behavioral Event Instrumentation

    Designing tracking plans, event taxonomies, properties, identity resolution, QA and governance so behavior data is accurate and usable.

    📡 Tracking Plan and Taxonomy

    textTRACKING PLAN (excerpt)
Event: product_viewed      Trigger: product detail page rendered (client)
  Properties: product_id (string, required), category (string), price_minor (int), currency (string), source (enum: search|home|recs|ad), position (int)
Event: item_added_to_cart  Trigger: add-to-cart confirmed by server
  Properties: product_id, quantity (int >= 1), cart_value_minor (int)
Event: checkout_completed  Trigger: payment success (server-side)
  Properties: order_id (unique), total_minor, currency, payment_method, coupon_code (optional)
User properties: plan, signup_date, country, platform
Naming: object_action in snake_case, past tense; no PII in properties
    PrinciplePractice
    Object + action namingproduct_viewed, not "click_btn_47"
    Few events, rich propertiesAvoid hundreds of near-duplicate events
    Server-side for moneyAuthoritative counts for purchases
    Consistent enumsControlled values for source, plan
    Versioned schemaTrack changes; avoid breaking silently
    Privacy by designNo PII in event properties; consent respected

    🧱 Semantic Layer and dbt Models

    code<span class="tok-c">-- dbt model: fct_orders (grain: one row per order)</span>
<span class="tok-k">SELECT</span>
  o.order_id, o.user_id, o.created_at, <span class="tok-f">DATE</span>(o.created_at) <span class="tok-k">AS</span> order_date,
  o.total_minor / <span class="tok-n">100.0</span> <span class="tok-k">AS</span> revenue,
  u.country, u.plan
<span class="tok-k">FROM</span> {{ ref(<span class="tok-s">'stg_orders'</span>) }} o
<span class="tok-k">JOIN</span> {{ ref(<span class="tok-s">'dim_users'</span>) }} u <span class="tok-k">ON</span> u.user_id = o.user_id
<span class="tok-k">WHERE</span> o.status = <span class="tok-s">'paid'</span>

    Module 11

    Interview Preparation

    Questions asked in Product Analyst interviews about BI and instrumentation, grouped by level. Draft your answer, then compare with the model answer.

    🌱 Beginner Interview Questions

    IQ1.How do you decide which chart to use?
    Start from the question: trends use lines, comparisons sorted bars, distribution histograms or box plots, relationships scatter plots, cohorts heatmaps. Keep one message per chart and honest scales.
    IQ2.How do you design a dashboard for executives?
    Five to seven KPIs against targets, trend context, short commentary, links to definitions and drill-down, with clear ownership and freshness.
    IQ3.How do you ensure dashboard numbers are trusted?
    Use a governed semantic layer, tests, validation against source and finance, documentation, certification and a change log.

    🛠️ Intermediate Interview Questions

    IQ4.Compare Tableau, Looker, Metabase and Power BI.
    Tableau excels at exploration, Looker at governed modeling via LookML, Metabase at simple open-source self-service and Power BI in the Microsoft ecosystem with DAX. Choose by governance need, skills, cost and stack.
    IQ5.How do you speed up a slow dashboard?
    Measure tile queries, pre-aggregate in the warehouse, reduce tiles and filters, use extracts or caches and monitor performance.
    IQ6.What is a tracking plan?
    A document that lists events, properties, triggers, owners and rules so instrumentation is consistent and testable.

    🚀 Advanced Interview Questions

    IQ7.How do you name events?
    Object_action in snake_case and past tense, few events with rich properties, controlled values and no PII.
    IQ8.Client-side or server-side tracking?
    Client-side for interactions and UI events, server-side for authoritative outcomes like payments, and compare both for parity.
    IQ9.How do you QA instrumentation?
    Test in staging with debug tools, validate schemas, check volumes after release, compare client and server counts and alert on drops.

    🏆 Expert Interview Questions

    IQ10.How do you handle identity across devices?
    Use anonymous ids before login, stitch to a stable user id after login with documented rules and consent, and watch for merge errors.
    IQ11.How do you drive adoption of dashboards?
    Documentation, training, office hours, templates, usage analytics, feedback loops and retiring unused assets.
    IQ12.Tell me about a dashboard that changed a decision.
    Describe the stakeholders, key metrics, design choices, the insight surfaced, the decision taken and the measurable outcome.
