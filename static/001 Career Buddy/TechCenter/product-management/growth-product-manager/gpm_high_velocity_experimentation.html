    Module 01

    High-Velocity Experimentation for Growth Product Managers

    Rapid hypothesis generation, continuous multivariate testing, landing page and conversion rate optimization (CRO): running more, better experiments per quarter without sacrificing rigor.

    🏛️ Course Overview: What the Role Needs

    High-velocity experimentation turns a growth team into a learning machine. The Growth PM builds the hypothesis pipeline, the testing methods and the operating rhythm that let the team run many valid experiments and compound wins.

    💡
    Hypotheses
    Generate, score and queue ideas fast.
    🧪
    Testing engine
    A/B, multivariate and bandit methods.
    🛬
    CRO
    Landing pages and conversion funnels.
    🏎️
    Velocity
    Process, tooling and culture for speed.
    💡
    Experiment velocity matters only if the tests are valid. The goal is more learning per week, not more tests per week.

    🎯 Learning Objectives

    By the end of this course you will be able to:

    1. Build a hypothesis backlog and prioritize with ICE, PIE or RICE.
    2. Run A/B, multivariate, factorial and bandit tests appropriately.
    3. Compute sample sizes and plan experiments under traffic constraints.
    4. Optimize landing pages and funnels with CRO research and testing.
    5. Design experiment operations: intake, review, launch, analysis, learning library.
    6. Avoid velocity traps: peeking, overlapping tests, novelty, false wins.
    7. Measure program health: velocity, win rate, impact per test and learning rate.

    Module 03

    Testing Methods: A/B, Multivariate, Bandits

    Choosing the right method, factorial and multivariate designs, sample size under traffic constraints, sequential testing and bandits.

    🧪 Sample Size and Traffic Planning

    textRule of thumb (alpha 5%, power 80%): n per arm = 16 x p(1-p) / delta^2

Landing page: baseline conversion 4.0%, target MDE = +10% relative = 0.4pp absolute
  n = 16 x 0.04 x 0.96 / 0.004^2 = 16 x 0.0384 / 0.000016 = 38,400 per arm
  Traffic 3,000 visitors/day -> 76,800 / 3,000 = 25.6 days

If you can only detect +25% relative (1.0pp): n = 16 x 0.0384 / 0.0001 = 6,144 per arm -> 4.1 days
Trade-off: bigger MDE = faster test but only big wins detected.
    Traffic situationStrategy
    High trafficMany small tests, sensitive MDE
    Medium trafficFewer, bolder changes; larger MDE; CUPED
    Low trafficBig changes, qualitative research, sequential tests, pre/post with caution
    Parallel testsUse orthogonal traffic split or separate surfaces
    Figure 3.1 · Planning an A/B test

    🧩 Intermediate: Multivariate and Factorial Tests

    FactorLevel ALevel B
    HeadlineBenefit-ledFeature-led
    Hero imageProduct screenshotCustomer photo
    CTA textStart freeGet started
    text3 factors x 2 levels = 2 x 2 x 2 = 8 combinations (cells)

Full-factorial analysis: each factor level is seen by half of all users.
Main effect of headline: compare all users with benefit-led vs feature-led (4 cells vs 4 cells)
  -> needs about the same traffic as ONE A/B test (38,400 per level = 76,800 total) if no interactions matter
Interaction tests (e.g., headline x image) need much more traffic.

If you instead ran 8 separate A/B tests vs control, you would need 8 x 38,400 = 307,200 in variants alone.
Caution: too many levels (4x4x4 = 64 cells) is not feasible at normal traffic.
    Figure 3.2 · Reading a factorial test

    🎰 Intermediate: Bandits and Sequential Methods

    MethodIdeaBest forCaution
    Fixed-horizon A/BDecide at planned nClear decisions, learningWaits for end
    Sequential testingValid repeated looksFaster stops for big effectsNeeds correct method
    Thompson sampling banditAllocate to better arms over timeShort-lived promotions, many variantsBiased effect estimates; harder inference
    Contextual banditPersonalize by contextRanking and offersComplex; needs data
    Figure 3.3 · How a bandit works
    💡
    Use A/B tests when you need to learn a trustworthy effect size; use bandits when you need to earn during a short window.

    Module 06

    Statistical Pitfalls in Fast Testing

    Peeking, multiple comparisons, novelty, winner's curse, SRM, interaction effects and how to keep speed without false wins.

    ⚠️ Common Pitfalls and Fixes

    PitfallConsequenceFix
    PeekingAbout 14% false positives with 5 looks at 5% alphaFixed horizon or sequential method
    Underpowered testsMissed wins and inflated liftsPower analysis; bolder changes
    Winner's curseReported lift overstates true liftReplicate; discount; holdouts
    Many metricsSpurious winsOne primary; correct others
    Novelty effectEarly lift fadesFull weekly cycles; cohort checks
    SRMInvalid randomizationAutomatic chi-square check
    Test overlapInterferenceLayering or exclusion
    Segment fishingFalse discoveriesPre-register; label exploratory
    textWINNER'S CURSE EXAMPLE
20 tests all with true effect of +1%. Noise makes observed lifts range -2% to +4%.
If you ship only those that look significant, the average observed lift of shipped ones may be about +3%
-> you report 3%, deliver 1%. Fix: replicate big wins, run holdouts, shrink estimates.

    📉 Troubleshooting: Winner Disappears After Launch

    StepAction
    1Check implementation parity between test and production
    2Check novelty and seasonality
    3Check winner's curse and sample size
    4Compare with holdout group
    5Replicate before building on it

    ⚔️ Scenario: A Director Wants to Stop a Test Early

    Day 4 shows +8% with p = 0.03. Explain peeking, show the planned horizon and what a sequential method would require, offer to monitor guardrails daily, and agree to stop early only if the pre-set sequential boundary is crossed or guardrails fail.

    Two arms.
    60,800 / 5,000 = 12.2 days; run 14 days to cover two full weeks.

    Task 5AdvancedFactorial design
    Design a 2x2x2 landing page test and state the cell count and main-effect sample need given 38,400 per level.
    Product of levels.
    8 cells. Each factor level is seen by half the traffic; main effects need roughly 76,800 total visitors if interactions are small; interactions need more.
    Task 6AdvancedChoose the method
    A flash sale runs 3 days with 5 banner variants. A/B, factorial or bandit?
    Earn vs learn.
    A bandit: short window and many variants favor shifting traffic to the best performer. Accept less precise effect estimates; reserve A/B for learning durable effects.

    Bold changes, research.

    Module 11

    Interview Preparation

    Questions asked in Growth Product Manager interviews about experimentation, grouped by level. Draft your answer, then compare with the model answer.

    🌱 Beginner Interview Questions

    IQ1.How do you generate and prioritize hypotheses?
    Combine funnel data, replays, interviews, surveys and behavioral science to write if-then-because hypotheses, score with ICE or PIE with evidence-based confidence, and balance quick wins with bigger bets.
    IQ2.How do you increase experiment velocity without losing rigor?
    Standardize intake, templates and launch checklists, automate assignment and analysis, run layered tests, pre-register decision rules and check SRM, so speed comes from process not shortcuts.
    IQ3.A/B test or multivariate test?
    A/B for clear single changes or low traffic. Factorial or multivariate when several factors need evaluating and traffic supports the cells; main effects are efficient, interactions need more traffic.

    🛠️ Intermediate Interview Questions

    IQ4.When would you use a bandit?
    For short-lived promotions or many variants where earning matters more than precise learning, accepting biased effect estimates; use A/B when you need trustworthy effect sizes.
    IQ5.How do you run tests on low-traffic pages?
    Use bolder changes, larger MDEs, combine related changes, qualitative research, sequential testing, variance reduction and upstream tests.
    IQ6.How do you optimize a landing page?
    Research with analytics, heatmaps, replays and surveys; ensure message match, one CTA, trust, short forms and speed; prioritize tests with PIE; verify mobile.

    🚀 Advanced Interview Questions

    IQ7.What is the winner's curse?
    Selecting significant winners overstates their true effect; replicate, shrink estimates and keep holdouts.
    IQ8.What is a healthy win rate?
    Typically 20–30%. Much higher suggests weak hypotheses, peeking or biased analysis; much lower suggests poor ideas or underpowered tests.
    IQ9.How do you avoid test interference?
    Layered or orthogonal assignment, mutual exclusion for related surfaces, and tracking of overlaps.

    🏆 Expert Interview Questions

    IQ10.How do you decide when to stop a test?
    At the planned horizon or at a pre-set sequential boundary, or earlier if guardrails fail; never because p briefly dipped below 0.05.
    IQ11.How do you build an experimentation culture?
    Celebrate learning, pre-agree decision rules, publish a learning library, involve leaders and train teams on rigor.
    IQ12.Tell me about an experiment that surprised you.
    Describe hypothesis, design, unexpected result, what you learned and how it changed later decisions.
