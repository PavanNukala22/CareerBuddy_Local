    📘Fundamentals & Basics

    Before climbing the data structure mountain, you need a base camp. This section establishes the vocabulary: what DSA actually is, the programming primitives you'll use, and the mathematical lens (asymptotic analysis) we use to compare algorithms.

    1. Introduction to DSA

    What is DSA?

    A data structure is an organized way to store data. An algorithm is a finite sequence of well-defined steps to solve a problem. Together, they form the bridge between "I have a problem" and "I have an efficient program that solves it."

    Data Structures and Algorithms are two sides of the same coin.

    📌

    Real-world analogy: A library is a data structure (books organized by genre, author, ISBN). The librarian's lookup procedure ("Fiction → F → Fitzgerald → Great Gatsby") is the algorithm. Reorganize the books and the algorithm changes too.

    Programming Basics

    You can't build a house without knowing what a brick is. Before DSA, make sure these are second nature:

    • Variables & data types — int, float, char, bool, string. Know the size and range of each.
    • Control structures — if/else, for, while, switch, break, continue.
    • Functions — parameters, return values, recursion, scope.
    • Object-Oriented Programming — classes, objects, inheritance, encapsulation, polymorphism. You'll model nodes, lists, and trees as classes.
    // A "Node" — the building block of dozens of data structures
class Node {
    int data;
    Node* next;       // pointer/reference to another Node

    Node(int value) {
        data = value;
        next = nullptr;
    }
};

    2. Analysis of Algorithms

    If two algorithms solve the same problem, which is "better"? Asymptotic analysis answers this by measuring how the running time grows as input size grows — independent of hardware, language, or compiler.

    Worst, Best, and Average Case

    ⚠

    Worst Case

    Maximum operations the algorithm could ever perform. Use this for guarantees.

    ✨

    Best Case

    Minimum possible operations. Rarely useful in practice.

    📊

    Average Case

    Expected operations across all inputs. Useful when distribution is known.

    Example — Linear Search: Looking for x in an unsorted array of size n:

    • Best case: x is the first element → O(1)
    • Worst case: x is the last (or absent) → O(n)
    • Average case: x is somewhere in the middle → O(n)

    Big O, Omega (Ω), and Theta (Θ)

    These are mathematical notations for bounding growth rates:

    NotationBoundMeaningExample
    Big O — O(f(n))Upper boundAlgorithm grows at most as fast as f(n)Sorting is O(n log n)
    Omega — Ω(f(n))Lower boundAlgorithm grows at least as fast as f(n)Sorting is Ω(n)
    Theta — Θ(f(n))Tight boundAlgorithm grows exactly as fast as f(n)Merge sort is Θ(n log n)

    Growth rates compared. Anything to the right of O(n log n) gets ugly fast.

    Time vs Space Complexity

    ⏱ Time Complexity

    How the number of operations scales with input size. This determines how long your program runs.

    Goal: minimize operations.

    💾 Space Complexity

    How much extra memory the algorithm uses, beyond the input itself. Includes auxiliary arrays, recursion stack, etc.

    Goal: minimize allocation.

    ⚖️

    The classic tradeoff: Often you can save time by using more space (e.g., memoization in DP), or save space at the cost of time (e.g., recomputing instead of storing). Knowing where to land is part of the craft.

    3. Amortized Analysis

    Some operations are cheap almost every time but occasionally expensive. Amortized analysis spreads the occasional expensive cost over all the cheap ones, giving a realistic per-operation bound — not just a worst-single-call bound.

    📦 Aggregate Method

    Sum the total cost of n operations, then divide by n. Used for dynamic array doubling: n appends cost at most 1+2+4+...+n ≈ 2n total, so 2n/n = O(1) per append.

    🏦 Accounting Method

    Charge each operation a fixed "amortized cost", overcharging cheap ones to build a credit that pays for the rare expensive one. Used to prove O(1) amortized for stack-based queue implementations.

    💡

    Interview framing: if asked "why is list.append() O(1)?" in Python or vector.push_back() in C++, the precise answer is O(1) amortized — most calls are O(1), but a resize is O(n), and resizes happen exponentially less often as the array grows.

    4. The Master Theorem

    Most divide-and-conquer algorithms produce a recurrence of the form T(n) = a·T(n/b) + f(n) — split into a subproblems of size n/b, then spend f(n) combining them. The Master Theorem gives a shortcut to solve it without drawing a recursion tree every time.

    CaseConditionResultExample
    1f(n) = O(nlogba − ε)T(n) = Θ(nlogba)Binary tree traversal recurrences
    2f(n) = Θ(nlogba)T(n) = Θ(nlogba · log n)Merge Sort: T(n)=2T(n/2)+O(n) → Θ(n log n)
    3f(n) = Ω(nlogba + ε), regularity holdsT(n) = Θ(f(n))Work dominated by the "combine" step

    Worked example — Binary Search: T(n) = T(n/2) + O(1), so a=1, b=2, f(n)=O(1). Since log21 = 0 and f(n)=Θ(n⁰), this is Case 2 → T(n) = Θ(log n), matching what we already know intuitively.

    Recognizing Common Recurrences

    📊Linear Data Structures

    Data laid out in a single sequence — element after element. Linear structures are the workhorses: simple to reason about, and the foundation for almost every more complex structure you'll meet later.

    1. Arrays

    An array is a contiguous block of memory holding elements of the same type. Each element has an index — its position. Because memory is contiguous, accessing arr[i] is a single arithmetic step: base_address + i × element_size.

    An array of 7 integers. Index 3 holds the value 4.

    Basic Operations

    OperationWhat it doesTime Complexity
    Access (arr[i])Read the i-th elementO(1)
    TraversalVisit every elementO(n)
    Search (linear)Find a valueO(n)
    Insertion (at end)Append (dynamic array)O(1) amortized
    Insertion (at index)Shift elements rightO(n)
    Deletion (at index)Shift elements leftO(n)

    Static vs Dynamic Arrays

    📌 Static Array

    Size fixed at creation. Once you say int arr[10], you have exactly 10 slots — forever.

    C arrays Java int[]

    📈 Dynamic Array

    Grows automatically. When full, allocates a bigger block (usually 2×) and copies. Append is O(1) amortized.

    C++ vector Java ArrayList Python list

    2. Linked Lists

    A linked list stores elements in nodes, each pointing to the next. Memory isn't contiguous — nodes can live anywhere. The trade: slower access (O(n) to reach index k), but blazingly fast O(1) insertion/deletion at known positions.

    Each node stores data + a pointer to the next node. The last node's pointer is NULL.

    # Singly linked list node in Python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

# Build 10 -> 25 -> 7
head = Node(10)
head.next = Node(25)
head.next.next = Node(7)

    Other Types of Linked Lists

    🔗 Doubly Linked

    Each node has prev AND next pointers. Bidirectional traversal.

    🔄 Circular

    Last node's next points back to head. Useful for round-robin scheduling.

    ⚡ XOR Linked

    Stores prev XOR next in a single field — saves memory at the cost of complexity.

    3. Stacks and Queues

    Stack — LIFO

    A stack is Last-In-First-Out. Imagine a stack of plates: you can only add to or remove from the top.

    Both push and pop happen at the top — that's why stacks are LIFO.

    Operations: push(x) — add to top, pop() — remove from top, peek() — see top without removing. All O(1).

    Real uses: function call stack, undo/redo, expression evaluation, matching brackets, browser back-button history.

    Queue — FIFO

    A queue is First-In-First-Out. Like a line at a coffee shop — the first person in line is the first served.

    Add at the rear, remove from the front. Just like a real-world queue.

    Variations

    🎯 Priority Queue

    Highest-priority element comes out first, regardless of insertion order. Backed by a heap.

    🔁 Circular Queue

    Rear wraps around to position 0 when it reaches the end — efficient use of fixed memory.

    ↔️ Deque

    Double-ended queue. Insert/remove from both ends in O(1).

    4. Hashing

    Hashing maps a key (any data) to a fixed-size index in an array — letting you find, insert, and delete in average O(1). It's the magic behind dictionaries, sets, and database indexes.

    A hash function deterministically maps keys to array indices.

    Collision Handling

    What happens when two keys hash to the same index? A collision. Two main strategies:

    🔗 Chaining

    Each slot holds a linked list of all keys that hash there. Simple, handles unlimited collisions, but uses extra memory.

    🔍 Open Addressing

    If slot is full, probe for the next empty one.

    Linear probing step by 1
    Quadratic probing step by 1, 4, 9, …
    Double hashing step by hash₂(k)

    Load factor (α = n/table size) drives resizing decisions. Most implementations resize (usually double) once α passes ~0.7, keeping average-case O(1) lookups. A poorly chosen hash function that clusters keys degrades every operation to O(n) — this is why cryptographic-quality hashing matters less than uniform distribution for hash tables.

    5. Disjoint Set Union (Union-Find)

    A Union-Find (a.k.a. Disjoint Set Union, DSU) structure tracks a collection of elements split into non-overlapping sets, and answers two questions fast: "are these two elements in the same group?" and "merge these two groups." It's the backbone of Kruskal's MST, cycle detection in undirected graphs, and dynamic connectivity problems.

    Two Key Optimizations

    🛤 Path Compression

    During find(), point every visited node directly to the root. Future lookups become near-instant.

    ⚖️ Union by Rank/Size

    Always attach the smaller/shallower tree under the larger/taller one's root, keeping trees flat.

    Combined, both optimizations give an amortized time complexity of O(α(n)) per operation — where α is the inverse Ackermann function, which grows so slowly it's effectively constant (< 5) for any realistic input size.

    # Union-Find with path compression + union by rank
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])  # path compression
        return self.parent[x]

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False          # already connected — this edge forms a cycle
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        return True
    🎯

    Where interviewers use this: Number of Connected Components, Redundant Connection (cycle detection), Accounts Merge, Kruskal's MST — whenever the phrase "groups that merge over time" appears, think DSU before graphs/DFS.

    🌳Non-Linear Data Structures

    When data has hierarchy, networks, or relationships, linear sequences aren't enough. Trees, heaps, and graphs let us model the world's actual messiness — file systems, social networks, road maps, AI search spaces.

    1. Trees

    A tree is a hierarchical structure of nodes: one root at the top, branching down into children. Every node (except the root) has exactly one parent. No cycles. Think family tree, file system, HTML DOM.

    Binary Trees

    A binary tree restricts each node to at most two children — a left and a right. Simple shape, enormous power.

    A binary tree with root = 1, depth 3, and four leaves.

    Tree Traversals

    Visiting every node — but in what order?

    TraversalVisit OrderResult on tree above
    Inorder (DFS)Left → Root → Right4, 2, 8, 5, 1, 6, 3, 7
    Preorder (DFS)Root → Left → Right1, 2, 4, 5, 8, 3, 6, 7
    Postorder (DFS)Left → Right → Root4, 8, 5, 2, 6, 7, 3, 1
    Level Order (BFS)Top to bottom, left to right1, 2, 3, 4, 5, 6, 7, 8

    Binary Search Tree (BST)

    A BST adds a single rule: for every node, all values in its left subtree are smaller; all values in its right subtree are larger. That ordering enables search, insert, and delete in O(log n) — when the tree is balanced.

    In a BST, the inorder traversal always yields sorted values.

    BST Operations — How Search Works

    1. Compare target with current node's value.
    2. If equal — found.
    3. If smaller — recurse left.
    4. If larger — recurse right.
    5. If you hit a NULL — not found.
    // BST search in C++
Node* search(Node* root, int key) {
    if (root == nullptr || root->data == key)
        return root;
    if (key < root->data)
        return search(root->left, key);
    return search(root->right, key);
}

    Self-Balancing Trees

    A BST can degrade into a "linked list" if you insert sorted data — making operations O(n). Self-balancing trees automatically restructure on insert/delete to keep height ≈ log n.

    🌲 AVL Tree

    Strictly balanced: heights of left and right subtrees differ by at most 1. Faster lookups, more rotations during insertion.

    🔴⚫ Red-Black Tree

    Loosely balanced via color rules. Used in Java's TreeMap, C++'s std::map, Linux kernel's CFS scheduler.

    2. Heaps

    A heap is a complete binary tree that satisfies the heap property:

    • Max-Heap: every parent ≥ its children. Root holds the max.
    • Min-Heap: every parent ≤ its children. Root holds the min.

    Heap property holds along every path from root to leaf.

    Applications

    • Priority Queue — extract-min/max in O(log n).
    • Heap Sort — sort in O(n log n) with O(1) extra space.
    • Top-K problems — keep a min-heap of size K.
    • Dijkstra & Prim — graph algorithms use heaps for efficient minimum extraction.

    3. Graphs

    A graph is a set of vertices (nodes) connected by edges. Edges may be directed or undirected, weighted or unweighted. Graphs model anything with relationships: friends, websites, cities, courses, atoms.

    Vertices A–F connected by weighted edges.

    Representation

    📋 Adjacency Matrix

    An n × n matrix where matrix[i][j] = 1 if there's an edge from i to j.

    Pros: O(1) edge lookup. Cons: O(n²) space — wasteful for sparse graphs.

    📝 Adjacency List

    For each vertex, a list of its neighbors.

    Pros: O(V + E) space — perfect for sparse graphs. Cons: O(degree) edge lookup.

    # Adjacency list in Python
graph = {
    "A": ["B", "D"],
    "B": ["A", "C", "E"],
    "C": ["B", "E", "F"],
    "D": ["A", "E"],
    "E": ["B", "C", "D", "F"],
    "F": ["C", "E"]
}

    Traversals: BFS & DFS

    🌊 Breadth-First Search

    Explore neighbors first, then their neighbors. Uses a queue. Finds shortest path in unweighted graphs.

    Order from A: A → B → D → C → E → F

    🔦 Depth-First Search

    Go as deep as possible, then backtrack. Uses a stack (or recursion). Used for cycle detection, topological sort, connected components.

    Order from A: A → B → C → E → D → F

    BFS spreads level-by-level; DFS plunges down one branch first.

    4. Tries (Prefix Trees)

    A trie stores strings by sharing common prefixes along root-to-node paths. Each node represents one character; a path from the root spells a prefix, and a marked "end of word" flag confirms a complete word. Lookup, insert, and prefix search all run in O(L), where L is the word's length — independent of how many other words are stored.

    Purple nodes (marked *) are word endings. "car" and "card" share the c→a→r path.

    class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.is_end = True

    def search(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                return False
            node = node.children[ch]
        return node.is_end

    Used for: autocomplete, spell-checkers, IP routing (longest prefix match), and word search puzzles where many prefixes are checked repeatedly.

    5. Segment Tree & Fenwick Tree (BIT)

    Arrays are fast to read but slow to answer range questions ("sum of index 3 to 87?") after updates — recomputing each time is O(n) per query. Both structures below answer range queries and point updates in O(log n), trading a bit of memory and complexity for that speed.

    🌲 Segment Tree

    A binary tree where each node stores the aggregate (sum, min, max, gcd…) of a range. Leaves are single elements; each internal node combines its two children. Supports range updates with lazy propagation.

    Build: O(n)   Query/Update: O(log n)   Space: O(n)

    🎯 Fenwick Tree (BIT)

    A compact array-based structure using the binary representation of indices to maintain prefix sums. Simpler to code than a segment tree, but limited to invertible operations like sum (not min/max).

    Query/Update: O(log n)   Space: O(n), no extra tree nodes

    # Fenwick Tree (Binary Indexed Tree) — 1-indexed
class BIT:
    def __init__(self, n):
        self.tree = [0] * (n + 1)

    def update(self, i, delta):
        while i < len(self.tree):
            self.tree[i] += delta
            i += i & (-i)              # move to next responsible index

    def prefix_sum(self, i):
        total = 0
        while i > 0:
            total += self.tree[i]
            i -= i & (-i)              # move to parent range
        return total
    🎯

    Decision rule for interviews: "range sum + point update" → Fenwick Tree (less code). "range min/max, GCD, or range updates" → Segment Tree (more flexible). Both beat a plain prefix-sum array the moment updates are involved.

    ⚡Algorithms & Paradigms

    Data structures hold the data. Algorithms move it, sort it, search it, and combine it. This section covers the canonical operations and the high-level paradigms that frame them.

    1. Searching

    Linear Search

    Walk through every element. Simple, works on any data.

    Time: O(n)   Space: O(1)

    Binary Search

    Requires sorted data. Repeatedly halve the search range. Beats linear search by an exponential margin.

    9 elements, found in 3 steps. Linear search would have taken up to 9.

    Time: O(log n)   Space: O(1)

    These sidestep the O(n log n) lower bound by exploiting the structure of the data:

    🔢 Counting Sort

    Count occurrences of each value. Works for small integer ranges. O(n + k)

    📐 Radix Sort

    Sort digit by digit (LSD or MSD). Works for fixed-width keys. O(d × n)

    🪣 Bucket Sort

    Distribute into buckets, sort each, concatenate. Works when input is uniformly distributed.

    3. Algorithm Paradigms

    Recursion & Backtracking

    A function that calls itself, with two essentials:

    • Base case — when to stop.
    • Recursive case — break the problem into a smaller subproblem and combine.
    # Classic: factorial
def factorial(n):
    if n <= 1:           # base case
        return 1
    return n * factorial(n - 1)   # recursive case

    Backtracking = recursion + "if this branch fails, undo and try another." It's how you explore all configurations efficiently.

    Classic backtracking problems

    • N-Queens — place N queens on an N×N board with no two attacking each other.
    • Sudoku Solver — fill the grid satisfying row/column/box rules.
    • Subset/Permutation generation — produce all valid arrangements.

    Greedy Algorithms

    At each step, make the choice that looks best locally, hoping it builds up to a global optimum. Greedy works when the problem has the greedy choice property.

    ⚠️

    Greedy doesn't always work! Coin change with denominations {1, 5, 10, 25} → greedy gives optimal answer. But with {1, 3, 4} and target 6, greedy gives 4+1+1 = 3 coins, while optimal is 3+3 = 2 coins.

    Famous greedy algorithms

    • Huffman Coding — optimal prefix codes for compression.
    • Dijkstra's Algorithm — shortest path from a single source.
    • Activity Selection — schedule the most non-overlapping events.
    • Kruskal's / Prim's — minimum spanning tree.

    Dynamic Programming (DP)

    DP solves problems with two properties:

    • Overlapping subproblems — the same smaller problems are solved repeatedly.
    • Optimal substructure — the optimal answer can be built from optimal answers to subproblems.

    DP caches subproblem answers to avoid recomputation.

    DP turns exponential recursion into linear time by caching results.

    Two DP styles

    ⬇️ Memoization (Top-Down)

    Recursion + cache. Solve the big problem; sub-calls check the cache before recomputing. Natural to write.

    ⬆️ Tabulation (Bottom-Up)

    Iteratively fill a table from the smallest subproblem up. No recursion overhead. Often more efficient.

    5. Greedy Algorithms — Deeper Dive

    Building on the greedy intro above: a greedy algorithm builds a solution piece by piece, always choosing the option that looks best right now, never reconsidering earlier choices. It's fast (usually O(n log n) from sorting) but only produces the true optimum when the problem has two properties:

    • Greedy-choice property: a locally optimal choice leads to a globally optimal solution.
    • Optimal substructure: an optimal solution contains optimal solutions to subproblems.
    ProblemGreedy RuleWhy it works
    Activity SelectionPick the activity that finishes earliestLeaves maximum room for future activities
    Fractional KnapsackTake items by highest value/weight ratio firstDivisibility means no benefit to holding back
    Huffman CodingMerge the two lowest-frequency nodes firstMinimizes weighted path length (encoded size)
    Dijkstra's AlgorithmAlways expand the closest unvisited nodeNon-negative weights guarantee no shorter path appears later
    ⚠️

    Classic trap: 0/1 Knapsack (items can't be split) is not solvable greedily — the best-ratio item might not fit, and a locally worse choice can be globally better. That's precisely why 0/1 Knapsack needs DP while Fractional Knapsack doesn't.

    6. Backtracking

    Backtracking explores a decision tree of candidate solutions, abandoning ("pruning") a branch the moment it's clear it can't lead to a valid answer. It's exhaustive search made efficient by cutting off dead ends early.

    # N-Queens — place N queens so none attack each other
def solve_n_queens(n):
    results = []
    cols, diag1, diag2 = set(), set(), set()
    placement = []

    def backtrack(row):
        if row == n:
            results.append(placement[:])
            return
        for col in range(n):
            if col in cols or (row-col) in diag1 or (row+col) in diag2:
                continue            # prune — this column/diagonal is attacked
            cols.add(col); diag1.add(row-col); diag2.add(row+col)
            placement.append(col)
            backtrack(row + 1)
            cols.remove(col); diag1.remove(row-col); diag2.remove(row+col)  # undo — backtrack!
            placement.pop()

    backtrack(0)
    return results

    Recognize it by the shape: "choose → explore → un-choose". Common targets: N-Queens, Sudoku Solver, Subsets/Permutations/Combinations, Word Search on a grid, Palindrome Partitioning.

    7. Advanced Dynamic Programming Patterns

    Bitmask DP

    When a subproblem depends on which subset of a small set (n ≤ ~20) has been used — not just how many — encode the subset as an integer bitmask and use it as a dimension of the DP state: dp[mask][i] = best answer having visited the cities in mask, currently at city i. Classic use: Travelling Salesman Problem, reducing brute force O(n!) to O(n² · 2ⁿ).

    DP on Trees

    Run a post-order DFS so each node's DP value is computed after its children's. Typical state: dp[node][0] = best answer excluding this node, dp[node][1] = best answer including it. Classic problem: House Robber III (can't rob two directly-connected houses in a tree-shaped neighborhood) — combine children's "excluded" and "included" values at each step.

    Digit DP

    Counts numbers in a range [1, N] satisfying a digit property (e.g., "sum of digits ≤ K") by processing digits one at a time with a state of (position, tight-bound flag, running property), instead of iterating every number individually. Turns an O(N) scan into O(digits × states).

    8. Advanced Graph Algorithms

    Strongly Connected Components (Tarjan's / Kosaraju's)

    In a directed graph, a strongly connected component (SCC) is a maximal group of vertices where every vertex can reach every other. Tarjan's algorithm finds all SCCs in a single DFS pass using discovery times and "low-link" values — O(V + E), no second pass needed. Kosaraju's algorithm is simpler to reason about: DFS once for finish order, reverse all edges, DFS again in that order.

    Topological Sort

    A linear ordering of vertices in a Directed Acyclic Graph (DAG) such that every edge u→v has u appearing before v. Used for build systems, course prerequisites, task scheduling.

    🔦 DFS-based

    Run DFS; push each node to a stack when it finishes (post-order). Reverse the stack for the topological order.

    📊 Kahn's Algorithm (BFS-based)

    Repeatedly remove nodes with in-degree 0, decrementing their neighbors' in-degree. If fewer than V nodes get removed, the graph has a cycle.

    💼Interview Corner

    A field guide to the questions that actually show up in technical interviews. Each entry has the why, the answer, and a follow-up trap. Click any question to expand.

    📋

    Interview tip: Always state the brute-force solution first ("we could check every pair, that's O(n²)…"). Then optimize. Interviewers want to see the thinking, not just the answer. Talk through edge cases — empty input, single element, duplicates, overflow.

    Conceptual Questions

    1. What's the difference between an Array and a Linked List?

    Memory layout: Arrays are contiguous; linked lists are scattered nodes connected by pointers.

    Access: Array arr[i] is O(1); linked list requires traversing — O(n).

    Insertion/deletion: Array at arbitrary position is O(n) (must shift). Linked list at known node is O(1).

    Memory: Linked list uses extra space per node for pointers.

    Cache-friendliness: Arrays win — contiguous memory plays nicely with CPU caches.

    2. Explain Big O, Theta, and Omega.

    They are bounds on growth rate as input size n → ∞.

    • O(f(n)) — upper bound. f(n) is at most this fast.
    • Ω(f(n)) — lower bound. f(n) is at least this fast.
    • Θ(f(n)) — tight bound. f(n) grows exactly this fast (both upper and lower).

    In interviews, "complexity" almost always means Big O of the worst case.

    3. Stack vs Queue — when do you use each?

    Stack (LIFO): when the last thing in needs to be the first thing out — function calls, undo history, expression parsing, depth-first traversal.

    Queue (FIFO): when order of arrival matters — scheduling, BFS traversal, message buffers, request handling.

    4. What is a hash collision and how do you handle it?

    A collision happens when two distinct keys hash to the same index. Two main strategies:

    • Chaining — store all colliding keys in a linked list at that index.
    • Open addressing — probe the next available slot. Variants: linear probing (i+1), quadratic (i+1, i+4, …), double hashing.

    Follow-up: Why is load factor important? Beyond ~0.7, performance degrades — that's when most implementations resize and rehash.

    5. BFS vs DFS — when to use which?

    BFS — level-order, uses a queue. Best for shortest path in unweighted graphs, finding closest match, web crawlers (with depth cap).

    DFS — uses recursion or stack. Best for: cycle detection, topological sort, connected components, exhaustively exploring a tree (e.g., backtracking).

    Memory: BFS uses O(width); DFS uses O(depth). Pick the smaller one for your graph shape.

    6. What are overlapping subproblems and optimal substructure?

    These are the two prerequisites for Dynamic Programming.

    Overlapping subproblems — the recursion solves the same subproblem multiple times (Fibonacci is the textbook example).

    Optimal substructure — the optimal solution to the big problem is built from optimal solutions to its subproblems (shortest path: shortest A→C through B = shortest A→B + shortest B→C).

    7. What's the difference between a Binary Tree and a Binary Search Tree?

    A binary tree is any tree where each node has ≤ 2 children. No ordering rule.

    A BST is a binary tree with the property: for every node, all left descendants < node < all right descendants. This ordering enables O(log n) search/insert/delete (when balanced).

    8. Heap vs BST — both are tree-based, what's the difference?

    Heap: only the parent-child relationship is constrained (parent ≥ children for max-heap). Siblings are unordered. Optimized for finding min/max in O(1).

    BST: full left-right ordering. Optimized for searching arbitrary values in O(log n).

    If you only ever care about the extreme value, use a heap. If you need to find arbitrary values, use a BST.

    9. What is recursion and when should you avoid it?

    Recursion is a function calling itself with smaller subproblems until reaching a base case.

    Avoid when: Recursion depth could blow the stack (very deep trees, large n with no tail-call optimization). In that case, convert to iteration with an explicit stack/queue.

    Tradeoff: Recursion is often more readable; iteration is often more efficient.

    10. What's amortized time complexity? Give an example.

    Amortized = average cost per operation across a long sequence of operations, even if individual operations are sometimes expensive.

    Classic example: appending to a dynamic array (Python list, C++ vector). Most appends are O(1), but occasionally the array fills up and must double in size (O(n) copy). Spread across n appends, total work is O(n), so each append is amortized O(1).

    Coding Questions

    11. Reverse a linked list. 
    # Iterative — O(n) time, O(1) space
def reverse(head):
    prev = None
    curr = head
    while curr:
        nxt = curr.next
        curr.next = prev
        prev = curr
        curr = nxt
    return prev

    Trick: rotate three pointers (prev, curr, nxt) one step at a time.

    12. Detect a cycle in a linked list.

    Use Floyd's tortoise-and-hare: two pointers, one moves 1 step, the other moves 2. If there's a cycle, they will eventually meet. If the fast pointer hits NULL, no cycle.

    def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow == fast:
            return True
    return False
    13. Find the kth largest element in an array.

    Three approaches with increasing sophistication:

    • Sort + index: O(n log n) time, easy.
    • Min-heap of size k: O(n log k) time, smart.
    • Quickselect: O(n) average time, very smart. Use partition from quicksort but only recurse on the side containing kth.
    14. Implement a Least Recently Used (LRU) Cache.

    Combine a hash map (O(1) lookup) with a doubly linked list (O(1) move-to-front and remove-from-end). When you access a key, move its node to the head. When the cache is full, evict the tail.

    This is one of the most common system-design-flavored coding questions.

    15. Find the longest palindromic substring.

    Expand around center approach: for each index, try expanding outward as long as left == right. Handle both odd-length (single center) and even-length (two centers). O(n²) time, O(1) space.

    Manacher's algorithm achieves O(n) but is rarely required in interviews.

    16. Validate a Binary Search Tree.

    Wrong approach: only checking each node against its immediate children. A node's left child can be smaller, but a deeper descendant could violate the BST property.

    Right approach: pass down min and max bounds. Each node must satisfy min < node.val < max, then recurse with updated bounds.

    17. Implement a queue using two stacks.

    Stack in for enqueue; Stack out for dequeue. When you dequeue and out is empty, pop everything from in and push to out — this reverses order. Amortized O(1) per operation.

    18. Find all permutations of an array. 
    def permute(nums):
    result = []
    def backtrack(path, remaining):
        if not remaining:
            result.append(path[:])
            return
        for i in range(len(remaining)):
            path.append(remaining[i])
            backtrack(path, remaining[:i] + remaining[i+1:])
            path.pop()
    backtrack([], nums)
    return result

    Classic backtracking. There are n! permutations, so any solution is at least O(n × n!).

    19. Word Break — can a string be split into dictionary words?

    DP: let dp[i] = "can s[0:i] be segmented?". dp[0] = True. For each i, try every j < i: if dp[j] AND s[j:i] in dict, set dp[i] = True.

    O(n²) time with O(1) substring check via a set.

    20. Detect a cycle in a directed graph.

    DFS with three colors: WHITE (unvisited), GRAY (in current path), BLACK (fully done). If you encounter a GRAY node during DFS, you've found a back edge — a cycle.

    Alternatively, run topological sort (Kahn's algorithm). If the result has fewer nodes than the graph, there's a cycle.

    C++ starter — Two Sum with hash map

    #include <vector>
#include <unordered_map>
using namespace std;

vector<int> twoSum(vector<int>& nums, int target) {
    unordered_map<int, int> seen;
    for (int i = 0; i < nums.size(); ++i) {
        int need = target - nums[i];
        if (seen.count(need))
            return {seen[need], i};
        seen[nums[i]] = i;
    }
    return {};
}

public int[] twoSum(int[] nums, int target) {
