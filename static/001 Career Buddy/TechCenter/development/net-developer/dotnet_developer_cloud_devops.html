    Cloud & Azure Foundations

    Start from zero: what the cloud is, the service models, and how Azure is organised.

    ☁️ What is Cloud Computing?

    Cloud computing means renting computing resources (servers, storage, databases, networking) over the internet and paying only for what you use, instead of buying and running your own hardware.

    🔴 On-premises

    Buy servers upfront, wait weeks for setup, patch and power them yourself, over-provision for peak load.

    🟢 Cloud

    Create resources in minutes, scale up or down on demand, pay per use, provider manages the hardware.

    🧱 Service Models and Deployment Types

    ModelYou manageProvider managesAzure example
    IaaS (Infrastructure)OS, runtime, app, dataHardware, virtualisation, networkVirtual Machines
    PaaS (Platform)App code and dataOS, runtime, scaling, patchingApp Service, Azure SQL
    FaaS / ServerlessFunction code onlyEverything else, incl. scaling to zeroAzure Functions
    SaaS (Software)Just use itEverythingMicrosoft 365, Azure DevOps Services

    Deployment types: Public shared provider infrastructure, Private dedicated to one organisation, Hybrid a mix of both.

    🏛️ How Azure is Organised

    Everything you create lives inside a resource group, inside a subscription, inside a tenant.
    RegionA geographic location with datacenters, e.g. Central India, West Europe.
    Availability ZonePhysically separate datacenters inside one region for high availability.
    Resource GroupContainer for resources that share a lifecycle; deleting the group deletes everything in it.
    ARMAzure Resource Manager, the deployment and management layer behind Portal, CLI and templates.
    BicepDeclarative Infrastructure as Code language that compiles to ARM templates.
    Managed IdentityAn Entra ID identity for an Azure resource so code needs no stored passwords.

    🌐 What is App Service?

    Azure App Service is a fully managed PaaS for hosting web apps, REST APIs and mobile backends. It supports .NET, Java, Node.js, Python and containers, and handles OS patching, load balancing and scaling for you.

    App Service PlanThe compute (VM size, region, OS, instance count) your apps run on. You pay for the plan, and several apps can share one.
    Web AppYour application running inside a plan.
    Deployment SlotA live staging copy of your app with its own URL, used for zero-downtime releases.
    Kudu / SCMAdvanced tools site at yourapp.scm.azurewebsites.net for logs and deployments.

    📦 Plan Tiers (Types)

    TierBest forNotable features
    Free / SharedLearning, demosShared CPU, quotas, no SLA
    BasicDev / testDedicated VMs, manual scale, custom domains
    StandardProduction starterAutoscale, deployment slots, daily backups
    Premium (v3 and newer)Production at scaleFaster hardware, more slots, VNet integration, zone redundancy
    Isolated v2Compliance, isolationDedicated App Service Environment inside your virtual network

    🚀 Create and Deploy a .NET App (Practice)

    EXAMPLE · First deployment with Azure CLI

    Create a plan and web app, then deploy a published .NET app as a zip.

    azure cliaz group create -n rg-web -l centralindia
az appservice plan create -n plan-web -g rg-web --sku B1
az webapp create -n mywebapp-demo123 -g rg-web -p plan-web --runtime "dotnet:8"
dotnet publish -c Release -o ./publish
cd publish && zip -r ../app.zip . && cd ..
az webapp deploy -n mywebapp-demo123 -g rg-web --src-path app.zip --type zip

    App names must be globally unique because they become name.azurewebsites.net.

    ⚙️ Configuration, Slots and Scaling (Intermediate)

    App settings are injected as environment variables and override appsettings.json. Use a double underscore for nested keys.

    azure cliaz webapp config appsettings set -n mywebapp-demo123 -g rg-web \
  --settings ConnectionStrings__Default="..." Logging__LogLevel__Default=Warning

    Zero-downtime release with slots

    azure cliaz webapp deployment slot create -n mywebapp-demo123 -g rg-web --slot staging
# deploy to staging, test on its URL, then swap
az webapp deployment slot swap -n mywebapp-demo123 -g rg-web --slot staging --target-slot production
    ScalingWhat it doesWhen to use
    Scale upBigger VM size (more CPU/RAM)App is CPU or memory bound
    Scale outMore instances behind the load balancerHigh traffic, needs availability
    AutoscaleRules on CPU, memory or scheduleVariable load, cost control
    💡
    Mark settings like connection strings as slot settings so they stay with the slot and are not swapped into production.

    🔐 Security and Operations (Expert)

    • Managed identity + Key Vault references: set an app setting to @Microsoft.KeyVault(SecretUri=...) so secrets never appear in config or source.
    • VNet integration and private endpoints: reach private databases and block public inbound traffic.
    • Health checks: configure a health check path so unhealthy instances are removed from rotation.
    • Observability: enable Application Insights and alert on failure rate and response time.
    • Always On keeps the app loaded (Basic and above); disable ARR affinity for stateless APIs.
    csharpvar builder = WebApplication.CreateBuilder(args);
builder.Services.AddApplicationInsightsTelemetry();
builder.Services.AddHealthChecks();
var app = builder.Build();
app.MapHealthChecks("/health");   // point the App Service health check here
app.Run();

    ❓ Interview Questions

    App Service vs Virtual Machine?
    App Service is PaaS: Azure manages OS, patching and scaling. A VM is IaaS with full control but more operational work.
    How do you do a zero-downtime deployment?
    Deploy to a staging slot, warm it up, validate, then swap. Revert by swapping back.
    Scale up vs scale out?
    Up = bigger instance; out = more instances. Stateless apps scale out best.

    Azure Functions

    Event-driven serverless code in C#: triggers, bindings, hosting plans, Durable Functions and production patterns.

    0 / 0 correct

    ⚡ What is Azure Functions?

    Azure Functions is a serverless compute service: you write small pieces of code that run in response to an event (HTTP call, timer, queue message, new blob) and Azure handles servers and scaling. You pay for execution, and several plans scale to zero when idle.

    Function AppThe hosting unit that groups functions sharing settings and scale.
    TriggerWhat starts a function. Exactly one per function.
    BindingDeclarative input or output connection to another service, so you write less plumbing code.
    Isolated worker modelRecommended .NET model where functions run in their own process; the older in-process model is being retired.
    Cold startDelay when a new instance starts after being idle.

    🔔 Triggers and Bindings (Types)

    TriggerFires whenTypical use
    HTTPA request arrivesAPIs, webhooks
    TimerA CRON schedule hitsNightly jobs, cleanup
    BlobA blob is created or updatedImage processing, imports
    Queue / Service BusA message arrivesBackground work, decoupling
    Event Grid / Event HubsAn event or stream arrivesReacting to Azure events, telemetry
    Cosmos DBA document changesChange feed processing

    🧪 Your First Functions (Practice)

    EXAMPLE · HTTP trigger

    Isolated worker model with ASP.NET Core integration, .NET 8.

    csharppublic class HelloFunction(ILogger<HelloFunction> log)
{
    [Function("Hello")]
    public IActionResult Run(
        [HttpTrigger(AuthorizationLevel.Function, "get", "post")] HttpRequest req)
    {
        var name = req.Query["name"].ToString();
        log.LogInformation("Hello called for {Name}", name);
        return new OkObjectResult($"Hello, {(string.IsNullOrEmpty(name) ? "world" : name)}!");
    }
}
    EXAMPLE · Blob trigger with a blob output binding

    When a file lands in uploads, write a processed copy to processed.

    csharppublic class ProcessImage
{
    [Function("ProcessImage")]
    [BlobOutput("processed/{name}", Connection = "StorageConn")]
    public byte[] Run(
        [BlobTrigger("uploads/{name}", Connection = "StorageConn")] byte[] data, string name)
    {
        // transform data here
        return data;
    }
}

    🧠 Durable Functions and Production Patterns (Expert)

    Durable Functions add stateful workflows to serverless code. An orchestrator coordinates activity functions and survives restarts.

    PatternIdea
    Function chainingRun steps A → B → C in order
    Fan-out / fan-inRun many tasks in parallel, then aggregate
    Human interactionWait for an approval event with a timeout
    MonitorPoll until a condition is met
    csharp[Function("OrderOrchestrator")]
public static async Task<string> Run([OrchestrationTrigger] TaskOrchestrationContext ctx)
{
    var id = ctx.GetInput<string>();
    await ctx.CallActivityAsync("ReserveStock", id);
    await ctx.CallActivityAsync("TakePayment", id);
    return await ctx.CallActivityAsync<string>("SendReceipt", id);
}

    Production checklist

    • Idempotency: queue triggers can deliver a message more than once, so handlers must be safe to repeat.
    • Retries and poison messages: configure retry policies and monitor poison queues or dead-letter queues.
    • Dependency injection: register HttpClient and services in Program.cs; never create a new client per call.
    • Identity-based connections: use managed identity instead of connection strings where supported.
    • Observability: Application Insights, structured logging and failure alerts.

    ❓ Interview Questions

    Function vs Web API on App Service?
    Functions are event-driven and scale to zero, ideal for short background tasks. App Service suits always-on web apps with many routes.
    Trigger vs binding?
    A trigger starts the function; bindings are optional declarative inputs and outputs.
    When use Durable Functions?
    For multi-step, long-running or human-approval workflows that need reliable state.

    Azure Blob Storage

    Store files and unstructured data at scale: tiers, redundancy, access control and .NET SDK usage.

    0 / 0 correct

    🗄️ What is Blob Storage?

    Blob Storage is Azure's object storage for unstructured data such as images, videos, documents, backups and logs. Data is organised as storage account → container → blob.

    Storage AccountTop-level namespace with a unique name; defines region, performance and redundancy.
    ContainerA folder-like group of blobs; access is configured here.
    BlobThe object itself plus metadata.
    SAS tokenShared Access Signature: a time-limited, permission-scoped URL for delegated access.

    🧩 Types, Tiers and Redundancy

    Blob types

    TypeUse
    Block blobFiles, media, documents (most common)
    Append blobLogs; only appends allowed
    Page blobRandom read/write, VM disks

    Access tiers

    TierStorage costAccess costUse
    HotHighestLowestFrequently accessed
    CoolLowerHigherInfrequent (30+ days)
    ColdLower stillHigherRare (90+ days)
    ArchiveLowestHighest; hours to rehydrateLong-term retention (180+ days)

    Redundancy

    OptionCopiesProtects against
    LRS3 in one datacenterHardware failure
    ZRS3 across zonesDatacenter failure
    GRSLRS + secondary regionRegional outage
    GZRSZRS + secondary regionZone and regional failure

    💻 Using Blobs from .NET (Practice)

    EXAMPLE · Upload, list and download

    Install Azure.Storage.Blobs and Azure.Identity. DefaultAzureCredential uses your developer login locally and managed identity in Azure.

    csharpvar service = new BlobServiceClient(
    new Uri("https://mystorageacct.blob.core.windows.net"),
    new DefaultAzureCredential());

var container = service.GetBlobContainerClient("documents");
await container.CreateIfNotExistsAsync();

// Upload
var blob = container.GetBlobClient("reports/2026/q1.pdf");
await using var fs = File.OpenRead("q1.pdf");
await blob.UploadAsync(fs, overwrite: true);

// List
await foreach (var item in container.GetBlobsAsync(prefix: "reports/"))
    Console.WriteLine(item.Name);

// Download
await blob.DownloadToAsync("copy.pdf");

    🔑 Access Control and Lifecycle (Intermediate)

    MethodHow it worksRecommendation
    Microsoft Entra ID + RBACIdentity-based roles such as Storage Blob Data ReaderPreferred
    User delegation SASSAS signed with Entra credentialsFor temporary client access
    Service / Account SASSAS signed with the account keyUse sparingly, short expiry
    Account keyFull-control secret keyAvoid; disable shared key access when possible
    csharp// Time-limited read link. In production prefer a user delegation SAS
// (BlobServiceClient.GetUserDelegationKeyAsync + BlobSasBuilder).
var uri = blob.GenerateSasUri(BlobSasPermissions.Read, DateTimeOffset.UtcNow.AddMinutes(15));

    Lifecycle management rules move or delete blobs automatically, e.g. Hot → Cool after 30 days, Archive after 180, delete after 7 years.

    🛡️ Data Protection and Scale (Expert)

    • Soft delete and versioning: recover deleted or overwritten blobs and containers.
    • Immutable storage (WORM): time-based retention or legal hold for compliance.
    • Private endpoints + firewall: remove public network access; combine with managed identity.
    • Large uploads: use BlobUploadOptions.TransferOptions for parallel block uploads and stream instead of buffering.
    • Event-driven: Event Grid BlobCreated events trigger Functions more reliably at scale than polling.
    • Static websites: serve a SPA from the $web container, fronted by Azure CDN or Front Door.

    ❓ Interview Questions

    Blob vs File vs Queue vs Table storage?
    Blob: objects. Files: SMB/NFS file shares. Queue: simple messaging. Table: NoSQL key-attribute data.
    How do you give a browser temporary upload access?
    Generate a short-lived user delegation SAS scoped to one blob with write permission only.
    How do you cut storage costs?
    Lifecycle rules, correct tiering, and deleting old versions and snapshots.

    🔄 What is Azure DevOps?

    DevOps is a culture and set of practices that unite development and operations to deliver software faster and more reliably. Azure DevOps is Microsoft's toolset to support that lifecycle.

    📋
    Boards
    Work items, Kanban, sprints, backlogs.
    📁
    Repos
    Git repositories, pull requests, branch policies.
    🚀
    Pipelines
    CI/CD builds and deployments in YAML.
    🧪
    Test Plans
    Manual and exploratory testing.
    📦
    Artifacts
    NuGet, npm and other package feeds.
    CIContinuous Integration: every commit is built and tested automatically.
    CDContinuous Delivery/Deployment: validated builds are released automatically or after approval.
    IaCInfrastructure as Code: environments defined in versioned files (e.g. Bicep).

    🧭 Pipeline Concepts (Types)

    ConceptMeaning
    PipelineAutomated workflow defined in azure-pipelines.yml
    StageMajor phase: Build, Test, Deploy
    JobSet of steps that runs on one agent
    Step / TaskA script or prebuilt task
    Agent / PoolMachine that runs jobs: Microsoft-hosted or self-hosted
    EnvironmentDeployment target with approvals and checks
    Service connectionStored identity used to reach Azure

    🧱 YAML pipelines

    Versioned with code, reviewable, supports multi-stage CI/CD. Recommended.

    🖱️ Classic pipelines

    Visual editor with separate build and release definitions. Legacy for new work.

    🛠️ Build Your First CI/CD Pipeline (Practice)

    EXAMPLE · Build, test, publish and deploy a .NET web app to App Service

    Commit this file as azure-pipelines.yml, then create a pipeline from it in Azure DevOps.

    yamltrigger:
  branches: { include: [ main ] }

pool:
  vmImage: ubuntu-latest

variables:
  buildConfiguration: Release

stages:
- stage: Build
  jobs:
  - job: BuildTest
    steps:
    - task: UseDotNet@2
      inputs: { packageType: sdk, version: 8.x }
    - script: dotnet restore
    - script: dotnet build --configuration $(buildConfiguration) --no-restore
    - script: dotnet test --configuration $(buildConfiguration) --no-build
    - script: dotnet publish src/WebApp -c $(buildConfiguration) -o $(Build.ArtifactStagingDirectory)
    - publish: $(Build.ArtifactStagingDirectory)
      artifact: drop

- stage: DeployProd
  dependsOn: Build
  jobs:
  - deployment: Deploy
    environment: production        # approvals and checks live on the environment
    strategy:
      runOnce:
        deploy:
          steps:
          - task: AzureWebApp@1
            inputs:
              azureSubscription: sc-azure-prod   # service connection
              appName: mywebapp-demo123
              package: $(Pipeline.Workspace)/drop/**/*.zip

    🔧 Branching, Quality and Variables (Intermediate)

    • Branch policies: require pull requests, reviewers, a passing build and linked work items before merging to main.
    • Branching strategies: trunk-based (short-lived branches, fast) or GitFlow (release branches, slower).
    • Variables: pipeline variables, variable groups in the Library (can link to Key Vault), and secret variables masked in logs.
    • Tests and caching: publish test results and code coverage; cache NuGet packages to speed up builds.
    yamlvariables:
- group: webapp-prod           # variable group
- name: buildConfiguration
  value: Release

# Run a step only on main
- script: echo "Deploying"
  condition: eq(variables['Build.SourceBranch'], 'refs/heads/main')

    🏆 Secure, Scalable Delivery (Expert)

    • Workload identity federation: create the Azure service connection with federated credentials so there is no client secret to rotate.
    • Environments with checks: manual approvals, branch control and business-hours gates.
    • YAML templates: extract shared build/deploy steps into reusable templates, enforced across teams.
    • Infrastructure as Code in the pipeline: deploy Bicep before the app and use what-if to preview changes.
    • Release strategies: slots + swap, canary, blue-green; roll back on failed health checks.
    • Security scanning: dependency, secret and static analysis as pipeline gates.
    • Self-hosted or scale-set agents when you need private network access or custom tooling.

  inputs:
    azureSubscription: sc-azure-prod

    scriptLocation: inlineScript

    🛒 Scenario: Contoso Orders

    Contoso has an ASP.NET Core Orders API. Customers upload invoice PDFs, and each upload must be processed and a summary stored. The team wants automated builds, a staging environment and zero-downtime releases.

    1️⃣ Task 1 · Architecture

    ✍️ Which Azure services would you choose for the API, the invoice processing and the file storage, and why?
    Model answer: API: App Service (Standard or higher for slots). Processing: Azure Functions with a Blob/Event Grid trigger so it scales with uploads and costs little when idle. Storage: Blob Storage with a private container, Hot tier then lifecycle to Cool/Archive. Use managed identities between all three.

    2️⃣ Task 2 · Security

    Q. How should the API let a browser upload an invoice directly to Blob Storage?
    • A Embed the account key in JavaScript
    • B Return a short-lived user delegation SAS scoped to one blob
    • C Make the container public
    • D Email the file
    ✍️ List 3 ways to secure secrets and network access.
    Model answer: Managed identity with RBAC instead of keys; Key Vault references for remaining secrets; private endpoints or storage firewall with App Service VNet integration; disable shared key access.

    3️⃣ Task 3 · Pipeline

    ✍️ Describe the stages and checks of the CI/CD pipeline.
    Model answer: Build stage: restore, build, unit tests, publish artifact. Deploy to a staging slot, run smoke tests, then the production environment with manual approval and slot swap. Branch policy requires PR + passing build on main. Federated service connection, no stored secrets.

    4️⃣ Task 4 · Reliability and Cost

    Q. The function sometimes processes the same invoice twice. Best fix?
    • A Ignore it
    • B Make the handler idempotent (e.g. check a processed marker keyed by blob name/ETag)
    • C Delete the queue
    • D Switch to the Free plan
    Q. Invoices older than 1 year are rarely read but must be kept 7 years. What helps most?
    • A Delete them
    • B Lifecycle rule moving to Cool then Archive
    • C Keep all in Hot
    • D Copy to a laptop
