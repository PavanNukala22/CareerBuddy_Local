    Module 01

    What is Data Access & Storage?

    Start from zero: how .NET applications talk to databases, the types of approaches, and the vocabulary you need.

    🧭 What is Data Access?

    Data access is the code layer that lets your application create, read, update and delete (CRUD) data kept in a storage system. Storage is where data lives permanently — usually a relational database such as Microsoft SQL Server.

    🗄️
    SQL Server
    The database engine that stores and queries data.
    🧩
    EF Core
    Full ORM: work with C# objects, not SQL.
    ⚡
    Dapper
    Micro-ORM: write SQL, get objects, very fast.

    🗂️ Types of Data Access Approaches

    ApproachWhat it isProsCons
    ADO.NETLow-level API (SqlConnection, SqlCommand, SqlDataReader)Full control, fastestLots of boilerplate
    Micro-ORM (Dapper)Thin layer mapping SQL results to objectsFast, simple, SQL controlYou write all SQL
    Full ORM (EF Core)Maps classes to tables, translates LINQ to SQL, tracks changesProductive, migrations, less SQLOverhead, learning curve
    Stored proceduresLogic stored inside SQL ServerSecure, reusable, tunableHarder to version and test
    C#using var con = new SqlConnection(connStr);
con.Open();
using var cmd = new SqlCommand("SELECT Name FROM Customers WHERE Id=@id", con);
cmd.Parameters.AddWithValue("@id", 1);
var name = (string?)cmd.ExecuteScalar();

    Every approach ultimately sits on ADO.NET — EF Core and Dapper are built on it.

    💾 Types of Storage

    TypeExamplesBest for
    Relational (SQL)SQL Server, PostgreSQLStructured data, transactions, joins
    Document (NoSQL)MongoDB, Cosmos DBFlexible JSON documents
    Key-value / cacheRedisFast lookups, caching
    File / blobAzure Blob StorageImages, documents

    📖 Key Terms (What is What)

    Connection stringText that tells the app which server, database and credentials to use.
    ORMObject-Relational Mapper: maps tables ↔ classes.
    EntityA C# class that represents a table row.
    SchemaStructure of tables, columns and relations.
    TransactionA group of operations that succeed or fail together.
    Connection poolingReusing open connections for speed (built into ADO.NET).
    SQL injectionAttack by inserting SQL via input; prevent with parameters.
    Q. Which approach is built on top of ADO.NET?

    • B Only Dapper

    • D Neither

    SQL Server Fundamentals

    What SQL Server is, its editions, data types, keys, constraints, CRUD and joins.

    🗄️ What is SQL Server?

    Microsoft SQL Server is a relational database management system (RDBMS) that stores data in tables and is queried using T-SQL (Transact-SQL). Tools: SSMS, Azure Data Studio.

    EditionUse
    ExpressFree, small apps (10 GB limit)
    DeveloperFree, full features, non-production
    Standard / EnterpriseProduction; Enterprise adds advanced HA and scale
    Azure SQL Database / Managed InstanceCloud-hosted SQL Server

    📐 Data Types, Keys & Constraints

    CategoryTypes
    Numbersint, bigint, decimal(18,2), bit
    Textvarchar(n), nvarchar(n) (Unicode)
    Date/timedate, datetime2, datetimeoffset
    Otheruniqueidentifier (GUID), varbinary, xml
    PRIMARY KEYUniquely identifies each row.
    FOREIGN KEYLinks to another table’s key.
    UNIQUE / NOT NULL / CHECK / DEFAULTRules that keep data valid.
    T-SQLCREATE TABLE Customers(
  Id INT IDENTITY(1,1) PRIMARY KEY,
  Name NVARCHAR(100) NOT NULL,
  Email NVARCHAR(200) UNIQUE,
  CreatedAt DATETIME2 DEFAULT SYSUTCDATETIME());
CREATE TABLE Orders(
  Id INT IDENTITY PRIMARY KEY,
  CustomerId INT NOT NULL REFERENCES Customers(Id),
  Total DECIMAL(18,2) CHECK (Total >= 0));

    ✏️ CRUD & Joins

    T-SQLINSERT INTO Customers(Name,Email) VALUES(N'Asha','a@x.com');
SELECT Id,Name FROM Customers WHERE Name LIKE N'A%' ORDER BY Name;
UPDATE Customers SET Name=N'Asha K' WHERE Id=1;
DELETE FROM Customers WHERE Id=1;
    JoinReturns
    INNEROnly matching rows
    LEFTAll left rows + matches
    RIGHT / FULLAll right / all rows from both
    CROSSEvery combination
    T-SQLSELECT c.Name, COUNT(o.Id) AS Orders, SUM(o.Total) AS Revenue
FROM Customers c LEFT JOIN Orders o ON o.CustomerId=c.Id
GROUP BY c.Name HAVING SUM(o.Total) > 1000;
    Q. Which join keeps customers who have no orders?
    • A INNER JOIN

    Module 03

    SQL Server: Intermediate to Expert

    Indexes, transactions, isolation, window functions, tuning, and security.

    🌲 Indexes

    IndexNotes
    ClusteredDefines physical row order; one per table (usually the PK)
    Non-clusteredSeparate structure with pointers; many per table
    Covering (INCLUDE)Contains all columns a query needs — avoids lookups
    FilteredIndex over a subset of rows
    ColumnstoreColumn storage for analytics
    T-SQLCREATE NONCLUSTERED INDEX IX_Orders_Customer
ON Orders(CustomerId, CreatedAt) INCLUDE (Total);
    💡
    Put equality columns first, range columns next. Every index speeds reads but slows writes.

    🔒 Transactions & Isolation

    T-SQLBEGIN TRAN;
UPDATE Accounts SET Bal=Bal-100 WHERE Id=1;
UPDATE Accounts SET Bal=Bal+100 WHERE Id=2;
COMMIT; -- or ROLLBACK on error

    ACID: Atomic, Consistent, Isolated, Durable.

    Isolation levelPrevents
    READ UNCOMMITTEDNothing (dirty reads possible)
    READ COMMITTED (default)Dirty reads
    REPEATABLE READ+ non-repeatable reads
    SERIALIZABLE+ phantom rows
    SNAPSHOT / RCSIReaders don’t block writers (row versioning)

    🧠 Advanced T-SQL

    T-SQLWITH Ranked AS (
  SELECT CustomerId, Total,
         ROW_NUMBER() OVER (PARTITION BY CustomerId ORDER BY Total DESC) rn
  FROM Orders)
SELECT * FROM Ranked WHERE rn = 1;  -- top order per customer

    Also learn: stored procedures, views, functions, triggers, MERGE, JSON functions, temporal tables (SYSTEM_VERSIONING), partitioning.

    🚀 Tuning, Security & Operations

    Execution planShows how SQL Server runs a query; look for scans, key lookups, warnings.
    Query StoreTracks query performance and plan regressions over time.
    StatisticsData distribution used by the optimizer; keep them updated.
    Parameter sniffingPlan built for one parameter value is slow for others.
    DeadlockTwo transactions block each other; keep transactions short, access tables in the same order.
    SecurityLeast-privilege logins, Row-Level Security, Dynamic Data Masking, Always Encrypted, TDE.
    Backup / HAFull + differential + log backups; Always On availability groups.
    Q. A query does an index seek plus a Key Lookup for one extra column. Best fix?
    • A Drop the index
    • B Add the column with INCLUDE
    • C Use NOLOCK
    • D Rebuild the table

    Entity Framework Core: Basics to Intermediate

    What EF Core is, DbContext, entities, migrations, CRUD, LINQ and relationships.

    🧩 What is EF Core?

    EF Core is Microsoft’s open-source, cross-platform ORM. You define C# classes; it generates SQL, tracks changes and manages the schema.

    ApproachMeaning
    Code-FirstWrite classes → generate DB with migrations (most common)
    Database-FirstExisting DB → scaffold classes: dotnet ef dbcontext scaffold
    CLIdotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet add package Microsoft.EntityFrameworkCore.Design

    🏗️ DbContext, Entities & Migrations

    C#public class Customer { public int Id {get;set;} public string Name {get;set;} = "";
  public List<Order> Orders {get;set;} = new(); }
public class Order { public int Id {get;set;} public decimal Total {get;set;}
  public int CustomerId {get;set;} public Customer? Customer {get;set;} }

public class ShopDb : DbContext {
  public ShopDb(DbContextOptions<ShopDb> o) : base(o) {}
  public DbSet<Customer> Customers => Set<Customer>();
  public DbSet<Order> Orders => Set<Order>();
  protected override void OnModelCreating(ModelBuilder b) {
    b.Entity<Customer>().Property(c => c.Name).HasMaxLength(100).IsRequired();
    b.Entity<Order>().Property(o => o.Total).HasPrecision(18,2);
  }
}
// Program.cs
builder.Services.AddDbContext<ShopDb>(o => o.UseSqlServer(conn));
    CLIdotnet ef migrations add Init
dotnet ef database update

    ✏️ CRUD & LINQ

    C#db.Customers.Add(new Customer { Name = "Asha" });
await db.SaveChangesAsync();                       // INSERT
var c = await db.Customers.FindAsync(1);
c!.Name = "Asha K"; await db.SaveChangesAsync();   // UPDATE (tracked)
db.Remove(c); await db.SaveChangesAsync();         // DELETE

var top = await db.Orders.Where(o => o.Total > 500)
    .OrderByDescending(o => o.Total).Select(o => new { o.Id, o.Total })
    .Take(10).ToListAsync();
    📝
    LINQ is translated to SQL only when you call ToListAsync, FirstAsync, etc. (deferred execution).

    🔗 Relationships & Loading

    RelationshipConfiguration
    One-to-manyCustomer.Orders + Order.CustomerId
    One-to-oneHasOne().WithOne()
    Many-to-manySkip navigations (List<Tag> on both sides)
    LoadingHow
    Eager.Include(c => c.Orders)
    Explicitdb.Entry(c).Collection(x => x.Orders).LoadAsync()
    LazyProxies; easy to cause N+1 — use carefully
    Q. When does EF Core send the INSERT to SQL Server?
    • A On Add()
    • B On SaveChanges()
    • C On ToList()
    • D On Include()

    EF Core: Advanced & Expert

    Performance, concurrency, inheritance, bulk operations, interceptors and production practices.

    ⚡ Performance

    C#// Read-only: skip change tracking
var list = await db.Orders.AsNoTracking().ToListAsync();
// Avoid cartesian explosion on multiple collections
var q = db.Customers.Include(c => c.Orders).AsSplitQuery();
// Set-based writes, no loading
await db.Orders.Where(o => o.Total == 0).ExecuteDeleteAsync();
await db.Orders.ExecuteUpdateAsync(s => s.SetProperty(o => o.Total, o => o.Total * 1.1m));
// Compiled query for hot paths
static readonly Func<ShopDb,int,Task<Customer?>> ById =
  EF.CompileAsyncQuery((ShopDb d,int id) => d.Customers.FirstOrDefault(c => c.Id == id));
    N+1 problemLoading a list then querying related data per item. Fix with Include or projection.
    ProjectionSelect only needed columns — often the biggest win.
    DbContext poolingAddDbContextPool reuses context instances.
    PaginationPrefer keyset (WHERE Id > @last) over Skip/Take on big tables.

    🛡️ Concurrency, Transactions & Resilience

    C#public byte[] RowVersion { get; set; }   // [Timestamp] column
try { await db.SaveChangesAsync(); }
catch (DbUpdateConcurrencyException) { /* reload, merge or tell the user */ }

await using var tx = await db.Database.BeginTransactionAsync();
// ... multiple SaveChanges ...
await tx.CommitAsync();

o.UseSqlServer(conn, s => s.EnableRetryOnFailure(5));

    SaveChanges is already atomic. Use explicit transactions to span several calls.

    🧱 Advanced Modeling

    FeaturePurpose
    Inheritance: TPH / TPT / TPCOne table / table per type / table per concrete type
    Owned typesValue objects (e.g. Address) in the owner’s table
    Value convertersEnum ↔ string, strongly typed IDs
    Global query filtersSoft delete, multi-tenancy: HasQueryFilter(x => !x.IsDeleted)
    InterceptorsAudit fields, logging, slow-query hooks
    Raw SQLFromSql($"... {id}") — parameterized automatically
    ⚠️
    Never concatenate user input into FromSqlRaw. Use FromSql interpolation or parameters.

    🏭 Production Practices

    Migrations in CI/CDGenerate idempotent scripts: dotnet ef migrations script --idempotent.
    TestingUse SQL Server in a container (Testcontainers); InMemory provider hides SQL behaviour.
    Repository patternDbContext already is a Unit of Work; add repositories only for real needs.
    LoggingLogTo / EnableSensitiveDataLogging in dev only.
    Q. Best fix for slow read-only list pages?
    • A Lazy loading
    • B AsNoTracking + Select projection
    • C Include everything
    • D Remove indexes

    Dapper: Micro-ORM

    What Dapper is, its methods, parameters, multi-mapping, stored procedures, transactions and when to pair it with EF Core.

    ⚡ What is Dapper?

    Dapper is a lightweight NuGet library (Dapper) that adds extension methods to IDbConnection. You write SQL; Dapper maps results to objects quickly. No change tracking, no migrations, no LINQ.

    MethodUse
    Query<T>Many rows → list
    QueryFirstOrDefault<T> / QuerySingleOne row
    ExecuteScalar<T>Single value
    ExecuteINSERT / UPDATE / DELETE; returns rows affected
    QueryMultipleSeveral result sets in one call

    ✏️ Examples

    C#using var con = new SqlConnection(conn);
var cust = await con.QueryFirstOrDefaultAsync<Customer>(
  "SELECT * FROM Customers WHERE Id=@Id", new { Id = 1 });

await con.ExecuteAsync(
  "INSERT INTO Orders(CustomerId,Total) VALUES(@CustomerId,@Total)",
  new[] { new { CustomerId=1, Total=50m }, new { CustomerId=1, Total=75m } }); // batch

// Multi-mapping (join)
var rows = await con.QueryAsync<Order,Customer,Order>(
  "SELECT o.*, c.* FROM Orders o JOIN Customers c ON c.Id=o.CustomerId",
  (o,c) => { o.Customer = c; return o; }, splitOn: "Id");

// Stored procedure + output parameter
var p = new DynamicParameters(); p.Add("@Id",1); p.Add("@Count",dbType:DbType.Int32,direction:ParameterDirection.Output);
await con.ExecuteAsync("usp_CountOrders", p, commandType: CommandType.StoredProcedure);
int count = p.Get<int>("@Count");

// Multiple result sets
using var g = await con.QueryMultipleAsync("SELECT * FROM Customers; SELECT * FROM Orders");
var customers = g.Read<Customer>(); var orders = g.Read<Order>();

    🎯 Best Practices

    Always parameterizeDapper parameters prevent SQL injection; never build SQL with string concatenation.
    Transactionscon.BeginTransaction() and pass transaction: to each call.
    Column mappingUse aliases or DefaultTypeMap.MatchNamesWithUnderscores = true.
    HybridEF Core for writes and migrations; Dapper for heavy reports and read models (CQRS style).
    ChooseWhen
    EF CoreCRUD apps, rapid development, schema management
    DapperPerformance-critical queries, complex hand-tuned SQL
    ADO.NETBulk copy (SqlBulkCopy), streaming, maximum control
    Q. Which statement about Dapper is true?
    • A It tracks changes
    • B It generates migrations
    • C You write the SQL
    • D It translates LINQ

    Practice: ShopEase Data Layer

    Apply SQL Server, EF Core and Dapper to one realistic scenario.

    0 / 0 correct

    🛒 Scenario

    ShopEase has Customers and Orders tables. The order list page takes 6 seconds and the admin sales report is slow. You own the data layer.

    1️⃣ Task 1 · SQL Server

    ✍️ Write a query for each customer’s total spend, highest first, including customers with no orders.
    Model answer: SELECT c.Name, COALESCE(SUM(o.Total),0) AS Spend FROM Customers c LEFT JOIN Orders o ON o.CustomerId=c.Id GROUP BY c.Name ORDER BY Spend DESC;
    ✍️ Which index would speed up “orders for a customer, newest first”?
    Model answer: CREATE INDEX IX_Orders_Cust_Date ON Orders(CustomerId, CreatedAt DESC) INCLUDE (Total); — equality column first, then sort column, plus INCLUDE to avoid lookups.

    2️⃣ Task 2 · EF Core

    ✍️ The order list loads each order’s customer in a loop. Name the problem and fix it.
    Model answer: N+1 queries. Use AsNoTracking().Select(o => new { o.Id, o.Total, CustomerName = o.Customer.Name }) to fetch everything in one query with only needed columns.
    Q. Two admins edit the same product at once. Which EF Core feature detects the conflict?
    • A AsNoTracking
    • B Concurrency token (RowVersion)
    • C Include
    • D Compiled query

    3️⃣ Task 3 · Dapper

    ✍️ Write a Dapper call returning the top 10 products by revenue for a date range, safely.
    Model answer: await con.QueryAsync<ProductSales>("SELECT TOP 10 ProductId, SUM(Total) Revenue FROM OrderItems WHERE CreatedAt BETWEEN @From AND @To GROUP BY ProductId ORDER BY Revenue DESC", new { From=from, To=to }); — parameterized, no string concatenation.
    Q. For the admin report, the best tool is…
    • A EF Core change tracking
    • B Dapper with tuned SQL
    • C Lazy loading
    • D InMemory provider
