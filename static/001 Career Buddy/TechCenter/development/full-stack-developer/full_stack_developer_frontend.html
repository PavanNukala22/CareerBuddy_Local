    Module 01 · Foundations

    What is Frontend Development?

    Start from zero: what the frontend is, what it is made of, and the kinds of web apps you can build.

    🧭 What is the Frontend?

    The frontend is everything a user sees and touches in a browser: layout, text, buttons, forms, animations. A frontend developer turns designs and data into an interface that is fast, accessible and works on any screen.

    🏗️ HTML

    Structure — headings, paragraphs, forms, links. The skeleton.

    🎨 CSS

    Presentation — colour, spacing, layout, responsiveness. The skin.

    ⚡ JavaScript

    Behaviour — clicks, data fetching, updating the page. The muscles.

    🔷 TypeScript

    JavaScript plus types, so mistakes are caught before the code runs.

    🗺️ Types of Frontend Applications

    TypeWhat it meansBest forExample tech
    Static sitePre-built HTML files served as-isDocs, blogs, landing pagesHTML/CSS, Astro, Next.js SSG
    SPA (Single Page App)One HTML page; JS swaps views in the browserDashboards, tools behind loginReact + Vite
    SSR (Server-Side Rendering)Server builds HTML for every requestSEO-critical, personalised pagesNext.js, Remix
    SSG / ISRHTML built at build time, refreshed on a scheduleMarketing, catalogues, newsNext.js
    PWAInstallable web app with offline supportMobile-like experiencesService workers
    💡
    Rule of thumb: public pages that must rank on Google → SSR/SSG. Private app screens → SPA is fine.

    🔄 What Happens When You Open a Page?

    1. Browser sends an HTTP request to the server.
    2. Server returns an HTML document.
    3. Browser parses HTML into the DOM (a tree of elements), loads CSS and builds the CSSOM.
    4. JavaScript runs and can change the DOM.
    5. Browser lays out and paints pixels on screen.

    📖 Key Terms

    DOMTree representation of the page that JavaScript can read and modify.
    ResponsiveLayout that adapts to any screen width.
    Accessibility (a11y)Making UI usable with keyboard, screen readers and low vision.
    BundlerTool (Vite, webpack) that combines your modules into optimised files.
    HydrationAttaching JavaScript behaviour to server-rendered HTML.
    Core Web VitalsGoogle metrics: LCP (loading), INP (interaction), CLS (layout shift).

    📦 The Box Model

    Every element is a box: content → padding → border → margin. Always set box-sizing: border-box so width includes padding and border.

    css*{ box-sizing: border-box; }
.card{
  width: 300px;
  padding: 16px;          /* inside space */
  border: 1px solid #ddd;
  margin: 0 auto 24px;    /* outside space */
}

    📐 Flexbox (1-D) vs Grid (2-D)

    ↔️ Flexbox

    Lays items in a row or column. Great for navbars, button groups, centring.

    ▦ Grid

    Rows and columns together. Great for page layouts and card galleries.

    css.nav{ display:flex; justify-content:space-between; align-items:center; gap:12px; }

.gallery{
  display:grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap:16px;
}
    EXAMPLE · Perfect centring

    display:grid; place-items:center; min-height:100vh; centres anything both ways.

    📱 Responsive Design

    Mobile-first: write the small-screen styles first, then add min-width media queries for larger screens.

    css.layout{ display:block; }
@media (min-width: 768px){
  .layout{ display:grid; grid-template-columns: 240px 1fr; }
}
h1{ font-size: clamp(1.75rem, 4vw, 3rem); } /* fluid type */
    📝
    Always include <meta name="viewport" content="width=device-width, initial-scale=1"> or mobile browsers will zoom out the desktop layout.

    🚀 Expert Tips

    🎛️
    CSS variables
    Define design tokens once with --color-primary; enable theming and dark mode.
    🧩
    Container queries
    Components respond to their parent width, not the viewport.
    ♿
    Focus & contrast
    Never remove focus outlines; keep 4.5:1 text contrast.
    ⚡
    Performance
    Use loading="lazy", modern formats (WebP/AVIF), and avoid layout shift with width/height.

    ⏳ Asynchronous JavaScript

    JavaScript is single-threaded. The event loop runs slow tasks (network, timers) in the background and calls you back when ready. Evolution: callbacks → Promises → async/await.

    javascriptasync function loadCourses() {
  try {
    const res = await fetch("/api/courses");
    if (!res.ok) throw new Error("HTTP " + res.status);
    return await res.json();
  } catch (err) {
    console.error(err);
    return [];
  }
}
// run in parallel
const [a, b] = await Promise.all([fetch("/a"), fetch("/b")]);
    ⚠️
    fetch only rejects on network failure. A 404 or 500 is still a resolved promise — always check res.ok.

    Module 04 · React & Next.js

    React & Next.js

    Components, state, hooks, data fetching and the Next.js rendering model.

    ⚛️ What is React?

    React is a library for building UIs from components — small reusable functions that return JSX. You describe what the UI should look like for the current state; React updates the DOM efficiently (virtual DOM diffing).

    jsxfunction CourseCard({ title, level }) {
  return (
    <article className="card">
      <h3>{title}</h3>
      <span>{level}</span>
    </article>
  );
}
// <CourseCard title="HTML Basics" level="Basic" />

    🪝 State & Hooks

    useStateLocal state that triggers a re-render when changed.
    useEffectRun side effects (fetching, subscriptions) after render. Return a cleanup function.
    useMemo / useCallbackCache values/functions between renders — use only for real performance issues.
    useContextShare data (theme, user) without prop drilling.
    useReducerComplex state transitions in one place.
    Custom hooksExtract reusable logic, e.g. useDebounce.
    jsxfunction Search() {
  const [q, setQ] = useState("");
  const [rows, setRows] = useState([]);
  useEffect(() => {
    const ctrl = new AbortController();
    fetch(`/api/search?q=${q}`, { signal: ctrl.signal })
      .then(r => r.json()).then(setRows).catch(() => {});
    return () => ctrl.abort();           // cleanup
  }, [q]);
  return <input value={q} onChange={e => setQ(e.target.value)} />;
}
    ⚠️
    Never mutate state directly (items.push(x)). Create a new array: setItems([...items, x]). Give list items a stable key, not the array index.

    ▲ Next.js: Routing & Rendering

    ModeWhen HTML is builtUse for
    Static (SSG)At build timeRarely changing content

export default async function Course({ params }: { params: { id: string } }) {
  const res = await fetch(`https://api.example.com/courses/${params.id}`, { next: { revalidate: 60 } });
  const course = await res.json();
  return <h1>{course.title}</h1>;
}

    🎯 Scenario

    Your LMS needs a responsive course catalogue: a search box, a grid of course cards loaded from /api/courses, loading and error states, and full keyboard accessibility.

    1️⃣ Task 1 · Layout

    Q. Which CSS gives a responsive card grid with no media queries?
    • A display:flex; width:300px
    • B grid-template-columns: repeat(auto-fit, minmax(220px,1fr))
    • C float:left
    • D position:absolute
    ✍️ Write semantic HTML for one course card (title, level, button).
    Model answer: <article class="card"><h3>HTML Basics</h3><p>Level: Basic</p><button type="button">Enroll</button></article> — article for a self-contained item, a real heading, a real button (keyboard-focusable).

    2️⃣ Task 2 · Data & State

    ✍️ List the three UI states your React component must handle while loading courses, and the hooks you would use.
    Model answer: Loading, error, success (plus empty). Use useState for courses, loading, error; useEffect with an AbortController to fetch on mount/query change; debounce the search input.
    Q. Why add an AbortController in useEffect?
    • A To speed up the network
    • B To cancel stale requests and avoid setting state after unmount or on outdated queries
    • C To cache the response
    • D To retry on failure

    3️⃣ Task 3 · Next.js

    ✍️ The catalogue changes a few times a day and must rank on Google. Which rendering mode do you pick and why?
    Model answer: ISR (Static generation with revalidate): pre-built HTML is fast and SEO-friendly, and refreshes periodically without rebuilding the whole site.
