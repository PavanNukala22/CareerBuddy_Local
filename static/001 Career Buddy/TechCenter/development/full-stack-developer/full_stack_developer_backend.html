    Module 01 · Foundations

    What is Backend Development?

    Start from zero: what a backend is, how clients talk to it, and the architectures you will meet.

    🧭 What is the Backend?

    The backend is the part of an application that runs on a server. It receives requests from the frontend, applies business rules, talks to databases and other services, and sends back a response. Users never see it, but it holds the logic, the data and the security.

    🖥️ Frontend

    Runs in the browser. Shows the UI and collects input.

    🗄️ Backend

    Runs on a server. Validates, authenticates, stores and processes data.

    🔁 The Request–Response Cycle

    1. Client sends POST /api/enroll with JSON.
    2. Server routes it to a handler.
    3. Middleware checks authentication and validates input.
    4. Handler runs business logic and queries the database.
    5. Server replies with a status code and body (e.g. 201 Created).
    LayerResponsibility
    Routes/ControllersParse request, call service, return response
    ServicesBusiness rules (e.g. "can this user enrol?")
    Repositories/ORMDatabase access
    MiddlewareCross-cutting: auth, logging, errors, CORS

    🏛️ Types of Backend Architecture

    StyleDescriptionUse when
    MonolithOne deployable app containing all featuresStarting out, small teams
    Modular monolithMonolith with strict internal modulesGrowing apps; easiest path to scale
    MicroservicesMany small services, each owning its dataLarge teams, independent scaling
    ServerlessFunctions run on demand (AWS Lambda)Spiky traffic, event-driven tasks
    💡
    Start with a modular monolith. Split into microservices only when you feel a real pain, not because it is fashionable.

    🧰 Choosing a Stack

    OptionLanguageStrengths
    Node.js + ExpressJavaScript/TSSame language as frontend, huge ecosystem, great for APIs
    DjangoPythonBatteries included: ORM, admin, auth
    FastAPIPythonFast, async, auto docs, type-hinted
    Spring BootJavaEnterprise-grade, strongly typed, mature tooling

    📖 Key Terms

    ServerA program listening for requests on a port.
    EndpointA URL + HTTP method, e.g. GET /users/5.
    MiddlewareFunction that runs between request and handler.
    StatelessServer stores no per-user session in memory; each request carries what it needs.
    IdempotentRepeating the request gives the same result (GET, PUT, DELETE).
    Environment variablesConfig and secrets kept outside the code.

    Module 02 · Node.js & Express

    Node.js & Express

    JavaScript on the server: routing, middleware, validation, error handling and authentication.

    🟢 What are Node.js and Express?

    Node.js runs JavaScript outside the browser using Chrome's V8 engine and a non-blocking event loop, so one process handles thousands of connections. Express is a minimal web framework on top of it for routing and middleware.

    javascriptimport express from "express";
const app = express();
app.use(express.json());                       // parse JSON bodies

app.get("/health", (req, res) => res.json({ ok: true }));

app.listen(process.env.PORT || 3000, () => console.log("Server running"));

    🛣️ Routing & Middleware

    javascript// Router per resource
const router = express.Router();
router.get("/:id", async (req, res) => {
  const course = await Course.findById(req.params.id);
  if (!course) return res.status(404).json({ error: "Not found" });
  res.json(course);
});
app.use("/api/courses", router);

// Custom middleware
function logger(req, res, next) { console.log(req.method, req.url); next(); }
app.use(logger);
    📝
    Order matters: middleware runs top to bottom. Register error-handling middleware last.

    ✅ Validation & Error Handling

    🔐 Authentication with JWT

    javascriptimport jwt from "jsonwebtoken";
import bcrypt from "bcrypt";

// login: verify password hash, issue token
const ok = await bcrypt.compare(password, user.passwordHash);
const token = jwt.sign({ sub: user.id, role: user.role }, process.env.JWT_SECRET, { expiresIn: "15m" });

// protect routes
function auth(req, res, next) {
  const raw = req.headers.authorization?.split(" ")[1];
  try { req.user = jwt.verify(raw, process.env.JWT_SECRET); next(); }
  catch { res.status(401).json({ error: "Unauthorized" }); }
}
    ⚠️
    Never store plain-text passwords or put secrets in the repo. Hash with bcrypt/argon2 and load secrets from environment variables.

    Module 03 · Python: Django & FastAPI

    Python: Django & FastAPI

    Two Python approaches: Django (batteries included) and FastAPI (modern, async, typed).

    🐍 Django vs FastAPI

    🎸 Django

    Full framework: ORM, migrations, admin panel, auth, templates. Follows MTV (Model–Template–View). Best for content-heavy or admin-driven apps.

    ⚡ FastAPI

    API-first, async, built on type hints and Pydantic. Auto-generates OpenAPI docs at /docs. Best for APIs and ML services.

    🎸 Django Essentials

class Course(models.Model):

# views.py (Django REST Framework)

    serializer_class = CourseSerializer

# urls.py
router.register("courses", CourseViewSet)

    ⚡ FastAPI Essentials

    pythonfrom fastapi import FastAPI, HTTPException, Depends
from pydantic import BaseModel, Field

app = FastAPI()

class CourseIn(BaseModel):
    title: str = Field(min_length=3)
    price: float = Field(ge=0)

@app.post("/courses", status_code=201)
async def create(course: CourseIn, db=Depends(get_db)):
    return await db.save(course)

@app.get("/courses/{course_id}")
async def read(course_id: int, db=Depends(get_db)):
    c = await db.get(course_id)
    if not c: raise HTTPException(404, "Not found")
    return c

    Depends() is FastAPI's dependency injection — perfect for database sessions and the current user.

    Module 04 · Java & Spring Boot

    Java & Spring Boot

    Enterprise-grade backends with annotations, dependency injection and layered design.

    ☕ What is Spring Boot?

    Spring Boot is an opinionated layer over the Spring framework. It auto-configures an embedded server (Tomcat), database access and security, so you can run an application with one main method. Core idea: Inversion of Control / Dependency Injection — Spring creates and wires your objects (beans) for you.

    🧱 Layered Structure

    java@Entity
public class Course {
  @Id @GeneratedValue private Long id;
  private String title;
}

public interface CourseRepository extends JpaRepository<Course, Long> {}

@Service
public class CourseService {
  private final CourseRepository repo;
  public CourseService(CourseRepository repo) { this.repo = repo; }   // constructor injection
  public Course get(Long id) {
    return repo.findById(id).orElseThrow(() -> new NotFoundException("Course " + id));
  }
}

@RestController
@RequestMapping("/api/courses")
public class CourseController {
  private final CourseService service;
  public CourseController(CourseService s) { this.service = s; }
  @GetMapping("/{id}") public Course get(@PathVariable Long id) { return service.get(id); }
  @PostMapping @ResponseStatus(HttpStatus.CREATED)
  public Course create(@Valid @RequestBody CourseDto dto) { return service.create(dto); }
}
    AnnotationMeaning
    @RestControllerClass handles HTTP and returns JSON
    @ServiceBusiness logic bean
    @Repository / JpaRepositoryData access
    @ValidRun bean validation on the request body
    @TransactionalWrap method in a database transaction
    @ControllerAdviceGlobal exception handling

    Module 05 · Production Patterns

    Production Patterns

    What separates a demo from a production-grade backend: security, performance, reliability and testing.

    🛡️ Security Checklist

    🔑
    AuthN vs AuthZ
    Authentication = who you are. Authorization = what you may do (roles/permissions).
    💉
    Injection
    Always use parameterised queries/ORMs; never concatenate SQL.
    🚦
    Rate limiting
    Throttle login and public endpoints to stop brute force and abuse.
    🌐
    CORS & HTTPS
    Allow only trusted origins; terminate TLS everywhere.

    🚀 Performance & Scaling

    TechniqueWhat it does
    Caching (Redis)Keep hot data in memory; set a TTL
    PaginationNever return unbounded lists
    Background jobs / queuesSend emails, process uploads asynchronously (BullMQ, Celery, RabbitMQ)
    Connection poolingReuse DB connections
    Horizontal scalingRun many stateless instances behind a load balancer
    javascript// Cache-aside pattern
async function getCourse(id) {
  const hit = await redis.get(`course:${id}`);
  if (hit) return JSON.parse(hit);
  const course = await db.course.findById(id);
  await redis.set(`course:${id}`, JSON.stringify(course), "EX", 300);
  return course;
}

    🧪 Testing, Logging & Observability

    Unit testsTest one function/service in isolation with mocks.
    Integration testsTest routes with a real/test database (Supertest, pytest, MockMvc).
    Structured loggingJSON logs with request IDs (pino, structlog, Logback).
    Health checks/health endpoint for load balancers and orchestrators.
    12-factor configConfig via environment, logs to stdout, stateless processes.
    ✅
    A production-ready service has: input validation, central error handling, auth, tests, structured logs, health checks and graceful shutdown.

    🎯 Scenario

    Build an Enrolment service for an LMS: students enrol in courses, only logged-in students may enrol, a student cannot enrol twice, and a confirmation email is sent.

    1️⃣ Task 1 · Design

    ✍️ List the endpoints (method + path) and the status codes each should return.
    Model answer: POST /api/courses/:id/enrol → 201 (created), 401 (not logged in), 404 (no course), 409 (already enrolled). GET /api/me/enrolments → 200. DELETE /api/enrolments/:id → 204.
    Q. Which status code best fits "already enrolled"?
    • A 200
    • B 409 Conflict
    • C 500
    • D 302

    2️⃣ Task 2 · Reliability

    ✍️ How do you stop duplicate enrolments even under two simultaneous requests?
    Model answer: Add a unique constraint on (student_id, course_id) in the database and handle the violation as 409. Application-level checks alone are racy.
    Q. The confirmation email should be sent…
    • A Inside the request, blocking the response
    • B Via a background job/queue
    • C By the frontend
    • D Never
