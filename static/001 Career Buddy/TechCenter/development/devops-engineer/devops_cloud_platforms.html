    Module 01 · Cloud Platforms

    Cloud Foundations

    What cloud computing is, IaaS/PaaS/FaaS/SaaS, regions and AZs, shared responsibility and how AWS, Azure and GCP map to each other.

    ☁️ What is Cloud Computing?

    Cloud computing is renting IT resources — compute, storage, databases, networking, AI — over the internet on demand, paying only for what you use, instead of buying and running your own data centre. The three big providers are Amazon Web Services (AWS), Microsoft Azure and Google Cloud Platform (GCP).

    📈
    Elasticity
    Scale up and down in minutes to match demand.
    💸
    Pay-as-you-go
    OPEX instead of big upfront CAPEX.
    🌍
    Global reach
    Deploy near users in dozens of regions.
    🛠️
    Managed services
    Provider runs databases, queues, Kubernetes for you.

    Service models — "What is What"Basic

    Who manages what (more provider-managed as you go down)
    On-premisesyou manage everything
    IaaS — Infrastructure as a Serviceprovider: hardware & virtualisation · you: OS, runtime, app (EC2, Azure VMs, Compute Engine)
    PaaS — Platform as a Serviceprovider also: OS & runtime · you: code & data (Elastic Beanstalk, App Service, App Engine)
    FaaS / Serverlessyou ship functions only (Lambda, Azure Functions, Cloud Functions)
    SaaS — Software as a Serviceprovider runs it all (Microsoft 365, Gmail, Salesforce)
    Deployment modelMeaning
    Public cloudShared provider infrastructure (AWS/Azure/GCP)
    Private cloudDedicated to one organisation (on-prem OpenStack, VMware)
    Hybrid cloudPublic + private connected (Azure Arc, AWS Outposts, GCP Anthos)
    Multi-cloudUsing more than one public provider

    🧱 Core Concepts every DevOps Engineer must know

    ConceptMeaning
    RegionGeographic area containing multiple data centres (e.g. Mumbai, N. Virginia)
    Availability Zone (AZ)Isolated data centre(s) inside a region. Spread across ≥2 AZs for high availability.
    Edge / CDNPoints of presence caching content close to users (CloudFront, Azure Front Door, Cloud CDN)
    IAMIdentity and Access Management — who can do what to which resource
    VPC / VNetYour private, isolated virtual network with subnets, routes and firewalls
    High Availability vs Disaster RecoveryHA = survive component/AZ failure. DR = recover from region-level disaster (RTO / RPO targets).
    ScalabilityVertical (bigger machine) vs horizontal (more machines) — prefer horizontal
    Shared Responsibility ModelProvider secures of the cloud (hardware, facilities); you secure in the cloud (data, IAM, config)
    Cost modelsOn-demand · Reserved/Savings Plans/Committed use · Spot/Preemptible (up to ~90% cheaper, can be reclaimed)
    ⚠️
    Most cloud breaches are customer misconfigurations (public storage buckets, leaked keys, over-broad IAM) — not provider failures.

    ItemMeaning

    json{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:GetObject", "s3:ListBucket"],
    "Resource": ["arn:aws:s3:::my-app-data", "arn:aws:s3:::my-app-data/*"]

    Evaluation rule: explicit Deny always wins, otherwise an explicit Allow is needed, otherwise default deny. Always apply least privilege.

    Three-tier VPC patternIntermediate

    Typical production VPC (10.0.0.0/16) across 2 AZs
    Public subnetsALB, NAT Gateway, bastion/SSM · route to Internet Gateway
    Private app subnetsEC2 / ECS / EKS nodes · outbound via NAT
    Private data subnetsRDS / ElastiCache · no internet route
    Security Groups are stateful, per-ENI; NACLs are stateless, per-subnet.

    🚀 AWS for DevOps & Expert Topics

    • CI/CD: CodeCommit/CodeBuild/CodeDeploy/CodePipeline — or GitHub Actions using OIDC to assume a role (no static keys); ECR for images; ECS/EKS deploys.
    • IaC: CloudFormation, CDK, Terraform; Systems Manager (Session Manager replaces SSH, Parameter Store, Patch Manager); Secrets Manager; KMS for encryption keys.
    • Observability: CloudWatch (metrics, logs, alarms), X-Ray tracing, CloudTrail (audit of API calls), AWS Config (compliance), GuardDuty (threat detection).
    • Resilience: multi-AZ everywhere, Route 53 health-check failover, cross-region replication, backups (AWS Backup); DR strategies: Backup & Restore → Pilot Light → Warm Standby → Multi-site active/active.
    • Multi-account landing zone: Control Tower / Organizations, SCPs, centralised logging & security accounts, IAM Identity Center.
    • Cost: Cost Explorer, Budgets, tagging, Savings Plans, Spot with Karpenter, S3 lifecycle, right-sizing (Compute Optimizer).
    • Well-Architected Framework pillars: Operational Excellence, Security, Reliability, Performance Efficiency, Cost Optimization, Sustainability.

def handler(event, context):
    rec = event["Records"][0]["s3"]
    bucket = rec["bucket"]["name"]
    key = urllib.parse.unquote_plus(rec["object"]["key"])

    print(f"New file {key} ({head['ContentLength']} bytes)")
    return {"status": "ok"}

    ✅ Cloud Best Practices for DevOps

    • Security first: least-privilege IAM, MFA, no long-lived keys (use OIDC/workload identity), encrypt at rest & in transit, private networking, central audit logs.
    • Reliability: multi-AZ, health checks, autoscaling, tested backups and DR runbooks (know your RTO/RPO).
    • Everything as code: IaC + GitOps; no manual console changes in production.
    • Cost control (FinOps): mandatory tags/labels, budgets and alerts, right-size, shut down idle dev, use Spot for fault-tolerant work, commitments for steady load.
    • Multi-account/project strategy: separate prod/non-prod, shared services and security/logging accounts.
    • Observability: metrics, logs and traces with alerts tied to SLOs.
