    Computer Science Fundamentals: The Big Picture

    Start from zero: what computer science is, what data structures, algorithms and OOP are, and how they fit together.

    🧭 What is Computer Science?

    Computer science (CS) is the study of how to represent information, process it step by step, and build reliable software around it. A software developer uses three core ideas every day:

    🗄️
    Data Structures
    Ways to organise data in memory so it can be used efficiently.
    ⚙️
    Algorithms
    Step-by-step procedures that solve a problem.
    🧩
    OOP
    A way to structure code as objects that combine data and behaviour.
    📈
    Complexity
    How cost (time/memory) grows as input grows.
    💡
    Programs = Data Structures + Algorithms. Choosing the right structure often makes the algorithm simple; OOP then keeps the code organised and maintainable.

    🗺️ Learning Roadmap: Basic → Expert

    ExpertTrie, segment tree, union-find, balanced treesDP, greedy, backtracking, Dijkstra, topological sortSOLID, design patterns, composition, clean architecture

    📖 Key Terms (What is What)

    DataRaw facts or values: numbers, text, records.
    Data structureA format for storing and organising data plus the operations allowed on it.
    AlgorithmA finite, unambiguous sequence of steps that solves a problem.
    ComplexityA measure of time or memory used as input size n grows.
    AbstractionHiding details and exposing only what is needed.
    Class / ObjectBlueprint / a real instance built from it.
    PseudocodePlain-language description of an algorithm before coding.
    RecursionA function solving a problem by calling itself on a smaller version.

    ⏱️ What is Big-O (Complexity)?

    Big-O notation describes how the running time or memory of an algorithm grows with input size n, ignoring constants. It describes the worst case unless stated.

    Big-ONameExamplen = 1,000 → ops
    O(1)ConstantArray index access1
    O(log n)LogarithmicBinary search~10
    O(n)LinearScan a list1,000
    O(n log n)LinearithmicMerge sort~10,000
    O(n²)QuadraticNested loops, bubble sort1,000,000
    O(2ⁿ)ExponentialNaive subset/recursionastronomical
    O(n!)FactorialBrute-force permutationsastronomical
    pythondef first(items):        # O(1)
    return items[0]

def total(items):        # O(n)
    s = 0
    for x in items: s += x
    return s

def has_pair(items):     # O(n^2)
    for i in items:
        for j in items:
            if i != j: return True
    📝
    Rules: drop constants (2n → n), keep the dominant term (n² + n → n²), sequential steps add, nested steps multiply. Space complexity measures extra memory used.

# Reverse a string (two pointers)
def reverse(s):
    a = list(s); i, j = 0, len(a) - 1
    while i < j:
        a[i], a[j] = a[j], a[i]; i += 1; j -= 1
    return "".join(a)
    EXAMPLE · Technique: Two pointers & sliding window

    Max sum of any 3 consecutive numbers in [2,1,5,1,3,2]: slide a window, add the new element, subtract the old one → 9 in O(n), instead of recomputing each window in O(n·k).

    🔗 Linked Lists

    A linked list is a chain of nodes; each node holds a value and a pointer to the next node. Types: singly, doubly (prev + next) and circular.

    pythonclass Node:
    def __init__(self, val):
        self.val, self.next = val, None

class LinkedList:
    def __init__(self): self.head = None
    def push_front(self, v):          # O(1)
        n = Node(v); n.next = self.head; self.head = n
    def find(self, v):                # O(n)
        cur = self.head
        while cur and cur.val != v: cur = cur.next
        return cur

def reverse(head):                    # classic interview question
    prev = None
    while head:
        head.next, prev, head = prev, head, head.next
    return prev
    💡
    Array vs linked list: arrays win on random access and cache speed; linked lists win on fast insert/delete at a known node. Floyd's slow/fast pointers detect cycles in O(1) space.

    🥞 Stacks & Queues

    🥞 Stack — LIFO

    Last In, First Out. Operations: push, pop, peek (all O(1)). Used for undo, function call stack, bracket matching.

    🚶 Queue — FIFO

    First In, First Out. Operations: enqueue, dequeue (O(1)). Used for task scheduling, BFS, print jobs. Variants: deque, circular queue, priority queue.

    pythonfrom collections import deque

def balanced(s):                      # stack example
    pairs = {")":"(", "]":"[", "}":"{"}; st = []
    for ch in s:
        if ch in "([{": st.append(ch)
        elif ch in pairs:
            if not st or st.pop() != pairs[ch]: return False
    return not st

q = deque(); q.append("A"); q.append("B")
print(q.popleft())   # A  (FIFO)

    #️⃣ Hash Tables, Maps & Sets

    A hash table uses a hash function to convert a key into an array index, giving average O(1) insert, lookup and delete. A set stores unique keys only.

    ConceptMeaning
    Hash functionMaps key → integer index
    CollisionTwo keys land on the same index
    ChainingEach slot holds a list of entries
    Open addressingProbe for the next free slot (linear/quadratic/double hashing)
    Load factorentries ÷ slots; resize when too high (~0.75)
    pythondef two_sum(nums, target):            # O(n) using a hash map
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen: return [seen[target - x], i]
        seen[x] = i

from collections import Counter
print(Counter("banana"))   # frequency count
    ⚠️
    Worst case is O(n) if many keys collide. Keys must be hashable/immutable (lists cannot be dict keys in Python).

    🌳 Trees & Binary Search Trees

    A tree is a hierarchy of nodes: one root, each node has children; nodes without children are leaves. Height = longest root-to-leaf path.

    TypeRule / use
    Binary treeEach node has ≤ 2 children
    Binary Search Tree (BST)Left < node < right → search in O(h)
    Balanced (AVL, Red-Black)Keep height ≈ log n → guaranteed O(log n)
    B-Tree / B+ TreeWide nodes; used by databases and file systems
    TrieCharacters on edges; autocomplete, prefix search
    Segment / Fenwick treeRange queries and updates in O(log n)
    pythonclass TreeNode:
    def __init__(self, v): self.v, self.l, self.r = v, None, None

def insert(root, v):                  # BST insert
    if not root: return TreeNode(v)
    if v < root.v: root.l = insert(root.l, v)
    else:          root.r = insert(root.r, v)
    return root

def inorder(n):                       # gives sorted order for a BST
    return inorder(n.l) + [n.v] + inorder(n.r) if n else []

def height(n): return 0 if not n else 1 + max(height(n.l), height(n.r))
    EXAMPLE · Traversals

    For tree 4 → (2, 6): Inorder 2,4,6 · Preorder 4,2,6 · Postorder 2,6,4 · Level-order (BFS) 4,2,6.

    📝
    An unbalanced BST built from sorted input degrades to a linked list: O(n). That is why self-balancing trees exist.

    ⛰️ Heaps & Priority Queues

    A heap is a complete binary tree where each parent ≤ children (min-heap) or ≥ children (max-heap). It is stored in an array. Push/pop are O(log n); peek is O(1).

    pythonimport heapq
h = []
for x in [7, 2, 9, 4]: heapq.heappush(h, x)
print(heapq.heappop(h))   # 2 (smallest)

def k_largest(nums, k):               # O(n log k)
    return heapq.nlargest(k, nums)

    Use cases: task schedulers, Dijkstra, top-K problems, median maintenance (two heaps), heap sort.

from collections import deque
def bfs(g, start):                    # shortest path in unweighted graph
    seen, q, order = {start}, deque([start]), []
    while q:
        u = q.popleft(); order.append(u)
        for v in g[u]:
            if v not in seen: seen.add(v); q.append(v)
    return order

    ParadigmIdeaExample

    🔍 Searching

    pythondef linear(a, t):                     # O(n), works on unsorted data
    for i, x in enumerate(a):
        if x == t: return i
    return -1

def binary(a, t):                     # O(log n), needs SORTED data
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == t: return mid
        if a[mid] < t: lo = mid + 1
        else: hi = mid - 1
    return -1
    EXAMPLE · Binary search trace

    Find 23 in [2,5,8,12,16,23,38]: mid=12 → go right; mid=23 → found in 2 steps. 1 billion items need only ~30 steps.

    📝
    Binary search also solves "find the first value that satisfies a condition" (search on answer), a common expert-level pattern.

    📶 Sorting

    AlgorithmBestAverageWorstSpaceStable
    Bubble / Selection / InsertionO(n)*O(n²)O(n²)O(1)Bubble, Insertion: yes
    Merge sortO(n log n)O(n log n)O(n log n)O(n)Yes
    Quick sortO(n log n)O(n log n)O(n²)O(log n)No
    Heap sortO(n log n)O(n log n)O(n log n)O(1)No

    * Insertion sort is O(n) on already sorted data. A stable sort keeps equal items in their original order.

    pythondef merge_sort(a):
    if len(a) <= 1: return a
    m = len(a) // 2
    L, R = merge_sort(a[:m]), merge_sort(a[m:])
    out, i, j = [], 0, 0
    while i < len(L) and j < len(R):
        if L[i] <= R[j]: out.append(L[i]); i += 1
        else:            out.append(R[j]); j += 1
    return out + L[i:] + R[j:]

def quick_sort(a):
    if len(a) <= 1: return a
    p = a[len(a)//2]
    return (quick_sort([x for x in a if x < p]) +
            [x for x in a if x == p] +
            quick_sort([x for x in a if x > p]))
    💡
    Real languages use hybrids: Python and Java use Timsort (merge + insertion). Any comparison sort needs at least Ω(n log n) comparisons.

    🔁 Recursion & Divide and Conquer

    Recursion = a base case + a smaller recursive call. Each call is stacked on the call stack, so very deep recursion can overflow it.

    pythondef fact(n):                          # O(n) time, O(n) stack
    return 1 if n <= 1 else n * fact(n - 1)

def fib_slow(n):                      # O(2^n) - repeats work
    return n if n < 2 else fib_slow(n-1) + fib_slow(n-2)

def power(x, n):                      # O(log n) divide & conquer
    if n == 0: return 1
    h = power(x, n // 2)
    return h * h if n % 2 == 0 else h * h * x
    📝
    Master theorem (idea): T(n) = a·T(n/b) + f(n). Merge sort: 2·T(n/2) + n → O(n log n).

    💰 Greedy Algorithms

    Pick the locally best option at each step; it works only when a problem has the greedy-choice property and optimal substructure.

    pythondef max_activities(intervals):        # sort by end time, O(n log n)
    intervals.sort(key=lambda x: x[1])
    count, end = 0, float("-inf")
    for s, e in intervals:
        if s >= end: count += 1; end = e
    return count

    Other examples: Huffman coding, fractional knapsack, Kruskal and Prim (minimum spanning tree). Greedy fails for coins [1,3,4] making 6 (greedy gives 4+1+1, optimal is 3+3).

    🧮 Dynamic Programming (DP)

    DP solves problems with overlapping subproblems and optimal substructure by storing results: top-down (memoisation) or bottom-up (tabulation).

    pythonfrom functools import lru_cache
@lru_cache(None)
def fib(n): return n if n < 2 else fib(n-1) + fib(n-2)   # O(n)

def coin_change(coins, amount):       # O(amount * len(coins))
    dp = [0] + [float("inf")] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if a >= c: dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] != float("inf") else -1

def lcs(a, b):                        # longest common subsequence
    dp = [[0]*(len(b)+1) for _ in range(len(a)+1)]
    for i in range(1, len(a)+1):
        for j in range(1, len(b)+1):
            dp[i][j] = dp[i-1][j-1]+1 if a[i-1]==b[j-1] else max(dp[i-1][j], dp[i][j-1])
    return dp[-1][-1]
    🧭
    DP recipe: define the state → write the recurrence → set base cases → choose the order → optimise space. Classics: knapsack, edit distance, longest increasing subsequence.

    ↩️ Backtracking

    pythondef subsets(nums):
    res = []
    def go(i, cur):
        if i == len(nums): res.append(cur[:]); return
        go(i + 1, cur)                # skip
        cur.append(nums[i]); go(i + 1, cur); cur.pop()   # take, then undo
    go(0, []); return res
print(subsets([1, 2]))   # [[], [2], [1], [1, 2]]

    Use for permutations, combinations, N-Queens, Sudoku. Prune invalid branches early to avoid exponential blow-up.

    pythonimport heapq
def dijkstra(g, src):                 # g[u] = [(v, weight), ...]
    dist = {u: float("inf") for u in g}; dist[src] = 0
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]: continue
        for v, w in g[u]:
            if d + w < dist[v]:
                dist[v] = d + w; heapq.heappush(pq, (dist[v], v))
    return dist

    🧩 What is OOP?

    Object-Oriented Programming models software as objects that bundle data (attributes) and behaviour (methods). A class is the blueprint; an object is an instance of it.

    pythonclass BankAccount:
    def __init__(self, owner, balance=0):   # constructor
        self.owner = owner                   # attribute
        self.balance = balance
    def deposit(self, amount):               # method
        self.balance += amount

acc = BankAccount("Asha", 500)               # object
acc.deposit(250); print(acc.balance)         # 750

    ❓ Frequently Asked Questions

    Array vs linked list?
    Arrays: O(1) access, contiguous, cache friendly, costly middle inserts. Linked lists: O(1) insert/delete at a known node, O(n) access, extra pointer memory.
    How does a hash map work?
    A hash function maps the key to a bucket index; collisions are handled by chaining or open addressing; resize when load factor grows to keep O(1) average.
    Quick sort vs merge sort?
    Quick sort is in-place and fast in practice but O(n²) worst case and unstable. Merge sort is always O(n log n) and stable but needs O(n) extra space.
    Recursion vs iteration?
    Recursion is clearer for trees and divide and conquer but uses call-stack memory; iteration is leaner. Any recursion can be converted using an explicit stack.
    Abstract class vs interface?
    Abstract class: shared state and partial implementation, single inheritance. Interface: a pure contract that many classes can implement.
    Overloading vs overriding?
    Overloading: same name, different parameters, resolved at compile time. Overriding: subclass redefines a parent method, resolved at run time.
    What is the SOLID principle you apply most?
    Answer with a real example, e.g. Dependency Inversion: injecting a repository interface so you can mock it in tests.
    How do you approach an unknown problem?
    Clarify, give examples, state brute force and its complexity, optimise with a structure/pattern, code cleanly, test edge cases (empty, one item, duplicates, large input).

    ✅ Interview Checklist

    • Think aloud; confirm constraints before coding.
    • Always state time and space complexity.
    • Test with empty input, single element, duplicates, negative numbers.
    • Write readable names and small functions.
    • Practise 2–3 problems per pattern, not 200 random ones.
