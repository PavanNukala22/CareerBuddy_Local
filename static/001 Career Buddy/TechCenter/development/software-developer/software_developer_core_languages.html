    Programming Fundamentals

    The ideas every language shares — how code runs, how types work, and how memory is managed — shown side by side in Python, Java, C++ and C#.

    🧭 What is a programming language?

    A programming language is a precise, written way to give instructions to a computer. The CPU only understands machine code — raw numbers that mean things like “add these two registers”. A language lets humans write readable text (the source code) that tools then translate into something the machine can run.

    Every general-purpose language gives you the same core building blocks: values and variables, operators, decisions (if/else), repetition (loops), functions to name and reuse logic, and ways to group data (arrays, lists, objects). Once you know these ideas in one language, learning the next one is mostly learning new spelling.

    🏭 Compiled, interpreted, bytecode and JIT

    Source code must be turned into machine instructions at some point. Languages differ in when and how that happens.

    ModelHow it worksExamplesTrade-off
    Ahead-of-time (AOT) compiledA compiler turns the whole program into a native executable before it runs.C, C++, Rust, GoFast start and fast run, but you build per platform (Windows, Linux, ARM…).
    InterpretedAn interpreter reads the program and executes it step by step at run time.Classic shell scripts, early BASICVery flexible, quick edit-run cycle, slower execution.
    Bytecode + virtual machineA compiler produces portable bytecode; a VM runs it on each platform.Java (JVM), C# (CLR), Python (CPython VM)“Write once, run anywhere”; the VM adds start-up cost.
    Just-in-time (JIT)The VM compiles hot bytecode into native machine code while the program runs.JVM HotSpot, .NET RyuJIT, PyPySpeed close to native for long-running programs; warm-up time.
    The managed-language pipeline used by Java and C# (C++ compiles straight to machine code; CPython interprets its bytecode)
    EXAMPLE · The same idea, four routes
    • C++: g++ main.cpp -o app → native app executable → run directly by the OS.
    • Java: javac Main.java → Main.class bytecode → java Main runs it on the JVM, which JIT-compiles hot methods.
    • C#: dotnet build → a .dll containing IL (Intermediate Language) → the CLR JIT-compiles it.
    • Python: python app.py → CPython compiles to bytecode (cached in __pycache__) → the CPython VM interprets it.
    📝
    “Compiled vs interpreted” describes an implementation, not the language itself. Python is usually run by CPython (bytecode interpreter), but PyPy JIT-compiles it. C# can also be compiled ahead of time with Native AOT.

    🔤 Typing: static vs dynamic, strong vs weak

    A type says what kind of value something is (a whole number, text, a list…) and what you can do with it. Two separate questions describe a language's type system.

    QuestionOption AOption B
    When are types checked?Static — at compile time. Variables have a fixed type. (Java, C++, C#)Dynamic — at run time. Values have types; names can point to anything. (Python, JavaScript)
    How strict are conversions?Strong — mixing incompatible types is an error, not silently converted. (Python, Java, C#)Weak — the language converts implicitly and freely. (JavaScript "5" * 2 is 10; C lets you reinterpret memory)
    python# Python: dynamic + strong
x = 5          # x refers to an int
x = "five"     # now refers to a str - allowed (dynamic)
"5" + 2        # TypeError: can only concatenate str (not "int") to str  (strong)

    java// Java: static + strong
int x = 5;
x = "five";          // compile error: incompatible types
String s = "5" + 2;  // "52" - string concatenation is a defined rule, not weak typing

    C++ is statically typed but sits nearer the weak end: it allows many implicit numeric conversions (double → int truncates silently, with at most a warning) and lets you bypass types with casts and pointers. C# and Java also have type inference (var) — the type is still static, the compiler just works it out for you.

    💡
    Static typing catches many mistakes before the program runs and powers great IDE auto-complete. Dynamic typing is faster to write and change. Python's optional type hints plus a checker such as mypy give you some of both.

    🔭 Scope and lifetime

    Scope is where in the code a name can be used. Lifetime is how long the value it refers to exists. They are related but not the same.

    🧠 Memory: stack, heap and garbage collection

    Running programs use two main memory areas. The stack holds function call frames — parameters and local variables. It is fast and automatically cleaned up when a function returns. The heap holds data whose size or lifetime is not known at compile time, such as objects created with new. Something has to free heap memory when it is no longer needed.

    Stack

    • Allocation is just moving a pointer — very fast
    • Freed automatically when the function returns
    • Small (often about 1–8 MB per thread)
    • Too-deep recursion → stack overflow

    Heap

    • Larger, flexible lifetime
    • Allocation is slower
    • Must be reclaimed: by a GC, reference counting or the programmer
    • Mistakes → leaks or dangling pointers
    LanguageHow heap memory is reclaimed
    Python (CPython)Reference counting frees most objects immediately, plus a cyclic garbage collector for reference cycles.
    JavaTracing garbage collector (G1 by default; ZGC, Parallel also available). Unreachable objects are reclaimed in the background.
    C#Generational tracing GC in the CLR (gen 0/1/2 + large object heap). IDisposable/using handles non-memory resources.
    C++Manual / deterministic. Objects on the stack die at scope end; heap objects are freed by delete or, in modern code, by RAII owners such as std::unique_ptr.
    Garbage collection (GC)The runtime finds objects no longer reachable from the program and frees them for you.
    RAIIResource Acquisition Is Initialization — in C++, a resource is owned by an object and released in its destructor when the object goes out of scope.
    Memory leakMemory that is no longer needed but never freed. Possible even with a GC, if you keep references alive (e.g. an ever-growing static cache).
    Dangling pointerA pointer to memory that has already been freed. Using it is undefined behaviour in C++.
    💡
    A GC removes most memory bugs, but not resource bugs: files, sockets and database connections must still be closed. That is why Python has with, Java has try-with-resources and C# has using.

    The mutable-default trap

    Default values are evaluated once, when the def statement runs — not on every call. A mutable default is therefore shared between calls.

    basket.append(item)

    🔁 Iterators, generators, decorators and context managers

    An iterable is anything you can loop over (it has __iter__). An iterator produces the next value with __next__ and raises StopIteration when finished. A generator is the easy way to write an iterator: a function with yield.

    pythondef read_large_file(path):

def countdown(n):
    while n > 0:
        yield n
        n -= 1

gen = countdown(3)
print(next(gen), list(gen))         # 3 [2, 1]  - a generator is consumed once

    Decorators

    A decorator is a function that takes a function and returns a new one. @timer above def f means f = timer(f).

    pythonimport functools, time

def timer(func):
    @functools.wraps(func)          # keep func's name and docstring
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.3f}s")
        return result
    return wrapper

@timer
def slow_add(a, b):
    time.sleep(0.1)
    return a + b

    The GIL

    CPython has a Global Interpreter Lock (GIL): only one thread executes Python bytecode at a time in a process. Threads still help with I/O-bound work (the GIL is released while waiting on network or disk), but they do not speed up CPU-bound Python code.

    Heavy computation in Pythonmultiprocessing / ProcessPoolExecutorSeparate processes, each with its own GIL.

    📝
    Python 3.13 added an experimental free-threaded build (no GIL), and 3.14 made it officially supported, but the standard build still has the GIL. In interviews, explain the GIL and the workarounds above.

    PEP 8 essentials

    • 4 spaces per indent; lines around 79–99 characters.
    • snake_case for functions and variables, PascalCase for classes, UPPER_CASE for constants.

    🔒 RAII and smart pointers

    RAII (Resource Acquisition Is Initialization): wrap every resource — memory, file, lock, socket — in an object whose destructor releases it. Destructors run automatically when the object goes out of scope, even when an exception is thrown. This gives deterministic cleanup with no garbage collector.

    cpp#include <memory>
#include <mutex>
#include <fstream>

struct Engine { void start() {} };

void demo(std::mutex& m) {
    std::lock_guard<std::mutex> lock(m);        // locked here...
    std::ofstream log("log.txt");                // file opened here...

    auto e = std::make_unique<Engine>();         // sole owner
    e->start();
    auto e2 = std::move(e);                      // ownership transferred; e is now null

    auto s1 = std::make_shared<Engine>();        // shared ownership, use_count 1
    {
        auto s2 = s1;                            // use_count 2
    }                                            // use_count back to 1
    std::weak_ptr<Engine> w = s1;                // observes, does not own
    if (auto locked = w.lock()) { locked->start(); }
}   // ...destructors run in reverse order: s1, e2, log closes, lock releases
    Smart pointerOwnershipCopyable?CostUse when
    std::unique_ptr<T>ExclusiveNo (move only)Same as a raw pointerDefault choice for heap objects
    std::shared_ptr<T>Shared, reference-countedYesControl block + atomic countSeveral owners with unclear lifetime
    std::weak_ptr<T>None (observer)YesSmallBreak shared_ptr cycles, caches, back-pointers
    ⚠️
    Two objects holding shared_ptrs to each other form a cycle: their counts never reach zero and both leak. Make one direction a weak_ptr (e.g. child → parent).
    💡
    Prefer std::make_unique / std::make_shared over new: they are exception-safe and make_shared allocates the object and control block together.

    Rule of 3 / 5 / 0

    If a class manages a resource directly, the compiler-generated copy operations will copy the raw pointer, and two objects will free the same memory (a double free).

    • Rule of 3: if you need a custom destructor, copy constructor or copy assignment, you probably need all three.
    • Rule of 5: since C++11, also add the move constructor and move assignment.
    • Rule of 0 (preferred): hold resources in members that already manage themselves (std::string, std::vector, std::unique_ptr) and write none of the five.
    cpp#include <algorithm>
#include <cstddef>
#include <utility>

class Buffer {                                   // rule of 5, for illustration
public:
    explicit Buffer(std::size_t n) : size_(n), data_(new int[n]{}) {}
    ~Buffer() { delete[] data_; }
    Buffer(const Buffer& o) : size_(o.size_), data_(new int[o.size_]) {
        std::copy(o.data_, o.data_ + size_, data_);
    }
    Buffer& operator=(Buffer o) noexcept {       // copy-and-swap handles copy AND move
        std::swap(size_, o.size_);
        std::swap(data_, o.data_);
        return *this;
    }
    Buffer(Buffer&& o) noexcept : size_(o.size_), data_(o.data_) {
        o.size_ = 0;
        o.data_ = nullptr;
    }
private:
    std::size_t size_;
    int* data_;
};
// Rule of 0 version: class Buffer { std::vector<int> data_; };  - done.

    🚚 Move semantics basics

    Copying a big object (a vector of a million items) is expensive. Moving transfers its internal buffer to a new object and leaves the source in a valid but unspecified (typically empty) state — usually just a few pointer assignments.

    cpp#include <vector>
#include <string>
#include <utility>

std::vector<std::string> load() {
    std::vector<std::string> v(1'000'000, "row");
    return v;                        // no copy: moved or elided (RVO)
}

std::vector<std::string> a = load();
std::vector<std::string> b = a;              // copy - a still has 1M items
std::vector<std::string> c = std::move(a);   // move - steals a's buffer; a is now valid but unspecified (in practice empty)

std::string name = "Ana";
std::vector<std::string> names;
names.push_back(name);              // copies
names.push_back(std::move(name));   // moves; don't rely on name's value afterwards
names.emplace_back("Ben");          // constructs in place
    lvalueSomething with a name and an address you can take (x, v[0]).
    rvalueA temporary (x + 1, load()). Can bind to T&&.
    std::moveDoes not move anything — it casts to an rvalue reference so a move constructor/assignment can be chosen.
    RVO / copy elisionThe compiler builds a returned object directly in the caller's storage. Guaranteed for returning a prvalue since C++17.
    💡
    Mark move constructors noexcept. std::vector only moves elements during reallocation if the move cannot throw; otherwise it copies them for safety.

    ⚖️ Value types vs reference types

    A value type variable holds the data itself; assigning it copies the data. A reference type variable holds a reference to an object on the heap; assigning it copies the reference, so both variables see the same object.

    🚀 How to learn a second language fast

    1. Map what you know. Make a table: variables, loops, collections, classes, errors, modules in your first language vs the new one.
    2. Learn the memory and type model first. Value vs reference, who frees memory, how equality works. Most switching bugs live here.
    3. Learn the idioms, not just syntax. Comprehensions in Python, streams in Java, RAII in C++, LINQ in C#.
    4. Use the standard toolchain. Build tool, package manager, formatter, linter, test framework — set them up on day one.
    5. Port a small project. Rewrite something you already built (a CLI to-do app, a REST endpoint). You know the logic, so you only learn the language.
    6. Read idiomatic code. The language's standard library and popular open-source projects show how experts write it.
    7. Get code reviewed. A reviewer fluent in the language will spot “accent” — code that works but is written like your old language.

    🧭 Fundamentals

    What is the difference between a compiled and an interpreted language?

    A compiler translates the whole program ahead of time into machine code (C++) or bytecode (Java, C#). An interpreter executes code step by step at run time. Strictly, these describe implementations: Java and C# compile to bytecode which a VM then JIT-compiles; CPython compiles to bytecode which it interprets. Compiled native code is usually faster; interpreted code gives a quicker edit-run loop and more run-time flexibility.

    Explain static vs dynamic typing and strong vs weak typing.

    Static vs dynamic is about when types are checked: at compile time (Java, C++, C#) or at run time (Python). Strong vs weak is about how freely the language converts between types implicitly. Python is dynamic and strong ("5" + 2 raises TypeError); JavaScript is dynamic and weak; Java and C# are static and strong; C++ is static but allows many implicit conversions.

    What is the difference between the stack and the heap?

    The stack stores call frames — parameters and locals — and is freed automatically when a function returns; it is fast but small. The heap stores dynamically allocated objects with flexible lifetimes; it is larger but slower and must be reclaimed by a GC (Java, C#, Python) or by the programmer/RAII (C++). Deep recursion overflows the stack; forgetting to free heap memory leaks it.

    What is garbage collection and can a garbage-collected program still leak memory?

    A GC automatically frees objects that are no longer reachable from roots (stack variables, static fields). Yes, it can still leak: if you keep references to objects you no longer need — an ever-growing static cache, listeners never unsubscribed, a map keyed by request IDs — they stay reachable and are never collected.

    What is pass-by-value vs pass-by-reference? Which do Java and Python use?

    Pass-by-value copies the argument; pass-by-reference passes an alias so the callee can rebind the caller's variable. Java is always pass-by-value — for objects, the reference is copied, so a method can mutate the object but cannot make the caller's variable point elsewhere. Python is similar (“pass by object reference”). C++ supports both (T vs T&); C# supports both with ref/out.

    🐍 Python

    What is the difference between a list and a tuple?

    A list is mutable — you can append, remove and change items. A tuple is immutable, so it can be used as a dict key or set member (if its items are hashable) and signals “fixed record”. Tuples are slightly smaller and faster to create. Use a list for a collection that changes, a tuple for a fixed group of values such as (lat, lon).

    Explain the mutable default argument problem.

    Default values are evaluated once, when the function is defined. A mutable default like def f(x, acc=[]) is therefore shared across calls and accumulates data. Fix: default to None and create a new list inside the function.

    pythondef f(x, acc=None):
    if acc is None:
        acc = []
    acc.append(x)
    return acc
    What is the GIL and how do you work around it?

    The Global Interpreter Lock in CPython allows only one thread to execute Python bytecode at a time. Threads still help for I/O-bound work because the GIL is released while waiting. For CPU-bound work use multiprocessing/ProcessPoolExecutor, vectorised libraries such as NumPy that run in C, or C extensions that release the GIL. Python 3.13+ offers an optional free-threaded build without the GIL.

    What are generators and why use them?

    A generator is a function that uses yield to produce a sequence lazily — one value at a time, keeping its state between calls. It uses constant memory regardless of sequence length, so it is ideal for large files, streams and pipelines. A generator can be iterated only once.

    pythondef evens(limit):
    for n in range(0, limit, 2):
        yield n
print(sum(evens(10)))   # 20
    How does a decorator work? Write one that logs calls.

    A decorator is a callable that takes a function and returns a replacement. @log is shorthand for f = log(f). Use functools.wraps to keep the original name and docstring.

    pythonimport functools

def log(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"calling {func.__name__}{args}")
        return func(*args, **kwargs)
    return wrapper

@log
def add(a, b):
    return a + b

    ☕ Java

    Explain JDK, JRE and JVM.

    The JVM executes bytecode, manages memory with the GC and JIT-compiles hot code. The JRE is the JVM plus the standard libraries — enough to run an application. The JDK is the JRE plus development tools such as javac, jar and jshell. Modern Java ships as a JDK; jlink can create a custom runtime.

    Why must you override hashCode() when you override equals()?

    Hash-based collections (HashMap, HashSet) first use hashCode() to find a bucket, then equals() within it. The contract says equal objects must have equal hash codes. If you override only equals, two equal objects may land in different buckets, so set.contains(x) returns false and duplicates appear. Records generate both correctly.

    What is the difference between checked and unchecked exceptions?

    Checked exceptions extend Exception but not RuntimeException; the compiler forces you to catch them or declare them with throws (IOException). Unchecked exceptions extend RuntimeException and usually signal programming errors (NullPointerException, IllegalArgumentException). Many modern APIs prefer unchecked exceptions and wrap checked ones.

    Why is String immutable in Java?

    Immutability makes strings safe to share between threads without locks, allows the JVM to cache and intern literals in a string pool, makes them reliable HashMap keys (the hash can be cached), and protects security-sensitive values such as class names and file paths from being changed after validation.

    How do HashMap and ConcurrentHashMap differ?

    HashMap is not thread-safe: concurrent modifications can lose updates or corrupt its state. ConcurrentHashMap supports safe concurrent reads and writes using fine-grained locking and CAS operations, offers atomic methods like computeIfAbsent and merge, and does not allow null keys or values. Iterators are weakly consistent rather than fail-fast.

    ⚙️ C++

    What is RAII and why is it important?

    Resource Acquisition Is Initialization: acquire a resource in a constructor and release it in the destructor. Because destructors run automatically when objects leave scope — including during exception unwinding — resources can never leak. std::vector, std::unique_ptr, std::lock_guard and std::fstream are all RAII types.

    Compare unique_ptr, shared_ptr and weak_ptr.

    unique_ptr: exclusive ownership, move-only, zero overhead — the default. shared_ptr: shared ownership with an atomic reference count; the object dies when the last owner goes. weak_ptr: a non-owning observer of a shared_ptr object, used to break cycles; call lock() to get a temporary shared_ptr if the object still exists.

    What is the rule of three / five / zero?

    If a class needs a custom destructor, copy constructor or copy assignment operator, it almost certainly needs all three (rule of three), plus the move constructor and move assignment since C++11 (rule of five). The rule of zero says: design classes so they need none of them, by holding resources in RAII members like std::vector and std::unique_ptr.

    What does std::move do?

    std::move does not move anything. It is a cast to an rvalue reference (T&&), which allows overload resolution to pick a move constructor or move assignment. The moved-from object is left in a valid but unspecified state — you may assign to it or destroy it, but should not rely on its value.

    What is undefined behaviour? Give examples.

    Behaviour for which the C++ standard imposes no requirements — the program may crash, seem to work, or be “optimised” into something unexpected. Examples: out-of-bounds array access, dereferencing a null or dangling pointer, use after delete, double delete, signed integer overflow, reading an uninitialised variable, and data races. Detect it with sanitizers (-fsanitize=address,undefined) and avoid it with RAII and bounds-checked containers.

    🟪 C#

    What is the difference between a struct and a class in C#?

    A struct is a value type: variables contain the data, assignment copies it, it cannot be inherited from, and its default value is all-zero. A class is a reference type allocated on the heap: assignment copies the reference. Use structs for small, immutable, value-like data (Point, Money); use classes for everything else.

    How does async/await work?

    An async method is compiled into a state machine. At each await on an incomplete task, the method returns to its caller and the thread is freed; when the task completes, the rest of the method resumes as a continuation. It improves scalability for I/O-bound work because threads are not blocked while waiting.

    What is LINQ deferred execution?

    Most LINQ operators (Where, Select) build a query but do not run it. The query executes when it is enumerated — foreach, ToList(), Count(), First(). It re-runs every time it is enumerated, which can repeat expensive work or database calls; materialise with ToList() when you need the results more than once.

    What is the difference between IEnumerable and IQueryable?

    IEnumerable<T> runs LINQ in memory using delegates. IQueryable<T> builds an expression tree that a provider such as Entity Framework Core translates into SQL, so filtering happens in the database. Calling AsEnumerable() or ToList() too early pulls all rows into memory before filtering.

    What does the using statement do?

    It guarantees Dispose() is called on an IDisposable object when the block (or, with a using declaration, the enclosing scope) ends, even if an exception is thrown. It compiles to a try/finally. await using does the same for IAsyncDisposable.

    csharpusing var conn = new SqlConnection(connString);
await conn.OpenAsync();
// conn.Dispose() runs automatically at the end of the scope

    🔀 Cross-language and scenario

    How would you compare memory management in Python, Java, C++ and C#?

    Python (CPython) uses reference counting plus a cycle-detecting GC. Java and C# use tracing, generational garbage collectors, with try-with-resources/using for non-memory resources. C++ has no GC: lifetimes are deterministic — stack objects die at scope end and heap objects are owned by RAII types like unique_ptr. The trade-off is safety and productivity vs control and predictable latency.

    Your Python service is too slow. What do you do?

    First measure with a profiler (cProfile, py-spy) to find the hot spot. Then: fix the algorithm or data structure (a set instead of a list for lookups), cache results, batch I/O, use async for I/O-bound waits, vectorise with NumPy, use multiprocessing for CPU-bound work, and only then move the hot path to a C/C++ extension or a separate service. Re-measure after every change.

    When would you choose C++ over Java or C#?

    When you need predictable low latency with no GC pauses, tight control over memory layout, very small footprint or direct hardware access — game engines, trading systems, embedded firmware, browsers, databases. Choose Java/C# when developer productivity, safety, rich frameworks and easier hiring matter more than the last bit of performance.

    How is equality handled differently across the four languages?

    Python: == is value equality via __eq__; is is identity. Java: == is identity for objects; use equals(). C#: == is reference equality for classes by default but overloaded for string and records; Equals() can be overridden. C++: == calls operator==, which you define (or default in C++20); comparing pointers compares addresses.

    You are moving from Java to C#. What would you focus on first?

    Most concepts map directly (classes, interfaces, generics, GC, exceptions). Focus on what differs: properties instead of getters/setters, struct value types, LINQ instead of streams, async/await and Task, events and delegates, nullable reference types, no checked exceptions, using for disposal, and the dotnet CLI with NuGet instead of Maven/Gradle.
