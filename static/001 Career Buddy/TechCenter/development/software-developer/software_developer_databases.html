    Foundations

    What databases are, how relational databases work, and how PostgreSQL and MySQL fit in.

    🧭 What is a Database?

    A database is an organised collection of data stored so applications can save, find, update and delete it reliably. A DBMS (database management system) is the software that manages it; developers talk to it through a query language.

    💾
    Persist
    Data survives restarts, unlike variables in memory.
    🔍
    Query
    Find exactly the rows you need, fast.
    🔒
    Protect
    Control who can read or change data.
    🤝
    Share
    Many users and services use the same data safely.

    🗂️ Types of Databases

    💡
    This course focuses on relational databases — the default choice for most business applications.

    🧱 The Relational Model

    Data lives in tables (relations). Each row is one record, each column is one attribute with a data type. Tables connect through keys.

    SQLCREATE TABLE customers (id INT PRIMARY KEY, name VARCHAR(50), city VARCHAR(30));
CREATE TABLE orders (id INT PRIMARY KEY, customer_id INT REFERENCES customers(id),
                     amount DECIMAL(10,2), status VARCHAR(15), ordered_on DATE);
    EXAMPLE · Shop data

    customers holds people; orders holds purchases. orders.customer_id points to customers.id, so one customer can have many orders (one-to-many).

    🐘 PostgreSQL vs MySQL

    PostgreSQLMySQL
    StyleObject-relational, standards-focused, very extensibleSimple, fast, hugely popular for web apps
    StrengthsComplex queries, JSON/JSONB, window functions, extensionsEasy setup, strong read performance, wide hosting support

    Text quotingSingle quotes for strings; double quotes for identifiersSingle quotes for strings; backticks for identifiers
    📌
    Both speak SQL. Core syntax is ~90% identical; differences appear in data types, functions and advanced features.

    SchemaThe structure: tables, columns, types, constraints.

    ➕ INSERT, UPDATE, DELETE

    SQLINSERT INTO customers (id, name, city) VALUES (1,'Asha','Hyderabad'), (2,'Ravi','Vijayawada');
INSERT INTO orders VALUES (101,1,2500.00,'PAID','2026-09-01'), (102,1,800.00,'PENDING','2026-09-05'), (103,2,1200.00,'PAID','2026-09-07');
UPDATE orders SET status='PAID' WHERE id=102;
DELETE FROM orders WHERE status='CANCELLED';
    ⚠️
    Always include WHERE on UPDATE/DELETE — without it, every row is changed or removed.

    Module 03

    Joins & Aggregation

    Combine tables, summarise data with GROUP BY, and write subqueries.

    🔗 JOINs

    JoinReturns
    INNER JOINOnly rows that match in both tables
    LEFT JOINAll left rows + matches (NULL if none)
    RIGHT JOINAll right rows + matches
    FULL JOINAll rows from both (PostgreSQL; emulate in MySQL with UNION)
    CROSS JOINEvery combination
    SQLSELECT c.name, o.amount FROM customers c
INNER JOIN orders o ON o.customer_id = c.id;
-- customers with NO orders
SELECT c.name FROM customers c LEFT JOIN orders o ON o.customer_id = c.id WHERE o.id IS NULL;

    📊 Aggregates, GROUP BY, HAVING

    SQLSELECT c.name, COUNT(*) AS orders, SUM(o.amount) AS total
FROM customers c JOIN orders o ON o.customer_id = c.id
WHERE o.status = 'PAID'
GROUP BY c.name
HAVING SUM(o.amount) > 1000
ORDER BY total DESC;
    💡
    WHERE filters rows before grouping; HAVING filters groups after. Functions: COUNT SUM AVG MIN MAX.

    🪆 Subqueries & CASE

    SQLSELECT * FROM orders WHERE amount > (SELECT AVG(amount) FROM orders);
SELECT id, amount, CASE WHEN amount>=2000 THEN 'High' WHEN amount>=1000 THEN 'Medium' ELSE 'Low' END AS tier FROM orders;
    Q. Which clause filters groups after GROUP BY?
    • A WHERE
    • B HAVING
    • C ORDER BY
    • D LIMIT

    Design & Constraints

    Design clean schemas: keys, constraints, relationships and normalization.

    🔐 Keys & Constraints

    ConstraintPurpose
    PRIMARY KEYUnique, not null identifier
    FOREIGN KEYKeeps references valid
    UNIQUENo duplicates (e.g. email)
    NOT NULLValue required
    CHECKCustom rule, e.g. amount >= 0
    DEFAULTValue when none supplied
    SQLCREATE TABLE products (
  id SERIAL PRIMARY KEY,             -- MySQL: INT AUTO_INCREMENT PRIMARY KEY
  sku VARCHAR(20) UNIQUE NOT NULL,
  price DECIMAL(10,2) CHECK (price >= 0),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP);

    🔀 Relationships

    TypeExampleHow
    One-to-oneUser ↔ profileFK that is also UNIQUE
    One-to-manyCustomer → ordersFK on the “many” side
    Many-to-manyStudents ↔ coursesJunction table with two FKs

    🧹 Normalization

    1NFAtomic values — no lists in a cell.
    2NFEvery non-key column depends on the whole key.
    3NFNo column depends on another non-key column.
    DenormalizeDeliberately duplicate data to speed up reads (trade-off: consistency).
    EXAMPLE · Fixing a bad table

    orders(id, customer_name, customer_city, item) repeats customer data. Split into customers and orders with a foreign key — update a city once, not in 50 rows.

    ⚛️ Transactions & ACID

    SQLBEGIN;  -- MySQL: START TRANSACTION;
UPDATE accounts SET balance = balance - 500 WHERE id = 1;
UPDATE accounts SET balance = balance + 500 WHERE id = 2;
COMMIT;   -- or ROLLBACK; to undo both
    Isolation levelPreventsNotes
    Read CommittedDirty readsPostgreSQL default
    Repeatable Read+ non-repeatable readsMySQL InnoDB default
    Serializable+ phantomsStrictest, slowest

    ⚡ Indexes & EXPLAIN

    SQLCREATE INDEX idx_orders_customer ON orders (customer_id);
CREATE UNIQUE INDEX idx_cust_email ON customers (email);
EXPLAIN ANALYZE SELECT * FROM orders WHERE customer_id = 1;  -- PostgreSQL
EXPLAIN SELECT * FROM orders WHERE customer_id = 1;          -- MySQL
    💡
    Index columns used in WHERE, JOIN and ORDER BY. Indexes speed reads but slow writes and use space. Look for “Seq Scan” / “ALL” (full scans) in plans. Wrapping a column in a function (WHERE LOWER(name)=…) can stop index use.

    🪟 CTEs & Window Functions

    SQLWITH paid AS (SELECT * FROM orders WHERE status='PAID')
SELECT customer_id, amount,
       RANK() OVER (PARTITION BY customer_id ORDER BY amount DESC) AS rnk,
       SUM(amount) OVER (PARTITION BY customer_id) AS customer_total
FROM paid;

    Window functions calculate across related rows without collapsing them like GROUP BY.

    🛡️ Production Practices

    SQL injectionNever concatenate user input into SQL; use parameterised queries.
    N+1 queriesFetch related rows in one JOIN, not one query per row.
    MigrationsVersion schema changes (Flyway, Liquibase, Alembic).
    BackupsRegular dumps (pg_dump, mysqldump) and tested restores.
    PoolingReuse connections (PgBouncer, HikariCP).

    Module 06

    Interview Preparation

    Common database questions with crisp answers.

    🌱 Basics

    DELETE vs TRUNCATE vs DROP?
    DELETE removes chosen rows (logged, can rollback); TRUNCATE empties a table quickly; DROP removes the table itself.
    Primary key vs unique key?
    A table has one primary key (not null); it can have many unique keys (NULLs allowed in most databases).
    WHERE vs HAVING?
    WHERE filters rows before grouping; HAVING filters groups after aggregation.

    🚀 Intermediate & Expert

    INNER vs LEFT JOIN?
    INNER keeps only matches; LEFT keeps all left rows and fills NULL when no match.
    What is an index and its cost?
    A structure (usually B-tree) for fast lookups; costs storage and slows INSERT/UPDATE/DELETE.
    Explain ACID.
    Atomic (all or nothing), Consistent (rules preserved), Isolated (concurrent transactions don’t interfere), Durable (committed data survives crashes).
    PostgreSQL vs MySQL — when to choose which?
    PostgreSQL for complex queries, JSONB, extensions and strict standards; MySQL for simple, read-heavy web workloads and broad hosting support.
    How do you find a slow query?
    Use EXPLAIN (ANALYZE), slow query log / pg_stat_statements, then add indexes or rewrite the query.

    🛒 Scenario: ShopKart

    Use the customers and orders tables from Module 01. Try each task in PostgreSQL or MySQL before checking the model answer.

    1️⃣ Task 1 · Basic

    ✍️ List names of customers from Hyderabad, sorted A–Z.
    Model answer: SELECT name FROM customers WHERE city='Hyderabad' ORDER BY name;

    2️⃣ Task 2 · Joins

    ✍️ Show each customer’s name and total PAID amount, highest first.
    Model answer: SELECT c.name, SUM(o.amount) AS total FROM customers c JOIN orders o ON o.customer_id=c.id WHERE o.status='PAID' GROUP BY c.name ORDER BY total DESC;

    3️⃣ Task 3 · Find gaps

    ✍️ Find customers who have never placed an order.
    Model answer: SELECT c.name FROM customers c LEFT JOIN orders o ON o.customer_id=c.id WHERE o.id IS NULL;

    4️⃣ Task 4 · Expert

    ✍️ Add an index for “orders of a customer by date” and describe how to confirm it is used.
    Model answer: CREATE INDEX idx_orders_cust_date ON orders (customer_id, ordered_on); then run EXPLAIN and look for an index scan instead of a full table scan.
