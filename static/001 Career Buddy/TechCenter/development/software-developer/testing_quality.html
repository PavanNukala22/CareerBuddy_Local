    Course Overview

    Testing & Quality: unit testing, code reviews, debugging and basic CI/CD awareness, from "what is a test?" to designing a team quality strategy. Examples use Python and pytest; the ideas apply to any language.

    🎯 What is Software Quality?

    Software quality is how well software does what users need, correctly, reliably, securely and maintainably. It is built into every change, not inspected at the end.

    🏛️ The Four Pillars

    🧪
    Unit Testing
    Small automated checks proving each piece of code works.
    👀
    Code Reviews
    Teammates inspect changes before they are merged.
    🐞
    Debugging
    A repeatable method to find and fix the cause of defects.
    🔄
    CI/CD Awareness
    Automation that builds, tests and ships every change.

    🧭 How They Fit Together

    Write code→Unit tests→Pull request→Code review→CI pipeline→Deploy→Monitor→Debug→Fix + new test

    Module 04 · What is what
    Basic

    Fundamentals

    Definitions and types for every pillar, starting from zero.

    🔍 Bug, Fault, Failure

    A defect (mistake in code) causes a fault that may appear as a failure (wrong behaviour users see). Testing reveals failures; debugging locates the defect.

    🧪 What is Testing? Types

    Testing runs software with chosen inputs and compares the actual result with the expected result.

    TypeChecksExample
    UnitOne function or class in isolationadd(2,3) == 5
    IntegrationModules working togetherSave a user, read it back
    System / End-to-endWhole app as a user sees itSign up → log in → buy
    Acceptance (UAT)Meets the business needClient sign-off
    RegressionOld features still workRe-run suite after change
    SmokeBuild basically startsHome page loads
    Performance / SecuritySpeed, load, vulnerabilities1000 concurrent users

    Also know: manual vs automated · black-box vs white-box · static analysis (no run) vs dynamic (run).

    🔬 What is a Unit Test?

    An automated test of the smallest testable piece (a function or method) that runs in milliseconds, has no network or database, and passes or fails by itself.

    👀 What is a Code Review? Types

    A code review is a teammate examining your change before it is merged to find defects, share knowledge and keep the codebase consistent.

    TypeHow it works
    Pull / merge requestAsynchronous review on GitHub or GitLab (most common)
    Over-the-shoulderAuthor walks a colleague through the code
    Pair programmingTwo people write together; review is continuous
    Formal inspectionStructured meeting with roles; used in safety-critical work
    Automated reviewLinters, static analysers and bots comment on the PR

    🐞 What is Debugging? Bug Types

    Debugging is the process of finding the root cause of a failure and removing it.

    Bug typeMeaningExample
    SyntaxCode breaks language rulesMissing colon
    RuntimeCrashes while runningZeroDivisionError
    LogicRuns but gives wrong result< instead of <=
    PerformanceCorrect but too slow or heavyQuery inside a loop
    ConcurrencyFails depending on timingRace condition

    🔄 What is CI/CD?

    Continuous Integration
    Merge small changes often; each triggers an automatic build and tests.
    Continuous Delivery
    Every passing change is release-ready; a human clicks deploy.
    Continuous Deployment
    Every passing change goes to production automatically.
    Module 05

    Core Concepts

    The ideas you will reuse in every project.

    🧱 Anatomy of a Test

    def test_discount_applied():
    price = 200                          # Arrange: set up data
    result = apply_discount(price, 10)   # Act: call the code
    assert result == 180                 # Assert: verify outcome

    F.I.R.S.T.: Fast · Independent · Repeatable · Self-validating · Timely.

    📖 Test Vocabulary

    Test case / suite
    One check / a group run together.
    Assertion
    A statement that must be true.
    Fixture
    Reusable setup and teardown.
    Stub · Mock · Fake
    Stand-ins for real dependencies.
    Coverage
    % of code executed by tests.

    🤝 Review Principles

    • Review the code, not the person.
    • Small changes get better reviews; big PRs get rubber-stamped.
    • Ask questions before giving orders; praise good work.
    • Automate style so humans discuss design and logic.

    🧠 Debugging Mindset

    Treat debugging as a science experiment: form a hypothesis, test it, keep what the evidence supports. Never change code randomly hoping it works.

    🏗️ Pipeline Anatomy

    Trigger→Build→Lint→Test→Package→Deploy

    A quality gate stops the pipeline when a check fails.

    Module 07

    Practical Examples

    One worked example per pillar.

    🧪 First Unit Test

    # calc.py
def add(a, b):
    return a + b

# test_calc.py
from calc import add
def test_add_positive(): assert add(2, 3) == 5
def test_add_negative(): assert add(-1, -1) == -2

    Run pytest -v. Files named test_*.py and functions named test_* are discovered automatically.

    💥 Testing Errors

    import pytest
def divide(a, b):
    if b == 0: raise ValueError("b must not be zero")
    return a / b

def test_divide_by_zero():
    with pytest.raises(ValueError, match="zero"):
        divide(10, 0)

    👀 Reviewing a Snippet

    def avg(nums):
    return sum(nums) / len(nums)   # what if nums is empty?
    💬
    Good comment: "This raises ZeroDivisionError for an empty list. Should we return None or raise a clearer error? Could you add a test for it?"

    🐞 Debugging Walkthrough

    def largest(nums):
    big = 0                 # suspect: wrong start value
    for n in nums:
        if n > big: big = n
    return big

largest([-5, -2])   # returns 0, expected -2

    Reproduce with [-5, -2] → Isolate the starting value → Fix with big = nums[0] → Verify and keep the failing case as a regression test.

    🔄 A Basic CI File

    # .github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -r requirements.txt pytest
      - run: pytest

    Module 09
    Intermediate

    Intermediate Concepts

    Move from single tests to maintainable suites and real team workflows.

    🧰 Fixtures

    @pytest.fixture
def cart():
    c = Cart(); c.add("pen", 10)
    return c

def test_total(cart): assert cart.total() == 10

    🔢 Parametrization

    @pytest.mark.parametrize("n, expected", [(0, False), (2, True), (9, False), (13, True)])
def test_is_prime(n, expected): assert is_prime(n) is expected

    🎭 Mocking

    DoublePurpose
    StubReturns canned answers
    MockRecords calls so you can verify them
    FakeLight working version, e.g. in-memory DB
    from unittest.mock import patch
def test_msg():
    with patch("app.get_temp", return_value=35):
        assert weather_msg("Delhi") == "Hot"

    📊 Coverage

    Run pytest --cov=src --cov-report=term-missing. Coverage shows what was executed, not what was verified.

    🔁 TDD

    Red: failing test→Green: simplest code→Refactor

    💬 Review Craft

    • Blocking (must fix), suggestion (optional), nit (tiny style), question, praise: label each comment.
    • As author: self-review first, keep PRs under ~400 lines, respond to every comment.
    • Review order: description → tests → implementation.

    🔦 Debugger & Logging

    import logging
logging.basicConfig(level=logging.DEBUG)
log = logging.getLogger(__name__)
log.debug("cart=%s", cart)
breakpoint()   # pdb: n next, s step, c continue, p var, q quit

    ⚡ Pipeline Features

    • Caching dependencies for faster builds.
    • Matrix builds: test on several Python versions.
    • Secrets stored in the CI vault, never in code.
    • Environments: dev → staging → production.
    Module 10
    Expert

    Advanced Concepts

    Strategy, reliability and scale.

    🔺 Test Pyramid

    Many fast unit tests (~70%), fewer integration tests (~20%), very few end-to-end tests (~10%). An inverted pyramid gives slow, fragile suites.

    🎲 Flaky Tests

    Tests that pass and fail without code changes. Causes: shared state, time, randomness, network, ordering, async races. Fix: freeze time, seed random, isolate state, mock network; quarantine quickly.

    🧬 Property & Mutation Testing

    from hypothesis import given, strategies as st
@given(st.lists(st.integers()))
def test_sort_idempotent(xs): assert sorted(sorted(xs)) == sorted(xs)

    Mutation testing (mutmut) alters your code; if no test fails, your tests are too weak.

    🏢 Reviews at Scale

    • CODEOWNERS routes changes to the right reviewers.
    • Stacked PRs split large features into reviewable steps.
    • Track review turnaround and PR size; run blameless post-mortems.

    🕵️ Bisect & Root Cause

    git bisect start
git bisect bad            # current version broken
git bisect good v1.2.0    # old version worked
# mark each checkout good/bad until Git names the commit

    Use 5 Whys to move from symptom to root cause; profile with cProfile for performance bugs.

    🚀 Deployment Strategies

    StrategyIdea
    Blue-greenTwo identical environments; switch traffic instantly, roll back by switching back
    CanaryRelease to a small % of users first, then widen
    Feature flagsShip code turned off; enable gradually
    RollingReplace instances a few at a time

    Module 12

    Testing & Quality

    Bringing all four pillars into one quality process.

    🚧 Quality Gates

    Automatic rules that block a merge: failing tests, coverage below threshold, lint or type errors, security alerts, missing approval.

    ✅ Definition of Done

    • Tests for normal, edge and error cases.
    • CI green; at least one approval.
    • Useful logs and error messages; docs updated.

    📈 Quality Metrics

    MetricMeaningCaution
    Coverage% lines executedNot test quality
    Defect escape rateBugs found in productionNeeds honest tracking
    Flaky rate% unreliable testsAim for zero
    DORA metricsDeploy frequency, lead time, change failure rate, recovery timeTrack trends, not targets

    📝 Review Checklist

    Correctness · Design · Readability · Tests · Security · Performance. Leave style to automated tools.

    Module 14

    Best Practices

    Habits that separate reliable teams from fragile ones.

    🧪 Unit Testing

    ✅ Do

    • Test behaviour, not internals
    • Name tests like sentences
    • Cover empty, zero, negative, None

    ❌ Don't

    • Write tests with no assertions
    • Share state between tests
    • Chase 100% coverage

    👀 Code Reviews

    ✅ Do

    • Keep PRs small
    • Ask questions, give reasons
    • Review promptly

    ❌ Don't

    • Rubber-stamp approvals
    • Argue about style by hand
    • Make it personal

    🐞 Debugging

    ✅ Do

    • Reproduce first
    • Change one thing at a time
    • Add a regression test

    ❌ Don't

    • Guess and patch symptoms
    • Leave debug prints in code
    • Debug without version control

    🔄 CI/CD

    ✅ Do

    • Fix red builds immediately
    • Keep pipelines fast
    • Store secrets in a vault

    ❌ Don't

    • Merge with failing checks
    • Skip tests to ship faster
    • Deploy without rollback plan

    🧪 Testing Questions

    Unit test vs integration test?
    A unit test checks one piece in isolation with dependencies mocked. An integration test checks that components work together, e.g. code plus a real database.
    What is a mock and when do you use one?
    A fake dependency that records its usage. Use it to isolate code from slow or unpredictable things: networks, databases, clocks.
    Does 100% coverage mean no bugs?
    No. It shows lines executed, not behaviour verified. Weak assertions and missing edge cases still leave bugs.
    Explain TDD.
    Red-Green-Refactor: write a failing test, make it pass with minimal code, then clean up with tests as a safety net.
    How do you handle a flaky test?
    Reproduce it, find the nondeterminism, fix the root cause, and quarantine it meanwhile so it does not block the team.

    👀 Review & Debugging Questions

    What do you look for in a code review?
    Correctness, edge cases, design, readability, tests, security and performance. I leave style to linters and phrase feedback constructively.
    A production bug is reported. What do you do?
    Reproduce, check logs and recent changes, isolate (or git bisect), fix the root cause, add a regression test, ship, and write a blameless post-mortem.
    What is git bisect?
    A binary search through commit history that finds the exact commit that introduced a bug.

    🔄 CI/CD Questions

    CI vs Continuous Delivery vs Continuous Deployment?
    CI builds and tests every merge. Delivery keeps every build releasable with a manual release step. Deployment releases every passing build automatically.
    What is a canary release?
    Releasing to a small share of users first, watching metrics, then widening or rolling back.

    Test what you've learned

    • Difficulty from Simple to Hard

    🔒 Exam Rules & Security

    • The test runs in fullscreen with a countdown timer; it auto-submits when time is up.
    • No tab or window switching, no losing window focus and no exiting fullscreen. Each violation shows a warning screen; after 3 warnings the test auto-submits.
    • Copy, cut, print, save, view-source, right-click and the F12 developer-tools shortcut are disabled, and the PrintScreen key is blocked where the browser allows it. Refreshing or closing the page asks for confirmation.
    • Navigate freely, mark questions for review, then submit. Results and explanations appear only after submission.
    • Answers are graded on the LMS server when available, so they are never present in the page.
    Module 18

    Course Summary

    Quality is a habit built from four connected practices.

    🧾 Key Takeaways

    • Unit testing: fast, independent tests following Arrange-Act-Assert form the base of the pyramid.
    • Code reviews: small, kind, checklist-driven reviews catch defects and spread knowledge.
    • Debugging: reproduce, isolate, hypothesize, fix the root cause, verify, add a regression test.
    • CI/CD: automation runs quality checks on every change and makes releases safe and repeatable.
