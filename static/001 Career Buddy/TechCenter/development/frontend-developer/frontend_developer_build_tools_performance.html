    Module 01 · Basics

    What are Build Tools?

    Why we bundle code, and how Vite and Webpack work.

    🧭 What is what?

    Browsers don't understand TypeScript, JSX or hundreds of modules efficiently. A build tool transforms and bundles your source into optimised files the browser can load fast.

    📦
    Bundling
    Combine many modules into a few files.
    🔄
    Transpiling
    TS/JSX/modern JS → browser-compatible JS.
    🗜️
    Minifying
    Remove whitespace, shorten names.
    🌲
    Tree-shaking
    Drop unused exports.

    ⚡ Vite vs Webpack

    ViteWebpack
    Dev serverNative ES modules, instant startBundles before serving
    ProductionRollup (Rolldown soon)Webpack itself
    ConfigMinimalPowerful but verbose
    Best forNew projectsLegacy, complex setups

    🚀 Your first Vite project

    bashnpm create vite@latest my-app -- --template react-ts
cd my-app && npm install
npm run dev      # http://localhost:5173
npm run build    # outputs /dist

    Module 02 · Responsive & Compat

    Responsive Design & Cross-Browser Compatibility

    Make sites work on every screen and browser.

    📱 Responsive web design

    html<meta name="viewport" content="width=device-width, initial-scale=1">
    css.grid { display: grid; gap: 1rem; grid-template-columns: 1fr; }
@media (min-width: 768px) { .grid { grid-template-columns: repeat(3, 1fr); } }
img { max-width: 100%; height: auto; }
    • Mobile-first: base styles for small screens, enhance with min-width.
    • Use relative units (rem, %, vw, fr) and clamp().
    • <picture> + srcset for responsive images.

    🌍 Cross-browser compatibility

    • Check support on caniuse.com / MDN compatibility tables.
    • Progressive enhancement: core works everywhere, extras where supported (@supports).
    • Autoprefixer + browserslist add vendor prefixes automatically.
    • Babel / SWC transpile syntax; polyfills only if truly needed.
    • Test Chrome, Firefox, Safari (iOS!), Edge.
    css@supports (display: grid) { .layout { display: grid; } }

    Module 03 · Configuration

    Configuring Vite & Webpack

    Aliases, env variables, code splitting and loaders.

    🛠️ vite.config.ts

    typescriptimport { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
export default defineConfig({
  plugins: [react()],
  resolve: { alias: { "@": "/src" } },
  server: { proxy: { "/api": "http://localhost:3000" } },
  build: { rollupOptions: { output: { manualChunks: { vendor: ["react", "react-dom"] } } } },
});

    Env vars: only VITE_* are exposed — import.meta.env.VITE_API_URL.

    🧰 Webpack concepts

    EntryWhere bundling starts.
    OutputWhere bundles are written (use [contenthash]).
    LoadersTransform files: babel-loader, css-loader.
    PluginsWider tasks: HtmlWebpackPlugin, MiniCssExtractPlugin.
    Modedevelopment vs production.

    ✂️ Code splitting

    Module 04 · Web Vitals & Expert

    Core Web Vitals & Performance Optimisation

    Measure, diagnose and fix real-world performance.

    📊 Core Web Vitals

    MetricMeasuresGood
    LCPLargest Contentful Paint — loading≤ 2.5 s
    INPInteraction to Next Paint — responsiveness≤ 200 ms
    CLSCumulative Layout Shift — visual stability≤ 0.1
    javascriptimport { onLCP, onINP, onCLS } from "web-vitals";
[onLCP, onINP, onCLS].forEach(f => f(m => navigator.sendBeacon("/analytics", JSON.stringify(m))));

    🔧 Optimisation playbook

    Improve LCPPreload hero image, fetchpriority="high", use AVIF/WebP, CDN, SSR/SSG, inline critical CSS.
    Improve INPBreak long tasks, requestIdleCallback, Web Workers, debounce handlers, avoid heavy re-renders.
    Improve CLSSet width/height or aspect-ratio on media, reserve space for ads, font-display: swap.
    Bundle sizeAnalyse with rollup-plugin-visualizer, tree-shake, lazy-load routes, replace heavy libs.
    CachingHashed filenames + Cache-Control: immutable, service worker, HTTP/2/3.
    html<img src="hero.avif" width="1200" height="600" fetchpriority="high" alt="Hero">
<img src="below.avif" width="600" height="400" loading="lazy" decoding="async" alt="">
<link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>

    🧪 Tools

    • Lighthouse (lab), PageSpeed Insights / CrUX (field data), Chrome DevTools Performance panel.
    • Set performance budgets in CI (Lighthouse CI) so regressions fail the build.

    Module 05 · Practice

    Practice: Speed Up a Slow Landing Page

    Diagnose and fix a real-feeling performance problem.

    0 / 0 correct

    🎯 Scenario

    A landing page scores LCP 5.2 s, CLS 0.31, 2.4 MB JS. The hero is a 3 MB PNG, fonts load late and images have no dimensions.

    ✍️ List 5 fixes in priority order.
    Model answer: 1) Convert hero to AVIF/WebP, resize, fetchpriority="high". 2) Add width/height to all images (CLS). 3) Preload font + font-display: swap. 4) Code-split routes and remove unused libs (analyse bundle). 5) Lazy-load below-fold images; add CDN caching.
