    🌱 What is the Spring Framework?

    Spring is an open-source application framework for Java. Its heart is a container that creates your objects (called beans), wires them together and manages their lifecycle, so you write business logic instead of plumbing code.

    🔴 Without Spring

    Classes create their own dependencies with new. Code is tightly coupled, hard to test, and every project re-writes connection handling, transaction code and configuration.

    🟢 With Spring

    You declare what you need; Spring supplies it. Classes depend on interfaces, are easy to replace with mocks, and cross-cutting concerns (transactions, security, logging) are applied declaratively.

    Why was Spring created?

    • Early enterprise Java (EJB 2.x) was heavy: XML descriptors, application servers needed for even simple tests.
    • Spring offered a lightweight alternative based on plain Java objects (POJOs) — no special base classes or interfaces.
    • Today Spring is the de-facto standard for Java back-end development: REST APIs, microservices, batch, messaging, cloud.
    Example — the problem Spring solves
    java// Tightly coupled: OrderService decides WHICH payment class to use
public class OrderService {
    private final PaymentGateway gateway = new StripeGateway();   // hard-wired
    public void checkout(Order o) { gateway.charge(o.getTotal()); }
}
// To test or switch to PayPal you must edit OrderService.

    With Spring, OrderService only knows the PaymentGateway interface; the container injects the concrete implementation.

    📌
    Version note: examples use the Jakarta namespace (jakarta.*) and Java 17+, as in Spring Framework 6+/Spring Boot 3+. The concepts are identical in newer releases; always check the release notes for renamed starters or test annotations.

    🔌 Inversion of Control & Dependency Injection

    Inversion of Control means you give up control of creating and wiring objects to the container. Dependency Injection is how: the container hands each object the collaborators it needs.

    Types of dependency injection

    TypeHowWhen to useVerdict
    Constructor injectionDependencies are constructor parametersRequired dependencies; immutable classes✅ Recommended default
    Setter injectionContainer calls setter methodsOptional or re-configurable dependencies🟡 Acceptable
    Field injection@Autowired directly on a fieldQuick demos only🔴 Avoid in production code
    javapublic interface PaymentGateway { void charge(double amount); }

@Component
public class StripeGateway implements PaymentGateway {
    public void charge(double amount) { System.out.println("Stripe charged " + amount); }
}

@Service
public class OrderService {
    private final PaymentGateway gateway;          // final => immutable, never null

    // Constructor injection (single constructor => @Autowired optional since Spring 4.3)
    public OrderService(PaymentGateway gateway) { this.gateway = gateway; }

    public void checkout(double total) { gateway.charge(total); }
}
    ✅
    Why constructor injection? Dependencies are explicit and final, the object can never exist half-built, circular dependencies fail fast, and unit tests need no Spring at all: new OrderService(mock).

    🔁 Bean Scopes & Lifecycle

    Bean scopes

    ScopeMeaningTypical use
    singleton (default)One shared instance per containerStateless services, repositories
    prototypeNew instance on every request for the beanStateful, short-lived helpers
    requestOne per HTTP request (web only)Request-scoped data holders
    sessionOne per HTTP session (web only)User session state
    application / websocketPer ServletContext / WebSocket sessionRare
    ⚠️
    Singleton beans are shared by many threads. Never keep mutable per-request state in fields of a singleton — keep it stateless or use method-local variables.

    Bean lifecycle

    1. Container reads bean definitions
    2. Instantiates the bean (constructor)
    3. Injects dependencies
    4. Aware callbacks (BeanNameAware, ApplicationContextAware)
    5. BeanPostProcessor.postProcessBeforeInitialization
    6. @PostConstruct → InitializingBean.afterPropertiesSet → custom initMethod
    7. BeanPostProcessor.postProcessAfterInitialization (proxies are created here)
    8. Bean is ready
    9. On shutdown: @PreDestroy → DisposableBean.destroy → custom destroyMethod
    java@Component
public class CacheWarmer {
    @PostConstruct
    void init() { System.out.println("Warming cache..."); }   // after injection

    @PreDestroy
    void cleanup() { System.out.println("Flushing cache..."); } // before shutdown
}
    💡
    Prototype beans are not destroyed by the container — Spring does not call @PreDestroy for them. Inject a prototype into a singleton via ObjectProvider<T> to get a fresh instance each call.

    🎯 Aspect-Oriented Programming (AOP)

    AOP lets you add behaviour (logging, timing, security, transactions) around existing methods without touching their code. These are cross-cutting concerns — they cut across many classes.

    AspectA class holding cross-cutting logic (@Aspect).
    Join pointA point in execution — in Spring AOP, always a method execution.
    PointcutAn expression selecting which join points to intercept.
    AdviceThe action: @Before, @After, @AfterReturning, @AfterThrowing, @Around.
    WeavingLinking aspects to targets. Spring does it at runtime using proxies.
    java@Aspect
@Component
public class TimingAspect {
    private static final Logger log = LoggerFactory.getLogger(TimingAspect.class);

    @Around("execution(* com.example.shop.service..*(..))")   // every method in service package
    public Object time(ProceedingJoinPoint pjp) throws Throwable {
        long t0 = System.nanoTime();
        try {
            return pjp.proceed();                              // call the real method
        } finally {
            log.info("{} took {} ms", pjp.getSignature(), (System.nanoTime() - t0) / 1_000_000);
        }
    }
}

    Expert: how proxies really work

    • Spring wraps a bean in a proxy — a JDK dynamic proxy (when the bean implements an interface and proxy-target-class is off) or a CGLIB subclass proxy (Spring Boot default).
    • @Transactional, @Async, @Cacheable, @PreAuthorize all work through proxies.
    • CGLIB cannot proxy final classes/methods, and private methods are never intercepted.
    ⚠️
    Self-invocation pitfall: calling this.otherMethod() inside the same class bypasses the proxy, so @Transactional/@Async on otherMethod silently does nothing. Move it to another bean, or inject the proxy.
    java@Service
class ReportService {
    public void generate() { this.save(); }   // ❌ no transaction: call does not go through the proxy

    @Transactional
    public void save() { ... }
}

    🚀 Expert: Container Internals & Design Judgement

    • BeanFactoryPostProcessor modifies bean definitions before instantiation (e.g. property placeholder resolution); BeanPostProcessor modifies bean instances (e.g. creating AOP proxies, processing @Autowired).
    • Circular dependencies: A needs B, B needs A. Constructor injection fails fast (BeanCurrentlyInCreationException); Spring Boot 2.6+ forbids cycles by default. Fix the design — extract a third class or use events — rather than enabling allow-circular-references.
    • @Lazy defers creation until first use; useful for startup time and for breaking a cycle as a last resort.
    • FactoryBean<T> lets a bean produce another object (how many framework integrations work). &name fetches the factory itself.
    • Resource handling & type conversion: ConversionService, Converter, Formatter power @Value, request binding and @ConfigurationProperties.
    • Context hierarchy: child contexts (e.g. a web context) can see parent beans but not vice-versa.
    Design judgement checklist
    • Is this bean stateless? (If not, why is it a singleton?)
    • Does it depend on an interface I can swap in tests?
    • Am I using constructor injection with final fields?
    • Is cross-cutting logic in an aspect instead of copy-pasted?
    • Would a domain event make this coupling disappear?
    Q. A @Transactional method is called from another method in the same class. What happens?

    🥾 What is Spring Boot?

    Spring Boot is an opinionated layer on top of Spring that gives you a runnable, production-ready application with minimal setup. It does not replace Spring — it configures it for you.

    🔴 Plain Spring

    Manually pick compatible library versions, write DispatcherServlet/DataSource/TransactionManager configuration, build a WAR and deploy it to an external Tomcat.

    🟢 Spring Boot

    Add a starter, write main(). Boot auto-configures beans, embeds Tomcat, manages versions and ships a single runnable JAR.

    🧰
    Starters
    One dependency pulls a curated, version-aligned set of libraries.
    🤖
    Auto-configuration
    Beans are created automatically based on what is on the classpath.
    🖥️
    Embedded server
    Tomcat/Jetty/Undertow inside the JAR — java -jar app.jar.
    📊
    Actuator
    Health, metrics and info endpoints ready for production.
    ⚙️
    Externalised config
    Properties, YAML, env vars, profiles, config trees.

    🤖 Auto-Configuration Explained

    @SpringBootApplication is a shortcut for three annotations:

    AnnotationRole
    @SpringBootConfigurationMarks the class as a configuration class (@Configuration)
    @EnableAutoConfigurationTurns on auto-configuration
    @ComponentScanScans the main class package and below

    How auto-configuration works

    1. Boot reads the list of auto-configuration classes from META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports in every JAR.
    2. Each class is guarded by conditions (@ConditionalOnClass, @ConditionalOnMissingBean, @ConditionalOnProperty…).
    3. If the conditions pass, its @Bean methods are registered. Your own beans always win because of @ConditionalOnMissingBean.
    java@AutoConfiguration
@ConditionalOnClass(DataSource.class)                    // only if JDBC is on the classpath
public class DataSourceAutoConfiguration {
    @Bean
    @ConditionalOnMissingBean                            // back off if the user defined one
    DataSource dataSource(DataSourceProperties props) { ... }
}
    💡
    See why something was (not) configured: run with --debug or debug=true to print the conditions evaluation report; or call the /actuator/conditions endpoint.
    Conditional annotationPasses when
    @ConditionalOnClass / OnMissingClassA class is / is not on the classpath
    @ConditionalOnBean / OnMissingBeanA bean exists / does not exist
    @ConditionalOnPropertyA property has a given value
    @ConditionalOnWebApplicationApp is a (servlet/reactive) web app
    @ConditionalOnExpressionA SpEL expression is true

    Production-readiness techniques

    • Graceful shutdown: server.shutdown=graceful + spring.lifecycle.timeout-per-shutdown-phase=30s lets in-flight requests finish.
    • Virtual threads (Java 21+, Boot 3.2+): spring.threads.virtual.enabled=true — simple blocking code scales for I/O-bound workloads.
    • Observability: Micrometer metrics + tracing (OpenTelemetry bridge), structured logging, correlation IDs.
    • Startup/footprint: lazy initialisation (spring.main.lazy-initialization=true), class-data sharing, and GraalVM native images (./mvnw -Pnative native:compile) for fast start.
    • Connection pool: tune HikariCP maximum-pool-size to DB capacity, not to thread count.
    • Config for containers: one immutable image, behaviour via env vars/ConfigMaps; use liveness/readiness probes.
    • Fail fast: @Validated properties + Flyway validate so bad config stops startup, not production traffic.

    🌐 What is Spring MVC?

    Spring MVC is Spring's web framework built on the Servlet API. It implements the Model–View–Controller pattern: a Controller handles the request, the Model carries data, and the View (HTML template or JSON) produces the response.

    PartResponsibilityIn Spring
    ModelData and business rulesPOJOs, DTOs, services
    ViewPresentationThymeleaf/JSP template, or JSON via HttpMessageConverter
    ControllerReceives input, calls services, picks a response@Controller, @RestController

    Request lifecycle

    Spring MVC request lifecycle — the DispatcherServlet is the single front controller.
    1. The DispatcherServlet (front controller) receives every request.
    2. HandlerMapping finds the controller method matching URL + HTTP method.
    3. HandlerAdapter calls it, resolving arguments (@PathVariable, @RequestBody…) via argument resolvers.
    4. The method returns a view name (MVC) or an object (REST) that HttpMessageConverter writes as JSON/XML.
    5. Exceptions are handled by HandlerExceptionResolvers (@ControllerAdvice).

    🎛️ Types of Controllers & Mapping Annotations

    🖼️ @Controller

    Returns a view name; model attributes render into a template (Thymeleaf). Add @ResponseBody per method for JSON.

    🔗 @RestController

    @Controller + @ResponseBody — every method returns the response body (JSON by default). Used for REST APIs.

    🔐 What is Spring Security?

    Spring Security is the standard framework for securing Spring applications. It provides authentication (who are you?), authorization (what may you do?) and protection against common attacks (CSRF, session fixation, clickjacking, header attacks).

    🪪 Authentication (AuthN)

    Verifying identity: username + password, token, certificate, social login. Failure → 401 Unauthorized.

    🛂 Authorization (AuthZ)

    Deciding access for a known user: roles, permissions, ownership rules. Failure → 403 Forbidden.

    💡
    Adding spring-boot-starter-security secures everything immediately: all endpoints require login, a default user user is created and its password is printed in the startup log. You then customise from this safe default.

    📖 Core Concepts & Key Terms

    SecurityFilterChainThe ordered list of security filters applied to matching requests (Spring Security 6 bean-based config).
    AuthenticationObject holding principal, credentials and authorities; "unauthenticated" before login, "authenticated" after.
    SecurityContext / SecurityContextHolderWhere the current Authentication is stored (thread-local).
    UserDetails / UserDetailsServiceUser model and the service that loads a user by username.
    GrantedAuthorityA permission or role string, e.g. ROLE_ADMIN, product:write.
    AuthenticationManager / AuthenticationProviderCoordinates authentication; providers implement the actual checks.
    PasswordEncoderHashes and verifies passwords — never store plain text.
    PrincipalThe authenticated user (username or UserDetails).
    Spring Security is a chain of servlet filters in front of Spring MVC.
    1. A request enters the filter chain.
    2. An authentication filter extracts credentials and builds an unauthenticated Authentication.
    3. The AuthenticationManager delegates to AuthenticationProviders, which use UserDetailsService + PasswordEncoder.
    4. On success the authenticated Authentication is stored in the SecurityContext.
    5. The authorization filter checks access rules; the request continues or gets 401/403.

    🧯 Intermediate: CSRF, CORS, Sessions & Headers

    CSRF (Cross-Site Request Forgery)

    A malicious site makes the victim's browser send a state-changing request using the victim's cookies. Spring Security enables CSRF protection by default for browser flows: forms must include the CSRF token (Thymeleaf adds it automatically).

    • Keep CSRF on for session/cookie-based apps.
    • Disable only for stateless APIs that authenticate with a Bearer token header (no ambient cookies): http.csrf(c -> c.disable()).
    • For SPAs using cookies, use CookieCsrfTokenRepository.withHttpOnlyFalse().

    Issuing your own JWT (login endpoint) — what a custom flow needs

    1. POST /auth/login → authenticate with AuthenticationManager.authenticate(new UsernamePasswordAuthenticationToken(u, p)).
    2. Create a short-lived access token (5–15 min) signed with a strong key (RS256/ES256 or a 256-bit+ HS256 secret from a secret store) with claims: sub, iat, exp, roles.
    3. Issue a refresh token (stored server-side/hashed, rotated on use, revocable).
    4. Validate every request: signature, exp, issuer, audience. Prefer the resource-server support above (NimbusJwtDecoder) to a hand-written filter.
    ⚠️
    JWT pitfalls: never store secrets in the payload (it is only encoded, not encrypted); avoid long expiries; do not put tokens in localStorage if XSS is a risk (prefer HttpOnly cookies or a BFF pattern); always enforce the alg.

    Interview Preparation

    Frequently asked Spring questions grouped by topic, with concise model answers. Click a question to reveal the answer.

    🌱 Spring Core Questions

    What is the difference between BeanFactory and ApplicationContext?
    BeanFactory is the basic container (lazy bean creation). ApplicationContext extends it with eager singleton initialisation, event publishing, i18n, resource loading and AOP/annotation integration. Use ApplicationContext in real applications.
    Why prefer constructor injection over field injection?
    It makes dependencies explicit and final, guarantees a fully-initialised object, detects circular dependencies early, and lets you unit-test with plain new and mocks — no reflection or Spring needed.
    Explain bean scopes and a singleton-thread-safety risk.
    Scopes: singleton (default), prototype, request, session, application. A singleton is shared across threads, so mutable instance fields cause race conditions. Keep singletons stateless or synchronise carefully.
    How does Spring resolve two beans of the same type?
    By @Primary, @Qualifier, bean name matching the parameter name, or by injecting a List/Map of all candidates. Otherwise it throws NoUniqueBeanDefinitionException.
    How does AOP work in Spring? What is the self-invocation issue?
    Spring creates a JDK or CGLIB proxy around the bean and runs advice before/after/around the call. A call from inside the same object (this.method()) bypasses the proxy, so @Transactional, @Async, @Cacheable have no effect.
    Difference between @Component, @Service, @Repository, @Controller?
    All are stereotypes registered by component scanning. @Repository also translates persistence exceptions; @Controller marks web handlers; @Service is semantic for business logic.
    What is the bean lifecycle?
    Instantiate → populate dependencies → Aware callbacks → BeanPostProcessor before-init → @PostConstruct/afterPropertiesSet/init-method → after-init (proxies) → ready → @PreDestroy/destroy on shutdown.

    🥾 Spring Boot Questions

    What does @SpringBootApplication do?
    It combines @SpringBootConfiguration, @EnableAutoConfiguration and @ComponentScan.
    How does auto-configuration work?
    Boot loads candidate classes from AutoConfiguration.imports in every JAR and applies them only when their conditions match (@ConditionalOnClass, @ConditionalOnMissingBean, @ConditionalOnProperty). User-defined beans take precedence.
    How do you externalise configuration and handle environments?
    Use application.yml, profile files (application-prod.yml), environment variables and command-line args (higher precedence), plus @ConfigurationProperties for type-safe binding. Secrets go to env vars/secret stores.
    What is Spring Boot Actuator used for?
    Production endpoints: health (liveness/readiness), metrics, info, env, mappings, loggers, Prometheus export. Expose only what you need and secure them.
    @SpringBootTest vs @WebMvcTest vs @DataJpaTest?
    Full context vs MVC-only slice (controllers, advice, converters; services mocked) vs JPA-only slice with an embedded DB. Slices are faster and more focused.
    How would you create a custom starter?
    Create an auto-configuration class with conditional @Beans and a @ConfigurationProperties class, register it in AutoConfiguration.imports, and publish a starter module that depends on it.

    🌐 Spring MVC Questions

    Explain the Spring MVC request flow.
    Request → DispatcherServlet → HandlerMapping → HandlerAdapter → controller → service → return value converted by HttpMessageConverter (REST) or ViewResolver (MVC) → response. Exceptions go to HandlerExceptionResolver/@ControllerAdvice.
    @Controller vs @RestController?
    @RestController = @Controller + @ResponseBody: return values are written to the body (JSON) instead of resolved as view names.
    @PathVariable vs @RequestParam vs @RequestBody?
    Path segment (/users/{id}), query/form parameter (?page=2), and the deserialised request body (JSON).
    How do you handle exceptions globally?
    @RestControllerAdvice with @ExceptionHandler methods returning ProblemDetail/ResponseEntity, mapping domain exceptions to proper status codes and a consistent error body.
    Filter vs Interceptor?
    Filters are servlet-level and run before the DispatcherServlet (good for security, logging, compression). Interceptors are Spring MVC-level and have access to the handler (preHandle, postHandle, afterCompletion).
    How do you design REST APIs well?
    Nouns for resources, correct verbs and status codes, DTOs not entities, validation, pagination, idempotency, versioning, consistent error format, OpenAPI documentation.

    🗄️ Spring Data JPA Questions

    JPA vs Hibernate vs Spring Data JPA?
    JPA is the specification; Hibernate is an implementation; Spring Data JPA is a repository abstraction on top that generates implementations and queries.
    What is the N+1 problem and how do you fix it?
    One query for parents plus one per child to load a lazy association. Fix with JOIN FETCH, @EntityGraph, batch fetching (default_batch_fetch_size), or DTO projections.
    LAZY vs EAGER fetching?
    LAZY loads on first access (proxy); EAGER loads immediately with the owner. Prefer LAZY and fetch explicitly per use case; eager mappings cannot be turned off per query.
    How does @Transactional work? Rollback rules?
    A proxy opens/commits a transaction around public methods called from outside. By default only unchecked exceptions (and Error) roll back; use rollbackFor for checked ones.
    Explain propagation REQUIRED vs REQUIRES_NEW.
    REQUIRED joins the caller's transaction (or starts one). REQUIRES_NEW suspends it and runs an independent transaction that commits/rolls back separately.
    Optimistic vs pessimistic locking?
    Optimistic uses a @Version column and fails on conflicting updates (low contention). Pessimistic locks rows with SELECT … FOR UPDATE (high contention).
    What is dirty checking?
    Hibernate snapshots managed entities and, at flush/commit, issues UPDATEs for fields that changed — no explicit save needed inside a transaction.
    Why avoid ddl-auto=update in production?
    It is unpredictable, cannot handle data migrations or renames safely, and offers no review/rollback. Use Flyway/Liquibase and validate.

    🔐 Spring Security Questions

    Authentication vs authorization?
    Authentication proves identity (401 on failure); authorization decides what an identified user may do (403 on failure).
    Describe the Spring Security architecture.
    A DelegatingFilterProxy/FilterChainProxy runs a SecurityFilterChain. Authentication filters create an Authentication, the AuthenticationManager delegates to providers (UserDetailsService + PasswordEncoder), the result is stored in the SecurityContext, and the authorization filter enforces rules.
    How do you secure REST APIs with JWT?
    Stateless sessions, CSRF disabled for bearer-token APIs, configure oauth2ResourceServer().jwt() (or a validation filter), map claims to authorities, short-lived access tokens + refresh tokens, HTTPS, proper CORS.
    hasRole vs hasAuthority?
    hasRole("ADMIN") checks the authority ROLE_ADMIN (prefix added automatically); hasAuthority checks the exact string.
    What is CSRF and when can you disable it?
    An attack that abuses ambient browser credentials (cookies). Keep it enabled for cookie/session apps; for stateless APIs authenticated with an Authorization header it can be disabled.
    How do you store passwords?
    Hash with an adaptive, salted algorithm (BCrypt/Argon2) via PasswordEncoder, ideally DelegatingPasswordEncoder to allow upgrades. Never reversible encryption or plain hashes.
    How does method security differ from URL security?
    URL rules guard routes; method security (@PreAuthorize, @PostAuthorize) guards business operations with SpEL, can reference arguments and return values, and applies regardless of entry point.
