    Build & Dependency Tools

    Start from zero: what a build tool is, why Java projects need one, and the main types.

    🧭 What is a Build Tool?

    A build tool automates everything between your source code and a runnable product: downloading libraries, compiling, testing, packaging (JAR/WAR) and publishing. A dependency manager fetches the libraries you use — and the libraries they use — at the right versions.

    🔴 Without a build tool

    Copy JARs by hand, run javac and jar manually, "works on my machine", version clashes.

    🟢 With a build tool

    One command builds, tests and packages. Same result on every laptop and CI server.

    🏛️ Types of Build Tools

    ToolConfigModelBest for
    AntXML (build.xml)Imperative targets, no built-in dependency managementLegacy projects
    MavenXML (pom.xml)Declarative, fixed lifecycle, convention over configurationEnterprise, predictable builds
    GradleKotlin/Groovy DSLTask graph (DAG), incremental, cachedLarge/multi-module, Android
    BazelStarlarkHermetic, remote-cachedHuge monorepos
    💡
    Today ~everything in the Java ecosystem is Maven or Gradle. Both use Maven Central as the main repository.

    📖 Key Terms

    ArtifactA built output: JAR, WAR, POM.
    Coordinates (GAV)groupId : artifactId : version — unique address, e.g. org.slf4j:slf4j-api:2.0.13.
    RepositoryServer holding artifacts: Maven Central, company Nexus/Artifactory, local ~/.m2.
    Transitive dependencyA dependency of your dependency, pulled in automatically.
    Scope / ConfigurationWhen a dependency is needed: compile, test, runtime…
    SNAPSHOTUnreleased, changing version (1.0-SNAPSHOT).
    BOMBill of Materials: a POM that fixes compatible versions for a family of libraries.
    PluginAdds capability (compile, test, package, Docker image).
    Q. What does the coordinate groupId:artifactId:version identify?
    • A A Git commit
    • B A unique artifact in a repository
    • C A Java package
    • D A JVM flag

    Module 02 · Maven

    Apache Maven

    Convention over configuration: the POM, the lifecycle, dependency management and multi-module builds.

    🧰 What is Maven?

    Maven is a declarative build and dependency tool. You describe what the project is in a POM (Project Object Model, pom.xml); Maven follows a fixed lifecycle and standard directory layout to do the rest.

    layoutmy-app/
├─ pom.xml
└─ src/
   ├─ main/java        production code
   ├─ main/resources   config, templates
   ├─ test/java        tests
   └─ test/resources

    📄 The POM — Your First pom.xml

    xml<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>
  <groupId>com.acme</groupId>
  <artifactId>orders</artifactId>
  <version>1.0.0-SNAPSHOT</version>
  <packaging>jar</packaging>
  <properties>
    <maven.compiler.release>21</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>
  <dependencies>
    <dependency>
      <groupId>com.google.guava</groupId>
      <artifactId>guava</artifactId>
      <version>33.2.1-jre</version>
    </dependency>
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter</artifactId>
      <version>5.10.2</version>
      <scope>test</scope>
    </dependency>
  </dependencies>
</project>

    Every POM inherits from the Super POM; a <parent> element adds your own inheritance. Effective POM (mvn help:effective-pom) shows the final merged result.

    🔄 Lifecycle, Phases & Goals

    A lifecycle is an ordered list of phases; plugins bind goals to phases. Running a phase runs all earlier phases.

    PhaseWhat happens
    validateCheck project is correct
    compileCompile main sources
    testRun unit tests (Surefire)
    packageCreate JAR/WAR
    verifyRun integration tests (Failsafe), checks
    installCopy artifact to local ~/.m2
    deployPublish to remote repository

    Three built-in lifecycles: clean, default, site.

    shellmvn clean package           # clean + build + test + JAR
mvn -DskipTests package      # skip tests
mvn dependency:tree          # see transitive graph
mvn -pl core -am test        # one module + what it needs

    🔗 Dependencies, Scopes & Conflicts

    ScopeCompileTestRuntime / packaged
    compile (default)✔✔✔
    provided✔✔✘ (server supplies it)
    runtime✘✔✔
    test✘✔✘
    importBOM only, inside dependencyManagement
    • Nearest-wins: with two versions of a library, the one closest to your project in the tree wins.
    • Exclusions cut an unwanted transitive dependency.
    • dependencyManagement pins versions without adding the dependency.
    ⚠️
    Never depend on LATEST or version ranges in production — builds stop being reproducible.

    🚀 Expert: Multi-module, Profiles & Plugins

    xml<!-- parent pom.xml: multi-module + central version control -->
<packaging>pom</packaging>
<modules><module>core</module><module>api</module></modules>
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-dependencies</artifactId>
      <version>3.3.0</version>
      <type>pom</type><scope>import</scope>   <!-- BOM import -->
    </dependency>
  </dependencies>
</dependencyManagement>
<profiles>
  <profile><id>ci</id>
    <properties><skipITs>false</skipITs></properties>
  </profile>
</profiles>
    • Plugins to know: compiler, surefire/failsafe, jar, shade/assembly (fat JAR), spring-boot, jacoco, enforcer (ban duplicate classes/versions), versions, release.
    • Profiles switch behaviour per environment (-Pci).
    • Speed: mvn -T 1C parallel builds, mvnd daemon, Maven Wrapper (./mvnw) pins the Maven version.
    • Quality gates: enforcer rules, dependency:analyze, OWASP dependency-check, SBOM (CycloneDX).

    Module 03 · Gradle

    Gradle

    A flexible, fast, task-graph build tool with a Kotlin/Groovy DSL.

    🐘 What is Gradle?

    Gradle models a build as a directed acyclic graph (DAG) of tasks. Build files are real code (Kotlin DSL build.gradle.kts or Groovy build.gradle), so logic is easy to express. It is the default for Android and widely used for large Java/Kotlin systems.

    ProjectOne buildable unit; a build may have many (multi-project).
    TaskSmallest unit of work: compileJava, test, jar.
    PluginAdds tasks and conventions (java, java-library, application).
    ConfigurationNamed group of dependencies: implementation, api…
    Wrapper./gradlew downloads the exact Gradle version.
    DaemonLong-lived JVM that makes repeat builds fast.

    📄 Your First build.gradle.kts

    kotlinplugins {
    java
    application
}
group = "com.acme"; version = "1.0.0"

java { toolchain { languageVersion = JavaLanguageVersion.of(21) } }
repositories { mavenCentral() }

dependencies {
    implementation("com.google.guava:guava:33.2.1-jre")
    api("org.apache.commons:commons-lang3:3.14.0")   // java-library only
    runtimeOnly("org.postgresql:postgresql:42.7.3")
    testImplementation(platform("org.junit:junit-bom:5.10.2"))
    testImplementation("org.junit.jupiter:junit-jupiter")
}
application { mainClass = "com.acme.Main" }
tasks.test { useJUnitPlatform() }
    shell./gradlew build        # compile + test + jar
./gradlew test --tests "*OrderTest"
./gradlew dependencies --configuration runtimeClasspath
./gradlew build --scan      # build scan report

    🔗 Dependency Configurations

    ConfigurationMeaning
    implementationNeeded to compile & run; not exposed to consumers (faster rebuilds)
    apiExposed to consumers (java-library plugin)
    compileOnlyCompile only (like Maven provided)
    runtimeOnlyRuntime only (JDBC drivers)
    testImplementationTests only
    💡
    Prefer implementation over api: when an internal library changes, fewer modules recompile.

    🔄 How Gradle Runs: 3 Phases

    1. Initialization — read settings.gradle.kts, decide which projects exist.
    2. Configuration — evaluate build scripts and build the task graph.
    3. Execution — run only the tasks needed, skipping ones whose inputs/outputs are unchanged (UP-TO-DATE) or restored from the build cache.

    🚀 Expert: Catalogs, Custom Tasks, Convention Plugins

    kotlin// gradle/libs.versions.toml  (version catalog)
[versions]
guava = "33.2.1-jre"
[libraries]
guava = { module = "com.google.guava:guava", version.ref = "guava" }

// build.gradle.kts
dependencies { implementation(libs.guava) }

// custom task with inputs/outputs => incremental + cacheable
abstract class Hello : DefaultTask() {
    @get:Input abstract val who: Property<String>
    @TaskAction fun run() = println("Hello ${who.get()}")
}
tasks.register<Hello>("hello") { who = "LMS" }
    • Convention plugins (buildSrc or build-logic) share config across modules.
    • Toolchains download and use the exact JDK required.
    • Performance: enable org.gradle.caching, parallel, configuration cache; avoid work in configuration phase.
    • Composite builds (includeBuild) develop libraries and apps together.

    Maven vs Gradle

    StyleDeclarative XMLScripted DSL

    SpeedGood, mvnd helpsOften faster (incremental, cache)

    Module 04 · Language & Runtime

    Java Language Fundamentals

    What Java is, its types, and the core syntax every developer must master.

    ☕ What is Java?

    Java is a statically typed, object-oriented, general-purpose language. Source (.java) is compiled by javac into platform-neutral bytecode (.class) that any JVM runs — "write once, run anywhere".

    TermMeaning
    JVMVirtual machine that executes bytecode
    JREJVM + standard libraries (runtime only)
    JDKJRE + compiler and tools (javac, jar, jshell)
    javapublic class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
// javac Hello.java  ->  java Hello

    🔢 Data Types

    Two families: primitives (stored by value) and reference types (objects, stored as references).

    TypeSizeExample
    byte / short / int / long8 / 16 / 32 / 64 bitint n = 42; long big = 1L;
    float / double32 / 64 bitdouble p = 3.14;
    char16-bit Unicodechar c = 'A';
    booleantrue / falseboolean ok = true;
    ReferenceString, arrays, classes, interfaces, enums, recordsString s = "hi";
    📝
    Each primitive has a wrapper (Integer, Double…). Autoboxing converts automatically; compare wrappers with equals, not ==.

    🧩 Control Flow, Arrays & Strings

    javaint[] scores = {80, 92, 67};
int total = 0;
for (int s : scores) total += s;
String grade = switch (total / scores.length) {   // switch expression
    case 90, 91, 92 -> "A";
    default -> total / scores.length >= 70 ? "B" : "C";
};
var text = "Java";            // local type inference
String t2 = text.toUpperCase();   // Strings are IMMUTABLE

    String pool: literals are shared; new String("a") creates a separate object. Use StringBuilder for loops that concatenate.

    🏗️ Object-Oriented Programming

    📦
    Encapsulation
    Private fields, public methods.
    🧬
    Inheritance
    extends reuses behaviour.
    🎭
    Polymorphism
    Same call, different behaviour at runtime.
    🧩
    Abstraction
    Hide detail with interfaces / abstract classes.
    javasealed interface Shape permits Circle, Rect {}
record Circle(double r) implements Shape {}
record Rect(double w, double h) implements Shape {}

static double area(Shape s) {
    return switch (s) {                       // pattern matching
        case Circle c -> Math.PI * c.r() * c.r();
        case Rect r   -> r.w() * r.h();
    };
}
    • Interface = contract (can have default methods); abstract class = partial implementation with state.
    • Override equals and hashCode together.
    • Prefer composition over inheritance and immutability (record, final).

    🚨 Exceptions

    Checked exceptions (IOException) must be handled or declared. Unchecked (RuntimeException) signal bugs. Error (OutOfMemoryError) is not meant to be caught.

    javatry (var in = Files.newBufferedReader(path)) {   // auto-closes
    return in.readLine();
} catch (IOException e) {
    throw new UncheckedIOException(e);
}

    Collections, Generics, Streams & Concurrency

    The standard library and modern Java features used daily in real projects.

    📚 Collections Framework

    TypeImplementationsUse when
    ListArrayList, LinkedListOrdered, duplicates OK; ArrayList by default
    SetHashSet, LinkedHashSet, TreeSetUniqueness; Tree = sorted
    MapHashMap, LinkedHashMap, TreeMap, ConcurrentHashMapKey → value lookup
    Queue/DequeArrayDeque, PriorityQueueFIFO / LIFO / priority
    javaList<String> names = List.of("Ana", "Raj");       // immutable
Map<String,Integer> m = new HashMap<>();
m.merge("java", 1, Integer::sum);

    Expert: HashMap buckets use hashCode; collisions become trees at 8+ entries. Keys must be effectively immutable. Plain collections are not thread-safe.

    🧪 Generics

    Generics add compile-time type safety: List<String>. Types are erased at runtime. Wildcards: ? extends T (read, producer) and ? super T (write, consumer) — PECS.

    javastatic <T extends Comparable<T>> T max(List<T> xs) {
    return Collections.max(xs);
}

    ⚡ Lambdas, Streams & Optional

    javarecord Emp(String name, String dept, double pay) {}
Map<String, Double> avg = emps.stream()
    .filter(e -> e.pay() > 30_000)
    .collect(Collectors.groupingBy(Emp::dept,
             Collectors.averagingDouble(Emp::pay)));

Optional<Emp> top = emps.stream()
    .max(Comparator.comparingDouble(Emp::pay));
String n = top.map(Emp::name).orElse("none");
    💡
    Streams are lazy: nothing runs until a terminal operation (collect, forEach). Avoid side effects; use parallel() only after measuring.

    🧵 Concurrency

    A thread is a unit of execution. Share state safely or the program breaks (race conditions, deadlocks, visibility bugs).

    ToolPurpose
    synchronized, ReentrantLockMutual exclusion
    volatile, atomicsVisibility / lock-free counters
    ExecutorServiceThread pools
    CompletableFutureAsync pipelines
    Virtual threads (Java 21)Millions of cheap threads for blocking I/O
    javatry (var ex = Executors.newVirtualThreadPerTaskExecutor()) {
    var f = ex.submit(() -> fetch(url));   // blocks cheaply
    System.out.println(f.get());
}

    Module 06 · Language & Runtime

    The JVM & Runtime Internals

    How Java code actually runs: class loading, memory, garbage collection, JIT and tuning.

    🔄 From Source to Execution

    Java compile-and-run pipeline

    The JVM first interprets bytecode, then the JIT compiler compiles hot methods to native code (C1 quick, C2 optimised — tiered compilation).

    🧠 Class Loading & Memory Areas

    AreaHoldsShared?
    HeapObjects (Young: Eden + Survivors; Old)All threads
    StackFrames: locals, call chainPer thread
    MetaspaceClass metadata (native memory)All threads
    Code cacheJIT-compiled codeAll threads

    Class loaders (bootstrap → platform → application) use parent delegation. Loading → linking (verify, prepare, resolve) → initialization (static blocks).

    ♻️ Garbage Collection

    The GC reclaims objects that are no longer reachable from GC roots (stacks, statics). Most objects die young, so GCs are generational.

    CollectorGoalFlag
    SerialTiny apps, single core-XX:+UseSerialGC
    ParallelMax throughput-XX:+UseParallelGC
    G1 (default)Balanced, predictable pauses-XX:+UseG1GC
    ZGCSub-millisecond pauses, huge heaps-XX:+UseZGC
    ShenandoahLow pause, concurrent compaction-XX:+UseShenandoahGC
    ⚠️
    Memory leaks in Java = objects still reachable but no longer needed (static maps, unclosed listeners, ThreadLocals).

    🛠️ Tuning, Diagnostics & Versions

    shelljava -Xms2g -Xmx2g -XX:+UseG1GC \
     -XX:MaxGCPauseMillis=200 \
     -Xlog:gc*:file=gc.log \
     -XX:+HeapDumpOnOutOfMemoryError -jar app.jar
    ToolUse
    jcmd / jpsList & control JVMs
    jstackThread dumps (deadlocks)
    jmap / MATHeap dumps, leak analysis
    JFR + JMCLow-overhead profiling
    • Set -Xms = -Xmx on servers; measure before tuning; in containers the JVM respects cgroup limits.
    • LTS releases: 8, 11, 17, 21, 25 — use an LTS in production.
    • JPMS (Java 9+): module-info.java declares what a module requires and exports.

    Module 07 · Practice

    Hands-on Practice

    Apply what you learned across build tools and the language runtime.

    🎬 Scenario

    Your team maintains a Java 21 order service. Builds are slow, a transitive library conflict appears, and production shows long GC pauses.

    1️⃣ Task 1 · Maven

    ✍️ Two libraries pull different versions of jackson-databind. How do you find and fix it?
    Model answer: Run mvn dependency:tree -Dincludes=com.fasterxml.jackson.core, then pin the version in dependencyManagement (or import the Jackson BOM), exclude the unwanted transitive, and add the enforcer dependencyConvergence rule.

    2️⃣ Task 2 · Gradle

    ✍️ Write the dependency lines: Guava used internally, JDBC driver at runtime only, JUnit for tests.
    Model answer: implementation("com.google.guava:guava:33.2.1-jre"); runtimeOnly("org.postgresql:postgresql:42.7.3"); testImplementation("org.junit.jupiter:junit-jupiter").

    3️⃣ Task 3 · Language

    ✍️ Using streams, return the names of employees earning over 50 000, sorted alphabetically.
    Model answer: emps.stream().filter(e -> e.pay() > 50_000).map(Emp::name).sorted().toList();
    Q. Two Employee objects with equal data are not found in a HashSet. Likely cause?
    • A HashSet is broken
    • B equals/hashCode not overridden together
    • C Strings are immutable
    • D Wrong JDK

    4️⃣ Task 4 · Runtime

    ✍️ Production shows 3-second GC pauses on an 8 GB heap. List your investigation steps.
    Model answer: Enable GC logging (-Xlog:gc*), check pause cause and promotion rate, take a JFR recording and heap dump, look for leaks or large allocations, then consider G1 pause goals or ZGC, and re-measure after each change.
