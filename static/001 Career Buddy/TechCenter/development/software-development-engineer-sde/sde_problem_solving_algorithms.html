    Module 01 · Foundations

    What is Problem Solving?

    Start from zero: what an algorithm and a data structure are, and the 5-step routine every SDE uses to attack a problem.

    🧭 What is an Algorithm?

    An algorithm is a finite, step-by-step set of instructions that turns an input into a correct output. A recipe is an algorithm; so is the way your phone finds a contact in a sorted list.

    A data structure is a way of organising data in memory so that the operations you need (search, insert, delete, update) are fast. Algorithms and data structures always go together: the right structure often makes the algorithm trivial.

    🔴 Brute force thinking

    Try everything. Check each pair, each subset, each path. Works for tiny inputs, collapses at scale.

    🟢 Engineered thinking

    Pick the right data structure, spot a pattern, and cut the work from millions of steps to a handful.

    EXAMPLE · Finding a name in a phonebook of 1,000,000 entries
    • Linear scan: check every entry — up to 1,000,000 steps.
    • Binary search (book is sorted): halve the range each time — only about 20 steps.

    🎯 What makes a good algorithm?

    ✅
    Correct
    Gives the right answer for every valid input, including edge cases.
    ⚡
    Time-efficient
    Number of operations grows slowly as input grows.
    💾
    Space-efficient
    Uses a reasonable amount of extra memory.
    📖
    Readable
    Others (and future you) can understand and maintain it.

    🪜 The 5-step problem-solving routine

    1. Understand — restate the problem, list inputs, outputs, constraints (n ≤ 10⁵? values negative? duplicates?).
    2. Examples — work 2–3 small cases by hand, including an edge case (empty, single element, all equal).
    3. Brute force first — state the simplest correct solution and its complexity out loud.
    4. Optimise — look for repeated work, sorted order, or a better data structure. Ask: "what am I recomputing?"
    5. Code, test, analyse — write clean code, dry-run it on your examples, then state time and space complexity.
    💡
    Constraints are a hint. n ≤ 20 suggests exponential / bitmask; n ≤ 10³ allows O(n²); n ≤ 10⁵ needs O(n log n); n ≤ 10⁸ needs O(n) or better.

    📖 Key Terms

    Input size (n)The quantity that makes the problem "bigger": array length, number of nodes, digits in a number.
    Brute forceA direct solution that tries all possibilities.
    Edge caseUnusual valid input: empty, one element, duplicates, maximum size, negative numbers.
    InvariantA condition that stays true throughout a loop; the key to proving correctness.
    RecursionA function that solves a problem by calling itself on smaller inputs.
    PseudocodePlain-language, language-independent description of an algorithm.
    Q. Which is the best first step when given a new problem?
    • A Start coding immediately
    • B Restate the problem, clarify constraints and work small examples
    • C Pick a data structure at random
    • D Memorise a solution

    Module 02 · Complexity Analysis

    Space-Time Complexity Analysis

    Measure how an algorithm scales: Big-O, Omega, Theta, best/worst/average case, amortised cost and recursion analysis.

    ⏱️ What is time and space complexity?

    Time complexity counts how the number of basic operations grows as the input size n grows. Space complexity counts how the extra memory grows. We ignore constants and small terms because at large n only the growth rate matters: 3n² + 10n + 7 is simply O(n²).

    📝
    Space complexity usually means auxiliary space (extra memory your algorithm allocates), not the size of the input itself.

    📈 Asymptotic notations

    NotationMeaningPlain English
    O(f) Big-OUpper bound"No worse than f" — the worst-case guarantee most used in interviews.
    Ω(f) OmegaLower bound"At least f" — best-case or minimum work needed.
    Θ(f) ThetaTight bound"Exactly f growth" — both upper and lower bound.

    Also distinguish best case, average case and worst case. Quick sort is O(n log n) on average but O(n²) in the worst case; linear search is O(1) best, O(n) worst.

    📊 The common growth classes

    ClassNameTypical examplen = 1,000,000
    O(1)ConstantArray index, hash lookup1
    O(log n)LogarithmicBinary search, balanced BST~20
    O(n)LinearScan an array10⁶
    O(n log n)LinearithmicMerge sort, heap sort~2 × 10⁷
    O(n²)QuadraticNested loops, bubble sort10¹² (too slow)
    O(2ⁿ)ExponentialAll subsets, naive Fibonacciimpossible
    O(n!)FactorialAll permutationsimpossible
    Illustrative shapes: the steeper the curve, the sooner the algorithm becomes unusable.

    🔍 How to analyse code

    1. A single statement is O(1).
    2. A loop that runs n times multiplies the body cost by n.
    3. Nested loops multiply: two loops of n each is O(n²).
    4. Sequential blocks add; keep the largest term.
    5. A loop that halves (or doubles) its variable is O(log n).
    6. Recursion: write the recurrence, then solve it.
    pythondef a(n):                 # O(n)
    s = 0
    for i in range(n): s += i
    return s

def b(n):                 # O(n^2)
    c = 0
    for i in range(n):
        for j in range(n): c += 1
    return c

def c(n):                 # O(log n)
    while n > 1: n //= 2

def d(n):                 # O(n log n): outer n, inner log n
    for i in range(n):
        j = 1
        while j < n: j *= 2

    Recurrences and the Master Theorem

    For T(n) = a·T(n/b) + O(nᵈ): if d > logba the cost is dominated by the root work, O(nᵈ); if d = logba it is O(nᵈ log n); if d < logba it is O(n^(logba)).

    RecurrenceResultExample
    T(n) = T(n/2) + O(1)O(log n)Binary search
    T(n) = 2T(n/2) + O(n)O(n log n)Merge sort
    T(n) = T(n−1) + O(1)O(n)Linear recursion
    T(n) = 2T(n−1) + O(1)O(2ⁿ)Naive Fibonacci

    🔁 Amortised analysis

    Some operations are occasionally expensive but cheap on average over a sequence. A dynamic array doubles its capacity when full: one append may cost O(n) to copy, but spread across all appends the cost is O(1) amortised. Hash-table resizing and the monotonic stack follow the same idea.

    EXAMPLE · Why doubling gives O(1) amortised append

    Appending n items copies 1 + 2 + 4 + … + n/2 < n elements in total during resizes. Total work ≈ 2n, so average per append ≈ 2 = O(1).

    ⚠️
    Amortised is not average-case over random inputs — it is a guarantee over any sequence of operations.

    The building blocks: what each structure is, how it behaves in memory, its costs and when to use it.

    📏 Arrays and dynamic arrays

    An array stores elements in contiguous memory, so index access is O(1) and iteration is cache-friendly. Inserting or deleting in the middle shifts elements: O(n). A dynamic array (Python list, Java ArrayList, C++ vector, Go slice) grows automatically with O(1) amortised append.

    OperationArray / listNote
    Access by indexO(1)Contiguous memory
    Search (unsorted)O(n)Scan
    Append at endO(1) amortisedOccasional resize
    Insert / delete in middleO(n)Shifting

    🔗 Linked lists

    A linked list is a chain of nodes where each node stores a value and a pointer to the next node (singly) and optionally the previous node (doubly). Insert/delete at a known node is O(1), but there is no random access: finding the k-th element is O(k).

    pythonclass Node:
    def __init__(self, val, nxt=None):
        self.val, self.next = val, nxt

def reverse(head):                 # O(n) time, O(1) space
    prev = None
    while head:
        head.next, prev, head = prev, head, head.next
    return prev

def has_cycle(head):               # Floyd's tortoise & hare
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast: return True
    return False
    💡
    Two-pointer tricks on lists: slow/fast pointers find the middle, detect cycles and find the k-th node from the end (advance one pointer k steps first).

    📚 Stacks and queues

    📚 Stack (LIFO)

    Last in, first out. Push/pop at one end. Used for undo, recursion, expression parsing, DFS, balanced brackets.

    🚶 Queue (FIFO)

    First in, first out. Enqueue at back, dequeue at front. Used for BFS, task scheduling, buffering. A deque allows both ends.

    pythondef valid_brackets(s):
    pairs, st = {')':'(', ']':'[', '}':'{'}, []
    for ch in s:
        if ch in '([{': st.append(ch)
        elif not st or st.pop() != pairs[ch]: return False
    return not st

# Monotonic stack: next greater element, O(n)
def next_greater(a):
    res, st = [-1]*len(a), []          # st holds indexes with decreasing values
    for i, x in enumerate(a):
        while st and a[st[-1]] < x:
            res[st.pop()] = x
        st.append(i)
    return res

    🔑 Hash tables, maps and sets

    A hash table applies a hash function to a key to find a bucket, giving average O(1) insert, lookup and delete. Collisions (two keys, one bucket) are handled by chaining (a list per bucket) or open addressing (probe for the next free slot). When the load factor grows, the table is resized and rehashed.

    EXAMPLE · Two Sum in O(n) with a hash map
    pythondef two_sum(nums, target):
    seen = {}                      # value -> index
    for i, x in enumerate(nums):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i
    ⚠️
    Hash tables have O(n) worst-case when many keys collide, do not keep order (in most languages), and need hashable keys.

    Module 04 · Advanced Data Structures

    Trees, Heaps, Tries, Graphs & Range Structures

    Hierarchical and specialised structures: BSTs, balanced trees, heaps, tries, union-find, segment trees, Fenwick trees and LRU caches.

    🌳 Trees and binary search trees

    A tree is a connected acyclic graph with a root; each node has children. A binary tree has at most two children. A BST keeps left < node < right, so search, insert and delete take O(h) where h is the height. An unbalanced BST degenerates to O(n); AVL and Red-Black trees self-balance to guarantee O(log n), and B-trees do the same for disk-based databases.

    TraversalOrderUse
    Pre-orderNode, Left, RightCopy / serialise a tree
    In-orderLeft, Node, RightSorted output from a BST
    Post-orderLeft, Right, NodeDelete tree, evaluate expressions
    Level-orderRow by row (BFS)Shortest depth, level problems
    pythonfrom collections import deque

def inorder(r):
    return inorder(r.left) + [r.val] + inorder(r.right) if r else []

def height(r):
    return 0 if not r else 1 + max(height(r.left), height(r.right))

def level_order(root):
    out, q = [], deque([root] if root else [])
    while q:
        level = []
        for _ in range(len(q)):
            n = q.popleft(); level.append(n.val)
            if n.left: q.append(n.left)
            if n.right: q.append(n.right)
        out.append(level)
    return out

def is_bst(n, lo=float('-inf'), hi=float('inf')):
    return True if not n else lo < n.val < hi and is_bst(n.left, lo, n.val) and is_bst(n.right, n.val, hi)

    ⛰️ Heaps and priority queues

    A heap is a complete binary tree stored in an array where each parent is ≤ its children (min-heap) or ≥ (max-heap). It gives O(1) access to the min/max and O(log n) push/pop. Building a heap from n items is O(n). A priority queue is the abstract interface; the heap is the usual implementation.

    pythonimport heapq

def k_largest(nums, k):            # O(n log k) with a size-k min-heap
    h = []
    for x in nums:
        heapq.heappush(h, x)
        if len(h) > k: heapq.heappop(h)
    return sorted(h, reverse=True)

class MedianFinder:                # two heaps: lower half (max) + upper half (min)
    def __init__(self): self.lo, self.hi = [], []
    def add(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))
        if len(self.hi) > len(self.lo): heapq.heappush(self.lo, -heapq.heappop(self.hi))
    def median(self):
        return -self.lo[0] if len(self.lo) > len(self.hi) else (-self.lo[0] + self.hi[0]) / 2

    🔤 Tries (prefix trees)

    A trie stores strings character by character along a path from the root. Insert, search and prefix-search cost O(L) where L is the word length — independent of the number of words. It powers autocomplete, spell check and IP routing.

    pythonclass Trie:
    def __init__(self): self.kids, self.end = {}, False
    def insert(self, w):
        n = self
        for c in w: n = n.kids.setdefault(c, Trie())
        n.end = True
    def starts_with(self, p):
        n = self
        for c in p:
            if c not in n.kids: return False
            n = n.kids[c]
        return True

    🧩 Union-Find (Disjoint Set Union)

    Tracks which elements belong to the same group. find returns a group representative; union merges groups. With path compression and union by rank each operation is nearly O(1) (inverse Ackermann). Used for connected components, cycle detection and Kruskal's MST.

    pythonclass DSU:
    def __init__(self, n): self.p, self.r = list(range(n)), [0]*n
    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]     # path compression (halving)
            x = self.p[x]
        return x
    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b: return False
        if self.r[a] < self.r[b]: a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]: self.r[a] += 1
        return True

    📐 Range-query structures: Fenwick and Segment trees

    When you need many prefix sums / range queries with point updates, a plain array gives O(n) for one of the two. A Fenwick tree (BIT) and a segment tree give O(log n) for both. Segment trees are more general (min, max, gcd, lazy range updates).

    pythonclass Fenwick:                     # 1-indexed, O(log n) update & prefix query
    def __init__(self, n): self.t = [0]*(n+1)
    def add(self, i, d):
        while i < len(self.t): self.t[i] += d; i += i & -i
    def prefix(self, i):
        s = 0
        while i > 0: s += self.t[i]; i -= i & -i
        return s
    def range_sum(self, l, r): return self.prefix(r) - self.prefix(l-1)

    🗃️ Design problem: LRU Cache (hash map + doubly linked list)

    Requirement: get and put in O(1), evicting the least recently used entry at capacity. Combine a hash map (O(1) key → node) with a doubly linked list (O(1) move-to-front and remove-tail).

    pythonfrom collections import OrderedDict     # an ordered hash map = map + linked list

class LRU:
    def __init__(self, cap): self.cap, self.d = cap, OrderedDict()
    def get(self, k):
        if k not in self.d: return -1
        self.d.move_to_end(k); return self.d[k]
    def put(self, k, v):
        self.d[k] = v; self.d.move_to_end(k)
        if len(self.d) > self.cap: self.d.popitem(last=False)
    💡
    Choosing a structure: need min/max fast → heap. Prefix search → trie. Groups merging → DSU. Range sum + updates → Fenwick. Ordered keys with floor/ceiling → balanced BST (TreeMap).

    Sorting, Searching & Optimisation Patterns

    The patterns that turn O(n²) into O(n log n) or O(n): sorting, binary search, two pointers, sliding window, prefix sums, greedy, divide-and-conquer and backtracking.

    🔢 Sorting algorithms

    AlgorithmBestAverageWorstSpaceStable?

    SelectionO(n²)O(n²)O(n²)O(1)No

    pythondef merge_sort(a):
    if len(a) <= 1: return a
    m = len(a) // 2
    l, r = merge_sort(a[:m]), merge_sort(a[m:])
    out, i, j = [], 0, 0
    while i < len(l) and j < len(r):
        if l[i] <= r[j]: out.append(l[i]); i += 1
        else: out.append(r[j]); j += 1
    return out + l[i:] + r[j:]

def quickselect(a, k):             # k-th smallest, O(n) average
    p = a[len(a)//2]
    lo = [x for x in a if x < p]; eq = [x for x in a if x == p]; hi = [x for x in a if x > p]
    if k < len(lo): return quickselect(lo, k)
    if k < len(lo) + len(eq): return p
    return quickselect(hi, k - len(lo) - len(eq))

    🎯 Binary search — including "search on the answer"

    Binary search works on any monotonic condition, not just sorted arrays. If you can write a function ok(x) that is False…False True…True, you can find the boundary in O(log range).

    pythondef lower_bound(a, x):             # first index with a[i] >= x
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x: lo = mid + 1
        else: hi = mid
    return lo

def min_capacity(weights, days):   # search on the answer: ship packages in <= days
    def feasible(cap):
        d, load = 1, 0
        for w in weights:
            if load + w > cap: d, load = d + 1, 0
            load += w
        return d <= days
    lo, hi = max(weights), sum(weights)
    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid): hi = mid
        else: lo = mid + 1
    return lo
    ⚠️
    Classic bugs: infinite loops from wrong lo/hi updates, and overflow of lo+hi in C++/Java (use lo + (hi-lo)/2).

    👉 Two pointers, sliding window and prefix sums

    👉
    Two pointers
    Sorted array pair sums, removing duplicates, palindromes — O(n) instead of O(n²).
    🪟
    Sliding window
    Longest/shortest subarray or substring satisfying a condition by expanding and shrinking a window.
    ➕
    Prefix sums
    Precompute running totals so any range sum is O(1).
    pythondef longest_unique_substring(s):   # sliding window, O(n)
    last, left, best = {}, 0, 0
    for right, ch in enumerate(s):
        if ch in last and last[ch] >= left: left = last[ch] + 1
        last[ch] = right
        best = max(best, right - left + 1)
    return best

def subarray_sum_k(a, k):          # prefix sum + hash map, O(n)
    cnt, pre, res = {0: 1}, 0, 0
    for x in a:
        pre += x
        res += cnt.get(pre - k, 0)
        cnt[pre] = cnt.get(pre, 0) + 1
    return res

    🤑 Greedy algorithms

    A greedy algorithm makes the locally best choice at every step and never reconsiders. It is correct only when the problem has the greedy-choice property and optimal substructure — prove it with an exchange argument.

    pythondef max_non_overlapping(intervals):          # activity selection: sort by END time
    intervals.sort(key=lambda x: x[1])
    cnt, end = 0, float('-inf')
    for s, e in intervals:
        if s >= end: cnt += 1; end = e
    return cnt

def can_jump(nums):                          # farthest reachable index
    far = 0
    for i, x in enumerate(nums):
        if i > far: return False
        far = max(far, i + x)
    return True
    ⚠️
    Greedy fails for coin change with coins {1, 3, 4} and amount 6: greedy picks 4+1+1 (3 coins) but 3+3 (2 coins) is optimal — that needs DP.

    ✂️ Divide & conquer and backtracking

    Divide & conquer: split the problem, solve the parts, combine (merge sort, closest pair, fast exponentiation). Backtracking: build a solution incrementally and abandon (prune) a path as soon as it cannot lead to a valid answer.

    pythondef power(x, n):                   # fast exponentiation, O(log n)
    if n == 0: return 1
    h = power(x, n // 2)
    return h * h if n % 2 == 0 else h * h * x

def subsets(nums):                 # backtracking: choose / explore / un-choose
    res, path = [], []
    def go(i):
        if i == len(nums): res.append(path[:]); return
        go(i + 1)                  # skip
        path.append(nums[i]); go(i + 1); path.pop()   # take
    go(0); return res

def n_queens(n):
    cols, d1, d2, cnt = set(), set(), set(), 0
    def go(r):
        nonlocal cnt
        if r == n: cnt += 1; return
        for c in range(n):
            if c in cols or r-c in d1 or r+c in d2: continue   # prune
            cols.add(c); d1.add(r-c); d2.add(r+c)
            go(r + 1)
            cols.remove(c); d1.remove(r-c); d2.remove(r+c)
    go(0); return cnt

    Module 06 · Graph Algorithms

    Graph Traversal, Shortest Paths & Beyond

    BFS, DFS, topological sort, Dijkstra, Bellman-Ford, minimum spanning trees and when to use each.

    🧭 BFS and DFS

    🌊 BFS (queue)

    Explores level by level. Finds the shortest path in unweighted graphs. O(V + E).

    🕳️ DFS (stack / recursion)

    Goes deep first. Used for cycle detection, topological sort, connected components, backtracking. O(V + E).

    pythonfrom collections import deque, defaultdict

def bfs_shortest(graph, s, t):
    dist, q = {s: 0}, deque([s])
    while q:
        u = q.popleft()
        if u == t: return dist[u]
        for v in graph[u]:
            if v not in dist: dist[v] = dist[u] + 1; q.append(v)
    return -1

def num_islands(grid):             # DFS on a grid
    R, C, seen, cnt = len(grid), len(grid[0]), set(), 0
    def dfs(r, c):
        if not (0 <= r < R and 0 <= c < C) or grid[r][c] != '1' or (r, c) in seen: return
        seen.add((r, c))
        for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)): dfs(r+dr, c+dc)
    for r in range(R):
        for c in range(C):
            if grid[r][c] == '1' and (r, c) not in seen: cnt += 1; dfs(r, c)
    return cnt

    📋 Topological sort (DAGs)

    A topological order lists vertices so every edge goes from earlier to later — used for build systems, course prerequisites and task scheduling. Kahn's algorithm: repeatedly remove nodes of in-degree 0. If some nodes remain, the graph has a cycle.

    pythondef topo_sort(n, edges):
    g, indeg = defaultdict(list), [0]*n
    for a, b in edges: g[a].append(b); indeg[b] += 1
    q, order = deque(i for i in range(n) if indeg[i] == 0), []
    while q:
        u = q.popleft(); order.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0: q.append(v)
    return order if len(order) == n else []     # [] means cycle

    pythonimport heapq

def dijkstra(g, src):              # g[u] = [(v, w), ...], all w >= 0
    dist, h = {src: 0}, [(0, src)]
    while h:
        d, u = heapq.heappop(h)
        if d > dist.get(u, float('inf')): continue      # stale entry
        for v, w in g[u]:
            nd = d + w
            if nd < dist.get(v, float('inf')):
                dist[v] = nd; heapq.heappush(h, (nd, v))
    return dist
    ⚠️

    🌉 Minimum spanning tree and cycle detection

    An MST connects all vertices with minimum total edge weight and no cycles. Kruskal sorts edges and adds them if they join different components (use DSU) — O(E log E). Prim grows a tree from a start vertex using a heap — O(E log V).

    pythondef kruskal(n, edges):             # edges = [(w, u, v)]
    dsu, total = DSU(n), 0         # DSU from the Advanced Data Structures module
    for w, u, v in sorted(edges):
        if dsu.union(u, v): total += w
    return total

    Module 07 · Dynamic Programming

    Dynamic Programming from Scratch to Expert

    What DP is, how to recognise it, memoisation vs tabulation, and the classic families: 1-D, 2-D, knapsack, strings, intervals, bitmask and state-machine DP.

    🧠 What is dynamic programming?

    DP solves a problem by breaking it into overlapping subproblems, solving each only once, and storing the result. Two properties must hold: optimal substructure (the best answer is built from best answers of subproblems) and overlapping subproblems (the same subproblem appears again and again).

    EXAMPLE · Fibonacci: why DP matters

    Naive fib(n) = fib(n-1) + fib(n-2) recomputes values exponentially: O(2ⁿ). Store each result once and it drops to O(n); keep only the last two values and space drops to O(1).

    pythonfrom functools import lru_cache

@lru_cache(None)                   # top-down: memoisation
def fib(n): return n if n < 2 else fib(n-1) + fib(n-2)

def fib_tab(n):                    # bottom-up: tabulation, O(n) time, O(1) space
    a, b = 0, 1
    for _ in range(n): a, b = b, a + b
    return a
    Top-down (memoisation)Bottom-up (tabulation)
    StyleRecursion + cacheLoops fill a table
    ComputesOnly needed statesAll states
    RiskRecursion depth limitNeed correct fill order
    Space optimisationHarderEasy (rolling array)

    🪜 A 5-step DP framework

    1. Define the state: what does dp[i] (or dp[i][j]) mean, in one sentence?
    2. Write the transition: how does a state depend on smaller states?
    3. Set base cases: the smallest states you know directly.
    4. Choose the order: iterate so dependencies are ready first.
    5. Locate the answer and optimise space if each row needs only the previous one.

    📏 1-D DP

    pythondef climb(n):                      # dp[i] = dp[i-1] + dp[i-2]
    a, b = 1, 1
    for _ in range(n - 1): a, b = b, a + b
    return b

def rob(nums):                     # dp[i] = max(dp[i-1], dp[i-2] + nums[i])
    prev2 = prev1 = 0
    for x in nums: prev2, prev1 = prev1, max(prev1, prev2 + x)
    return prev1

def coin_change(coins, amt):       # dp[a] = min coins to make a
    INF = amt + 1; dp = [0] + [INF] * amt
    for a in range(1, amt + 1):
        for c in coins:
            if c <= a: dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amt] if dp[amt] != INF else -1

def lis(a):                        # O(n log n) with binary search
    import bisect; t = []
    for x in a:
        i = bisect.bisect_left(t, x)
        t[i:i+1] = [x]
    return len(t)

    🧮 2-D DP, grids and knapsack

    pythondef unique_paths(m, n):            # dp[r][c] = dp[r-1][c] + dp[r][c-1]
    dp = [1] * n
    for _ in range(1, m):
        for c in range(1, n): dp[c] += dp[c - 1]
    return dp[-1]

def knapsack_01(wt, val, W):       # each item used at most once
    dp = [0] * (W + 1)
    for w, v in zip(wt, val):
        for cap in range(W, w - 1, -1):     # go BACKWARDS to avoid reuse
            dp[cap] = max(dp[cap], dp[cap - w] + v)
    return dp[W]

def subset_sum(nums, target):
    dp = [True] + [False] * target
    for x in nums:
        for s in range(target, x - 1, -1): dp[s] = dp[s] or dp[s - x]
    return dp[target]
    💡
    0/1 knapsack loops capacity downwards; unbounded knapsack (coin change) loops capacity upwards because items may repeat.

    🔤 String DP

    pythondef lcs(a, b):                     # longest common subsequence
    dp = [[0]*(len(b)+1) for _ in range(len(a)+1)]
    for i in range(1, len(a)+1):
        for j in range(1, len(b)+1):
            dp[i][j] = dp[i-1][j-1] + 1 if a[i-1] == b[j-1] else max(dp[i-1][j], dp[i][j-1])
    return dp[-1][-1]

def edit_distance(a, b):           # insert / delete / replace
    dp = [[0]*(len(b)+1) for _ in range(len(a)+1)]
    for i in range(len(a)+1): dp[i][0] = i
    for j in range(len(b)+1): dp[0][j] = j
    for i in range(1, len(a)+1):
        for j in range(1, len(b)+1):
            dp[i][j] = dp[i-1][j-1] if a[i-1] == b[j-1] else 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
    return dp[-1][-1]

    🚀 Advanced DP: intervals, bitmask, state machines, digits

    📐
    Interval DP
    dp[l][r] over ranges: matrix-chain multiplication, burst balloons, palindrome partitioning. Usually O(n³).
    🔢
    Bitmask DP
    State = subset of items as a bitmask. Travelling salesman in O(n²·2ⁿ), assignment problems for n ≤ 20.
    🔀
    State-machine DP
    Stock buy/sell with cooldown or k transactions: states like hold / sold / rest.
    🌲
    Tree & digit DP
    DP on subtrees (rob houses in a tree); count numbers ≤ N with digit constraints.
    pythondef max_profit_cooldown(prices):   # state machine: hold, sold, rest
    hold, sold, rest = float('-inf'), 0, 0
    for p in prices:
        hold, sold, rest = max(hold, rest - p), hold + p, max(rest, sold)
    return max(sold, rest)

def tsp(dist):                     # bitmask DP, O(n^2 * 2^n)
    n, INF = len(dist), float('inf')
    dp = [[INF]*n for _ in range(1 << n)]; dp[1][0] = 0
    for mask in range(1 << n):
        for last in range(n):
            if dp[mask][last] == INF: continue
            for nxt in range(n):
                if mask >> nxt & 1: continue
                nm = mask | 1 << nxt
                dp[nm][nxt] = min(dp[nm][nxt], dp[mask][last] + dist[last][nxt])
    return min(dp[-1][i] + dist[i][0] for i in range(n))

    🧠 Concepts

    Difference between O(n) and Θ(n)?
    O(n) is only an upper bound (the algorithm is at most linear). Θ(n) is a tight bound: it grows exactly linearly. Interviewers often say "O" when they mean Θ.
    Array vs linked list — when to use which?
    Array: fast random access, cache-friendly, best default. Linked list: O(1) insert/delete when you already hold the node, no resizing; but poor cache locality and O(n) access.
    How does a hash table handle collisions?
    Chaining (bucket lists / trees) or open addressing (linear/quadratic probing, double hashing). Resize when the load factor exceeds a threshold to keep operations O(1) average.
    Why is heap build O(n) and not O(n log n)?
    Sift-down from the last parent: most nodes are near the bottom and move very few levels. The sum of heights over all nodes is O(n).
    Quick sort vs merge sort?
    Quick sort: in-place, usually fastest due to cache behaviour, but O(n²) worst case and unstable. Merge sort: guaranteed O(n log n), stable, but needs O(n) extra space. Preferred for linked lists and external sorting.
    What is amortised O(1)?
    Average cost per operation over a worst-case sequence, e.g. dynamic array append where rare O(n) resizes are paid for by many cheap appends.

    ⚙️ Technique & DP

    How do you decide between greedy and DP?
    Try to prove the greedy choice (exchange argument) or find a counter-example. If a local choice can be regretted later and subproblems overlap, use DP.
    BFS vs DFS vs Dijkstra?
    BFS: fewest edges in unweighted graphs. DFS: exploration, cycles, topological order. Dijkstra: cheapest path with non-negative weights.
    How do you optimise DP space?
    If dp[i] depends only on a few previous rows or values, keep just those (rolling array), e.g. Fibonacci O(1), knapsack 1-D array.
    Detect a cycle in a directed graph?
    DFS with three colours (white / grey / black) — an edge to a grey node is a cycle; or Kahn's algorithm — leftover nodes mean a cycle.
    Design a data structure for O(1) insert, delete and getRandom.
    Dynamic array + hash map of value → index. To delete, swap the element with the last one, pop, and update the map.
    Find the median of a data stream.
    Two heaps: max-heap for the lower half and min-heap for the upper half, balanced by size. O(log n) add, O(1) median.

    🗣️ How to perform in a coding round

    • Think aloud: restate, clarify constraints, give the brute force and its complexity, then improve it.
    • Name the pattern you are using ("sliding window", "monotonic stack"), then code it.
    • Write clean helper functions and meaningful names; test with a normal case and an edge case.
    • Finish with time and space complexity and mention trade-offs and follow-ups.

    ✍️ Given an array, return the length of the longest consecutive sequence in O(n).
    Model answer: Put all numbers in a set. For each number x where x−1 is not in the set (a sequence start), count upwards while x+1 exists. Each element is visited at most twice: O(n) time, O(n) space.
    def longest_consecutive(a):
    s, best = set(a), 0
    for x in s:
        if x - 1 not in s:
            y = x
            while y + 1 in s: y += 1
            best = max(best, y - x + 1)
    return best
