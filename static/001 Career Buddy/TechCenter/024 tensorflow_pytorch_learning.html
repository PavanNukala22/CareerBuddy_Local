    Module 01 · Foundations

    Foundations & Setup

    What deep learning frameworks actually do under the hood, and the two dominant ecosystems you'll use to build, train, and ship models.

    🧠 What is Deep Learning?

    Deep learning is a subset of machine learning that uses layered neural networks to learn hierarchical representations of data directly from examples, rather than relying on hand-engineered features. A framework like TensorFlow or PyTorch exists to solve one core problem efficiently: computing derivatives of a loss function with respect to millions of parameters, automatically and on a GPU.

    🔢
    Tensors
    N-dimensional arrays — the single data structure everything is built from.
    📉
    Autograd
    Automatic differentiation computes gradients for you — no manual calculus.
    ⚡
    GPU acceleration
    Matrix operations run in parallel on CUDA/Metal/TPU hardware.
    🧱
    Layers & Modules
    Pre-built building blocks (Dense, Conv2D, Attention) you compose into models.

    Module 02 · Core Data Structures

    Tensors & Autograd

    Everything a neural network computes is tensor math — and every parameter update depends on gradients computed automatically by the framework.

    🔢 What is a Tensor?

    A tensor is a generalization of scalars, vectors, and matrices to arbitrary dimensions (rank). Both frameworks use tensors as their universal data container — for input images, weights, gradients, and outputs alike.

    RankNameExample
    0ScalarA single loss value
    1VectorA row of feature values
    2MatrixA grayscale image, or a batch of vectors
    3+N-D TensorA batch of RGB images: [batch, height, width, channels]
     
    python — pytorchimport torch
x = torch.tensor([[1., 2.], [3., 4.]])
print(x.shape)   # torch.Size([2, 2])
print(x.dtype)   # torch.float32
    python — tensorflowimport tensorflow as tf
x = tf.constant([[1., 2.], [3., 4.]])
print(x.shape)   # (2, 2)
print(x.dtype)   # tf.float32

    ➕ Tensor Operations & Broadcasting

    Broadcasting lets operations work on tensors of different (but compatible) shapes without explicit copies — e.g. adding a shape-(3,) bias vector to every row of a shape-(32, 3) batch.

    📝
    Broadcasting rules are identical to NumPy in both frameworks: shapes are compared from the trailing dimension, and a dimension of size 1 is stretched to match. Mismatched shapes that don't follow this rule raise a runtime error.
    pythonbatch = torch.randn(32, 3)      # 32 samples, 3 features
bias  = torch.tensor([0.1, 0.2, 0.3])
result = batch + bias            # bias broadcasts across all 32 rows

    📉 Automatic Differentiation

    Training a network means repeatedly asking: "how should each weight change to reduce the loss?" That requires the gradient of the loss with respect to every parameter — computed via the chain rule across every operation that touched that parameter. Autograd tracks this automatically.

    python — pytorch autogradx = torch.tensor(2.0, requires_grad=True)
y = x**2 + 3*x
y.backward()          # computes dy/dx via the chain rule
print(x.grad)      # tensor(7.)  since dy/dx = 2x + 3 = 7 at x=2
    python — tensorflow gradienttapex = tf.Variable(2.0)
with tf.GradientTape() as tape:
    y = x**2 + 3*x
grad = tape.gradient(y, x)
print(grad)         # tf.Tensor(7.0, shape=(), dtype=float32)
    💡
    PyTorch tracks gradients implicitly for any tensor with requires_grad=True. TensorFlow instead requires an explicit GradientTape context to "record" the operations it should differentiate through — a key API-style difference to memorize.

    🕸️ The Computational Graph

    Every tensor operation implicitly builds a graph of dependencies. Calling .backward() (PyTorch) or exiting the tape (TensorFlow) walks that graph backward, applying the chain rule at each node.

    Module 03

    Building Neural Networks

    Composing layers into architectures — and the different philosophies each framework brings to model definition.

    🧱 Layers as Building Blocks

    A layer wraps a set of trainable weights and a forward computation — e.g. Dense/Linear performs y = xW + b. Stacking layers lets a network build increasingly abstract representations of the input.

    ➡️
    Dense / Linear
    Fully-connected layer; every input connects to every output neuron.
    🖼️
    Conv2D / Conv2d
    Slides learnable filters across spatial data like images.
    🎲
    Dropout
    Randomly zeroes activations during training to reduce overfitting.
    📊
    BatchNorm
    Normalizes layer activations to stabilize and speed up training.

    🧩 Keras: Sequential vs Functional API

    The Sequential API handles simple linear stacks of layers. The Functional API is required for architectures with multiple inputs/outputs or non-linear connections (like skip connections).

    python — keras functional apiinputs = tf.keras.Input(shape=(784,))
x = tf.keras.layers.Dense(64, activation='relu')(inputs)
skip = x
x = tf.keras.layers.Dense(64, activation='relu')(x)
x = tf.keras.layers.Add()([x, skip])   # residual connection
outputs = tf.keras.layers.Dense(10)(x)

model = tf.keras.Model(inputs, outputs)

    🐍 PyTorch: nn.Module

    Every PyTorch model — simple or complex — subclasses nn.Module. Layers are declared in __init__, and the forward computation (including any control flow, branching, or loops) is written explicitly in forward().

    python — pytorch residual blockclass ResBlock(nn.Module):
    def __init__(self, dim):
        super().__init__()
        self.fc1 = nn.Linear(dim, dim)
        self.fc2 = nn.Linear(dim, dim)

    def forward(self, x):
        skip = x
        x = torch.relu(self.fc1(x))
        x = self.fc2(x)
        return torch.relu(x + skip)   # residual add, explicit in code
    💡
    Because forward() is regular Python, PyTorch models can contain arbitrary control flow — different layers used based on an if statement, or a loop with a variable number of iterations — something the declarative Keras Functional API can't express as naturally.

    📈 Activation Functions

    FunctionRangeCommon use
    ReLU[0, ∞)Default hidden-layer activation; cheap, avoids vanishing gradients for positive inputs
    Sigmoid(0, 1)Binary classification output; gate values in LSTMs
    Softmax(0, 1), sums to 1Multi-class classification output layer
    GELU≈(-0.17, ∞)Default in Transformer architectures (BERT, GPT)
    ⚠️
    Applying softmax and then a cross-entropy loss that itself expects raw logits is a common bug — nn.CrossEntropyLoss in PyTorch and from_logits=True in Keras both expect unnormalized outputs, not post-softmax probabilities.

    Module 04

    Training Loops & Optimization

    The four-step loop that repeats millions of times to turn random weights into a working model.

    🔁 The Training Loop

    Figure 4.1 · One iteration of gradient-descent training
    python — pytorch manual training loopoptimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
loss_fn = nn.CrossEntropyLoss()

for epoch in range(5):
    for x_batch, y_batch in train_loader:
        optimizer.zero_grad()               # 0. clear old gradients
        preds = model(x_batch)               # 1. forward pass
        loss = loss_fn(preds, y_batch)       # 2. compute loss
        loss.backward()                     # 3. backward pass (autograd)
        optimizer.step()                    # 4. update weights
    ⚠️
    Forgetting optimizer.zero_grad() is one of the most common PyTorch bugs — gradients accumulate by default across calls to .backward(), silently corrupting training if not cleared each step.

    Keras hides these four steps inside model.fit(), which is why it needs a compile() step to know which optimizer and loss to use internally.

    📏 Loss Functions

    LossTask
    Mean Squared Error (MSE)Regression (predicting continuous values)
    Cross-Entropy / NLLMulti-class classification
    Binary Cross-EntropyBinary or multi-label classification
    Contrastive / Triplet LossEmbedding/similarity learning (face recognition, retrieval)

    🎯 Optimizers & Learning Rate

    The optimizer decides how to use the computed gradient to update each weight. Plain Stochastic Gradient Descent (SGD) moves every weight by -lr × gradient; adaptive optimizers like Adam maintain per-parameter momentum and scaling, converging faster with less manual tuning.

    📝
    The learning rate is the single most impactful hyperparameter: too high causes the loss to diverge or oscillate; too low makes training impractically slow. Learning-rate schedules (warmup, cosine decay, step decay) address this by adapting it over the course of training.

    📉 Overfitting & Regularization

    A model overfits when it memorizes training data instead of learning generalizable patterns — visible as training loss continuing to drop while validation loss rises.

    🎲
    Dropout
    Randomly disable neurons during training to prevent co-adaptation.
    ⚖️
    Weight Decay (L2)
    Penalizes large weights, encouraging simpler learned functions.
    ⏹️
    Early Stopping
    Halt training once validation loss stops improving.
    🔄
    Data Augmentation
    Synthetically expand training data via crops, flips, noise, etc.

    Module 05

    CNNs for Computer Vision

    Convolutional networks exploit the spatial structure of images — nearby pixels are related — to learn far more efficiently than a fully-connected network could.

    🖼️ Why Convolutions?

    A fully-connected layer applied directly to a 224×224 RGB image would need over 150,000 weights per single output neuron. Convolutional layers instead slide a small, shared filter (e.g. 3×3) across the whole image — drastically reducing parameters while exploiting the fact that useful visual features (edges, textures) are local and translation-invariant.

    🔲 Convolution, Padding & Stride

    Figure 5.1 · A single filter sliding over the input reduces spatial size
    ParameterEffect
    Kernel sizeHow large a local region each filter examines (commonly 3×3)
    StrideHow far the filter moves each step; stride 2 halves output resolution
    Padding"Same" padding keeps output size equal to input; "valid" shrinks it

    🔽 Pooling Layers

    Max pooling downsamples a feature map by keeping only the strongest activation in each local window, reducing computation and adding a degree of translation invariance. It's increasingly being replaced in modern architectures by strided convolutions, but remains common in classic CNNs.

    🏗️ A Complete CNN in Both Frameworks

    python — tensorflow / kerasmodel = tf.keras.Sequential([
    tf.keras.layers.Conv2D(32, 3, activation='relu', input_shape=(28,28,1)),
    tf.keras.layers.MaxPooling2D(),
    tf.keras.layers.Conv2D(64, 3, activation='relu'),
    tf.keras.layers.MaxPooling2D(),
    tf.keras.layers.Flatten(),
    tf.keras.layers.Dense(10, activation='softmax')
])
    python — pytorchclass CNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(1, 32, 3)
        self.conv2 = nn.Conv2d(32, 64, 3)
        self.pool  = nn.MaxPool2d(2)
        self.fc    = nn.Linear(64*5*5, 10)

    def forward(self, x):
        x = self.pool(torch.relu(self.conv1(x)))
        x = self.pool(torch.relu(self.conv2(x)))
        x = torch.flatten(x, 1)
        return self.fc(x)

    Module 06

    RNNs & Transformers

    Modeling data where order matters — from classic recurrent networks to the attention-based architecture behind today's large language models.

    🔗 Sequence Data & RNNs

    A Recurrent Neural Network (RNN) processes a sequence one step at a time, carrying a hidden state forward as memory of everything seen so far — suited to text, time series, or audio.

    ⚠️
    Vanilla RNNs suffer from the vanishing/exploding gradient problem over long sequences — gradients shrink or blow up as they're backpropagated through many time steps, making it hard to learn long-range dependencies.

    🚪 LSTM & GRU

    LSTM (Long Short-Term Memory) and the simpler GRU (Gated Recurrent Unit) address vanishing gradients with learned gates that control what information to keep, forget, or output at each step.

    python — pytorch lstmlstm = nn.LSTM(input_size=128, hidden_size=256, batch_first=True)
output, (h_n, c_n) = lstm(x)   # x: [batch, seq_len, 128]

    🎯 Attention & the Transformer

    The 2017 "Attention Is All You Need" architecture replaced recurrence entirely with self-attention: every token directly computes a weighted relationship to every other token in the sequence, in parallel, rather than passing information step by step. This unlocked far better parallelization and long-range dependency modeling — the foundation of BERT, GPT, and virtually every modern LLM.

    Figure 6.1 · Self-attention connects every token to every other token

    💻 Transformers in Code

    Both frameworks provide low-level attention primitives, but in practice most Transformer work uses the Hugging Face Transformers library, which supports both backends interchangeably.

    python — pytorch multiheadattentionattn = nn.MultiheadAttention(embed_dim=512, num_heads=8, batch_first=True)
out, weights = attn(query, key, value)
    python — hugging face (framework-agnostic)from transformers import AutoModel, AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModel.from_pretrained("bert-base-uncased")  # loads PyTorch weights by default
    💡
    Hugging Face's from_pretrained can load the same architecture as a PyTorch, TensorFlow (prefix TF), or JAX/Flax model — the library was explicitly designed to decouple "which model" from "which backend."

    Module 07

    Data Pipelines

    Feeding a GPU fast enough that it's never left waiting on the CPU — the unglamorous engineering that determines real-world training speed.

    🚰 Why Pipelines Matter

    A GPU can process a batch in milliseconds; if loading and preprocessing the next batch on CPU takes longer than that, the GPU sits idle. Both frameworks provide pipeline APIs that prefetch and parallelize this work so I/O overlaps with computation instead of blocking it.

    📊 tf.data

    python — tensorflowdataset = tf.data.Dataset.from_tensor_slices((images, labels))
dataset = (dataset
    .shuffle(1000)
    .batch(32)
    .map(augment_fn, num_parallel_calls=tf.data.AUTOTUNE)
    .prefetch(tf.data.AUTOTUNE))
    📝
    AUTOTUNE lets TensorFlow dynamically tune the number of parallel calls and prefetch buffer size at runtime, instead of hand-picking a fixed worker count.

    📦 torch.utils.data

    python — pytorchclass ImageDataset(torch.utils.data.Dataset):
    def __len__(self):
        return len(self.files)

    def __getitem__(self, idx):
        img = load_image(self.files[idx])
        return transform(img), self.labels[idx]

loader = torch.utils.data.DataLoader(
    ImageDataset(), batch_size=32, shuffle=True, num_workers=4)

    PyTorch's DataLoader spins up num_workers background subprocesses to load and preprocess samples in parallel, feeding batches to the main training loop via a queue.

    Module 08

    Transfer Learning & Deployment

    Reusing pretrained models to get strong results with a fraction of the data, then getting a trained model out of a notebook and into a real application.

    ♻️ Transfer Learning & Fine-Tuning

    Rather than training from random weights, transfer learning starts from a model pretrained on a large dataset (like ImageNet) and adapts it to a new, often much smaller, task-specific dataset — dramatically reducing the data and compute required.

    🧊
    Feature extraction
    Freeze the pretrained backbone; train only a new classifier head.
    🔥
    Fine-tuning
    Unfreeze some/all backbone layers and continue training at a low learning rate.

    🧊 Freezing Layers

    python — tensorflow / kerasbase = tf.keras.applications.ResNet50(weights='imagenet', include_top=False)
base.trainable = False   # freeze all backbone weights

model = tf.keras.Sequential([base, tf.keras.layers.GlobalAveragePooling2D(),
                              tf.keras.layers.Dense(10, activation='softmax')])
    python — pytorchimport torchvision.models as models

model = models.resnet50(weights='IMAGENET1K_V2')
for param in model.parameters():
    param.requires_grad = False       # freeze backbone
model.fc = nn.Linear(model.fc.in_features, 10)  # new head, trainable

    Module 09

    TensorFlow vs PyTorch: The Full Picture

    Tying together every earlier module into a practical decision framework for choosing — or switching between — the two.

    🎭 Philosophy & API Style

    PyTorch's design philosophy is "Python first" — models are ordinary Python objects, debuggable with standard tools like pdb and print statements, executing eagerly by default. TensorFlow historically favored static computation graphs for production performance and portability; TF 2.x closed much of that gap by making eager execution the default while keeping tf.function graph compilation available on demand.

    🧭 Choosing the Right Framework

    🎓
    Learning / research
    PyTorch — most tutorials, papers, and course material default to it today.
    📱
    Mobile-first product
    TensorFlow — TFLite's tooling and community support remain ahead.
    🏢
    Existing team/infra
    Match whatever the team already runs — switching costs usually outweigh marginal gains.
    💡
    The two frameworks share enough conceptual DNA (tensors, autograd, layers, optimizers) that fluency in one transfers quickly to the other — interviewers often care more that you understand why a training loop works than which framework's syntax you used.

    🖥️ Distributed & Multi-GPU Training

    Large models outgrow a single GPU's memory or would simply train too slowly on one. Both frameworks support data parallelism (splitting a batch across GPUs, each holding a full copy of the model) and, for very large models, model parallelism (splitting the model itself across devices).
