    Module 01 · Foundations

    What is Evaluative Research?

    Start from zero: why designers test their work, the types of evaluative methods, and the vocabulary of usability.

    🧭 What is Evaluative Research?

    Evaluative research checks whether a design works for real users: can they complete tasks, where do they struggle, and why? For a UI/UX designer, it is the fastest way to replace opinions with evidence.

    🌱 Generative

    Finds needs before designing: "What problems do users have?"

    🧪 Evaluative

    Tests a design: "Can users complete checkout on this prototype?"

    🗂️ Types of Evaluative Methods

    MethodWhoWhat you learn
    Moderated usability testUsers + facilitatorProblems and reasons, with follow-up questions
    Unmoderated usability testUsers alone via a toolTask success at scale, fast
    Heuristic evaluationExpertsViolations of usability principles
    Session replaysReal users in productionActual behaviour, rage clicks, drop-offs
    First-click / 5-second testsUsersFirst impressions and findability
    A/B testsReal usersWhich version performs better

    📏 Usability Components

    🎯
    Effectiveness
    Can users complete the task?
    ⏱️
    Efficiency
    How fast and with how many errors?
    😊
    Satisfaction
    How do they feel? (SEQ, SUS)
    📚
    Learnability
    How quickly do new users succeed?

    📖 Key Terms

    TaskRealistic goal given to a participant.
    Think-aloudParticipant speaks thoughts while working.
    Task successCompleted the task correctly.
    SeverityHow serious a problem is.
    HeuristicA rule of thumb for good usability.
    Session replayRecording of a real user session in the product.
    Rage clickRepeated rapid clicks signalling frustration.

    Moderated Usability Testing

    Plan and run live sessions where you can observe and ask "why".

    📋 Planning a Test

    Plan itemExample
    GoalCan first-time users book a doctor appointment?
    Participants5 users who booked a medical appointment in the last 6 months
    Tasks"Book a skin specialist near you for this Saturday morning."
    MetricsSuccess, time, errors, SEQ, observed issues
    PrototypeFigma mid-fi, mobile
    Logistics45 min, remote on Zoom, recording consent
    📌
    About 5 users per round find most major issues. Fix, then test again.

    ✍️ Writing Tasks

    🔴 Leading task

    "Click Doctors, then filter by Dermatology and pick Saturday."

    🟢 Realistic task

    "You have a skin rash. Book a specialist near you for this Saturday morning."

    Module 03 · Unmoderated Testing

    Unmoderated Usability Testing

    Run fast, larger tests with tools — and design them so they still give useful answers.

    ⚖️ Moderated vs Unmoderated

    ModeratedUnmoderated
    FacilitatorPresentAbsent
    DepthDeep (follow-ups)Shallower
    Speed & scaleSlower, 5–10 usersFast, 20–100+ users
    Best forComplex flows, early ideasSimple tasks, validation, benchmarks
    ToolsZoom, LookbackMaze, UserTesting, Lyssna, Useberry

    🛠️ Designing an Unmoderated Test

    • Very clear, self-contained task wording.
    • Define success screens in the tool to auto-measure success.
    • Add a short SEQ or open question after each task.
    • Pilot with 1–2 people before launching.
    • Screen participants and include an attention check.
    • Limit to 3–5 tasks (15–20 minutes).
    💡
    Tools like Maze show heatmaps, misclick rates and paths automatically for Figma prototypes.

    🧠 Check Yourself

    Q. You need quick validation of a simple navigation change with 50 users. Best?
    • A Moderated in-person test
    • B Unmoderated test
    • C Focus group
    • D Diary study

    Module 04 · Heuristics

    Heuristic Evaluations

    Review interfaces against proven usability principles — quickly and without users.

    📜 Nielsen's 10 Usability Heuristics

    #HeuristicExample violation
    1Visibility of system statusNo feedback after tapping Pay
    2Match between system and real worldJargon like "Beneficiary A/C"
    3User control and freedomNo undo after deleting
    4Consistency and standardsDifferent icons for the same action
    5Error preventionAllows past dates for future bookings
    6Recognition rather than recallUser must remember an order ID
    7Flexibility and efficiency of useNo shortcuts for frequent tasks
    8Aesthetic and minimalist designCluttered dashboard
    9Help users recognise, diagnose and recover from errors"Error 500"
    10Help and documentationNo help for complex forms

    🔄 Running a Heuristic Evaluation

    1. Define scope (flows/screens) and user goals.
    2. 3–5 evaluators review independently (one person finds only part of the issues).
    3. Log each issue: location, heuristic, description, severity (0–4), screenshot.
    4. Merge findings, remove duplicates, agree severity.
    5. Recommend fixes and prioritise.
    SeverityMeaning
    0Not a problem
    1Cosmetic
    2Minor
    3Major
    4Catastrophe — must fix

    ⚖️ Strengths & Limits

    ✅ Strengths

    Fast, cheap, no recruitment, good for catching obvious issues early.

    ⚠️ Limits

    Expert opinion, not real behaviour; misses domain-specific issues; should complement user testing.

    Q. "Error 500" shown to users violates…
    • A Heuristic 9 — error recovery
    • B Heuristic 8
    • C Heuristic 7
    • D None

    Module 05 · Session Replays

    Session Replays & Behaviour Analytics

    Watch real user sessions to find friction you'd never see in a lab.

    🎥 What are Session Replays?

    Session replay tools record (reconstruct) real user sessions — clicks, scrolls, taps, navigation — so you can watch how people actually use the live product. Tools: Microsoft Clarity, Hotjar, FullStory, LogRocket, Smartlook, Mixpanel/Amplitude replays.

    🔍 Signals to Look For

    SignalMeaning
    Rage clicksRepeated clicks — element not responding or not clickable
    Dead clicksClicks on non-interactive elements users think are clickable
    Error clicksClicks followed by JavaScript errors
    Quick backs / U-turnsUser went somewhere wrong
    Excessive scrollingCan't find content
    Form abandonmentDrop-off at specific fields
    HeatmapsWhere users click, move and scroll

    🔄 Using Replays Well

    1. Start from a question or metric (e.g. checkout drop-off at the address step).
    2. Filter sessions by segment and event (dropped at step 3, Android).
    3. Watch 10–20 sessions; note patterns, not single anecdotes.
    4. Combine with analytics and usability tests to confirm.
    5. Share short clips to build empathy.
    ⚠️
    Privacy: mask passwords, card numbers, OTPs and personal data; follow consent rules (GDPR, India's DPDP Act).
    Q. Many users repeatedly click a product image that isn't interactive. This is a…
    • A Rage click on a broken button
    • B Dead click — users expect it to be clickable
    • C Error click
    • D Scroll issue

    Module 06 · Interview Preparation

    Interview Preparation

    Click a question to reveal a model answer.

    🧪 Usability Testing Questions

    Moderated vs unmoderated testing?
    Moderated has a live facilitator for depth and follow-ups; unmoderated runs through a tool for speed and scale with simpler tasks.
    How many users do you test with?
    About 5 per round for qualitative testing, then iterate; larger samples for benchmarks or unmoderated metrics.
    How do you write a good task?
    A realistic scenario in the user's words with a clear end point, without revealing the path.
    What do you measure?
    Task success, time, errors, SEQ after tasks, SUS at the end, plus observed issues and quotes.
    How do you stay neutral as a moderator?
    Ask open questions, don't help or praise, turn questions back ("What would you do?"), and let silence work.

    📜 Heuristic Evaluation Questions

    Name Nielsen's 10 heuristics.
    System status visibility; match with the real world; user control and freedom; consistency and standards; error prevention; recognition over recall; flexibility and efficiency; aesthetic and minimalist design; error recovery; help and documentation.
    Why use multiple evaluators?
    Each evaluator finds only a portion of issues; 3–5 independent reviewers find many more.
    Heuristic evaluation vs usability testing?
    Heuristic evaluation is an expert review — fast but opinion-based. Usability testing observes real users. Use both.
    How do you rate severity?
    By frequency, impact and persistence, on a 0–4 scale from not a problem to catastrophe.

    🎥 Session Replay Questions

    What are session replays useful for?
    Seeing real behaviour in production: rage clicks, dead clicks, form abandonment and confusing paths.
    What is a dead click?
    A click on a non-interactive element users expect to be clickable.
    How do you avoid bias when watching replays?
    Start from a metric, filter by segment, watch enough sessions to see patterns and confirm with other methods.
    What privacy steps are needed for replays?
    Mask sensitive fields, obtain consent where required, limit access and retention, and follow GDPR/DPDP rules.

    Practice: Evaluate a Food Delivery Checkout

    Combine heuristic review, usability testing and session replays for a real-feeling problem.

    0 / 0 correct

    🍕 Scenario: TastyGo Checkout

    TastyGo's checkout drop-off rose from 22% to 35% after a redesign. Replays show rage clicks on "Apply coupon" and many users scrolling up and down on the address step.

    1️⃣ Task 1 · Heuristic Review

    ✍️ List 3 likely heuristic violations and their heuristics.
    Model answer: (1) No spinner after "Apply coupon" → visibility of system status. (2) Address form asks for landmark and pin code before showing saved addresses → recognition over recall / flexibility. (3) Invalid coupon shows "Error" only → help users recover from errors.

    2️⃣ Task 2 · Replays

    Q. Rage clicks on "Apply coupon" most likely mean…
    • A Users love coupons
    • B The button seems unresponsive (no feedback or slow)
    • C The colour is wrong
    • D Users are bots

    3️⃣ Task 3 · Usability Test Plan

    ✍️ Write the test goal, participants and 2 tasks.
    Model answer: Goal: find why users abandon at coupon and address steps. Participants: 5 users who ordered food online in the last month, mix of Android/iOS. Tasks: "Order a veg pizza to your office using the code SAVE50." · "Change your delivery address to your home address."

    4️⃣ Task 4 · Prioritise

    Q. Which finding is fixed first?
    • A Inconsistent icon stroke (5/5 noticed, no impact)
    • B Coupon button gives no feedback; 4/5 tapped repeatedly and 2 abandoned
    • C Footer spacing
    • D Long privacy text
