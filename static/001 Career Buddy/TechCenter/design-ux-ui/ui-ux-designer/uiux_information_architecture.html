    Module 01 · Foundations

    What is Information Architecture?

    Start from zero: what IA is, its four systems, organisation schemes and the vocabulary used by designers.

    🧭 What is IA?

    Information Architecture (IA) is the practice of organising, structuring and labelling content so people can find what they need and understand where they are. Good IA is invisible; bad IA makes users lost, confused and frustrated.

    🏛️ The Four Systems of IA

    🗂️
    Organisation
    How content is grouped and categorised.
    🏷️
    Labelling
    What things are called.
    🧭
    Navigation
    How users move through content.
    🔍
    Search
    How users look for content directly.
    📌
    These come from Rosenfeld & Morville's classic "Information Architecture" (the polar bear book).

    🗂️ Types of Organisation Schemes

    SchemeTypeExample
    AlphabeticalExactContacts, glossary
    ChronologicalExactNews, order history
    GeographicalExactStore locator, delivery areas
    Topic / subjectAmbiguousHelp centre categories
    Task-basedAmbiguous"Pay a bill", "Transfer money"
    Audience-basedAmbiguous"For students", "For businesses"
    HybridMixedE-commerce: categories + brands + offers

    📖 Key Terms

    TaxonomyHierarchical classification of content.
    Metadata / tagsData describing content for filtering and search.
    SitemapDiagram of all pages and their hierarchy.
    User flowPath a user takes to complete a task.
    Mental modelHow users expect information to be organised.
    Breadth vs depthMany items per level vs many levels.
    WayfindingCues showing where users are and can go.
    Q. Which IA system answers "what is it called?"
    • A Organisation
    • B Labelling
    • C Navigation
    • D Search

    Module 03 · Site Mapping

    Site Mapping

    Plan and document the structure of every page or screen in a product.

    🗺️ What is a Sitemap?

    A sitemap is a hierarchical diagram of all pages/screens and how they are grouped. It is the backbone of navigation, content planning and development scoping.

    Figure 3.1 · One branch of an e-commerce sitemap

    🗂️ Types of Sitemaps

    TypePurpose
    Visual (UX) sitemapPlanning structure and navigation
    XML sitemapFor search engines (SEO), built by developers
    HTML sitemapA page listing links for users
    Content inventorySpreadsheet of every existing page with owner, status, metrics
    Content auditEvaluating each page: keep, update, merge, delete

    ⚖️ Breadth vs Depth

    🌳 Broad & shallow

    Many top-level items, few levels. Fewer clicks but more choices per screen.

    🪜 Narrow & deep

    Few items per level, many levels. Simpler screens but users can get lost deep down.

    • Most products aim for 3 levels or fewer for key content.
    • Use search, filters and cross-links to avoid deep hierarchies.
    • Validate structure with card sorting (generate) and tree testing (evaluate).
    Q. Which method evaluates whether users can find items in a proposed sitemap?
    • A Card sorting
    • B Tree testing
    • C Mood boards
    • D A/B testing colours

    Module 04 · Task Analysis

    Task Analysis

    Break user goals into steps to find complexity, pain points and design opportunities.

    🧩 What is Task Analysis?

    Task analysis studies how users accomplish a goal — the steps, decisions, information and tools involved — so the design can support or simplify them.

    🗂️ Types of Task Analysis

    TypeHowUse
    Hierarchical Task Analysis (HTA)Goal → tasks → subtasks with a planComplex workflows
    Cognitive task analysisFocus on decisions, knowledge and judgementExpert tools, high-risk tasks
    Task flow / sequenceOrdered steps with timingsProcess optimisation
    Contextual task analysisObservation in the real environmentDiscovering workarounds

    🌳 Example: Hierarchical Task Analysis

    EXAMPLE · Goal 0: Pay electricity bill
    1. Open payments1.1 Open app · 1.2 Tap "Pay bills"
    2. Find biller2.1 Choose "Electricity" · 2.2 Select state board · 2.3 Enter consumer number
    3. Check bill3.1 View amount and due date · 3.2 Confirm name
    4. Pay4.1 Choose UPI · 4.2 Enter UPI PIN
    5. Confirm5.1 See receipt · 5.2 Save/share
    PlanDo 1–5 in order; if biller is saved, skip 2.
    💡
    Look for steps that can be removed or automated: saving the biller removes step 2 for repeat payments.

    Module 05 · Navigation

    Navigation Hierarchies & Patterns

    Choose navigation patterns that match content structure, platform and user tasks.

    🧭 Types of Navigation

    TypePurposeExample
    Global / primaryTop-level sectionsTop bar, bottom nav, sidebar
    Local / secondaryWithin a sectionTabs, sub-menus
    ContextualRelated content in page"Related products", inline links
    UtilityAccount, settings, helpProfile menu
    BreadcrumbsLocation in hierarchyHome › Men › Shoes
    Search & filtersDirect accessSearch bar, faceted filters

    📱 Navigation Patterns

    PatternBest forNotes
    Bottom navigation (mobile)3–5 top destinationsAlways visible, thumb-friendly
    Tab barPeer sections within a screenAvoid more than ~5
    Hamburger / drawerMany secondary itemsHides options — lower discoverability
    Sidebar (desktop)Complex apps, dashboardsCollapsible
    Mega menuLarge e-commerce/content sitesGroup with headings
    StepperLinear processesShow progress
    ⚠️
    Hidden navigation (hamburger) reduces discoverability. Keep the most important destinations visible.

    📍 Wayfinding

    • Highlight the current location (active tab, selected sidebar item).
    • Clear page titles matching navigation labels.
    • Breadcrumbs for deep hierarchies.
    • Consistent back behaviour on mobile.
    • Labels in users' words (validated by card sorting).
    Q. A mobile app has 4 main sections. Best primary navigation?
    • A Hamburger menu only
    • B Bottom navigation bar
    • C Mega menu
    • D Footer links

    Module 06 · Interview Preparation

    Interview Preparation

    Click a question to reveal a model answer.

    🏛️ IA Fundamentals

    What is information architecture?
    Organising, structuring and labelling content so users can find what they need and understand where they are.
    What are the four IA systems?
    Organisation, labelling, navigation and search.
    Exact vs ambiguous organisation schemes?
    Exact schemes (alphabetical, chronological, geographical) have one right place; ambiguous ones (topic, task, audience) depend on interpretation and need user validation.
    How do you validate IA?
    Open card sorting to learn users' groupings and labels, then tree testing to check findability; iterate.

    🔀 Flows & Sitemaps

    Task flow vs user flow?
    A task flow is one linear path; a user flow includes entry points, decisions and multiple outcomes.
    What goes into a sitemap?
    All pages/screens, their hierarchy and grouping, sometimes with templates, status and owners.
    Breadth vs depth?
    Broad hierarchies mean more choices per level but fewer clicks; deep ones mean fewer choices but more clicks. Aim for balance, usually 3 levels or fewer for key content.
    Content inventory vs audit?
    An inventory lists every page; an audit evaluates each page to keep, update, merge or delete.
    How do you show error paths in a flow?
    With decision diamonds and branches for invalid input, failures and edge cases, each leading to a designed state.

    🧭 Task Analysis & Navigation

    What is hierarchical task analysis?
    Breaking a goal into tasks and subtasks with a plan describing order and conditions, to find complexity and opportunities.
    Bottom nav vs hamburger?
    Bottom nav keeps 3–5 key destinations visible and thumb-friendly; hamburgers hide items and reduce discoverability, so use them for secondary content.
    When do you use breadcrumbs?
    In deep hierarchies such as e-commerce categories or documentation, to show location and allow quick jumps up.
    How do you choose navigation labels?
    Use users' language from research and card sorts, keep them short and distinct, and test with tree testing.

    Practice: Restructure a College Portal

    Design the IA for a real-feeling portal with many audiences and tasks.

    0 / 0 correct

    🎓 Scenario: Vidya College Student Portal

    Vidya College's portal has 140 pages organised by department names. Students can't find fee payment, exam results or hall tickets; the help desk gets 900 calls a month. You must restructure the IA for students on mobile.

    1️⃣ Task 1 · Organisation

    Q. Which scheme best fits students' needs?
    • A Alphabetical by department
    • B Task-based (Pay fees, Check results, Download hall ticket) plus topic sections
    • C Chronological by upload date
    • D Random

    2️⃣ Task 2 · Sitemap

    ✍️ Propose top-level sections for the mobile app.
    Model answer: 1. Home (deadlines, notices, quick actions). 2. Academics (timetable, attendance, results, hall ticket). 3. Fees (pay, receipts, scholarships). 4. Campus (library, events, hostel, transport). 5. Profile & Help (documents, settings, support). Bottom nav for these five.

    3️⃣ Task 3 · User Flow

    ✍️ Write the user flow for downloading a hall ticket.
    Model answer: Login (or saved session) → Home quick action "Hall ticket" → decision: fees cleared? No → message with "Pay fees" link → Yes → exam selection (if multiple) → preview → Download PDF / Share → success. Edge: hall ticket not yet released → show release date and notify option.

    4️⃣ Task 4 · Validation

    ✍️ How will you validate the new IA?
    Model answer: Open card sort with 30 students on 40 key items to confirm groupings and labels; tree test with 60 students on 8 tasks (fees, results, hall ticket…), target ≥ 80% success and ≥ 70% directness; then usability test the prototype with 6 students; post-launch track help-desk calls.
