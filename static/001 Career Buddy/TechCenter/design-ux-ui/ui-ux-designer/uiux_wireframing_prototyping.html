    Module 01 · Foundations

    What are Wireframes & Prototypes?

    Start from zero: what wireframes, mockups and prototypes are, the fidelity spectrum, and why designers prototype before building.

    🧭 What is Wireframing?

    A wireframe is a simplified layout of a screen showing structure, content and hierarchy — without final colours, images or styling. A prototype is an interactive simulation of the product used to test flows and ideas before development.

    🧱 Wireframe

    Static structure: where things go and what they are. "Search bar at top, filters on the left, results as cards."

    🖱️ Prototype

    Clickable or interactive: what happens when users act. "Tap a card → product page opens; tap Add → cart badge updates."

    🎚️ The Fidelity Spectrum

    Figure 1.1 · From rough to realistic
    FidelityGood forAvoid when
    LowExploring many ideas, early alignment, cheap testing of flowsYou need visual sign-off
    MidAgreeing layout and content with real componentsExploring radically different directions
    HighUsability details, stakeholder sign-off, handoffThe concept is still uncertain

    🎯 Why Prototype?

    💸
    Save cost
    Fixing a flow in Figma costs minutes; in code, days.
    🧪
    Test early
    Validate ideas with users before building.
    🤝
    Align teams
    Everyone sees the same thing.
    🗣️
    Communicate
    Show behaviour that static screens can't.

    Sketching & Low-Fidelity Wireframes

    Explore many ideas quickly with sketches and grey-box wireframes.

    ✏️ Sketching Techniques

    TechniqueHowWhy
    Crazy 8sFold paper into 8; sketch 8 ideas in 8 minutesForces quantity over perfection
    Thumbnail sketchesMany tiny layoutsExplore composition fast
    StoryboardsComic-style frames of a user's journeyShow context and emotion
    Paper prototypesCut-out screens users "tap"Test flows in minutes
    Whiteboard flowsBoxes and arrows with the teamAlign on structure

    🧱 Low-Fi Wireframe Conventions

    ElementConvention
    ImagesBox with an X or mountain icon
    Text blocksGrey lines (or real headings)
    ButtonsRectangle with a real label
    IconsSimple circles or squares
    AnnotationsNumbered notes explaining behaviour
    💡
    Use real labels and realistic content even in low-fi. "Lorem ipsum" hides content problems such as long names or missing data.

    Module 03 · High-Fidelity

    Mid- & High-Fidelity Design

    Move from structure to polished screens with components, real content and every state.

    🎛️ Mid-Fidelity

    • Use real components from a UI kit or design system, but in neutral greys.
    • Define layout grid and spacing.
    • Add real content and data.
    • Map every screen in the flow, including errors and empty states.

    🎨 High-Fidelity

    AddDetail
    Visual styleBrand colours, typography scale, iconography
    ImageryReal photos/illustrations
    StatesHover, pressed, disabled, loading, error, empty, success
    Responsive versionsMobile, tablet, desktop
    Micro-copyFinal button labels, errors, tooltips
    AccessibilityContrast, focus, target sizes
    ⚠️
    Going high-fidelity too early makes stakeholders comment on colours instead of whether the flow works.

    🗺️ Covering Every Screen & State

    ScreenStates to design
    LoginDefault, typing, invalid email, wrong password, locked, loading, success
    Product listLoading skeleton, results, no results, error, end of list
    CartEmpty, items, item out of stock, coupon applied/invalid
    PaymentDefault, processing, failed, success
    Q. Which is a mid-fidelity characteristic?
    • A Final brand colours and photos
    • B Real components and layout in neutral greys
    • C Pen sketches
    • D Animated transitions

    Module 04 · Prototyping

    Interactive Prototyping

    Build clickable and animated prototypes that test real behaviour.

    🗂️ Types of Prototypes

    TypeWhat it isUse
    PaperPhysical screens swapped by handVery early flow tests
    Click-throughLinked static screens with hotspotsNavigation and flow validation
    Interactive / high-fiTransitions, overlays, variables, conditionsUsability testing, demos
    Coded prototypeHTML/React prototypeReal data, performance, complex logic
    Wizard of OzHuman fakes the system behind the scenesTest AI or complex features cheaply

    ⚙️ Prototype Building Blocks (Figma)

    FeatureUse
    TriggersOn click, on drag, while hovering, key/gamepad, after delay
    ActionsNavigate to, open overlay, swap overlay, scroll to, back, set variable
    AnimationsInstant, dissolve, move in/out, push, slide, smart animate
    OverlaysModals, bottom sheets, menus
    Interactive componentsHover/pressed states built into components
    Variables & conditionalsCounters, login logic, cart totals
    Flows / starting pointsMultiple test scenarios in one file

    🧪 Prototyping for Testing

    • Prototype only the paths you will test, plus a few realistic dead ends.
    • Use realistic data (names, prices, dates).
    • Set a clear starting point per task.
    • Test on the target device (Figma mobile app / mirror).
    • Note limitations so testers don't confuse prototype gaps with design problems.
    EXAMPLE · Checkout prototype

    Starting point: cart with 2 items. Interactive quantity stepper using a variable; "Apply coupon" overlay with a valid and invalid code; payment success via smart animate; one failure path triggered by a specific card number.

    Module 06 · Interview Preparation

    Interview Preparation

    Click a question to reveal a model answer.

    🧱 Wireframing Questions

    Wireframe vs mockup vs prototype?
    A wireframe shows structure; a mockup shows final static visuals; a prototype is interactive and shows behaviour.
    When do you use low vs high fidelity?
    Low-fi to explore many ideas and test flows cheaply; high-fi for usability details, sign-off and handoff once the concept is validated.
    Why avoid lorem ipsum?
    Real content reveals length, hierarchy and missing-data problems early.
    What is Crazy 8s?
    A rapid sketching exercise: 8 ideas in 8 minutes to push quantity over perfection.

    🖱️ Prototyping Questions

    What types of prototypes are there?
    Paper, click-through, high-fidelity interactive, coded and Wizard of Oz — chosen by the question you need to answer.
    How do you build a prototype for a usability test?
    Prototype only the tested paths with realistic data, set starting points per task, include key error paths, test on the target device and note prototype limits.
    What is smart animate?
    A Figma transition that animates matching layers between frames, useful for realistic state changes.
    How do variables help prototypes?
    They store values like cart count or login status so prototypes behave realistically with conditions.
    How do you avoid over-investing in a prototype?
    Match fidelity to the question, timebox it, and reuse components.

    🧰 Tools & Process Questions

    Figma vs Sketch vs Adobe XD?
    Figma leads for collaboration, components and prototyping; Sketch is macOS-native with strong symbols; XD is in maintenance mode and mostly used for legacy files.
    How do you organise a Figma file?
    Pages for exploration, ready for dev and archive; named frames; components from the library; a cover page with status.
    How do you present wireframes to stakeholders?
    Explain the goal and user, walk through the flow, state what feedback you need (structure, not colour), and show alternatives.
    How do you move from wireframe to high-fi?
    Validate structure, swap in system components, apply type and colour, add real content, design all states and responsive variants.

    Practice: Prototype a Doctor Booking Flow

    Wireframe and prototype a real-feeling flow from sketch to clickable test.

    0 / 0 correct

    🩺 Scenario: CareNow Appointment App

    CareNow lets patients find a doctor, choose a slot, pay a consultation fee and get a confirmation. You have 1 week to test the booking flow with 5 users.

    1️⃣ Task 1 · Sketch

    ✍️ List the screens you would sketch for the flow.
    Model answer: 1. Search/home (specialty, location). 2. Doctor list (filters, cards). 3. Doctor profile (fees, ratings, next slots). 4. Slot picker (date + time). 5. Patient details. 6. Payment. 7. Confirmation (date, clinic map, add to calendar). Plus error/empty: no slots, payment failed.

    2️⃣ Task 2 · Fidelity

    Q. Which fidelity for the 5-user flow test?
    • A Final high-fi with animations everywhere
    • B Mid-fi clickable prototype with realistic content
    • C Only sketches on paper, never digital
    • D No prototype

    3️⃣ Task 3 · Prototype

    ✍️ Which interactions and states will the prototype include?
    Model answer: Interactions: filter chips toggle, slot selection with selected state, "Pay" opens processing overlay → success. States: no slots for chosen date ("Next available: Thu"), payment failed path with retry, form validation error on phone number. Starting point at the home screen with a task-specific scenario.

    4️⃣ Task 4 · Hand Over

    ✍️ After testing, what do you change before high-fi?
    Model answer: Fix flow issues found (e.g. users missed the date picker — make dates horizontally scrollable with "Today/Tomorrow" labels), then apply visual system, add all states, responsive layouts and annotations for handoff.
