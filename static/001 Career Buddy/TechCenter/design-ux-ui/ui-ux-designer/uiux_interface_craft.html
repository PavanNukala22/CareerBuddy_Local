    Module 01 · Foundations

    What is Interface Craft?

    Start from zero: what makes an interface well-crafted, the building blocks of UI, and core visual principles.

    🧭 What is Interface Craft?

    Interface craft is the skill of turning structure into clear, consistent and attractive screens using grids, typography, colour, UI patterns and platform conventions. Good craft makes interfaces easy to scan, trustworthy and pleasant.

    📏 Core Visual Principles

    PrincipleIn practice

    ContrastPrimary actions stand out; text is readable

    Layout Grids & Spacing

    Use column grids and spacing systems to create consistent, responsive layouts.

    📐 Anatomy of a Grid

    ColumnsVertical sections that hold content.
    GuttersSpace between columns.
    MarginsSpace between content and screen edge.
    Rows / baselineHorizontal rhythm for text and modules.

    🗂️ Types of Grids

    GridUse
    Column gridMost app and web layouts
    Modular gridDashboards, galleries, card layouts
    Baseline gridConsistent vertical text rhythm
    Manuscript (single column)Articles, forms

    📏 Spacing System

    Use an 8-point system (4 for fine details): 4, 8, 12, 16, 24, 32, 48, 64. Keep spacing inside a group smaller than spacing between groups.

    Module 04 · UI Patterns

    UI Patterns

    Use familiar patterns so users don't have to learn every screen from scratch.

    🧩 What is a UI Pattern?

    A UI pattern is a proven, reusable solution to a recurring design problem — like a search bar, a card list or a modal. Following patterns reduces learning time (Jakob's law: users spend most time on other products).

    🗂️ Types of Patterns

    CategoryPatterns
    InputText fields, dropdowns, date pickers, steppers, toggles, sliders, chips
    NavigationBottom nav, tabs, sidebar, breadcrumbs, pagination
    ContentCards, lists, tables, carousels, accordions
    FeedbackToasts/snackbars, banners, inline validation, progress
    OverlaysModals, bottom sheets, popovers, tooltips
    OnboardingCoach marks, empty states, progressive onboarding
    Search & filterAutocomplete, faceted filters, sort

    ⚖️ Choosing the Right Pattern

    NeedUseAvoid
    Choose one of 2–5 optionsRadio buttons / segmented controlDropdown (hides options)
    Choose one of many optionsDropdown / searchable selectLong radio list
    On/off setting applied instantlyToggle switchCheckbox needing Save
    Short confirmationSnackbar with UndoBlocking modal
    Critical destructive actionConfirmation dialogSilent action
    Secondary detailsAccordion / bottom sheetNew page
    Q. A setting that takes effect immediately should use…
    • A Checkbox + Save button
    • B Toggle switch
    • C Dropdown
    • D Text field

    Responsive Web & Mobile Conventions

    Design layouts that adapt across devices and respect iOS, Android and web conventions.

    📱 Responsive Approaches

    ApproachIdea
    Mobile-firstDesign smallest screen first, then enhance
    Fluid layoutsPercentages and flexible grids
    BreakpointsLayout changes at defined widths
    AdaptiveDistinct layouts per device class
    Reflow patternsColumns stack, sidebar becomes drawer, table becomes cards

    🍎 Platform Conventions

    iOS (Human Interface Guidelines)Android (Material Design)Web
    NavigationTab bar at bottom, back at top-left, swipe backBottom nav / nav drawer, system backTop nav, sidebar, breadcrumbs
    Targets44 × 44 pt48 × 48 dp≥ 24 px (WCAG AA), aim 44
    TypeSF Pro (system)Roboto (system)Brand / web fonts
    Primary actionTop-right / bottomFAB / bottomProminent button
    Sheets & dialogsSheets, action sheetsBottom sheets, dialogsModals, popovers

    🧪 Responsive Checklist

    • Touch targets ≥ 44–48 px on touch devices.
    • No horizontal scrolling at 320 px width (except data tables).
    • Images scale with max-width: 100%.
    • Text readable at 200% zoom.
    • Hover-only interactions have touch alternatives.
    • Test in landscape and on real devices.

    Module 06 · Interview Preparation

    Interview Preparation

    Click a question to reveal a model answer.

    📐 Layout & Typography

    How do you set up a layout grid?
    Choose columns per breakpoint (4/8/12), margins and gutters, a max content width, and an 8-point spacing system; align all elements to it.
    Why use an 8-point spacing system?
    Consistent rhythm, easy maths, scales well across densities and maps to tokens and code.
    How do you create typographic hierarchy?
    A type scale with distinct sizes and weights, consistent line heights, limited families, and spacing that groups headings with their content.
    What is a comfortable line length?
    About 45–80 characters for body text.

    🎨 Colour & Patterns

    How do you apply colour in UI?
    Role-based palette (primary, surface, text, semantic), 60-30-10 balance, contrast checks and never colour alone for meaning.
    Radio buttons or dropdown?
    Radios for 2–5 visible options; dropdowns or searchable selects for many options.
    Toggle vs checkbox?
    Toggles apply immediately (settings); checkboxes are for selections submitted with a form.
    Snackbar vs modal?
    Snackbars for brief, non-blocking feedback (with undo); modals for decisions that require attention before continuing.
    Why follow UI patterns?
    Users already know them (Jakob's law), so they learn faster and make fewer errors.

    📱 Responsive & Platform

    What is mobile-first design?
    Design for the smallest screen first, focusing on essential content, then enhance layouts for larger screens.
    How do iOS and Android navigation differ?
    iOS uses a bottom tab bar and top-left back with swipe-back; Android uses bottom navigation or a drawer and the system back gesture/button.
    How does a data table adapt on mobile?
    Priority columns only, horizontal scroll with sticky first column, or reflow rows into cards.
    What touch target sizes do you use?
    iOS 44 pt, Android 48 dp, and at least 24 px on web for WCAG AA — usually aiming for 44–48 px.

    Practice: Craft a Travel Booking Screen

    Apply grids, type, colour, patterns and responsive rules to a real-feeling screen.

    0 / 0 correct

    🚆 Scenario: YatraGo Train Search Results

    YatraGo shows train search results: train name/number, departure/arrival times, duration, classes with availability and fares, and a "Book" action. Current screen: 4 fonts, tiny tap targets, red used for both "Waitlist" and "Book".

    1️⃣ Task 1 · Grid & Spacing

    ✍️ Define the mobile grid and card spacing.
    Model answer: 4-column grid, 16 px margins and gutters; card padding 16; 12 between internal groups; 16–24 between cards; class chips in a horizontal row with 8 px gap.

    2️⃣ Task 2 · Typography

    ✍️ Set the hierarchy for a train card.
    Model answer: Train name 16/600, number 13/400 secondary; times 20/700 (tabular figures) with stations 13/400; duration 13/400 centred; class chips 13/600; fare 16/700. One family (Noto Sans), two to three weights.

    3️⃣ Task 3 · Colour & Patterns

    Q. How should availability status be shown?
    • A Red for everything
    • B Colour + text label (Available 42 / RAC 5 / WL 18) with consistent semantic colours
    • C Icons only
    • D No status
    Q. Which pattern for choosing travel class?
    • A Dropdown hidden in a menu
    • B Horizontal chips/segmented options showing class, availability and fare
    • C Long text field
    • D Modal for each class

    4️⃣ Task 4 · Responsive

    ✍️ How does the layout adapt on desktop?
    Model answer: 12-column grid with filters in a left sidebar (3 columns) and results in 9 columns; each result becomes a wider row with classes visible inline; sticky summary of search at top; same components and tokens.
