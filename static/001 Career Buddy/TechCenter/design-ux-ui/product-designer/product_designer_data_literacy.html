    Module 01 · Foundations

    What is Data Literacy for Designers?

    Start from zero: what product analytics is, the types of data and metrics, and the vocabulary every analytics tool uses.

    🧭 What is Data Literacy?

    Data literacy is the ability to read, question and use data to make better decisions. For a Product Designer it means: knowing what users actually do in the product, spotting where they struggle, and proving whether a design change helped.

    🔍
    Find problems
    Where do users drop off or get stuck?
    🎯
    Prioritise
    Which problem affects the most users or revenue?
    🧪
    Prove impact
    Did the redesign really improve the metric?
    🗣️
    Persuade
    Back design decisions with evidence, not opinion.

    🗂️ Types of Data

    TypeWhat it tells youExamples
    QuantitativeWhat happened and how muchConversion 3.2%, 12,400 sign-ups
    QualitativeWhy it happenedInterview quotes, session recordings
    BehaviouralWhat users doClicks, page views, purchases
    AttitudinalWhat users say or feelSurveys, NPS, CSAT, reviews
    💡
    Analytics tells you what and where. Research tells you why. Strong designers combine both.

    📖 Key Terms (What is What)

    EventAn action a user takes or the system records, e.g. Checkout Started.
    PropertyDetail attached to an event or user, e.g. payment_method = UPI.
    User vs sessionA user is a person (or device); a session is one visit. One user can have many sessions.
    MetricA number computed from events, e.g. conversion rate.
    Dimension / segmentA way to split data: device, city, plan, new vs returning.
    FunnelAn ordered sequence of events showing drop-off between steps.
    CohortA group of users who share a start point, e.g. "signed up in March".
    DAU / MAUDaily / monthly active users; DAU ÷ MAU = stickiness.

    🧮 Types of Metrics

    Metric typeFormula styleExample
    CountTotal numberOrders placed: 4,200
    Rate / ratioPart ÷ wholeConversion = 4,200 ÷ 200,000 = 2.1%
    AverageSum ÷ countAvg. session = 4 min 30 s
    MedianMiddle valueMedian time to checkout = 2 min
    Time-basedChange over timeWeek-1 retention = 42%
    ✅
    North Star Metric: the single metric that best captures value delivered to users (e.g. Spotify: time spent listening). Design work should ladder up to it.

    🚫 Vanity vs Actionable Metrics

    🔴 Vanity

    Total downloads, page views, registered users. They only go up and rarely tell you what to change.

    🟢 Actionable

    Activation rate, week-1 retention, step conversion. They show cause and effect and guide decisions.

    Q. Which is an actionable metric?
    • A Total app downloads ever
    • B Percentage of new users who complete onboarding
    • C Instagram followers
    • D Total page views

    Module 03 · Reading Reports

    Reading Product Analytics Reports

    Interpret the five reports designers use most: funnels, retention, segmentation, paths and engagement.

    🔻 Funnel Reports

    Figure 3.1 · Onboarding funnel (Mixpanel/Amplitude style)
    1. Find the biggest drop between two steps (here: OTP → profile, −35 points).
    2. Segment it: device, OS, source, new vs returning. Is it worse on Android?
    3. Check time between steps: long gaps suggest confusion.
    4. Watch session replays for users who dropped there.

    🔁 Retention / Cohort Reports

    A cohort table shows, for each group of users who started in the same week, what % came back in later weeks.

    Sign-up weekUsersWeek 1Week 2Week 4Week 8
    Mar 32,10041%30%22%18%
    Mar 102,35043%31%23%19%
    Mar 17 (new onboarding)2,28052%39%29%—
    Mar 242,41053%40%——
    ✅
    How to read it: the curve flattens around 18–19% (that's your core retained users). The new onboarding (Mar 17) lifted week-1 retention by ~9 points, and the gain held in later weeks — a real improvement, not a spike.

    🧩 Segmentation

    SegmentCheckout conversion
    All users2.4%
    iOS3.6%
    Android1.9%
    Android, app version < 5.20.8%
    💡
    Averages hide problems. Here the "Android old version" segment points to a bug or layout issue — a design/engineering fix, not a marketing one.

    🛤️ Paths / Flows & Engagement

    • Paths (Amplitude Pathfinder, Mixpanel Flows): what users do before/after an event. E.g. 30% go from Pricing → Help → leave: pricing is unclear.
    • Feature adoption: % of active users who used a feature at least once.
    • Stickiness: DAU ÷ MAU. 20% means the average user is active ~6 days a month.
    • Frequency: how many days per week users perform the key action.

    🧠 Check Yourself

    Q. Week-1 retention jumps from 41% to 52% for the cohort that got new onboarding. Week-4 returns to the old 22%. What does this suggest?
    • A The redesign permanently improved retention
    • B Early engagement improved but long-term value did not change
    • C The data is wrong
    • D Retention cannot be measured

    Module 04 · Statistics & Pitfalls

    Statistics Basics & Data Pitfalls

    Avoid the mistakes that make smart teams draw wrong conclusions from correct data.

    📏 Average vs Median

    EXAMPLE · Time to complete checkout (7 users)

    Times: 1, 1, 2, 2, 2, 3, 35 minutes. Average = 6.6 min, median = 2 min. One user left the tab open. The median describes the typical user better.

    💡
    Use the median for time, money and other skewed data. Report percentiles (p75, p90) for performance.

    🔗 Correlation is not Causation

    Users who use the "Wishlist" buy 3× more. Does Wishlist cause buying? Maybe not — engaged shoppers both use Wishlist and buy more. Only a controlled experiment (A/B test) proves cause.

    ⚠️ Types of Data Pitfalls

    PitfallWhat happensProtection
    Small sampleBig % changes from tiny numbers (2 → 4 users = +100%)Always show absolute numbers
    SeasonalityDiwali sale lifts conversion, not your redesignCompare same period / use a control group
    Simpson's paradoxTrend reverses when data is split into groupsSegment before concluding
    Survivorship biasOnly analysing users who stayedInclude churned users
    Tracking errorsEvent fired twice or not at allCheck raw counts; QA tracking before launch
    Cherry-pickingShowing only the metric that improvedAgree on metrics before the test

    🧭 A Simple Analysis Process

    Module 05 · A/B Testing

    Running A/B Tests

    Design, size, run and read A/B tests correctly — and know when not to run one.

    🧪 What is an A/B Test?

    An A/B test randomly splits users into groups. Group A sees the current version (control); group B sees the new version (variant). Because the only difference is the design, a significant difference in the metric is caused by the design.

    🗂️ Types of Experiments

    TypeWhat it isUse when
    A/BOne control vs one variantTesting one clear change
    A/B/nControl vs several variantsComparing 2–4 alternatives (needs more traffic)
    Multivariate (MVT)Tests combinations of several elementsVery high traffic; optimising details
    Split URLDifferent pages/URLsBig redesigns of a page
    HoldoutSmall group never gets new featuresMeasuring long-term cumulative impact
    Feature-flag rolloutGradual release 5% → 50% → 100%Reducing risk; monitoring guardrails

    🔄 The A/B Testing Process

    Figure 5.1 · A/B test lifecycle

    📐 Key Concepts in Plain Words

    Primary metricThe one metric that decides the test.
    Guardrail metricMust not get worse (refunds, errors, load time).
    BaselineCurrent value of the metric, e.g. 5% conversion.
    MDEMinimum detectable effect — the smallest change worth detecting, e.g. +0.5 points.
    Statistical significanceHow unlikely the result is if there were really no difference. Common bar: 95% confidence (p < 0.05).
    PowerChance of detecting a real effect if it exists. Usually 80%.
    Sample sizeUsers needed per group. Smaller baseline or MDE → more users needed.
    📌
    Rule of thumb: baseline 5%, want to detect +0.5 points (5% → 5.5%) at 95% confidence and 80% power → roughly 31,000 users per group. Use a sample-size calculator before starting.

    ⏳ How Long to Run

    • Run until the planned sample size is reached — at least 1–2 full weeks to cover weekday/weekend behaviour.
    • Don't stop early because it "looks significant" (peeking inflates false positives).
    • Avoid launching during unusual periods (sales, holidays) unless that's what you're testing.

    📊 Example: Reading a Result

    MetricA · ControlB · VariantDifferenceSignificant?
    Users31,20031,050——
    Sign-up conversion5.0%5.6%+0.6 pts (+12%)Yes (p = 0.01)
    Activation (day 1)38%37%−1 ptNo
    Support tickets / 1k users4.14.3+0.2No (guardrail ok)
    ✅
    Decision: ship B. Primary metric improved significantly; guardrails held. Next: check whether the extra sign-ups activate at the same rate over 30 days.
    Q. A test shows +8% after 2 days and the PM wants to stop and ship. What do you say?
    • A Agree — it's clearly winning
    • B Wait until the planned sample size and full weeks are reached
    • C Restart with a new colour
    • D Stop the test and delete the data

    Module 06 · Interview Preparation

    Interview Preparation

    Click a question to reveal a model answer.

    📊 Analytics Fundamentals Questions

    Why should a product designer be data-literate?
    To find where users struggle, prioritise by impact, prove whether designs worked and persuade stakeholders with evidence rather than opinion.
    What is the difference between an event and a property?
    An event is an action (Order Placed); a property is a detail attached to it or the user (payment_method = UPI, plan = Pro).
    Vanity vs actionable metrics?
    Vanity metrics only go up and don't guide decisions (total downloads). Actionable metrics show cause and effect you can influence (activation rate, step conversion).
    Mixpanel vs Amplitude vs Google Analytics?
    Mixpanel and Amplitude are event-based product analytics for funnels, retention and paths; GA4 is strongest for marketing and traffic-source analysis. The core concepts are the same.

    🔻 Reading Reports Questions

    How do you analyse a funnel?
    Find the biggest drop between two steps, segment it (device, source, new vs returning), check time between steps, and watch session replays to understand why.
    How do you read a retention cohort table?
    Each row is a group that started together; columns show the share still active later. Look for where the curve flattens and whether changes lift retention across later weeks, not just week 1.
    Why segment data?
    Averages hide problems — e.g. overall conversion looks fine but one old Android app version converts at a third of the rate.
    Correlation vs causation?
    Two metrics moving together doesn't prove one causes the other. Only a controlled experiment (A/B test) establishes cause.

    🧪 A/B Testing Questions

    Walk me through running an A/B test.
    Write a hypothesis, choose one primary metric and guardrails, calculate sample size, randomise users, run for full weeks without peeking, check significance and guardrails, then ship, iterate or drop.
    What is statistical significance?
    How unlikely the observed difference would be if there were really no difference — commonly 95% confidence (p < 0.05).
    Why shouldn't you stop a test early?
    Peeking and stopping when results look good inflates false positives. Run until the planned sample size and at least 1–2 full weeks.
    What is a sample ratio mismatch?
    When a planned 50/50 split comes out noticeably uneven, signalling an assignment or tracking bug — results can't be trusted until it's fixed.
    When would you not run an A/B test?
    When traffic is too low, when fixing an obvious bug or accessibility issue, or when ethics are a concern. Use qualitative research instead.

    Practice: Analyse and Test

    Use analytics to find a problem, then design and read an A/B test for a real-feeling product.

    0 / 0 correct

    📚 Scenario: SkillUp Learning App

    SkillUp sells online courses. Leadership wants more course completions, because completers renew their subscription 3× more often.

    Figure 7.1 · Course funnel from Amplitude (last 30 days, 18,000 enrolments)
    SegmentLesson 1 finished → quiz started
    Web61%
    Android app38%
    iOS app52%

    1️⃣ Task 1 · Read the Funnel

    Q. Where should the designer focus first?
    • A Enrolment
    • B Lesson 1 → quiz 1 transition
    • C Course thumbnail colours
    • D The pricing page
    ✍️ What does the segment table suggest, and what would you check next?
    Model answer: Android users start the quiz much less (38% vs 61% web). Next: watch Android session replays at lesson end, check the "Next: Quiz" button visibility (autoplay next lesson? button below the fold?), check tracking accuracy on Android, and interview 5 Android learners who stopped after lesson 1.

    2️⃣ Task 2 · Write the Hypothesis

    ✍️ Replays show the Android app auto-plays lesson 2 and hides the quiz link in a menu. Write an A/B test hypothesis.
    Model answer: We believe that showing a full-screen "Lesson complete — Take the 3-minute quiz" card (instead of auto-playing lesson 2) for Android learners will increase lesson-1→quiz start from 38% to at least 50%, because replays show learners never see the quiz link.

    3️⃣ Task 3 · Design the Test

    Q. Which is the best guardrail metric?
    • A Quiz start rate
    • B Lesson 2 start rate and app uninstall rate
    • C Number of colours used
    • D Total downloads
    ✍️ Define primary metric, guardrails, sample and duration.
    Model answer: Primary: % of Android learners who start quiz 1 after finishing lesson 1. Secondary: course completion (30-day). Guardrails: lesson-2 start rate, uninstall rate, app rating. Sample: baseline 38%, MDE +4 pts → ~2,400 learners per group (calculator). Duration: ~2 weeks (≥ 2 full weeks), no peeking.

    4️⃣ Task 4 · Read the Result

    MetricA · ControlB · CardSignificant?
    Quiz start38%57%Yes (p < 0.001)
    Lesson 2 start71%69%No
    Uninstalls (14 d)3.1%3.0%No
    Split50.1%49.9%SRM check ✓
    ✍️ What is your decision and what will you tell leadership?
    Model answer: Ship B to all Android users, then test the same card on iOS. Story: "Android learners weren't skipping quizzes by choice — they never saw them. A completion card raised quiz starts from 38% to 57% with no harm to lesson-2 starts or uninstalls. Next we'll track 30-day course completion and renewals to confirm business impact."
