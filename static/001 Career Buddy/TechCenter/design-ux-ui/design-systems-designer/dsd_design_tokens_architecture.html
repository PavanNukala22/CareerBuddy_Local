    Module 01 · Foundations

    What are Design Tokens?

    Start from zero: what design tokens are, why design systems use them, and the vocabulary of token architecture.

    🧭 What is a Design Token?

    A design token is a named, platform-agnostic design decision — a colour, spacing value, font size, radius, shadow or duration — stored as data. Instead of writing #14213D in 300 places, every platform references color.action.primary.

    🔴 Hard-coded values

    Designers pick colours by eye; iOS, Android and web each copy values by hand. A brand change takes weeks and still misses screens.

    🟢 Tokens

    One source of truth exported to Figma, CSS, iOS and Android. Change the token once, every platform updates in the next release.

    🎯 Why Tokens Matter

    🔁
    Consistency
    Same decision everywhere.
    ⚡
    Speed
    Global changes in one place.
    🌗
    Theming
    Light/dark, brands, density by swapping values.
    🤝
    Shared language
    Designers and engineers use the same names.

    📖 Key Terms (What is What)

    Primitive / global tokenRaw value with no meaning: blue.700, space.4.
    Semantic / alias tokenPurpose-based reference: color.text.primary → {blue.900}.
    Component tokenScoped to one component: button.primary.bg → {color.action.primary}.
    Alias / referenceA token whose value points to another token.
    Mode / themeA set of values for the same tokens (light, dark, brand B).
    Source of truthThe single place tokens are defined (JSON in Git, Tokens Studio).
    TransformConverting token values for a platform (px → dp/pt, hex → UIColor).
    Q. Which is a design token?
    • A A login password
    • B A named design decision like color.action.primary = #14213D
    • C A React component
    • D A user persona

    Module 02 · Token Tiers

    Global, Semantic & Component Tokens

    Structure tokens in tiers so systems are flexible, themeable and easy to maintain.

    🏛️ The Three Tiers

    Figure 2.1 · Each tier references the one before it
    TierAnswersExampleWho changes it
    GlobalWhat values exist?blue.700 = #14213DBrand / core team, rarely
    SemanticWhat is this value for?color.text.primary = {neutral.900}System team, for themes
    ComponentWhere exactly is it used?button.primary.bg = {color.action.primary}Component owners

    🧩 Why Not Use Primitives Directly?

    EXAMPLE · Dark mode change

    If buttons use blue.700 directly, dark mode needs every button edited. If buttons use color.action.primary, dark mode just maps that semantic token to blue.300.

    ⚠️
    Over-tiering is also a problem: thousands of component tokens that all alias the same semantic token add maintenance without value. Create component tokens only where a component genuinely needs to diverge.

    🏷️ Naming Conventions

    A common structure: category.property.concept.variant.state

    TokenCategoryPropertyConcept / variantState
    color.bg.surface.raisedcolorbgsurface · raised—
    color.text.action.hovercolortextactionhover
    button.primary.bg.pressedbutton (component)bgprimarypressed
    space.inset.mdspaceinsetmd—
    • Name by purpose, not appearance ("danger", not "red").
    • Use consistent size scales (xs, sm, md, lg, xl or 100–900).
    • Avoid platform-specific words in names.
    • Document allowed values for each segment.

    Module 03 · Token Formats

    Token Formats, Types & Composites

    Store tokens in standard, tool-friendly formats including composite tokens for typography and shadows.

    📄 The W3C DTCG Format

    The Design Tokens Community Group (DTCG) format is the emerging standard JSON structure supported by Tokens Studio, Style Dictionary v4 and other tools. Each token has a $value and $type.

    json{
  "color": {
    "blue": { "700": { "$value": "#14213D", "$type": "color" } },
    "action": {
      "primary": { "$value": "{color.blue.700}", "$type": "color",
                   "$description": "Primary buttons and links" }
    }
  },
  "space": { "4": { "$value": "16px", "$type": "dimension" } }
}

    🧱 Composite Tokens

    Composite typeContains
    TypographyfontFamily, fontSize, fontWeight, lineHeight, letterSpacing
    ShadowoffsetX, offsetY, blur, spread, color
    Borderwidth, style, color
    Transitionduration, delay, timingFunction
    Gradientstops with colours and positions
    json"heading": { "lg": {
  "$type": "typography",
  "$value": { "fontFamily": "{font.family.sans}", "fontSize": "{font.size.700}",
              "fontWeight": "{font.weight.bold}", "lineHeight": "1.25", "letterSpacing": "-0.01em" }
}}

    📏 Scales & Math

    • Spacing often uses a 4/8-based scale: 4, 8, 12, 16, 24, 32, 48, 64.
    • Type sizes from a modular scale (e.g. ratio 1.25).
    • Colour scales in 10 steps (50–900), ideally generated in a perceptual space like OKLCH for even lightness.
    • Tokens can contain math in some tools: {space.4} * 2 — keep it simple and documented.
    Q. In DTCG JSON, which key holds a token's value?
    • A value
    • B $value
    • C val
    • D data

    Module 04 · Theming

    Theming, Modes & Figma Variables

    Use tokens to support light/dark, multiple brands, densities and platforms from one system.

    🌗 Types of Modes

    Mode typeExampleWhat changes
    Colour schemeLight / dark / high contrastSemantic colour tokens
    BrandBrand A / Brand B / white-labelPrimitive palettes, fonts, radius
    DensityComfortable / compactSpacing, sizing tokens
    PlatformiOS / Android / webSizes, fonts, motion conventions
    LocaleLTR / RTL, script-specific fontsTypography, direction

    🎛️ How Modes Work

    Semantic tokenLightDarkHigh contrast
    color.bg.surface{neutral.0}{neutral.900}{neutral.0}
    color.text.primary{neutral.900}{neutral.50}{neutral.1000}
    color.action.primary{blue.700}{blue.300}{blue.900}
    color.border.default{neutral.200}{neutral.700}{neutral.900}
    💡
    Only semantic tokens should change between colour modes. Components keep referencing the same semantic names.

    🟣 Figma Variables

    • Collections group variables (e.g. Primitives, Semantic, Density).
    • Modes per collection (Light/Dark; Brand A/B).
    • Aliasing: semantic variables reference primitive variables.
    • Scoping restricts where a variable appears (fill only, gap only).
    • Code syntax field stores the CSS/iOS/Android name for Dev Mode.
    📌
    Figma variables support colour, number, string and boolean. Composite values like typography and shadow still live in styles, or are managed via Tokens Studio.

    Module 05 · Multi-Platform Sync

    Tokens Studio, Style Dictionary & Sync Pipelines

    Automate the path from Figma to code for web, iOS and Android.

    🔄 The Token Pipeline

    Figure 5.1 · Design-to-code token pipeline

    🧰 Tokens Studio

    • Figma plugin to create and manage tokens, including composites and math.
    • Syncs JSON to GitHub, GitLab, Azure DevOps, JSONBin or URL storage.
    • Supports token sets and themes (combinations of sets).
    • Can create Figma variables and styles from tokens.
    • Designers open pull requests instead of sending values over chat.

    📚 Style Dictionary

    Style Dictionary (by Amazon) reads token JSON and outputs platform-specific files using transforms (convert values), formats (file syntax) and platforms.

    javascript// style-dictionary config (simplified)
export default {
  source: ["tokens/**/*.json"],
  platforms: {
    css:     { transformGroup: "css",     buildPath: "build/css/",     files: [{ destination: "tokens.css", format: "css/variables" }] },
    ios:     { transformGroup: "ios-swift", buildPath: "build/ios/",   files: [{ destination: "Tokens.swift", format: "ios-swift/class.swift" }] },
    android: { transformGroup: "android", buildPath: "build/android/", files: [{ destination: "colors.xml", format: "android/colors" }] }
  }
};
    css output--color-action-primary: #14213d;
--space-4: 1rem;
--radius-md: 0.5rem;

    ✅ Pipeline Governance

    • Token changes go through pull requests with design and engineering review.
    • CI builds and validates tokens (no broken references, contrast checks).
    • Semantic versioning and changelog: renaming or deleting tokens is a breaking change.
    • Deprecate before deleting; provide migration notes.
    Q. What does Style Dictionary do?
    • A Draws icons
    • B Transforms token JSON into platform-specific outputs (CSS, Swift, Android XML)
    • C Hosts documentation only
    • D Tests usability

    Module 06 · Interview Preparation

    Interview Preparation

    Click a question to reveal a model answer.

    🏛️ Token Architecture Questions

    What are design tokens and why use them?
    Named, platform-agnostic design decisions stored as data. They give a single source of truth, consistency across platforms, fast global changes and theming.
    Explain global, semantic and component tokens.
    Global (primitive) tokens hold raw values; semantic tokens give them purpose (color.text.primary); component tokens scope them to a component (button.primary.bg). Each tier references the one below.
    Why shouldn't components reference primitives directly?
    Because theming would require editing every component. Referencing semantic tokens lets modes swap values centrally.
    How do you name tokens?
    A consistent structure like category.property.concept.variant.state, named by purpose not appearance, with documented scales and no platform-specific words.
    When are component tokens worth it?
    When a component must diverge from semantic defaults or be themed independently; otherwise they add maintenance without value.

    🌗 Theming & Format Questions

    How do you implement dark mode with tokens?
    Keep the same semantic names, map them to different primitives per mode, and keep components referencing semantics. Check contrast in both modes.
    What is the DTCG format?
    The W3C Design Tokens Community Group JSON standard where tokens have $value, $type and optional $description, with references like {color.blue.700}.
    What are composite tokens?
    Tokens whose value groups several properties, like typography (family, size, weight, line height) or shadow (offsets, blur, colour).
    Figma variables vs Tokens Studio?
    Figma variables are native, support modes and aliasing for colour/number/string/boolean; Tokens Studio adds composites, math and Git sync. Many teams use both.

    🔄 Pipeline & Governance Questions

    Describe a token pipeline from Figma to production.
    Tokens Studio or Figma variables → JSON in Git via pull request → CI runs Style Dictionary to generate CSS, Swift and Android outputs → packages published and consumed by apps.
    How do you handle a token rename?
    Treat it as a breaking change: add the new token, deprecate the old one with an alias, announce in release notes, provide migration steps and remove in the next major version.
    How do you prevent broken tokens?
    Linting and CI checks for missing references, naming rules, type validation and automated contrast checks before merge.
    How do you get adoption of tokens?
    Make them easy to consume (packages, Figma libraries), document usage, show wins (theme switch in minutes), and track hard-coded values with lint rules.

    Practice: Tokenise a Multi-Brand App

    Design a token architecture for a real-feeling product with two brands and dark mode.

    0 / 0 correct

    🏦 Scenario: FinCore White-Label Banking App

    FinCore sells one banking app to two banks: Sahyadri Bank (green, rounded, friendly) and Meridian Bank (navy, sharp, premium). Each needs light and dark mode on web, iOS and Android. Today, colours are hard-coded in 600+ places.

    1️⃣ Task 1 · Tiers

    ✍️ Define tokens for the primary button background across all tiers.
    Model answer: Global: green.600 = #1E7B4F, green.300 = #6FCF97 (Sahyadri); navy.800 = #14213D, navy.300 = #8FA3D9 (Meridian). Semantic: color.action.primary → Sahyadri light {green.600}, dark {green.300}; Meridian light {navy.800}, dark {navy.300}. Component: button.primary.bg → {color.action.primary}.

    2️⃣ Task 2 · Modes

    Q. How should you structure modes?
    • A One mode per screen
    • B Brand collection (Sahyadri/Meridian) × colour-scheme collection (light/dark)
    • C Separate component libraries per bank
    • D Hard-code per platform
    ✍️ Which tokens differ between brands besides colour?
    Model answer: radius.md (Sahyadri 12px, Meridian 4px), font.family.heading (rounded sans vs serif), shadow.level.1 (soft vs crisp), motion.easing.standard (gentle vs precise), and logo assets.

    3️⃣ Task 3 · Pipeline

    ✍️ Describe the pipeline from Figma to the three apps.
    Model answer: Tokens managed in Tokens Studio with sets for primitives, semantic, brand and mode → synced to GitHub → pull request reviewed by design and engineering → CI runs Style Dictionary with one config per brand × mode → outputs CSS variables (web), Swift (iOS), Android XML/Compose → published as versioned packages per brand → apps update dependency.

    4️⃣ Task 4 · Migration

    Q. Best way to replace 600 hard-coded colours?
    • A Change everything in one release with no plan
    • B Map existing values to semantic tokens, add lint rules flagging hex values, migrate screen by screen and track progress
    • C Leave them
    • D Rename the colours
