    What is Front-End Interoperability?

    Start from zero: how the web stack works, why design systems designers need code literacy, and key front-end vocabulary.

    🧭 Why Designers Need Code Literacy

    Front-end interoperability means design decisions translate cleanly into code — same names, same structure, same behaviour. Design systems designers don't need to ship production code, but they must understand how components are built so Figma and code stay in sync.

    ⚡

    • Units: px (fixed), rem (relative to root font size — respects user settings), % and vw/vh, fr in grid.

    • Use logical properties (margin-inline-start) for RTL support.

    React Components & Lifecycles

    Understand props, state, lifecycle phases and hooks — and how design decisions map to them.

    ⚛️ Components, Props & State

    tsxexport function Button({ variant = "primary", size = "md", loading = false, disabled, children, ...rest }: ButtonProps) {
  return (
    <button
      className={`btn btn--${variant} btn--${size}`}
      disabled={disabled || loading}
      aria-busy={loading}
      {...rest}
    >
      {loading ? <Spinner aria-hidden /> : null}
      <span>{children}</span>
    </button>
  );
}

    📥 Props

    Passed in from outside; read-only inside the component. Maps to Figma component properties.

    💾 State

    Owned and changed by the component (open/closed, input value). Maps to interactive states in prototypes.

    🔄 Component Lifecycle

    🪝 Common Hooks

    HookPurpose
    useStateLocal state (open, value)
    useEffectSide effects tied to lifecycle
    useRefReference DOM elements (focus management)
    useMemo / useCallbackAvoid unnecessary recalculations/re-renders
    useContextRead shared values (theme, locale)
    useIdStable IDs for label/aria linking
    tsxfunction Dialog({ open, onClose, children }) {
  const ref = useRef<HTMLDivElement>(null);
  useEffect(() => {
    if (open) ref.current?.focus();          // move focus in on open
    const onKey = (e: KeyboardEvent) => e.key === "Escape" && onClose();
    document.addEventListener("keydown", onKey);
    return () => document.removeEventListener("keydown", onKey); // cleanup
  }, [open, onClose]);
  if (!open) return null;
  return <div role="dialog" aria-modal="true" tabIndex={-1} ref={ref}>{children}</div>;
}

    🧠 Controlled vs Uncontrolled

    🎛️ Controlled

    Parent owns the value: <Input value={v} onChange={setV}/>. Predictable, needed for validation.

    🆓 Uncontrolled

    Component keeps its own value internally. Simpler, less control.

    Module 06 · Interview Preparation

    Interview Preparation

    Click a question to reveal a model answer.

    🧱 HTML & CSS Questions

    Why does semantic HTML matter for a design system?
    Native elements bring keyboard support, focus and screen-reader semantics for free; specs should state which element each component uses.
    How does Figma auto layout map to CSS?
    Auto layout ≈ Flexbox: direction → flex-direction, gap → gap, padding → padding, hug → fit-content, fill → flex: 1, wrap → flex-wrap.
    px vs rem?
    px is fixed; rem scales with the root font size and respects user text-size settings — preferred for type and often spacing.
    What are container queries?
    CSS rules based on a component's container size rather than the viewport, so components adapt wherever they are placed.

    ⚛️ JavaScript & React Questions

    Props vs state?
    Props are inputs passed from outside and read-only inside; state is data the component owns and updates over time.
    Explain the React component lifecycle.
    Mount (created and inserted), update (re-render when props/state change) and unmount (removed, cleanup). In hooks, useEffect with dependencies and cleanup functions handles these phases.
    Controlled vs uncontrolled components?
    Controlled: parent owns the value via props and onChange. Uncontrolled: component keeps its own internal value.
    How do Figma properties map to React props?
    Variants → enum props, booleans → boolean props, text → string/children, instance swap → ReactNode/slot props, with names agreed in advance.
    How should a modal manage focus in code?
    On open move focus into the dialog (useRef + focus), trap focus inside, close on Esc via a key listener, clean up on unmount and return focus to the trigger.

    🔄 Pipeline Questions

    Describe a design-to-code pipeline.
    Figma variables/components → tokens via Tokens Studio and Style Dictionary → React component library → Storybook with a11y and visual tests → CI publishes versioned packages consumed by apps.
    What is visual regression testing?
    Automated screenshot comparison of components on each change, highlighting visual differences for review before merging.
    What is Figma Code Connect?
    A Figma feature that links design components to real code components so Dev Mode shows the actual implementation snippet.
    What belongs in the definition of done for a system component?
    Figma component, coded component, tokens only, all states, accessibility checks, Storybook stories, docs, tests and release notes.

    Practice: Ship a Toggle Switch End-to-End

    Take one component from Figma to code, documentation and release.

    0 / 0 correct

    🔘 Scenario: Pulse Design System — Toggle Switch

    Pulse needs a Toggle Switch for settings screens: on/off, disabled, loading (saving), with a label and optional description. It must work in light/dark themes, meet WCAG 2.2 AA, and ship to the React library with docs.

    1️⃣ Task 1 · Figma API

    ✍️ Define the Figma properties and the matching React props.
    Model answer: Figma: Checked (variant: on/off), State (default/hover/focus/disabled/loading), Label (text), Show description (boolean) + Description (text), Size (sm/md). React: <Switch checked onCheckedChange disabled loading size="md" label="Wi-Fi" description="…" />.

    2️⃣ Task 2 · Semantics

    Q. Which markup is best?
    • A <div class="switch">
    • B <button role="switch" aria-checked="true"> with a visible label
    • C <img src="switch.png">
    • D <span onclick>
    ✍️ List the accessibility requirements.
    Model answer: Accessible name from the visible label; role="switch" with aria-checked; Space/Enter toggles; visible focus ring (focus token); thumb/track contrast 3:1; hit area ≥ 44 px; loading announced (aria-busy or live region "Saving…"); disabled state with reason via description.

    3️⃣ Task 3 · Code

    ✍️ Sketch the React component.
    Model answer: function Switch({ checked, onCheckedChange, disabled, loading, label, description }) { const id = useId(); return (<div className="switch-row"><button id={id} role="switch" aria-checked={checked} aria-busy={loading} disabled={disabled || loading} onClick={() => onCheckedChange(!checked)} className="switch"><span className="thumb" /></button><label htmlFor={id}>{label}</label>{description && <p>{description}</p>}</div>); } — styles use tokens only.

    4️⃣ Task 4 · Pipeline & Release

    ✍️ List the steps to release it.
    Model answer: 1. Add component tokens (switch.track.bg.on/off) aliasing semantic tokens; rebuild with Style Dictionary. 2. Write stories for every state and theme; run a11y addon. 3. Chromatic visual review approved by design. 4. Docs page in Zeroheight embedding stories; Code Connect mapping in Figma. 5. Changeset as MINOR (new component, beta), publish package and release notes.
    Q. Releasing a brand-new component is which version bump?
    • A PATCH
    • B MINOR
    • C MAJOR
    • D None
