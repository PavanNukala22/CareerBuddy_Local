    Module 01 · Foundations

    What are Complex UI States?

    Start from zero: what a UI state is, the types of states every component has, and why complex products need state thinking.

    🧭 What is a UI State?

    A UI state is how an element or screen looks and behaves under specific conditions. Simple components have a few states; complex products have hundreds of combinations across data, permissions, connectivity and input methods. Interaction designers define them all.

    🗂️ Types of States

    CategoryStates
    Interaction statesDefault, hover, focus, pressed/active, dragged, disabled
    Selection statesUnselected, selected, indeterminate (partial), expanded/collapsed
    Data statesEmpty, loading, partial, ideal, overflow
    Outcome statesSuccess, warning, error, info
    Validation statesUntouched, valid, invalid, validating
    System statesOffline, syncing, conflict, read-only, permission denied
    Lifecycle statesDraft, pending, published, archived, deleted

    🧱 Example: One Checkbox, Many States

    DimensionValues
    SelectionUnchecked · checked · indeterminate
    InteractionDefault · hover · focus · pressed
    AvailabilityEnabled · disabled · read-only
    ValidationNormal · error
    📌
    3 × 4 × 3 × 2 = 72 possible combinations for one checkbox. Design systems define rules (layers) instead of drawing every one.

    📖 Key Terms

    Edge stateA rare or extreme condition: zero, max, error, conflict.
    Progressive disclosureShowing only what's needed now; revealing more on demand.
    GestureA touch movement with meaning: swipe, pinch, long press.
    Haptic feedbackVibration patterns that confirm actions through touch.
    IndeterminateNeither fully on nor off — e.g. some children selected.
    State layerA semi-transparent overlay showing hover/press/focus (Material).
    Q. A "Select all" checkbox where only some items are selected shows which state?
    • A Checked
    • B Unchecked
    • C Indeterminate
    • D Disabled

    Module 02 · Edge States

    Defining Edge States

    Find and design the extreme, rare and messy states that break interfaces in production.

    🧷 What is an Edge State?

    An edge state is a condition at the boundaries of normal use. It's rare for one user but common across millions. Undesigned edge states produce broken layouts, confusing dead-ends and support tickets.

    🗂️ Types of Edge States

    TypeExamples
    Quantity0 items, 1 item, 10,000 items, 99+ notifications
    ContentVery long names, missing images, emojis, multiple scripts, RTL
    TimeExpired session, deadline passed, time-zone boundaries
    Permission & roleViewer vs editor, suspended account, trial expired
    ConnectivityOffline, slow network, sync conflict
    ConcurrencyItem edited by someone else, sold out during checkout
    InterruptionApp backgrounded, call during payment, back pressed mid-flow
    Device & settingsLarge text, dark mode, landscape, low storage

    🧮 The Edge-State Matrix

    EXAMPLE · Shared task card in a team app
    Edge stateDesign decision
    Title 120 charactersClamp to 2 lines + ellipsis; full on open
    No assignee"Unassigned" chip with Assign action
    Due date passedRed "Overdue 3 days" label + icon (not colour alone)
    Edited by teammate while openBanner "Riya updated this task" + Refresh
    Viewer roleHide edit controls; show "View only" label
    OfflineChanges queued with "Will sync" indicator

    🔍 Finding Edge States

    1. Walk each state × event in your state machine — empty cells are edge states.
    2. Apply the 0–1–many rule to every list.
    3. Review production data: longest values, error logs.
    4. Pair with QA and engineering; they know where systems break.
    5. Test with accessibility settings and slow networks.
    Q. Which is a concurrency edge state?
    • A A long title
    • B Item goes out of stock while it is in the user's cart
    • C Dark mode
    • D Empty search

    Module 03 · Progressive Disclosure

    Progressive Disclosure

    Reduce complexity by showing the essentials first and revealing the rest when needed.

    🪜 What is Progressive Disclosure?

    Progressive disclosure defers advanced or rarely used features to a secondary screen or interaction. It keeps the interface simple for most users while keeping power available for those who need it.

    🔴 Everything at once

    A transfer screen with 18 fields: amount, payee, remarks, schedule, recurrence, purpose code, SWIFT, charges…

    🟢 Disclosed

    Amount + payee visible; "Schedule or repeat" and "More options" expand when needed.

    🗂️ Types of Progressive Disclosure

    PatternHowExample
    Accordion / expanderSections expand in placeFAQ, advanced settings
    "More options" / show moreReveal extra fieldsSearch filters
    Staged disclosure (wizard)Steps in sequenceOnboarding, KYC
    Contextual disclosureOptions appear after a related choiceChoosing "Business" reveals GST field
    Hover / long-press revealSecondary actions on demandRow actions in tables
    Drill-downSummary → detail screensDashboard → report
    Tooltips / popoversExplanations on demand"What is IFSC?"

    📏 Rules of Thumb

    • Disclose based on frequency and importance — use analytics to decide what is primary.
    • Keep the trigger obvious and well-labelled ("Advanced filters (6)").
    • Usually limit to two levels; deeper nesting gets lost.
    • Preserve state: expanded sections stay open when returning.
    • Don't hide anything users need to make the main decision (e.g. total price).

    🧠 Check Yourself

    Q. Which should NOT be hidden behind "More details" on a payment screen?
    • A Transaction reference format
    • B Total amount including fees
    • C Purpose code for rare transfers
    • D Help article link
    ✍️ Apply progressive disclosure to a flight search form.
    Model answer: Visible: From, To, Date, Passengers (1 adult default), Search. Disclosed: "Return trip" toggle reveals return date; "Passengers & class" opens a sheet; "More filters" (airlines, stops, times, baggage) after results; multi-city as a separate tab.

    Module 04 · Gesture-Based Inputs

    Gesture-Based Inputs

    Design touch gestures that are discoverable, forgiving and never the only way to act.

    👆 What is a Gesture?

    A gesture is a movement on a touch surface that triggers an action. Gestures are fast for experts but invisible — users must discover and remember them.

    🗂️ Types of Gestures

    GestureCommon meaningExample
    TapSelect / activateOpen item
    Double tapZoom / likeLike a photo
    Long pressContext menu / select modeMulti-select messages
    Swipe (horizontal)Reveal actions / dismiss / navigateSwipe email to archive
    Swipe (vertical) / pullScroll / refresh / dismiss sheetPull to refresh
    DragMove / reorderReorder playlist
    Pinch / spreadZoom out / inMaps, photos
    RotateRotate objectImage editing
    Edge swipeSystem back / navigationAndroid back gesture

    🧠 Gesture Design Rules

    RuleWhy
    Always provide a visible alternativeAccessibility, discoverability (WCAG 2.5.1 pointer gestures)
    Follow platform conventionsUsers carry expectations (Jakob's law)
    Show affordancesPeek of hidden actions, drag handles, "swipe" hint once
    Use thresholdsAction triggers only past e.g. 40% of width — prevents accidents
    Give continuous feedbackContent follows the finger; action icon appears as you swipe
    Allow undo for destructive gesturesSnackbar "Archived · Undo"
    Avoid conflictsHorizontal swipe in a carousel inside a swipeable tab view confuses

    Module 05 · Tactile Feedback

    Tactile & Haptic Feedback

    Use vibration to confirm actions and communicate states through touch — subtly and meaningfully.

    📳 What is Haptic Feedback?

    Haptic feedback uses the device's vibration motor to create touch sensations. Well-designed haptics confirm actions, mark boundaries and signal outcomes without needing the user to look.

    🗂️ Types of Haptics (iOS / Android)

    TypeFeels likeUse for
    Impact (light / medium / heavy)A tap or bumpSnapping into place, collisions, toggles
    SelectionTiny tickScrolling through picker values
    Notification: successDouble light tapPayment success, task complete
    Notification: warningMedium patternApproaching a limit
    Notification: errorStrong tripleFailed action
    Custom patternsDesigned sequences (Core Haptics)Games, rich experiences
    PlatformAPI
    iOSUIImpactFeedbackGenerator, UISelectionFeedbackGenerator, UINotificationFeedbackGenerator, Core Haptics
    AndroidHapticFeedbackConstants (CONFIRM, REJECT, CLOCK_TICK…), VibrationEffect
    Webnavigator.vibrate() — limited support (not on iOS Safari)

    📏 Haptic Design Rules

    • Pair haptics with a visible (and ideally audible) change — never haptics alone.
    • Use them for meaningful moments; constant buzzing becomes noise and drains battery.
    • Match intensity to importance: light for selection, stronger for errors.
    • Be consistent: the same event always feels the same.
    • Respect system settings (haptics off, low power).

    🎛️ Other Tactile Signals

    🧲
    Snap points
    Haptic tick when a slider reaches a meaningful value.
    🧱
    Boundaries
    Light impact when a list hits its end.
    🔐
    Security
    Distinct pattern for biometric success/failure.
    📍
    Drag & drop
    Tick when an item lifts and when it drops into place.
    Q. Which haptic suits scrolling through a time picker?
    • A Heavy impact
    • B Selection ticks
    • C Error notification
    • D No feedback ever

    Module 06 · Interview Preparation

    Interview Preparation

    Click a question to reveal a model answer.

    🧷 Edge State Questions

    What is an edge state, and how do you find them?
    A rare or extreme condition at the boundary of normal use. Find them by walking every state × event, applying the 0–1–many rule, reviewing production data, and pairing with QA and engineers.
    Give examples of concurrency edge states.
    An item sells out while in the cart, a teammate edits a record you have open, or two devices sync conflicting changes.
    How do you handle the "many" case for notifications?
    Cap the badge (99+), group items by day or type, offer "Mark all as read", and paginate or virtualise long lists.
    How do you prioritise which edge states to design first?
    By frequency × impact: how many users hit it and how badly it blocks them. Blocking, money-related or data-loss cases come first.

    🪜 Progressive Disclosure Questions

    What is progressive disclosure?
    Showing essentials first and revealing advanced or rare options on demand, keeping the interface simple for most users while keeping power available.
    What should never be hidden?
    Anything users need for the main decision — like the total price including fees, or important warnings.
    How many levels of disclosure are reasonable?
    Usually two. Deeper nesting makes features hard to find; use clear labels such as "Advanced filters (6)".
    Give an example of contextual disclosure.
    Selecting "Business account" reveals GST and company fields; personal users never see them.

    👆 Gesture & Haptic Questions

    What are the rules for designing gestures?
    Follow platform conventions, give continuous feedback, use thresholds to prevent accidents, allow undo for destructive actions, avoid gesture conflicts, and always provide a visible alternative.
    Why must every gesture have a visible alternative?
    Gestures are invisible and hard to discover, and some users can't perform them. WCAG 2.5.1 requires single-pointer alternatives for path-based gestures.
    Which haptic types exist on iOS?
    Impact (light/medium/heavy), selection (ticks), and notification (success/warning/error), plus custom patterns with Core Haptics.
    When should you not use haptics?
    For constant or trivial events, as the only feedback channel, or when the system haptics setting is off. Overuse becomes noise and drains battery.
    How do you manage state explosion in a component?
    Separate independent dimensions (selection, interaction, validation), use state layers for hover/press/focus, define priority rules (disabled overrides hover) and use component variants and properties.

    📥 Scenario: TeamMail Mobile Inbox

    TeamMail is a work email app. Users want faster triage on mobile. Proposed features: swipe actions, multi-select, smart filters, and offline support. Support logs show accidental deletions and confusion about "where emails went".

    1️⃣ Task 1 · Edge States

    ✍️ List 5 edge states for the inbox list and your decision for each.
    Model answer: (1) Empty inbox → "You're all caught up" + link to Archive. (2) 10,000 unread → "9,999+" badge, "Mark all as read". (3) Offline → cached list, banner, actions queued. (4) Email deleted on desktop while open on mobile → "This email was moved" + Back. (5) Very long subject/sender → 1-line clamp with ellipsis.

    2️⃣ Task 2 · Gestures

    Q. Users accidentally delete emails with swipe. Best fix?
    • A Remove swipe
    • B Make right-swipe Archive (reversible), require a longer swipe threshold for Delete, and show Undo
    • C Add more swipe actions
    • D Make swipe faster
    ✍️ Specify the swipe-to-archive behaviour (threshold, feedback, alternative).
    Model answer: Threshold 40% of row width; below it the row springs back. Feedback: archive icon fades in and grows as you swipe, background turns green at threshold + light impact haptic; on release row collapses (200 ms) and snackbar "Archived · Undo" for 5 s. Alternative: long-press → multi-select toolbar with Archive button; also an Archive action inside the email.

    3️⃣ Task 3 · Progressive Disclosure

    ✍️ How would you disclose smart filters?
    Model answer: Visible: chips for "Unread", "Mentions", "Attachments". Disclosed: "Filters (3)" opens a sheet with sender, date range, labels, size; active filters show as removable chips above the list.

    4️⃣ Task 4 · Haptics

    Q. Which moment deserves a success haptic?
    • A Every scroll
    • B Archiving reaches the threshold / bulk action completes
    • C Opening the app
    • D Typing each letter

    5️⃣ Task 5 · Multi-Select States

    ✍️ Define the states of the "Select all" checkbox in selection mode.
    Model answer: Unchecked (none selected), Indeterminate (some selected, aria-checked="mixed"), Checked (all loaded selected). Tapping indeterminate selects all; tapping checked clears all. If the list has more than loaded items, show "All 50 on this page selected · Select all 1,240".
