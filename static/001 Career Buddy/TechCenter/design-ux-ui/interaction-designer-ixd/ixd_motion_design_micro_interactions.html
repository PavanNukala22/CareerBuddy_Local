    Module 01 · Foundations

    What is Motion Design in UI?

    Start from zero: why interfaces move, the types of UI motion, and the principles behind good animation.

    🧭 What is UI Motion Design?

    UI motion design is the planned use of animation in interfaces to explain change, give feedback, guide attention and express brand. Good motion is functional first: it helps users understand what happened and where things went.

    🧭
    Orient
    Show where content came from and went.
    💬
    Feedback
    Confirm an action was received.
    👀
    Focus
    Draw attention to what matters now.
    ✨
    Character
    Express brand personality — sparingly.

    🗂️ Types of UI Motion

    TypePurposeExample
    TransitionsMove between screens or statesCard expands into a detail page
    FeedbackRespond to inputButton press scale, ripple
    Status / progressShow system activityUpload progress, skeleton shimmer
    Micro-interactionsSmall single-purpose momentsLike heart, toggle switch
    Attention / hintGuide the eyeGentle bounce on a new badge
    Expressive / brandPersonality, delightAnimated illustration on success

    🎞️ Animation Principles Applied to UI

    Principle (Disney)In UI
    TimingDuration sets the feel: fast = responsive, slow = heavy
    Easing (slow in / slow out)Natural acceleration instead of robotic linear motion
    AnticipationSlight pull-back before a big move (use rarely)
    Follow-through & overlapElements settle at slightly different times (staggering)
    Squash & stretchSubtle scale on press for "squishy" buttons
    ArcsNatural curved paths for moving objects
    StagingAnimate one main thing at a time

    📖 Key Terms (What is What)

    DurationHow long an animation lasts (ms).
    EasingHow speed changes over time.
    DelayWait before an animation starts.
    StaggerSmall delays between items in a group.
    KeyframeA defined value at a point in time.
    InterpolationCalculating values between keyframes.
    SpringPhysics-based motion defined by stiffness and damping.
    ChoreographyCoordinating multiple animations into one clear sequence.
    Q. Which is a functional use of motion?
    • A Confetti on every page load
    • B Showing a card expand into its detail view so users keep their place
    • C Random bouncing icons
    • D Animated background gradients

    Module 02 · Easing

    Easing Curves

    Understand how speed changes over time, read cubic-bezier curves and choose the right easing for each job.

    📈 What is Easing?

    Easing describes how an animation's speed changes from start to end. Real objects don't start or stop instantly — they accelerate and decelerate. Easing makes UI motion feel natural.

    Figure 2.1 · Easing curves: x = time, y = progress. Steeper = faster

    🗂️ Types of Easing & When to Use

    EasingFeelsUse for
    Ease-out (decelerate)Arrives quickly, settles gentlyElements entering the screen; most UI responses
    Ease-in (accelerate)Starts slowly, leaves fastElements leaving the screen
    Ease-in-out (standard)Smooth start and stopElements moving from one place to another on screen
    LinearMechanicalProgress bars, spinners, colour/opacity loops
    SpringPhysical, can overshootDrag release, sheets, playful interactions
    StepsFrame-by-frame jumpsSprite animations, ticking counters

    🔢 Reading cubic-bezier()

    CSS and most tools define easing with cubic-bezier(x1, y1, x2, y2) — two control points that shape the curve.

    NameValue (Material 3 / common)
    Standardcubic-bezier(0.2, 0, 0, 1)
    Emphasized decelerate (enter)cubic-bezier(0.05, 0.7, 0.1, 1)
    Emphasized accelerate (exit)cubic-bezier(0.3, 0, 0.8, 0.15)
    CSS ease-outcubic-bezier(0, 0, 0.58, 1)
    CSS ease-incubic-bezier(0.42, 0, 1, 1)
    css.sheet { transition: transform 300ms cubic-bezier(0.05, 0.7, 0.1, 1); }

    🌀 Spring Physics

    Stiffness / tensionHow strongly the spring pulls to its target — higher = faster.
    Damping / frictionHow quickly motion settles — lower = more bounce.
    MassHeavier objects move slower and overshoot more.
    VelocityInitial speed — useful after a fling gesture.
    💡
    Springs are great for interruptible, gesture-driven motion: they continue naturally from the finger's velocity. iOS and Framer use springs heavily.
    Q. A bottom sheet slides in. Best easing?
    • A Ease-in
    • B Ease-out / decelerate
    • C Linear
    • D Steps

    Module 03 · Timing

    Kinetic Timing & Choreography

    Choose durations, delays and staggers that feel fast, clear and coordinated.

    ⏱️ Duration Guidelines

    InteractionTypical duration
    Hover, press, ripple start50–100 ms
    Small change (toggle, checkbox, icon swap)100–200 ms
    Medium (menu, dropdown, card expand)200–300 ms
    Large (full-screen transition, sheet)300–500 ms
    Exit animations~20–30% shorter than enter
    📌
    Response under 100 ms feels instant. Most UI animations should finish in 200–400 ms; beyond 500 ms users start waiting for the UI.

    📏 Duration by Distance & Size

    • Larger elements and longer distances need slightly more time.
    • On large screens (desktop/tablet), motion can be a bit longer than on phones.
    • Wearables need shorter durations (smaller distances).
    • Keep durations consistent across similar components via motion tokens.
    tokensmotion.duration.short   = 100ms   // toggles
motion.duration.medium  = 250ms   // menus, cards
motion.duration.long    = 400ms   // page transitions
motion.easing.enter     = cubic-bezier(0.05, 0.7, 0.1, 1)
motion.easing.exit      = cubic-bezier(0.3, 0, 0.8, 0.15)

    🎼 Stagger & Choreography

    Figure 3.1 · List items staggered by 30 ms (bar = start delay in ms)
    • Stagger 20–50 ms between items; cap the total so the last item isn't late.
    • Animate the most important element first (hero → content → secondary).
    • Use one shared direction and easing so the sequence reads as one movement.

    🖥️ Frame Rate & Smoothness

    Smooth motion needs 60 fps (one frame every 16.7 ms), or 120 fps on high-refresh displays. Dropped frames ("jank") make even good timing feel cheap.

    Q. A dropdown menu opens. Reasonable duration?
    • A 20 ms
    • B 200–250 ms
    • C 1.2 s
    • D 3 s

    Transitions & Feedback

    Design transitions that preserve context and feedback that confirms every action.

    🔀 Types of Transitions

    TransitionWhat happensUse when
    Container transformA card grows into the full pageOpening items from lists/grids
    Shared elementOne element (image) moves between screensGallery → detail
    Shared axis (X/Y/Z)Screens slide along an axisSteppers (X), tabs, onboarding

    FadeSimple opacity changeDialogs, menus appearing
    Push / slideNew screen pushes from the sideHierarchical navigation (iOS)

    💬 Types of Feedback

    FeedbackExampleTiming
    Press stateButton darkens / scales to 0.97Immediate (< 100 ms)
    ProgressSpinner in button, progress barWhile waiting
    SuccessTick morphs from spinnerOn completion
    ErrorField shakes gently + messageOn failure
    State changeToggle thumb slides, label updates150–200 ms
    UndoItem collapses + snackbar "Undo"On destructive action

    🧩 Micro-Interaction Anatomy (Saffer)

    Figure 4.1 · Four parts of a micro-interaction
    EXAMPLE · Button: Submit → Loading → Success

    2. Release: label fades out, button narrows to a circle (250 ms, standard easing), spinner appears.
    3. Success: spinner morphs into a tick (200 ms), background turns green.
    4. After 1.2 s: returns to "Submitted" disabled state.

    🥧 ProtoPie Concepts

    TriggerTap, drag, scroll, long press, voice, sensors (tilt, compass).
    ResponseMove, scale, opacity, rotate, text, jump to scene, play sound.
    ConditionRun response only if a rule is true.
    Variable & formulaStore values, compute positions, counters.
    Pie Studio / ConnectTest on real devices; connect hardware.

    🖼️ Framer Concepts

    • Components & variants with interactions between variants (hover, pressed, loading).
    • Smart animate between variants with spring or tween settings.
    • Code components in React for custom logic.
    • Publish as a live, shareable website.
    framer (react)<motion.div
  whileTap={{ scale: 0.97 }}
  animate={{ opacity: 1, y: 0 }}
  initial={{ opacity: 0, y: 12 }}
  transition={{ type: "spring", stiffness: 400, damping: 30 }}
/>

    🎬 After Effects & Lottie

    • Design detailed motion with keyframes, graph editor (speed/value graphs) and expressions.
    • Export vector animations as Lottie JSON via Bodymovin — tiny files that developers play natively on iOS, Android and web.
    • Use for illustrated empty states, onboarding, success animations, animated icons.
    ⚠️
    Lottie is for playback, not interaction logic. Keep files small and avoid unsupported effects (blurs, some masks).

    Interview Preparation

    Click a question to reveal a model answer.

    📈 Easing & Timing Questions

    Which easing do you use for entering vs exiting elements?
    Ease-out (decelerate) for entering, so elements arrive quickly and settle; ease-in (accelerate) for exiting; ease-in-out (standard) for elements moving within the screen.
    What durations do you use for UI animation?
    Roughly 100–200 ms for small changes like toggles, 200–300 ms for menus and cards, 300–500 ms for full-screen transitions. Exits are usually shorter than entries.
    What does cubic-bezier(x1, y1, x2, y2) define?
    Two control points of a curve mapping time to progress. The shape determines acceleration and deceleration.
    When would you use a spring instead of a duration-based curve?
    For gesture-driven, interruptible motion — sheets, drag release, flings — because springs continue naturally from the finger's velocity and feel physical.
    What is staggering and how much delay do you use?
    Small delays between items in a group so they read as a sequence. Typically 20–50 ms per item, with a cap so the last item is not late.

    ✨ Micro-Interaction & Transition Questions

    Describe the anatomy of a micro-interaction.
    Dan Saffer's model: trigger (what starts it), rules (what happens), feedback (what users see, hear or feel) and loops & modes (how it repeats or changes over time).
    Which transition would you use for opening an item from a grid?
    A container transform or shared-element transition, because it keeps spatial continuity — users see where the content came from.
    How do you justify motion to a stakeholder who thinks it is decoration?
    Show its function: it explains spatial change, confirms actions and reduces errors. Back it with usability evidence and keep it short so it never slows tasks.
    Design feedback for a Pay button.
    Press scale (~80 ms), button disabled with spinner during processing, spinner morphs into a tick with a success haptic, then transition to confirmation. On failure, a gentle shake and a clear message that no money was deducted.

    🧰 Tools, Accessibility & Performance Questions

    ProtoPie, Framer, Principle or After Effects — when do you use each?
    ProtoPie for logic-rich and sensor-based device prototypes; Framer for interactive web prototypes with code; Principle for quick timeline animations; After Effects for high-fidelity motion and Lottie exports.
    How do you make motion accessible?
    Respect prefers-reduced-motion by replacing movement with fades, never flash more than 3 times per second, allow pausing long animation, and never rely on motion alone to convey meaning.
    Which properties should you animate for performance?
    Transform and opacity, which run on the compositor. Avoid animating width, height, top, left or large shadows, and test on low-end devices at 60 fps.
    What goes into a motion spec for developers?
    Element, property, from/to values, duration, delay, easing token and trigger — ideally as shared motion tokens so design and code stay in sync.

    🛒 Scenario: SwiftCart Mobile Checkout

    SwiftCart is redesigning checkout: cart → address → payment → success. Users say the app "feels laggy" and "I wasn't sure my payment worked". Animations today are all 600 ms linear.

    1️⃣ Task 1 · Fix the Easing & Timing

    Q. What's wrong with "all animations 600 ms linear"?
    • A Nothing
    • B Too slow and mechanical; use 200–400 ms with ease-out/standard curves
    • C Too fast
    • D Should be 2 s
    ✍️ Propose duration + easing for: (a) address sheet opening, (b) sheet closing, (c) checkbox tick.
    Model answer: (a) 300 ms, emphasized decelerate (ease-out). (b) ~220 ms, accelerate (ease-in). (c) 120–150 ms, standard easing.

    2️⃣ Task 2 · Step Transitions

    Q. Moving cart → address → payment, which transition?
    • A Fade through
    • B Shared axis X (slide forward/back)
    • C Random zoom
    • D No transition

    3️⃣ Task 3 · Pay Button Micro-Interaction

    ✍️ Describe trigger, rules, feedback and loops for the Pay button.
    Model answer: Trigger: tap Pay. Rules: disable to prevent double payment; call payment API; on success go to success screen; on failure show reason and options. Feedback: press scale 0.97 (80 ms); label → spinner (200 ms); success: spinner morphs to tick + haptic success (200 ms), then container transform into the success screen; failure: gentle shake (300 ms) + message "No money was deducted". Loops: if the wait exceeds 5 s show "Still confirming with your bank…".

    4️⃣ Task 4 · Accessibility & Performance

    ✍️ List 3 rules you'll apply to keep this motion accessible and smooth.
    Model answer: 1. With reduced motion on, replace slides/morphs with quick fades. 2. Animate only transform/opacity; test on a low-end Android at 60 fps. 3. Success confirmation also uses text ("Payment successful · ₹1,499") and haptics, not motion alone.

    5️⃣ Task 5 · Tool Choice

    Q. You need a testable on-device prototype with real payment-failure logic. Best tool?
    • A After Effects
    • B ProtoPie or Framer (logic + device testing)
    • C Photoshop
    • D PowerPoint
